# 运算优先级实战

## 1. 从一个场景开始

同一道题 $100-3\times(4-10)$，甲算出 82，乙算出 118。谁对？——乙对。甲不是不会优先级规则，而是**在负数混进来的那一刻手一抖**。

这一课破例不讲任何新知识：规则你全都会（第 1 章 50 课《运算优先级与括号》），缺的只是熟练度。全部时间用来练，把"括号最优先、先乘除后加减、同级从左到右"练成不假思索的反应。

## 2. 直觉解释

把混合运算想成**拆快递**：

- 括号是最结实的木箱：不管里面装了什么，最先拆；
- 乘除是缠了三层胶带的包裹：它们把身边的数"抱得紧"，先于散件处理；
- 加减是散装零件，最后组装。

所以 $5-2\times 7$ 从来不该看成 $(5-2)\times 7$——2 和 7 已经被乘号捆成一个包裹，5 只能在旁边等。负号不改变这套次序：它只是让某些包裹里装了带符号的数。

## 3. 规则清单（复习卡）

来自上一章的三条铁律，外加负数时代的三条补充：

1. 先括号，再乘除，后加减；
2. 同级运算从左到右依次进行；
3. 括号可以嵌套：先算最里面一层，再一层层向外剥；
4. 负号紧跟它后面的那个数：$5\times(-3)$ 里的 $-3$ 是一个整体；
5. 遇到“减去一个括号”或“减去负数”，先用上一章法则改写成加相反数，再套用第 1、2 条；
6. 算完先估落点：结果大概在数轴哪个位置？偏得太离谱就回头查符号。

## 4. 分步例题

**例**：计算 $100-3\times(4-10)$。

1. 拆最里面的木箱：$4-10=-6$；
2. 代回原式：$100-3\times(-6)$；
3. 先乘：$3\times(-6)=-18$（异号得负）；
4. 再减：$100-(-18)=100+18=118$。

每一步只做一件事。甲同学错成 82，多半在第 3 步把异号当成了同号——**混合运算的翻车现场，九成在符号**。

## 5. 动手实验

### 实验 1：热身定位

动笔前先在数轴上"看见"落点。拖动滑块感受 $a-b$ 的走法：

```viz
{
  "type": "numberline",
  "title": "热身：a - b 的落点",
  "min": -18,
  "max": 18,
  "op": "-",
  "sliders": [
    { "name": "a", "min": -9, "max": 9, "step": 1, "value": 3 },
    { "name": "b", "min": -9, "max": 9, "step": 1, "value": 8 }
  ]
}
```

两个挑战：

1. 让落点正好停在 $-5$，并找出**两组**不同的 $(a,b)$；
2. 把 $a$ 拖成负数，观察"负减正越减越小、负减负反而回头的"现象。

以后每做一道混合运算，都可以先心估落点区间——答案偏出区间，符号错误当场现形。

### 实验 2：让中间结果显形

```python title="变量接力法：每一步都存下来"
inner = 4 - 10              # 第 1 步：拆括号
product = 3 * inner         # 第 2 步：先乘（注意 inner 是负数）
answer = 100 - product      # 第 3 步：再减（减负数 = 加相反数）

print(f"括号内 = {inner}")
print(f"乘积   = {product}")
print(f"最终   = {answer}")

print(100 - 3 * (4 - 10))   # 一行写法殊途同归
```

变量接力法是排查错误的利器：哪一步输出不符合预期，错误就被困在哪一步。改改数字多跑几轮，直到你能在纸上复现每一步。

### 快问快答

```quiz
20 - 8 - 3 的正确算法是？
- 从右往左：20 - (8 - 3) = 15
- 从左往右：(20 - 8) - 3 = 9 [*]
- 先算 8 - 3，因为“减法更优先”
? 同级运算规定从左到右。减法既不交换也不结合，方向错了答案就错。
```

:::warning[常见误区]

**误区一**："负号可以只提到括号的第一个数前面。"
$-(3-4)$ 是"整个差的相反数"，等于 $1$；随手写成 $-3-4=-7$ 就错了。负号作用于**整个括号**，拆开时每一项都要变号。

**误区二**："加括号总会改变结果。"
$3+(4\times 5)$ 与 $3+4\times 5$ 都是 23。括号只在**打破原有优先级**时才改变命运，顺着优先级加等于白加。

**误区三**："连续加减从哪头开始算都一样。"
不一样：$20-8-3$ 从左到右得 9，从右往左得 15。方向感本身就是规则的一部分。

:::

## 6. 练习

以练代讲，先笔算再运行验证。

**练习 1**：混合运算三连。第一题已示范：

```exercise
# @title: 练习：混合运算三连
# @check: -9
# @check: 21
# @check: 23
# @hint: (2) 给 5-2 套上括号即可；(3) 自编一道"两个小括号的乘积再接加减"的长式子（参考：(-30 + 2 * 9) * (7 - 11) + 5 * (3 - 8)，答案 23）
print(5 - 2 * 7)
print()  # (2)：把第 (1) 题的括号挪个位置，让结果由负转正
print()  # (3)：自己编一道含两个小括号的混合运算，别怕中间出现负数
```

<details>
<summary>点开查看逐步解答</summary>

第 (2) 题：$(5-2)\times 7=21$——对比第 (1) 题的 $5-14=-9$，一对括号改变了命运。
第 (3) 题：$-30+18=-12$；$7-11=-4$；$(-12)\times(-4)=48$（同号得正）；$3-8=-5$；$48+5\times(-5)=48-25=23$。
</details>

**练习 2**：长链条混合运算。下面的代码能跑，但两个答案都不对——请给该加括号的地方加上括号：

```exercise
# @title: 练习：长链条混合运算
# @check: -32
# @check: 80
# @hint: (1) 应为 (7-11) 整体乘上 (6+2)；(2) 是 100 减去 4×(13-8)，别让减法抢先
print(7 - 11 * 6 + 2)
print(100 - 4 * 13 - 8)
```

<details>
<summary>点开查看逐步解答</summary>

```python
print((7 - 11) * (6 + 2))    # -4 × 8 = -32
print(100 - 4 * (13 - 8))    # 100 - 20 = 80
```

初始代码的错法很典型：`7 - 11 * 6 + 2` 里乘法先吞掉了 11 和 6。括号一到位，负数包裹最先拆，顺序立刻清晰。
</details>

**练习 3**：在 $3\ \square\ 4\times 2$ 的方框里填上 $+$ 或 $\times$，哪种填法结果更小？相差多少？

<details>
<summary>点开查看逐步解答</summary>

填加号：$3+4\times 2=11$；填乘号：$3\times 4\times 2=24$。填加号更小，差 13。注意填加号时 $4\times 2$ **依然先算**——你的填法管不了优先级。
</details>

**练习 4**：只添加**一对**括号，使 $9-3\times 2+1$ 的结果最大。

<details>
<summary>点开查看逐步解答</summary>

逐一尝试：$(9-3)\times 2+1=13$；$9-3\times(2+1)=0$；$9-(3\times 2+1)=2$。最大是 13。规律：括号套住"被减的一侧"并把乘法圈进去时，减小的量最少。
</details>

## 7. 选读：计算器是怎么读算式的？

<details>
<summary>选读 · 表达式解析一句话版</summary>

你按 `100-3×(4-10)` 时，计算器并不傻乎乎地从左到右算，而是先把式子整理成一棵"运算树"：根节点是最后执行的那次运算（最外层减法），两个孩子分别是 `100` 和子树 `3×(4-10)`；计算自树叶向树根推进。"先乘除后加减"就是这棵树的生长规则。Python 解析你的代码用的也是同一套办法——所以你在 Python 里写的表达式和数学书写法天然一致。

</details>
