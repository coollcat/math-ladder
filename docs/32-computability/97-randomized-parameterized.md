# 随机化、计数与参数化：三张新的复杂度地图

## 1. 从一个场景开始

浏览器握手的第一个动作是"换一把新锁"，而锁芯需要一个 2048 位的大素数。问题是：**你怎么知道随机挑出来的这个 2048 位奇数就是素数？** 试除要一路试到它的平方根，宇宙年龄都不够跑完。可你的设备一秒就能"确信"它是素数。

诀窍在于松一次口：**允许算法掷骰子，允许它极小概率说错，而这个概率可以由你亲手压到任意小**。压到 $10^{-30}$ 之后，它出错的可能性还不如"键盘同时被宇宙射线打中两次"。

另一头是完全不同的绝境。SAT 问"有没有一组赋值让这个公式成立"；把它改成"**有多少组**赋值让它成立"，问题的难度竟然又跳了一级——数数比判断难得多，连近似地数都要另起一套理论。

中间还有一条缝。旅行商问题在一般图上没有已知快算法，但如果只关心 15 个城市，把 $2^{15}$ 种走法扫一遍完全可以接受。**把指数关进"参数"的笼子**，问题就从不可行变成可行。

本课画出三张新地图：随机化（RP / BPP / ZPP）、计数（#P）、参数化（FPT）。它们是 P-NP 僵局下三条公认的突围路线，加上第 75 课的近似，正好凑成一桌。

## 2. 直觉解释

三条路线的共同前提是：**不再指望"对所有输入都又快又准"**，而是各退一步，换一种赢法。

- **随机**：不再要求百分之百正确，只要"错得像中彩票一样难"。掷一次骰子不够可靠？那就掷 $k$ 次取多数——独立犯错要连错 $k$ 次，错率指数下降。速度一分没丢，只丢了一个可以忽略的正确性尾巴。
- **计数**：把问题从"有没有解"升级成"解有几个"。一旦会数，判断是顺手的副产品（看结果是否大于 0），所以计数至少和判断一样难；而反过来不成立——判"有解"很容易的几个问题，数解却是 #P-难的。
- **参数化**：把复杂度里的指数项，从输入的总规模 $n$ 挪到一个小参数 $k$ 上。$n$ 可以大到无法无天（图上的顶点几十万个），只要 $k$ 小，算法就用得起来。

随机算法内部还分两派。**蒙特卡洛**派："时间一定有保证，答案可能有点歪"——多跑几轮把歪的地方磨平。**拉斯维加斯**派："答案一定对，时间可能有点浪"——运气不好就重来，但交出来的东西从不掺假。这不是两种算法风格的区分，而是两个复杂度类之间的分界。

## 3. 正式定义

**定义一（随机化多项式时间）**：随机化图灵机在多项式时间内停机，但每一步可以掷硬币。对输入 $x$，记 $P[M(x)=1]$ 为"随机比特均匀抽取时接受的概率"。三个类由此划开：

| 复杂度类 | $x\in L$ 时 | $x\notin L$ 时 | 错误长什么样 |
| --- | --- | --- | --- |
| RP | 接受概率 $\ge 1/2$ | 一定拒绝 | 单边：可能漏报，绝不误报 |
| co-RP | 一定接受 | 拒绝概率 $\ge 1/2$ | 单边：可能误报，绝不漏报 |
| BPP | 接受概率 $\ge 2/3$ | 拒绝概率 $\ge 2/3$ | 双边错误，两边都很小 |
| ZPP | RP ∩ co-RP | 期望多项式时间 | 拉斯维加斯：答案永远正确 |

| 符号 | 名字 | 说明 |
| --- | --- | --- |
| $M$ | 随机化图灵机 | 手里有一枚理想硬币的判定程序 |
| $r$ | 随机比特串 | 一次运行的全部运气，长度是 $n$ 的多项式 |
| $k$ | 重复轮数 | 独立重跑的次数，也是错误率的旋钮 |
| $\epsilon$ | 目标错误率 | 想压到多低就压到多低 |

**放大引理**：把 BPP 算法独立跑 $k$ 次、取多数票，错误率降到 $2^{-\Omega(k)}$。要把错误率压到 $\epsilon$ 以下，只需 $k=O(\log(1/\epsilon))$ 轮——**轮数只按对数增长**，这就是"错得像中彩票"在数学上的兑现方式。

**定义二（#P 计数类）**：$\#P$ 是一类**函数**（不是语言）。$f\in\#P$ 当存在多项式时间验证器 $V$ 使得

$$f(x)=\#\lbrace\,y : |y|\le \mathrm{poly}(|x|),\ V(x,y)=1\,\rbrace$$

也就是"把所有可能的证书 $y$ 逐个试一遍，数出能让验证器点头的那些"。$\#\mathrm{SAT}$ 就是数一个公式有多少组成真赋值。

**关键关系**：如果某个 $\#P$ 函数能多项式时间算出，那么对应的 NP 判定问题也能多项式时间判出（把数出来的结果和 0 比一比）。于是 $\mathrm{NP}\subseteq\mathrm{P}^{\#\mathrm{P}}$——**计数不简单于判定**；而反过来不行，判定容易的问题数起来照样可以很难。

**定义三（固定参数可解 FPT）**：一个问题带上参数 $k$（例如"顶点覆盖不超过 $k$ 个点"）。若存在算法在

$$f(k)\cdot \mathrm{poly}(n)$$

时间内解决它，其中 $f$ 只依赖 $k$，就称它是 **FPT（固定参数可解）** 的。读法很重要：把 $k$ 钉死成一个常数，算法就成了多项式；指数部分被单独隔离在 $f(k)$ 里，与 $n$ 无关。

## 4. 分步例题

**例 1（蒙特卡洛，单边错误）：判一个数是不是合数**

Miller–Rabin 的判断逻辑（简化后的骨架）：

1. 随机挑一个底 $a\in\lbrace2,\dots,n-1\rbrace$；
2. 检查费马式条件 $a^{n-1}\equiv 1\pmod n$（以及若干平方根条件，这里略）；
3. 条件被破坏 → 立刻断言"**$n$ 是合数**"，并且**这个断言从不出错**：素数一定满足条件，过不了关的一定不是素数；
4. 条件全过 → 只能说"$n$ 是素数"，而这可能是冤枉——某些合数（伪素数）恰好也过得去。

所以错误只有一个方向：**把合数说成素数**。单轮欺骗成功的概率有理论界 $1/4$；跑 $k$ 轮独立抽查，误判率降到 $1/4^k$。$k=50$ 时约 $10^{-30}$——这就是"我说不清它是素数，但我敢拿它签合同"的底气所在。语言 $\lbrace$合数$\rbrace$ 因此落在 RP 里。

**例 2（拉斯维加斯：期望快 vs 最坏慢）**：随机化快排每次随机选主元。

1. 主元随机，期望比较次数 $O(n\log n)$；
2. 但最坏情况仍然存在——运气极差时主元总挑到最大值，退化成 $O(n^2)$；
3. 它交出的排序结果**永远是对的**，随机的只是耗时。这正是 ZPP 的味道：**答案不打折，时间按期望记账**。

**例 3（参数化：顶点覆盖的有界搜索树）**：五边形 $C_5$（顶点 1–5 成环），问最少几个点能盖住全部 5 条边。

1. 任取一条边，比如 $(1,2)$。要盖住它，只有两种可能：**选 1**，或**选 2**；
2. 分支一（选 1）：所有含 1 的边一次性作废，剩下 $(2,3),(3,4),(4,5)$；
3. 分支二（选 2）：剩下 $(3,4),(4,5),(5,1)$；
4. 对每个分支再来一次，直到"没有边剩"（成功）或"没手可用了"（失败）；
5. 分支树深度不超过 $k$，每层至多分两支，因此节点数不超过 $2^{k+1}-1$；每层只做一次"扫边、删边"，代价 $O(m)$。

总代价 $O(2^k\cdot m)$：**指数只跟 $k$ 有关，$n$（顶点数、边数）待在多项式里**。取 $k=3$ 得解 $\lbrace1,2,4\rbrace$（三个点盖住五边形，且 $k=2$ 无解）——五边形的最小顶点覆盖正好是 3，这正是练习里那两行输出。

### 实验 2（python）：蒙特卡洛地判素数，错误率自己会掉下去

```python title="费马测试：真正的随机算法骨架"
import random                                 # random：标准库的伪随机数工具箱（第 0 章已引入）

def fermat_test(n, rounds):
    # 蒙特卡洛风格：一定不会冤枉素数，只可能放过个别合数
    for _ in range(rounds):                   # _ 是"占位变量"：轮次本身用不上，只需要循环次数
        a = random.randint(2, n - 1)          # randint(起, 止)：随机挑一个底 a
        if pow(a, n - 1, n) != 1:             # pow(x, y, m) 是模幂：素数一定满足费马小定理
            return False                      # 当场揭穿：n 一定是合数
    return True                               # 没被揭穿：很可能是素数

print(fermat_test(97, 20))                    # 97 是素数，怎么抽都过
print(fermat_test(91, 20))                    # 91 = 7 × 13，抽几轮就被揭穿
```

两行输出都是令人满意的：素数全过、合数被逮。但别急着信任它——费马测试手里有个已知的窟窿：

```python title="Carmichael 数 561：骗子底占了大多数"
n = 561                                       # 561 = 3 × 11 × 17，是一个 Carmichael 数
liars = 0                                     # 统计"骗子底"：让合数通过检验的那些 a
total = 0
for a in range(2, n):                         # 逐个试所有可能的底（真实场景当然不会这么干）
    total = total + 1
    if pow(a, n - 1, n) == 1:                 # 明明 n 是合数，这一关却被骗过去了
        liars = liars + 1
print(liars, total, f"{liars / total:.1%}")   # {:.1%}：按百分比格式打印小数
```

输出 `319 559 57.1%`：超过一半的底都能骗过费马条件（精确地说，凡是与 561 互素的底都会上当，共 $\varphi(561)-1=320-1=319$ 个）。工程上因此换成 Miller–Rabin：它多检查几步"平方根"条件，把单轮错误率压到 $1/4$ 以下，Carmichael 数再也骗不过去。**"随机 + 重复"能压错误率，前提是单轮真的没被系统性骗过**——这是本课最值得记下的一条工程教训。

再看重复轮数是怎么把错误率按指数撕下来的：

```python title="错误率与轮数：k 只按对数增长"
p_single = 1 / 4                              # Miller–Rabin 单轮误判率的上界
print("轮数 k | 误判率上界")
for k in [1, 5, 10, 20, 50]:
    print(f"{k:>6} | {p_single ** k:.3e}")    # f-string：{:>6} 右对齐，{:.3e} 科学计数法
```

20 轮就已经小于 $10^{-12}$，50 轮约 $10^{-30}$——比磁盘静默出错的概率还低。注意 $k$ 从 20 涨到 50 只多跑 30 次，错误率却掉了 18 个数量级：**这就是"指数下降"和"多花一点点时间"之间的交易**。

### 实验 3（python）：参数化——顶点覆盖的分支搜索

```python title="O(2^k · m)：指数被赶进 k 的笼子"
calls = 0                            # 全局计数器：记下函数被调用了几次

def has_cover(edges, k):
    # edges：还没被盖住的边；k：还剩几个名额
    global calls                     # global：声明下面改的是外层那个 calls，而不是新建局部变量
    calls = calls + 1
    if not edges:                    # not edges：列表为空时为真——没有边要盖了
        return True
    if k == 0:                       # 还有边，却没人手了
        return False
    u, v = edges[0]                  # 拆包：把这条边拆成两个端点
    rest = [e for e in edges if u not in e]     # 列表推导：u 进覆盖后，含 u 的边全部作废
    if has_cover(rest, k - 1):       # 分支一：选 u
        return True
    rest = [e for e in edges if v not in e]
    return has_cover(rest, k - 1)    # 分支二：选 v

cycle = [(1, 2), (2, 3), (3, 4), (4, 5), (5, 1)]    # 五边形 C5
print(has_cover(cycle, 3), calls)    # 3 个点够：{1,2,4}
calls = 0                            # 重置计数器，单独数下一问
print(has_cover(cycle, 2), calls)    # 2 个点盖不住五边形
```

输出 `True 5` 与 `False 7`：$k=3$ 只探了 5 个节点，$k=2$ 探了 7 个，都远小于"枚举所有点集"要试的 $2^5=32$ 种。更关键的是**这个数字不随图变大而膨胀**：把五边形换成一千个点的环，只要 $k$ 还是 3，分支树的形状和规模一模一样，多出来的只是每层扫边的开销 $O(m)$。这就是 FPT 的全部承诺——**指数的账只让 $k$ 来付**。

## 6. 常见误区

:::warning[常见误区]

**误区一**："随机算法就是不准的算法。" 随机买的是一次大幅提速，正确性可以用重复买回来——放大引理保证 $k$ 轮多数表决后错误率是 $2^{-\Omega(k)}$，而 $k$ 只需要 $O(\log(1/\epsilon))$。现代密码库里到处跑着随机算法，它们的失败概率比硬件故障还低。真正需要小心的是**别被系统性欺骗**：费马测试之所以被淘汰，不是错率不够小，而是存在一整类 Carmichael 数能骗过它。

**误区二**："#P 和 NP 差不多，只是换个问法。" 计数**严格更难**：会数就会判（看结果是否大于 0），所以 #P 难蕴含 NP 难，反之不成立。更狠的是，$2^n$ 个子集要数，连"近似到 1% 误差"都可能做不到——近似计数得请出马尔可夫链蒙特卡洛那一整箱工具（第 39 章），而且仍然只对一部分问题有效。

**误区三**："参数化就是把输入变小，本质还是暴力枚举。" 有界搜索树确实是暴力，但账本完全不同：朴素枚举是 $O(2^n)$，参数化是 $O(2^k\cdot n)$——$n$ 再大也只付多项式。而且 FPT 不只有这一招：**核化**先用多项式时间把输入压到只跟 $k$ 有关的大小，再暴力；有的问题连核化都有理论大小下限。最后别忘了反面的存在：顶点覆盖是 FPT，但"在图上找 $k$ 个两两相邻的点"（$k$-团）是 W[1]-难的——**参数化能救的问题，是有边界的**。

:::

## 7. 练习

**练习 1**：下面的顶点覆盖搜索漏了一半分支，能跑但两问都答错。修到判题通过：

```exercise
# @title: 练习：顶点覆盖的分支少了半边
# @check: True
# @check: False
# @hint: 要盖住一条边 (u, v)，可以让 u 进覆盖，也可以让 v 进覆盖——两个分支都要试一遍，任一分支成功即成功。现在代码只试了 u。
def has_cover(edges, k):
    if not edges:
        return True
    if k == 0:
        return False
    u, v = edges[0]
    rest = [e for e in edges if u not in e]
    return has_cover(rest, k - 1)      # ← 只有这一个分支

cycle = [(1, 2), (2, 3), (3, 4), (4, 5), (5, 1)]
print(has_cover(cycle, 3))
print(has_cover(cycle, 2))
```

<details>
<summary>点开查看逐步解答</summary>

补上"选另一个端点"的分支即可：

```py
u, v = edges[0]
if has_cover([e for e in edges if u not in e], k - 1):    # 分支一：选 u
    return True
return has_cover([e for e in edges if v not in e], k - 1)  # 分支二：选 v
```

只看分支一，程序会把"必须选另一个端点"的解全部错过：$k=3$ 时它选 1 →（剩 $2\!-\!3\!-\!4\!-\!5$）→ 选 2 → 选 3，走到 $k=0$ 时还剩边 $(4,5)$，判负，于是第一问也输出 `False`。补上分支二后，第一问在 $\lbrace1,2,4\rbrace$ 处成功、第二问两条路都走不通——输出 `True` 与 `False`，与五边形最小顶点覆盖为 3 的事实吻合。**"或"的分支必须全部试过才能判负，这是搜索类算法的通用戒律**：漏一条分支，答案就从"不确定"变成"确定地错"。

<details>
<summary>点开查看逐步解答</summary>

前半句：给定 $x$，若能在多项式时间算出 $f(x)=\#\lbrace y:V(x,y)=1\rbrace$，那么只要判断 $f(x)>0$，就顺带解决了对应的 NP 判定问题——**数数是判断的"超集操作"**，于是 NP $\subseteq$ P$^{\#\text{P}}$。

后半句的例子：**完美匹配**。判断一个二分图有没有完美匹配很容易（多项式时间的匹配算法，第 29 章的那类工具就能办），但**数它有多少个完美匹配**是 #P-完全的——哪怕图只有几百个点，精确计数也远超任何现实算力。这正是"判定容易、计数困难"的典型对照：判断只需要找到一个解，计数却要把所有解一个不漏地穷举清楚。物理里的永久值（permanent）就是这个计数的矩阵形式，和行列式只差一个符号，难度却天壤之别。

</details>

## 8. 选读：核化与"参数化也有天花板"

<details>
<summary>选读 · FPT 的两条腿：有界搜索树与核化</summary>

有界搜索树只是 FPT 的入门招式，它的运行时间 $f(k)=2^k$ 在 $k=40$ 时就寸步难行了。工程上更常用的是**核化**：先用多项式时间把输入"拧干"，得到一个只与 $k$ 有关、大小不超过 $g(k)$ 的**核**，再对核暴力。

以顶点覆盖为例，有一条漂亮的化简规则。**度数规则**：若某个顶点的度数大于 $k$，它必进覆盖——因为它若是被漏掉，它的 $>k$ 个邻居都得进来，名额就不够了。于是逐个套用这条规则：每发现一个"必进"的点，就把它和它的边一并删去、$k$ 减一；若某一步 $k<0$，立刻判无解。当规则再也套不上时，剩下每个顶点的度数都 $\le k$。再用第二条规则继续削：每个顶点最多贡献 $k$ 条边，于是剩下的边数不超过 $k^2$——**核的大小是 $O(k^2)$**。$k=5$ 时核最多 25 条边，暴力扫它是瞬间的事。

有了这条腿，"$n$ 很大"就彻底不构成威胁了。

但参数化的世界里也有硬墙。$k$-团问题（找 $k$ 个两两相邻的点）被认为是 W[1]-难的：**它不属于 FPT，除非参数化复杂度层级塌掉**——这是与 P=NP 同量级的猜想。近二十年还有一条更强的经验假设 **ETH（指数时间假设）**：它说 3-SAT 无法在 $2^{o(n)}$ 时间内解决。ETH 一旦成立，就能反推出"顶点覆盖的 $2^{O(k)}$ 指数**不可能**再压成 $2^{o(k)}$"，也就是说现成算法已经接近最优了。

回头看这节课的三张地图，它们的共同姿态很一致：**不与 P-NP 硬碰，而是重新定义什么叫"赢"**。近似换精度、随机换确定性、参数化换规模——数学家没有攻破那座墙，而是在墙边开出了三条能通车的路。

</details>
