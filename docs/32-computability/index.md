# 可计算性与复杂度

有些问题只是还没找到快算法，有些问题原则上没有算法。本章建立这条边界，并解释为什么多项式时间会成为“可行计算”的分水岭。

本章你会学到：

1. [计算模型与算法直觉](./10-computational-models.md)——一个小朋友用手指算 $13+26$，另一个背过“个位相加、满十进一”，还有一个直接心算凑整；
2. [图灵机](./15-turing-machine.md)——假如你只剩一条无限长的纸带、一个能看清当前格子的眼睛、一支能擦写的笔和一张有限规则表，还能完成加法、搜索甚至解释程序吗？；
3. [可判定性与语言](./20-decidability-languages.md)——老师批卷有两种风格：一种保证每份卷子都给出“对”或“错”；
4. [通用图灵机](./30-universal-machine.md)——计算器只会算术，游戏机只跑某个卡带，可现代电脑却能安装不同软件；
5. [停机问题](./35-halting-problem.md)——调试时你最想拥有的工具也许不是更快电脑，而是一盏红灯：程序即将死循环就亮起来；
6. [归约](./40-reductions.md)——你不会开陌生的锁，但你会开自家门锁；
7. [不可判定问题族](./45-undecidable-families.md)——停机问题不可判定之后，你可能以为只有这个奇怪的自指问题例外；
8. [P 与 NP](./50-p-np.md)——给你一个数独答案，检查每行每列很快；
9. [多项式归约](./55-polynomial-reductions.md)——把课程表问题变成图着色，需要给每位老师、每间教室和每节课造点，再把冲突画成边；
10. [NP 完全性](./60-np-completeness.md)——如果有人在 NP 这片大陆上找到一座最高峰，并且所有山峰都能用缆车连到它，那么只要证明这座峰有快路径…；
11. [SAT 与 3-SAT](./65-sat-three-sat.md)——一场活动有三个约束：甲来则乙不来；
12. [图着色、团与独立集](./70-graph-reductions.md)——排课时，两位老师不能在同一时段进同一间教室；
13. [近似与启发式出口](./75-approximation-heuristics.md)——快递员要访问一百个地址，旅行商问题没有已知的多项式最优算法；
14. [复杂度类地图](./80-complexity-map.md)——旅行时你会问三个问题：能到吗、要多久、要带多少行李；
15. [PSPACE 与指数时间](./85-pspace-exp-time.md)——下一盘棋时，你不需要同时记住所有未来棋局；
16. [方法地图](./90-methods-map.md)——拿到新问题时，最有价值的第一个动作往往不是写代码，而是问：它属于哪种困难？；
17. [哥德尔不完备定理选讲](./95-godel-incompleteness.md)——自指句如何借编号术谈论自己：足够强的形式系统无法证明自身的完备与一致。

## 实战挑战 · 杀毒软件与停机问题的哲学困境

每个用过电脑的人都许过同一个愿：装一个杀毒软件，它扫描任何程序后准确告诉你"这个有没有害"。1984 年正式发表论文的计算机科学家弗雷德·科恩（Fred Cohen）证明了这个愿望在逻辑上不可能完全实现。他的证明几乎就是图灵 1936 年停机问题证明的翻版：先假设完美检测器存在，再构造一个"看检测器脸色行事"的程序，让它无论被怎么判都自相矛盾。用第 45 课的话说，"是否恶意"是由程序行为划定的非平凡语义性质——正好落在 Rice 定理的射程里。

**思辨题**

**(a)** 假设存在完美检测器 `DETECT`：对交给它的任何程序都停机，并永远正确地回答"有害"或"无害"。请你构造一个程序 `Q`，让 `DETECT` 在面对 `Q` 时左右为难。（提示：让 `Q` 读到自己被判成什么，再做相反的事——这正是第 35 课叛逆者 `D` 的构造思路。）

**(b)** 分别讨论两种情形：`DETECT` 判 `Q` 无害会发生什么？判 `Q` 有害又会发生什么？两个方向各自推出什么矛盾？

**(c)** 既然完美检测器不存在，现实中的杀毒软件为什么依然天天在抓病毒？它们悄悄放弃了哪个承诺，又用什么方式补偿？

先凭直觉选两题，再到折叠区对答案：

```quiz
一家安全厂商宣称"本引擎能准确判定任何程序是否有害"。按本章理论，最准确的评价是什么？
- 只要病毒样本库足够大，迟早能做到
- 若"有害"由程序行为定义且非平凡，这样的完美判定器原则上不存在 [*]
- 停机问题只适用于图灵机，与真实计算机无关
? 科恩 1984 年用停机式反证法证明了完美检测不可判定；真实产品做的是误报与漏报之间的工程折中。
```

```quiz
某公司把引擎调成"绝不冤枉一个好文件"（零误报）。理论上它能同时做到零漏报吗？
- 能，把启发式规则写得足够细就行
- 能，只要再禁止一切联网行为
- 不能；极端做法是全部放行，确实零误报，但也形同虚设 [*]
? 完美判定器不存在，两类错误无法同时归零；零误报可以平凡达成——把风险全推给漏报。
```

<details>
<summary>点开查看逐步解答</summary>

**(a)(b) 科恩式构造。** 反证法开局：假设 `DETECT` 总停机且永不犯错。构造程序 `Q`：

1. `Q` 先把自己的源码交给 `DETECT` 判定；
2. 若 `DETECT(Q)` 回答"无害"，`Q` 立刻执行破坏动作（复制自己、加密文件）；
3. 若 `DETECT(Q)` 回答"有害"，`Q` 什么都不做，直接退出。

现在问：`Q` 到底有没有害？

- 情形一：`DETECT` 判 `Q` 无害 → `Q` 按剧本发作 → `Q` 实际有害 → 判决错了；
- 情形二：`DETECT` 判 `Q` 有害 → `Q` 安静退出、毫无恶行 → 从行为看它无害 → 判决又错了。

两个方向都推翻"永不犯错"，所以这样的 `DETECT` 不存在。`Q` 正是第 35 课那个"对角线叛逆者 D"的网络安全版：两者都利用"程序可以拿到关于自己的判决"这一自指自由。

**(c) 工程出口。** 不可判定不等于不实用，关键是看清放弃了什么：

- 特征码扫描只查程序文本里的字节模式——这是第 45 课说的语法性质，可判定，只是抓不住改了外壳的老病毒；
- 启发式与行为分析观察"批量改文件名""高熵写入"等可疑举动，但备份软件也会这么干，于是出现误报；
- 沙箱让可疑程序限时试跑，等于放弃了对所有输入的完备性承诺，换取有限时间内的强证据；
- 多层防御互相补漏：单层检出率不高没关系，只要各层的洞不在同一处。

厂商真正在校准的不是"对错"，而是误报与漏报之间那条成本曲线——这正是第 75 课"承认困难后还能交付什么"的日常版本。

</details>

## Python 实战 · 把「能算」与「查得快」写成代码

上面是纸面上的思辨；这一节把本章两个最硬的结论落成可运行的 Python——一台真的会算的图灵机，和一个真的"查答案比找答案快"的验证器。

### 实战一：图灵机的二进制加一

第 15 课的图灵机只有一条纸带、一个读写头、一张规则表。下面用 Python 模拟一台最微小的图灵机——给二进制数加一。纸带 `[1, 0, 1]` 是二进制 101（最低位在最右），读写头从最低位（最右）出发，规则表只有两条：**遇到 1 改成 0、向左进一位继续；遇到 0 改成 1、停机**。初始代码把两条规则对调了，修到纸带变成 `[1, 1, 0]`：

```exercise
# @title: Python 实战：图灵机的二进制加一
# @check: [1, 1, 0]
# @hint: 遇到 1 要改成 0 并左移继续进位；遇到 0 才改成 1 停机。现在两条规则恰好对调了。
tape = [1, 0, 1]          # 纸带：二进制 101，最低位在最右
head = len(tape) - 1      # 读写头从最低位（最右）开始
halted = False            # 停机标志：halted = 真 表示进入停机状态

for step in range(10):    # 最多走 10 步，防呆：进位最多走完整条纸带
    if halted:
        break
    if tape[head] == 0:       # ← 问题在这：遇到 0 应该改成 1 并停机
        tape[head] = 0        #    这里却改成 0、继续左移
        head = head - 1
    else:                     #    遇到 1 应该改成 0、左移继续进位
        tape[head] = 1        #    这里却改成 1、直接停机
        halted = True

print(tape)
```

<details>
<summary>点开查看逐步解答</summary>

加一的进位规则：最低位是 1，就要把它"翻成 0"并往更高位（左边）借位继续；一旦遇到 0，就把它"翻成 1"并停下。所以正确的两条规则是——**遇到 1：改 0、左移；遇到 0：改 1、停机**。

```python
if tape[head] == 1:      # 遇到 1：改成 0，向左进一位继续
    tape[head] = 0
    head = head - 1
else:                    # 遇到 0：改成 1，停机
    tape[head] = 1
    halted = True
```

手工走一遍：head=2 处是 1 → 改成 0、head 左移到 1；head=1 处是 0 → 改成 1、停机。纸带变成 `[1, 1, 0]`——二进制 110，恰好是 101 + 1 = 110。一台图灵机就这样"算"出了加法：没有魔法，只有纸带、读写头与规则表三条朴素的部件。

</details>

### 实战二：NP 验证器——查答案比找答案快

第 50 课的核心洞察是"找答案慢、查答案快"。子集和问题：给一组数字和一个目标，问有没有子集加起来正好等于目标？自己找要枚举 $2^n$ 个子集；但别人递给你一个"候选子集"（证书），验证它只需一遍累加——多项式时间。下面这个验证器累加错了东西，修到输出 `True`、`False`：

```exercise
# @title: Python 实战：NP 验证器——查答案比找答案快
# @check: True
# @check: False
# @hint: 验证器累加的是"证书下标指向的数字"（numbers[idx]），不是下标本身。
numbers = [5, 8, 9, 14]    # 数字集合
target = 22                # 目标和

def verify(cert):          # 验证器：把证书指向的数字加起来，看是否等于目标
    total = 0
    for idx in cert:
        total = total + idx    # ← 问题在这：加了下标本身，而不是下标指向的数字
    return total == target

print(verify([0, 1, 2]))   # 证书一：下标 0、1、2 指向数字 5、8、9
print(verify([0, 3]))      # 证书二：下标 0、3 指向数字 5、14
```

<details>
<summary>点开查看逐步解答</summary>

验证器要把证书里每个下标**指向的数字**累加，而不是把下标本身相加：

```python
total = total + numbers[idx]   # 累加下标 idx 指向的数字 numbers[idx]
```

改完：证书一 $5 + 8 + 9 = 22$，等于目标 → `True`；证书二 $5 + 14 = 19 \neq 22$ → `False`。这个 `verify` 就是 NP 定义的活体：给一个解，多项式时间验得干干净净；但没人给你解时，你就得自己从 $2^4 = 16$ 个子集里翻——数字再多点，指数爆炸立刻把"自己找"压垮。**查答案与找答案之间的这道鸿沟，正是 P 与 NP 的悬案。**

</details>
