# 停机问题

## 1. 从一个场景开始

调试时你最想拥有的工具也许不是更快电脑，而是一盏红灯：程序即将死循环就亮起来。可惜这盏灯不可能对所有程序都造出来。

这不是工程不够好，而是逻辑上有一堵墙。停机问题的证明只有几步，却改变了我们对“算法万能”的想象。

## 2. 直觉解释

停机问题问的是：给定程序 $P$ 和输入 $w$，$P$ 最终会停吗？

有些情况容易判断，比如一眼看到有限循环；有些情况很难；关键是存在没有任何算法能完美处理的极端样本。

用“说谎者表格”看它。想象一张巨大表格：第 $i$ 行是第 $i$ 个程序，第 $j$ 列是输入 $j$，格子写“停”或“不停”。现在构造一个叛逆者 $D$：在第 $i$ 行做与对角线相反的事——若程序 $i$ 对输入 $i$ 会停，$D$ 就不停；若不会停，$D$ 就立刻停。

这里只需要“有限表格先看清翻转规则”的直觉。每个程序都有有限编码，所以通用图灵机保证了它们能被机械地排入这张表；完整的可数性理论会在逻辑与集合章继续展开。

那么 $D$ 面对自己的描述会发生什么？它停当且仅当它不停。这个自指矛盾说明那张完美预测表不可能由任何总停机算法生成。

## 3. 正式定义

定义停机语言

$$HALT=\lbrace \langle P,w\rangle : P \text{ 对输入 } w \text{ 在有限步后停机}\rbrace$$

**定理（停机问题不可判定）**：不存在总是停机的图灵机 $H$，使得对所有程序 $P$ 和输入 $w$，若 $P(w)$ 停机则 $H$ 接受，否则 $H$ 拒绝。

证明采用反证法。若 $H$ 存在，用它构造

$$D(P)=\text{loop if }H(P,P)=1;\ \text{accept if }H(P,P)=0$$

$D$ 是合法程序，因为它只在 $H$ 返回后再行动。现在问 $D(D)$：

1. 若 $D(D)$ 停机，则 $H(D,D)$ 必须接受，于是 $D(D)$ 进入死循环；
2. 若 $D(D)$ 不停机，则 $H(D,D)$ 拒绝，于是 $D(D)$ 立刻接受并停机；
3. 两种情形都得到矛盾，所以 $H$ 不存在。

注意：这里否定的是对所有输入都完美的总停机判定器，不是说任何具体程序的停机都不能分析。

## 4. 分步例题

例题：判断三个小片段是否一定停机。

1. `print(1)`：无循环，一定停机。
2. `for i in range(10): pass`：循环次数固定，一定停机。
3. `n = 10; while n > 0: n -= 1`：每轮严格减少且停在 0，一定停机。

这些例子都能可靠分析。停机问题不可判定性的力量出现在任意程序、任意嵌套、任意数学猜想的组合中：没有一个算法能把所有这类分析一次做完。

## 5. 动手实验

### 实验 1：对角线翻转


每一步都不是抽象口号：翻转依赖通用机可以把 $P$ 同时当程序和输入；矛盾依赖 $D$ 能在 $H$ 之后继续动作。

### 实验 2：只模拟有限对角表

```python title="有限世界里的对角翻转"
behaviors = [
    [1, 0, 1],   # 程序 0 对输入 0/1/2 是否停机：1 表示停
    [0, 1, 1],
    [1, 1, 0]
]

def rebel(row):                       # rebel 计算第 row 行的对角叛逆值
    diagonal = behaviors[row][row]    # 双下标取出对角格
    return 1 - diagonal               # 1 变 0，0 变 1

for p in range(len(behaviors)):       # range 生成 0 到长度减一的整数序列
    print(p, behaviors[p][p], rebel(p))
```

输出显示每个对角格都被翻转。若有人声称某张完整表来自完美预测器，叛逆者必然还在表里，却又与自己的格子冲突。

## 6. 常见误区

:::warning[常见误区]

**误区一**：你以为停机问题只是“有些程序太难”。证明给出的是原则上不存在总停机判定算法，而非目前没找到。

**误区二**：你以为可以靠“跑一段时间没停”来判断不停。超时只能给出近似警告，不能区分慢和永不停。

**误区三**：你以为所有静态分析都没用。限定语言、限制循环结构或允许超时的工具仍然非常有价值；它们只是放弃了对所有程序的完备性。

:::

## 7. 练习

```exercise
# @title: 练习：修正对角翻转方向
# @check: 0 0
# @check: 1 1
# @check: 2 1
# @hint: 表中 1 表示停机；叛逆者要在对角格为停时输出不停，反之输出停。
table = [
    [1, 0, 1],
    [0, 0, 1],
    [1, 1, 0]
]

def rebel_value(i):
    return table[i][i]

for i in range(3):
    print(i, rebel_value(i))
```

初始函数照抄对角线，没有翻转。请把返回值改成相反值；三行数据和三次循环已经准备好，不需要再扩展结构。

<details>
<summary>点开查看逐步解答</summary>

用整数运算可写 `return 1 - table[i][i]`，也可写条件语句增强可读性。三张对角格依次是 1、0、0，翻转后分别产生 `0`、`1`、`1`。这个看似小小的“相反回答”，正是无限证明里制造自相矛盾的发动机。

</details>

## 9. 选读：半可定性的一面

<details>
<summary>选读 · HALT 是递归可枚举但不可判定</summary>

$HALT$ 至少是半可定的：直接模拟 $P(w)$，若停机就接受。因此它属于递归可枚举语言。若它的补集也可枚举，就能让两侧赛跑并在有限时间内裁决每一例，从而判定 $HALT$，与定理冲突，所以补集不可枚举。这个不对称解释了为什么“找到停机证据容易，确认永不停机”原则上困难。

</details>
