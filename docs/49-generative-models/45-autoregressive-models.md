# 自回归模型与条件分解

## 1. 从一个场景开始

你在输入框敲下"今天天气"，候选栏已经排好队："不错""很好""如何"。手机并不是先想好整句再显示，而是**每敲一个字，就重新猜一次下一个字**。

GPT 这类语言模型写文章的方式一模一样：一次只吐一个 token，吐出来的部分原样摆在自己面前当上下文，再猜下一位。把"一句话出现的概率"整张算出来看似要一张天文数字大的联合概率表——但逐位来猜，每次只需要一张小表。这个"切开大表"的动作，就是本课的全部剧情。

## 2. 直觉解释

核心道具只有一件：**概率链式法则**。它说：一个长序列的概率，可以无损地改写成"第一位自己的概率 × 第二位看到前文后的概率 × 第三位看到前文后的概率……"。就像填一排格子：

- 第 1 格随便填（不用看别人）；
- 第 2 格抬头看第 1 格再填；
- 第 3 格抬头看前两格再填……

**生成 = 逐格打字**：从左到右每位采样一次，新写的字立刻变成后面格子的"前文"。同一个思想的两种皮肤：

- **PixelRNN / 图像版**：从左上角像素出发，一行扫到底，每位条件分布预测的是"下一个像素的颜色"；
- **GPT / 文本版**：token 流水线，每位条件分布预测的是"下一个词"。

还有一处张力值得提前立牌：**训练可以并行，生成本身必须串行**。训练时标准答案早已写在训练集里，模型可以一次性对整句所有位置同时算损失（这招叫 teacher forcing，见选读）；可轮到自己生成时，下一位依赖自己刚写的这位——只能一位一位憋出来。这两幅面孔都是自回归模型的本相。

## 3. 正式定义

$$p(x_1, x_2, \ldots, x_T) = \prod_{t=1}^{T} p\left(x_t \mid x_1, \ldots, x_{t-1}\right)$$

| 符号 | 名字 | 含义 |
| --- | --- | --- |
| $x_t$ | 序列的第 $t$ 位 | 一个字、一个 token 或一个像素 |
| $x_{<t}$ | 前缀 | 已经写出、摆在本位面前的全部上文 |
| $p(x_t \mid x_{<t})$ | 条件分布 | 一张小表：看着前文，给每个候选项发概率 |

两条立刻能验证的性质：

1. **整体自动归一化**：每个因子自己就是合法条件分布（对候选项求和为 1），连乘起来无需再做任何"善后"；
2. **分解方式不唯一但事实无损**：先写"猫"还是先写句子末字，链式法则给出同一结果；工程上固定从左往右，纯粹是为了让"猜下一位"这件事可学习。

## 4. 分步例题

三字短句"猫·瞪·鼠"。取三位条件概率：$p(\text{猫})=0.3$，$p(\text{瞪}\mid\text{猫})=0.4$，$p(\text{鼠}\mid\text{猫瞪})=0.5$。

1. 第一位：不看任何人，$\text{猫}$ 以 $0.3$ 的概率登场；
2. 第二位：前文是 $\text{猫}$，查表得 $0.4$；
3. 第三位：前文升级成 $\text{猫瞪}$，查表得 $0.5$；
4. 连乘：$0.3 \times 0.4 \times 0.5 = 0.06$——这句话占 $6\%$ 的比重。位数一多连乘只会越乘越小，这正是下一实验要用曲线看清的事。

### 实验 2（python）：手搓一个两字符迷你 GPT

语料只有七个小句子。我们统计"看到某字后下一个字是谁"的小表，然后让机器按这套条件分布逐格打字：

```python title="统计条件表并逐位采样"
import random

random.seed(7)                   # 固定种子：采样结果可复现
corpus = ["数学好玩", "数学有趣", "数学真妙", "数学习题",
          "习题很难", "游戏有趣", "游戏真好玩"]
vocab = ["数", "学", "习", "题", "游", "戏", "好", "玩",
         "真", "妙", "有", "趣", "很", "难"]

counts = {}                      # 大表里的 key 是前文字符
for s in corpus:
    for i in range(len(s) - 1):
        cur = s[i]
        nxt = s[i + 1]           # 当前字与紧随其后的字组成一对
        if cur not in counts:
            counts[cur] = {}
        counts[cur][nxt] = counts[cur].get(nxt, 0) + 1

def next_char(cur):              # 把频数表变成"抽签转盘"
    row = counts.get(cur, {})
    if not row:
        return vocab[random.randrange(len(vocab))]  # 没见过就均匀乱抽兜底
    total = sum(row.values())    # 该前文下所有去向的总次数
    r = random.random() * total  # 在总次数里掷一个落点
    acc = 0
    for ch, n in row.items():
        acc += n
        if r <= acc:
            return ch

for turn in range(3):
    word = "数"
    for step in range(3):
        word = word + next_char(word[-1])   # 新字入列，又成了下一位的前文
    print("第", turn + 1, "次逐格打字:", word)

joint = 0.3 * 0.4 * 0.5          # 例题那句「猫瞪鼠」的链式连乘
print("猫瞪鼠 出现概率:", round(joint, 3))
```

观察输出：三个"造句"全是语料里见过的搭法组合——条件表把局部习惯记下来了；而全局语法感这种高级货，小表给不了。真实的 GPT 只是把这张小表换成深度网络，"看着全部前文猜下一位"的骨架一字未改。

### 快问快答

```quiz
训练时能并行算一整句的损失，生成为什么只能一位一位吐？
- 因为训练用了更好的芯片，而生成阶段芯片不够
- 因为生成时"下一位"依赖自己刚写的"这一位"，答案还没存在 [*]
- 因为采样的随机性天然只能排队执行
? 训练时每个位置的正确答案（真实文本）已经在手，算哪个位置都不用等别的位置；生成时唯一的信息源是自己正在打出的草稿，必须串行等待。这就是"并行训练 vs 串行生成"张力的根源。
```

:::warning[常见误区]

**误区一**："你以为联合概率可以逐项加。" 链式法则是连乘不是累加；各位条件之间是"先后接力"，不是并列挑选。

**误区二**："你以为模型记住了整句的联合概率表。" 它存的只是若干张条件小表的参数；联合那件大事完全交给连乘公式现场拼装。

**误区三**："你以为逐位采样一定越采样越离谱。" 训练目标正是"让真实下一位的概率最大"（极大似然，上一课的老朋友），错误会在每位上被持续纠正；真正要担心的不是单点偏差，而是误差沿序列滚雪球。

:::

## 6. 练习

**练习**：链上三位的条件概率都已给出，把两句各自的联合概率补全成百分比整数。现在的代码能跑，但它偷工减料少乘了一步：

```exercise
# @title: 练习：把条件链乘完整
# @check: 4
# @check: 6
# @hint: 联合概率 = 三位各自条件概率的连乘，一步都不能省；最后换算成百分比整数。
# 句 A：「他 在 笑」
a1 = 0.2              # 开头抽中「他」
a2 = 0.5              # 看到「他」之后接「在」
a3 = 0.4              # 看到「他在」之后接「笑」
joint_a = a1 * a2     # ← 问题在这：第三位的条件还没乘进来

# 句 B：「猫 瞪 鼠」
b1 = 0.3
b2 = 0.4
b3 = 0.5
joint_b = b1 * b2 * b3

print(int(round(joint_a * 100)))
print(int(round(joint_b * 100)))
```

<details>
<summary>点开查看逐步解答</summary>

`joint_a = a1 * a2 * a3 = 0.2 × 0.5 × 0.4 = 0.04`，换算百分数为 $4\%$；句 B 是 $0.3 \times 0.4 \times 0.5 = 0.06$ 即 $6\%$。少乘一位等于宣布"最后那个字白送"——它把剩余概率全押给了缺失项。真实语言模型每一位都要交钱，且交的钱由那张条件小表现场报价。
</details>

## 7. 选读：teacher forcing 为什么能让训练并行

<details>
<summary>选读 · 串行公式里塞进并行计算的秘密</summary>

生成时模型只能吃自己产出的草稿；训练时却没有这个限制——每个训练样本本来就带着满分草稿（真实文本）。把真实前缀直接喂给每个位置的预测器，再对整句所有位置的目标 token 同时求交叉熵，这就是 teacher forcing。术语里的"强迫"指的是：不管模型前面猜得多么离谱，喂进下一步的上文永远是标准答案，硬扳着它学好每一步的局部预测。

代价同样明显：训练环境永远干净（吃真题），上线后却要吃自己写错的草稿——错误会滚进上下文带偏后续判断。工程上有一批补救术（ scheduled sampling、强化学习微调等），但骨架仍是本课这条链式法则。它在数学上还解释了为何自回归训练等价于逐位交叉熵之和：$\sum_t -\ln p_\theta(x_t \mid x_{<t})$，正是上一课负对数似然的序列版。
</details>
