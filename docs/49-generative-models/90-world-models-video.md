# 世界模型与视频生成：在脑内预演未来

## 1. 从一个场景开始

司机看到前车刹车灯亮起，右脚已经在挪——**他不是在等事故发生再反应，而是在脑内预演了"接下来两秒会发生什么"**。这种"给动作、预言未来画面"的能力，就是**世界模型**（world model）：一个学到"世界怎么运转"的内部模拟器。它也是视频生成模型（Sora 一类）的另一个名字：给一句描述，模型"脑内推演"出一段从未拍过的视频——推演得像不像，全看它学到的物理账本对不对。

## 2. 直觉解释

把第 45 课的自回归"逐格打字"搬到时间轴上：文本模型预测"下一个词"，世界模型预测"下一帧画面"——$p(s_{t+1} \mid s_t, a_t)$：现在的画面 $s_t$ 加上你采取的动作 $a_t$，决定下一帧。预测错了怎么办？跟真实未来一比，差距就是训练信号——**世界的物理规律就这样被"猜错-修正"的循环压进参数**。

实际工程里有两笔重要的账：

- ** latent 空间推演**：直接在像素上滚动太贵，先用编码器把每帧压成一小团潜在向量（第 52 课 VAE 的手艺），模型只在"概念压缩带"里推演，需要看画面时再解码回去；
- **扩散式视频生成**：把第 40/42 课的加噪-去噪搬到"一叠帧"上，时间维与画面维同时去噪——Sora 一类模型本质是"对一段时空做扩散"。

世界模型与视频生成是同一枚硬币：前者强调**带动作的条件**（机器人用它预演自己每一步），后者强调**不带动作的想象**（给你一句提示词自由发挥）。

## 3. 正式定义

带动作的世界模型是一对函数：

$$\text{编码：}\quad z_t = E(s_t) \qquad \text{推演：}\quad \hat z_{t+1} = D(z_t, a_t)$$

| 符号 | 名字 | 含义 |
| --- | --- | --- |
| $s_t$ | 时刻 $t$ 的观察 | 一帧画面（或传感器读数） |
| $z_t$ | 潜在状态 | 压缩后的"概念帧" |
| $a_t$ | 动作 | 智能体此刻的选择 |
| $D$ | 推演器（动力学） | 学到的"世界怎么走下一步" |
| $\hat z_{t+1}$ | 预测的下一状态 | 模型脑内的未来 |

训练目标极简：**预测要像真实**——$\lVert \hat z_{t+1} - z_{t+1} \rVert$ 越小越好。视频生成版把 $a_t$ 换成文本条件、把自回归换成扩散去噪，骨架不变。

## 4. 分步例题

一维玩具世界：真实动力学是 $s_{t+1} = 0.8\, s_t + a_t$；模型学到了一份稍偏的账本 $\hat s_{t+1} = 0.9\, s_t + a_t$。从 $s_0 = 0$ 出发，动作序列 $[1, -1, 2]$：

1. **模型脑内**（自己滚自己的）：$1.0 \to 0.9 \times 1 - 1 = -0.1 \to 0.9 \times (-0.1) + 2 = 1.91$；
2. **真实世界**：$1.0 \to 0.8 \times 1.0 - 1 = -0.2 \to 0.8 \times (-0.2) + 2 = 1.84$——注意第一拍两者相同（$s_0 = 0$ 时动作项占主导），差距从第二拍才开始长；
3. **差距**：$1.91 - 1.84 = 0.07$——三步只差 0.07，但滚 100 步呢？动力学系数差 0.1，误差按步数**指数累积**，脑内电影很快与真实世界分道扬镳。

这暴露了世界模型的核心矛盾：**短推演准、长推演漂**——自动驾驶的"预演两秒"够用，"预演两分钟"就是另一门科学。

## 5. 动手实验

### 实验（python）：脑内推演 vs 真实世界，误差怎么滚雪球

```python title="世界模型：自己滚自己的账本"
import math
import matplotlib.pyplot as plt

a_seq = [1.0, -1.0, 2.0, 0.5, -2.0, 1.0, 1.0, -1.0]   # 八步动作脚本

TRUE_B = 0.8                                     # 真实世界的"惯性系数"
MODEL_B = 0.9                                    # 模型学偏了的系数

s_true = 0.0                                     # 真实世界状态
s_model = 0.0                                    # 模型脑内状态
errs = []
for t in range(len(a_seq)):
    act = a_seq[t]
    s_model = MODEL_B * s_model + act            # 推演：只喂"自己上一拍的想象"
    s_true = TRUE_B * s_true + act               # 现实：只按真实规律走
    errs.append(abs(s_model - s_true))
    print("步", t + 1, " 模型 =", round(s_model, 3), " 真实 =", round(s_true, 3), " 误差 =", round(errs[t], 3))

fig, ax = plt.subplots(figsize=(7, 3))
ax.plot([t + 1 for t in range(len(errs))], errs, marker="o")   # 误差滚雪球曲线
ax.set_xlabel("step")
ax.set_ylabel("error")
plt.show()
```

怎么玩：八步之内误差从第一步的 0（动作项主导时两本账天然一致）一路滚到 0.5 量级——模型每一步都只"猜对一丁点"，可推演是**拿自己的想象当下一拍输入**，误差复利生息。把 `MODEL_B` 改成 0.81 再跑：误差压到 0.04 以内——世界模型的军备竞赛，争的就是这位小数点后第二位。这也是为什么机器人用世界模型时只信"前几步"的预演，走几步就得回来跟真实对一次表。

```quiz
"潜在空间推演"（先压缩再预测）主要省的是什么？
- 模型的参数量
- 在像素级高维画面上做昂贵推演的开销 [*]
- 训练数据的数量
? 编码器把一帧百万像素压成几百维潜在向量，动力学只在压缩带上滚动，需要看画面时再解码——省的是推演的算力账，这正是世界模型能跑起来的前提。
```

::::warning[常见误区]

**误区一**："你以为世界模型预测的是'像素'。" 好的世界模型在**潜在空间**里预测：它学的是"什么东西在往哪动"的概念账，不是每个像素的 RGB 值。在压缩带里推演，既省算力，也让"同一只猫换个背景"不至于推散架。

**误区二**："你以为视频生成模型'懂'物理。" 它学到的是海量视频里的**统计规律**：球扔出去大概率沿抛物线落——但玻璃杯碎不碎、火苗往哪飘，只在统计上"像"。物理幻觉（人手多一根手指、液体倒进杯里却变少）正是统计账本没把守恒律记死的证据。

**误区三**："你以为推演越长越好。" 推演每多一步，误差复利一层；工程上常用**短程推演 + 频繁校正**（每走几步拿真实观察重新锚定），而不是一条道滚到底——脑内电影看得越久，离片场越远。

::::

## 6. 练习

```exercise
# @title: 练习：把推演循环写对
# @check: 1.91
# @check: 1.84
# @check: 0.07
# @hint: 推演必须"自己滚自己的"——模型每一步的输入是它上一拍的预测，不是真实世界的状态。
a_seq = [1.0, -1.0, 2.0]                        # 三步动作
TRUE_B = 0.8                                    # 真实动力学系数
MODEL_B = 0.9                                   # 模型学到的系数

s_true = 0.0                                    # 真实状态
s_model = 0.0                                   # 模型脑内状态
for act in a_seq:
    s_model = MODEL_B * s_model + act           # 脑内推演
    s_true = TRUE_B * s_model + act             # ← 问题在这：现实不该吃模型的想象

print(round(s_model, 2))
print(round(s_true, 2))
print(round(abs(s_model - s_true), 2))
```

<details>
<summary>点开查看逐步解答</summary>

真实世界不理会模型的想象，每一步按自己的规律走：

```python
    s_true = TRUE_B * s_true + act              # 现实只看现实
```

修正后：模型 $1.0 \to -0.1 \to 1.91$；真实 $1.0 \to -0.2 \to 1.84$；末步误差 $\lvert 1.91 - 1.84 \rvert = 0.07$。初始代码写的是"现实吃模型"——真实状态被模型的想象污染，两列数字几乎重合，误差永远量不出来。这正是世界模型训练里最经典的实现错误：**teacher forcing 训练、自由推演使用**，两种模式必须分清——练的时候可以喂真值，考的时候只能靠自己。
</details>

**练习 2**：若模型系数完美（$0.8$），八步推演误差是多少？为什么"模型完美"时误差也不必是精确的 0？

<details>
<summary>点开查看逐步解答</summary>

系数相同时两条轨迹逐步重合，误差恒为 0。但真实世界还有**随机性**（噪声、扰动）与**未建模因素**（风、摩擦），完美确定性账本只对玩具世界成立；真实世界模型的误差永远有一层"世界本身不可预测"的地板——推演的目标不是零误差，而是"比瞎猜短得多的可信半径"。
</details>

## 7. 选读：从"看片学物理"到机器人预演

世界模型在机器人这边有个顺手的用法：**想象即规划**——把候选动作各推演几拍，挑"想象中结局最好"的那个执行（模型预测控制的世界模型版）。这与机器人卷 MPC 一课的骨架同源，只是"预测器"从手写方程换成了学出来的网络。风险也随之而来：想象与现实的缝隙（model bias）会被规划器钻空子——规划器专挑模型以为好、实际糟糕的动作。工程对策是推演短一点、真机校正勤一点，以及让模型在"最不确定的地方"保守些。视频生成与具身智能在这里握手：**能想象，才能预演；能预演，才敢行动。**
