# 数论：素数与整除——数学的女王

高斯说："数学是科学的皇后，数论是数学的皇后。"这门最古老、最"纯"的学问，研究的却是最朴素的问题：一个数能被谁整除？余数怎么循环？哪些数拆不动了？

别被"纯"字骗了。你每天都被数论包围着：

- **日历**是模 7 的世界——7 天一循环，100 天后是星期几，全看余数；
- **音乐**里两个音合不和谐，取决于频率之比是不是简单分数——公约数在管事；
- **密码学**（比如网购时的 RSA 加密）把整座互联网的安全押在一个问题上：把两个大素数的乘积拆回两个素数，难到全世界计算机一起算也算不完。

这一章你会拿到五件工具：**余数与模运算**（余数的世界观）、**素数与筛法**（数的原子）、**最大公约数与欧几里得算法**（两千年前最快的算法，至今仍在跑）、**最小公倍数**（gcd 的孪生兄弟，通分的另一半）、**同余与应用**（把它们连起来解决真问题）。

1. [整除、余数与模运算](./10-divisibility-mod.md)——钟面上没有 13 点：余数才是日常的主角；
2. [素数与筛法](./20-primes-sieve.md)——乘法世界的原子表，两千年前的筛子今天还能玩；
3. [最大公约数与欧几里得算法](./30-gcd-euclid.md)——一行顶二十行的最古老算法；
4. [最小公倍数：钟表重逢问题](./32-lcm.md)——两列倍数台阶的第一次撞车，gcd×lcm=a×b 的对偶恒等式；
5. [同余与应用](./40-congruence-apps.md)——算星期、加密、查哈希，全是同一件事。

学完这章你会发现："除不尽"不是失败，而是一个更精巧世界的入口。

## 实战挑战 · 数论

**改编自国家标准 GB 11643-1999《公民身份号码》的真实工程场景**（校验算法为 ISO 7064 MOD 11-2，示例号码采用标准说明中的演示号段）。你口袋里那张身份证的第 18 位，就是同余的一枚现役岗哨：输错任何一位，落点都会挪窝；很多两位对调也会被识破。它的强项和边界，下面算完再看。

**题目**：身份证前 17 位叫本体码，第 18 位是校验码，算法四步——

1. 加权求和：第 $i$ 位数字乘加权因子 $W_i$（就是 $2^{18-i} \bmod 11$ 的循环值）后全部加起来，得 $S$；
2. 取余：$T = S \bmod 11$；
3. 查表换算：余数 $0,1,2,\ldots,10$ 依次对应校验码 `1 0 X 9 8 7 6 5 4 3 2`（余 2 时写罗马数字 X，代表 10）；
4. 第 18 位就是查表结果。

已知某号码的本体码为 `12345678901234567`，加权因子表为 `[7, 9, 10, 5, 8, 4, 2, 1, 6, 3, 7, 9, 10, 5, 8, 4, 2]`。

- (a) 求 $T = S \bmod 11$；
- (b) 写出完整的 18 位号码。

下面的代码能跑但漏了一步——加了数字却忘了乘权重。修到通过：

```exercise
# @title: 练习：算出第 18 位
# @check: 5
# @check: 7
# @hint: 第 i 位要"数字 × 权重"再累加（s = s + digit * weights[i]）；拿到 T 后按题面给的 code_map 查表——注意下标从 0 起，正好用 T 当下标
body = "12345678901234567"
weights = [7, 9, 10, 5, 8, 4, 2, 1, 6, 3, 7, 9, 10, 5, 8, 4, 2]
code_map = "10X98765432"

s = 0
for i in range(17):
    digit = int(body[i])       # body[i] 按下标取出第 i 位字符；int(...) 再把它变回数字
    s = s + digit              # ← 少了乘加权因子这一步

t = s % 11                      # 取余：落进 0..10 共 11 格
check = code_map[t]

print(t)
print(check)
```

<details>
<summary>点开查看逐步解答</summary>

**(a)** 逐位相乘再累加：$S = 1{\times}7 + 2{\times}9 + 3{\times}10 + \cdots + 6{\times}4 + 7{\times}2$（17 对乘积，完整循环见下面验算代码），结果 $S = 368$。

$T = 368 \bmod 11$：因为 $11 \times 33 = 363$，所以 $T = 5$。

**(b)** 查表：余 5 对应校验码 `7`，完整号码为 **12345678901234567 末尾加 7**，即 `123456789012345677`。

顺带体会初始代码错在哪：只加数字时 $S=73$、$T = 73 \bmod 11 = 7$、"校验码"查成 `5`——与正确答案恰好互换。权重一乘，信息才真正掺进每一个位置；这就是"加权"二字的分量。

验算代码：

```python
body = "12345678901234567"
weights = [7, 9, 10, 5, 8, 4, 2, 1, 6, 3, 7, 9, 10, 5, 8, 4, 2]
code_map = "10X98765432"

s = 0
for i in range(17):
    s = s + int(body[i]) * weights[i]

t = s % 11
print(s)        # 368
print(t)        # 5
print(code_map[t])   # 7
```

为什么选模 11？权重 $7,9,10,\ldots$ 都不含因子 11，所以任何一位从 $a$ 改成 $b$，总和的变化量是 $(b-a)\times W_i$；只要 $a\ne b$ 且改动不超过 9，它就不可能是 11 的倍数——一位错误必然被抓。相邻两位对调会同时改变两个权重项，也逃不掉。不过相隔 10 位的两个位置权重相同（例如第 1 位与第 11 位），单纯对调它们可能骗过校验。真实系统常再加长度、出生日期等业务校验来补这类边界。这套思路的亲戚遍布生活：银行卡号的 Luhn 算法、商品条形码的 EAN 校验位，全是同余。

</details>

## 实战挑战 · 97 是不是素数

判素数就一句话：看 2 到 $n-1$ 之间有没有数能整除它。下面这题的判断条件写反了，把素数 97 判成了合数，修到输出 `True`：

```exercise
# @title: 实战挑战：素数判定的条件方向
# @check: True
# @hint: 找到"能整除"的因子才该判合数；现在条件反了。
n = 97
is_prime = True
for d in range(2, n):          # 试除 2 到 96 的每个数
    if n % d != 0:             # ← 问题在这：不能整除不该触发判合数
        is_prime = False
        break
print(is_prime)
```

<details>
<summary>点开查看逐步解答</summary>

素数是"没有真因子"，所以**一旦找到能整除的因子，才判合数**：

```python
if n % d == 0:        # 能整除 → 找到因子 → 合数
    is_prime = False
    break
```

初始代码把条件写成 `n % d != 0`（不能整除就判合数），第一个试除数 $d=2$ 就不整除 97，立刻误判。改回 `== 0` 后，$2$ 到 $96$ 无一能整除 97，`is_prime` 保持 `True`。判素数的"证伪"逻辑——找得到一个因子才算合数——正是本章筛法的第一块砖。

</details>
