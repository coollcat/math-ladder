# 数学建模五步：把现实问题翻译成算式

## 1. 从一个场景开始

手机营业厅挂着两块牌子。**A 套餐**：月租 30 元，送 5 GB 流量，超出部分每 GB 收 5 元。**B 套餐**：月租 50 元，送 20 GB，超出部分每 GB 收 3 元。

每月用多少流量时，两款套餐花的钱一样多？超过这个数又该选哪个？

牌子上的字谁都读得懂，可要回答这两个问题，先得把手里的"现实"变成"算式"。这一课讲的就是这个翻译动作——它有个正式名字，叫**数学建模**。

## 2. 直觉解释

建模的起点不是公式，而是一句很日常的困惑："到底该选哪款？"把它翻译成数学，要走五步：

**提问 → 抽象 → 建立关系 → 求解 → 检验回代。**

打个比方：现实问题是一份外语说明书，变量是生词的注音，关系式是语法，求解是照着它装一遍，检验回代是装完拧拧螺丝、看牢不牢。五步首尾相接，构成一个闭环——因为检验往往又逼出新的问题。

最常被跳过的是第五步。而它恰恰是唯一能抓住错误的环节。

## 3. 正式定义

**数学建模**：把现实情境翻译成数学式子，用数学工具求出结果，再把结果翻译回现实的过程。五个步骤：

| 步 | 名字 | 要做的事 | 本例 |
| --- | --- | --- | --- |
| ① | 提出问题 | 弄清到底要回答什么，答案长什么样 | "哪款更便宜？从多少 GB 开始分界？" |
| ② | 抽象变量 | 给会变的量取名字、定单位 | $x$ = 每月流量（GB）；$y_A,y_B$ = 月费（元） |
| ③ | 建立关系 | 用式子写下变量之间的关系 | 下方分段函数 |
| ④ | 求解 | 用数学手段算出那个关键点 | 解 $y_A = y_B$ |
| ⑤ | 检验回代 | 把答案代回原情境，查单位与常识 | 代 $x=9$ 各算一遍 |

套餐关系写成分段函数：

$$y_A = \begin{cases} 30, & 0 \le x \le 5 \\ 30 + 5(x-5), & x > 5 \end{cases} \qquad y_B = \begin{cases} 50, & 0 \le x \le 20 \\ 50 + 3(x-20), & x > 20 \end{cases}$$

符号逐一说明：

| 符号 | 名字 | 说明 |
| --- | --- | --- |
| $x$ | 自变量 | 每月用的流量，单位 GB，取 $x \ge 0$ |
| $y_A,y_B$ | 因变量 | 当月要交的钱，单位元；随 $x$ 变 |
| $30,\ 50$ | 常数项 | 月租，不随流量变，相当于"起步价" |
| $5,\ 3$ | 系数 | 超出部分的单价，单位是"元/GB" |
| $5,\ 20$ | 分界点 | 套餐包含的免费额度，超出后才按单价计费 |

留神单位：$5$ 是"元/GB"，$x-5$ 是 GB，两者相乘才得到元。**单位能对上，是模型没说错话的硬证据。**

## 4. 分步例题

**求分界线**：找出两套餐月费相等的那个流量点。

1. **先看哪些段值得比**。$x \le 5$ 时 $y_A = 30 < 50 = y_B$，A 一定便宜，不必细算。$5 < x \le 20$ 时 $y_B$ 仍停在 50，而 $y_A$ 开始爬升，交点必在这一段。
2. **把这一段的式子化简**。$y_A = 30 + 5(x-5) = 5x + 5$，$y_B = 50$。
3. **解方程**。$5x + 5 = 50 \Rightarrow 5x = 45 \Rightarrow x = 9$。
4. **回头核对假设**。$9$ 是否落在 $5 < x \le 20$ 内？是 ✓。再查下一段 $x>20$：$5x+5 = 3x-10 \Rightarrow x = -7.5$，不在段内，舍去——所以只有这一个交点。
5. **回代检验**。$y_A(9) = 30 + 5 \times 4 = 50$，$y_B(9) = 50$，两边相等 ✓。

结论：**9 GB 是分界线，低于 9 GB 选 A，高于 9 GB 选 B。**

## 5. 动手实验

### 实验 1（viz）：几个流量点上的两份月费

把高、中、低三档流量下的两种月费摆在一起，"谁更便宜"是怎么翻转的一眼可见：

```viz
{
  "type": "datachart",
  "title": "不同流量下两款套餐的月费（元）",
  "labels": ["A·5GB", "B·5GB", "A·15GB", "B·15GB", "A·25GB", "B·25GB"],
  "values": [30, 50, 80, 50, 130, 65]
}
```

5 GB 时 A 便宜 20 元；15 GB 时被反超 30 元；25 GB 时差距拉大到 65 元。**分界线就藏在头两对柱子之间**——正好是上面算出的 $x=9$。

### 实验 2（python）：让模型自己跑一遍

```python
# sliders: usage=9 [1:30:1]
# usage：每月使用的流量（GB），由滑块注入

def cost_a(gb):                 # def：把"套餐 A 怎么算钱"封进一个函数
    if gb <= 5:                 # if：条件成立才走这一支
        return 30               # 没超额度，只交月租
    return 30 + 5 * (gb - 5)    # 超出部分每 GB 收 5 元

def cost_b(gb):
    if gb <= 20:
        return 50
    return 50 + 3 * (gb - 20)

print(cost_a(usage))
print(cost_b(usage))
```

把 `usage` 拖到 9，两行都输出 50——**模型和手算对上了**。拖到 12：A 是 65、B 是 50，B 更划算；拖回 4：A 是 30、B 是 50，A 更划算。滑块就是那条分界线的探针。

## 6. 常见误区

:::warning[常见误区]

**误区一**："你以为建模就是套公式。" 第一步永远是"到底要回答什么问题"。把它改成"每月 30 GB 时贵多少"，模型、答案、结论会一起变。**问题没定，公式无从谈起。**

**误区二**："你以为算出 $x=9$ 就完事了。" 最后一步是回代：$y_A(9)$ 和 $y_B(9)$ 都得等于 50 才算数。省掉检验，把"每 GB 加 5 元"误写成"减 5 元"这种笔误就会原样交卷。

**误区三**："你以为模型越复杂越准。" 本例刻意忽略了两件事——促销折扣、流量结转。**模型是对现实的简化**，能用最简的关系抓住主要矛盾就够了；要加细节，先问它会不会改变结论。

:::

## 7. 练习

**练习 1**：算出 15 GB 时两款套餐的月费。下面的代码能跑，但套餐 A 忘了先扣掉免费的 5 GB，改到通过：

```exercise
# @title: 练习：两份月费单
# @check: 80
# @check: 50
# @hint: 超出的流量是 gb − 5 而不是 gb：已经免费的 5 GB 不该再收一次钱。
def cost_a(gb):
    if gb <= 5:
        return 30
    return 30 + 5 * gb        # ← 免费额度没扣掉
def cost_b(gb):
    if gb <= 20:
        return 50
    return 50 + 3 * (gb - 20)
print(cost_a(15))
print(cost_b(15))
```

**练习 2**：改一改模型——若 B 套餐月租降到 45 元，分界线会移到哪里？

<details>
<summary>点开查看逐步解答</summary>

$5 < x \le 20$ 这一段里 $y_B$ 仍是常数，只是从 50 变成 45，于是方程变成 $5x + 5 = 45$，得 $x = 8$。再查 $x>20$ 段：$5x+5 = 3x-15 \Rightarrow x = -10$，不在段内，舍去。结论：**分界线左移到 8 GB**。

```python
def cost_a(gb):
    if gb <= 5:
        return 30
    return 30 + 5 * (gb - 5)

def cost_b(gb):
    if gb <= 20:
        return 45
    return 45 + 3 * (gb - 20)

for gb in range(5, 13):          # range：生成 5 到 12 的整数序列
    print(gb, cost_a(gb), cost_b(gb))
```

输出里 8 那一行两边相等（都为 45），9 起 B 开始领先——分界线一眼现形。

</details>

**练习 3（概念）**：本题用了"流量是连续的"这条假设。现实里流量按 0.01 GB 计费，这会影响结论吗？

<details>
<summary>点开查看答案</summary>

不影响。因为分界点 $x=9$ 本身就是 0.01 GB 的整数倍，两种模型的结论完全一致。一般来说，当"离散步长"远小于结论要回答的精度时，用连续量作近似既省事又安全。这也是建模里反复出现的取舍：**先问精度要求，再决定模型要多细。**

</details>

**趁热打铁**：


## 8. 选读：假设的合理性，比答案更难

<details>
<summary>选读 · 每个模型背后都站着一排假设</summary>

本题悄悄用了三条假设：① 流量可以取任意实数（现实按 0.01 GB 计费，用连续量近似足够好）；② 单价不随用量变化（现实里可能存在阶梯折扣）；③ 除月费和超量费之外没有别的费用（现实里可能有合约机、捆绑服务）。

工程与建模竞赛里的口诀是：**先上一个能用的简单模型，再逐步加细节**。每加一条，都要问：它会不会改变结论？只有会改变结论的细节才值得进模型。这也是"检验回代"除了算数之外，还要抬头看一眼常识的原因。

</details>
