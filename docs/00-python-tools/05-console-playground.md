# 浮窗实验台与交互组件

## 1. 从一个场景开始

这本书的正文里到处是「▶ 浮窗运行」「▶ 浮窗实验」的按钮。第一次见到的人会有点懵：点下去会发生什么？我改代码会弄坏书吗？滑块又是干什么的？

这一课就是这些按钮的说明书。花十分钟读完，往后每一课的实验你都能玩得转。

## 2. 直觉：浮窗就是你的私人实验台

数学课本是**印在纸上的、死的**；代码是**活的**——按一下运行，它就当着你的面算一遍。而浮窗，就是专门放这些活代码的**实验台**：

- 可以在上面**随便改代码**，改坏了就点「恢复代码」，书里的原文原样回来；
- 可以**反复运行**，改一次跑一次，看数字怎么变；
- 还可以把参数做成**滑块**，拖一拖，代码自动用新参数重跑。

后面每一章，你都会在这个实验台上做数学实验。先记住三件事：**运行、修改、重跑**。

## 3. 怎么运行代码

### 3.1 三个入口

正文里的每个 Python 代码块，右下角都有一个按钮：

- 没有滑块的代码块显示「▶ 浮窗运行」——把代码装进浮窗跑一遍；
- 带滑块的代码块显示「▶ 浮窗实验」——装进浮窗，还能拖滑块调参数。

此外，页面右下角有一个悬浮的「⚙ Python」圆球，点开就是**随手算**草稿纸；快捷键 `Alt + P` 也能弹出/收起浮窗。

### 3.2 在浮窗里改代码

浮窗打开后，代码已经躺在编辑区里。直接改，然后按 `Ctrl + Enter`（或点「▶ 运行」）：

```python title="改改看：换个数再运行"
x = 10                        # 等号：把右边的值存进左边的变量名 x
print(f"现在 x = {x}")        # print：把括号里的内容打印出来；f-string 把花括号里的 x 换成它的值
```

把它改成 `x = 20` 再运行，输出立刻变成 `现在 x = 20`。**改坏了大不了点「恢复代码」**——这正是实验台的好处。

### 3.3 变量在两次运行之间保留

随手算的草稿纸有个贴心设计：变量会**保留到下一次运行**。比如先运行 `a = 3`，再运行 `print(a * 2)`，会输出 `6`——两次运行之间，`a` 一直记着 `3`。

工具栏的「重置变量」按钮可以把这些保留的变量全部清空（从头再来）；「清屏」只清输出，不动变量。

## 4. 交互组件：把参数做成滑块

数学实验经常要回答"参数变了，结果怎么变"。与其一次次手改代码，不如在代码里写一行魔法注释，浮窗就会自动生成**滑块**：

```python title="第一个滑块实验：拖 top 看和的增长"
# sliders: top=100 [10:500:10]
total = 0                     # 累加器：从零起账
for n in range(1, top + 1):   # for 循环：让 n 依次取 1 到 top；top 由滑块注入，代码里不用再赋值
    total = total + n         # 每轮把 n 记进总账
print(f"1 加到 {top} 的和是 {total}")
```

第二行的 `# sliders: top=100 [10:500:10]` 就是滑块配方，读作：

- `top`——滑块控制的变量名；
- `100`——初始值；
- `[10:500:10]`——最小值 `10`，最大值 `500`，步长 `10`（每拖一格跳 10）。

点「▶ 浮窗实验」打开它，然后**拖动滑块**：每停一次，代码就自动用滑块的新值重跑一遍，输出跟着变。把 `top` 一路拖到 500，感受一下"数字越大长得越快"。

滑块本身也能改：**在浮窗里直接编辑 `# sliders:` 那一行**——改初值、改范围、改进长都行，点一次「运行」（或「⇄ 从代码同步参数」），滑块就会按新行重建。

```quiz
带 # sliders: 的代码块，拖动滑块之后会发生什么？
- 需要手动点「▶ 运行」才会更新结果
- 代码自动用滑块的新值重跑一遍 [*]
- 滑块只能显示数值，不影响代码运行
? 滑块拖到底会触发一次自动重跑（带 260ms 防抖），输出立刻按新参数更新。这就是"交互组件"的含义：改参数，立刻看到结果。
```

## 5. 反向操作：从代码同步参数

滑块负责"把参数灌进代码"。那反过来呢？**你在代码里改好的参数，能不能同步回滑块？**

能。浮窗滑块区右上角有一个「⇄ 从代码同步参数」按钮，作用正相反：运行代码后，把代码运行产生的变量值**回填到滑块**，让交互组件跟着代码走。

看这个场景：你想试试"加到 200"，直接在代码里写了一行 `top = 200`：

```python title="在代码里直接改参数：top = 200"
# sliders: top=100 [10:500:10]
top = 200                     # 代码里直接赋值，会覆盖滑块注入的 top
total = 0
for n in range(1, top + 1):
    total = total + n
print(f"1 加到 {top} 的和是 {total}")
```

运行后输出按 200 算，但**滑块还停在原来的位置**。这时点一下「⇄ 从代码同步参数」：

1. 浮窗先把代码重新跑一遍，拿到 `top = 200`；
2. 滑块自动跳到 200，显示值同步更新；
3. 再用新参数跑一次——交互组件和代码完全对齐。

想回到滑块主导，把 `top = 200` 那行删掉（或点「恢复代码」），再拖动滑块即可。

这四步就是本站"写代码研究数学"的完整闭环：**改代码 → 运行 → 同步滑块 → 观察组件变化**。

```quiz
「⇄ 从代码同步参数」按钮做的是什么事？
- 把代码文件保存到本地电脑
- 把代码运行后的变量值回填到滑块，让交互组件跟上代码 [*]
- 让代码自动修改成滑块当前的值
? 方向正好和拖滑块相反：拖滑块是"滑块 → 代码"，同步按钮是"代码 → 滑块"。两者配合，代码和组件永远保持一致。
```

## 6. 判题模式与图片输出（预告）

实验台还有两种进阶玩法，后面的课会正式登场，这里先混个脸熟：

- **判题模式**：带判题要求的代码块显示「▶ 在浮窗作答」。你改代码跑到输出与期望一致，浮窗会显示「通过」并保存进度——这是本站练习的答题方式；
- **图片输出**：用了绘图库的代码，画出来的图会直接出现在浮窗输出区（下一课《matplotlib 入门》就是教你画图的）。

## 7. 小结与练习

这一课讲完了浮窗的三件套：**运行**（按钮 / `Ctrl+Enter`）、**修改**（随便改、可恢复）、**交互**（滑块注入参数、从代码反向同步）。后面的课程不再解释这些按钮，默认你已经会用实验台了。

**练习**：浮窗实验台里，`# sliders: n=10 [1:100:1]` 表示滑块控制变量 `n`，初始值是几？范围是什么？

<details>
<summary>点开查看答案</summary>

初始值 `10`，范围从 `1` 到 `100`，步长 `1`。格式是 `名字=初值 [最小值:最大值:步长]`。
</details>
