# 本站 Python 约定

## 1. 从一个场景开始

数学课本里的公式是**印在纸上的、死的**；而代码是**活的**——按一下运行，它就当着你的面算一遍。本站的许多结论都会配一段代码，让你亲手验证。这一课把你已经会的 Python 语法，对齐到"研究数学"的用法上。

## 2. 直觉：代码就是一台"可提问的计算器"

普通计算器只能回答"3+5 等于几"；代码能回答"从 1 加到 100 等于几"、"把 1 到 1000 全部加一遍要多久"。**数学关心的是规律，代码负责把规律摆到你眼前。**

## 3. 五个约定

### 约定一：变量起有意义的名字

```python title="变量名要说人话"
apples = 3
bananas = 5
total_fruit = apples + bananas
print(total_fruit)   # print：把括号里的值打印出来；等号表示把右边的值存进左边的变量名
```

### 约定二：用 f-string 把计算过程"说"出来

```python title="f-string：让输出自己解释自己"
a = 12
b = 25
print(f"{a} + {b} = {a + b}")   # f-string：把花括号里的表达式换成计算结果
```

`f"..."` 里的大括号 `{}` 会换成里面表达式的值。以后你会大量看到 `print(f"x = {x}")` 这种写法——它是我们的"实验记录仪"。先测一下你有没有装上这台记录仪：

```quiz
a = 3、b = 4 时，print(f"{a} + {b} = {a + b}") 输出什么？
- {a} + {b} = {a + b}
- 3 + 4 = 7 [*]
- 7
? 大括号会被逐个换成里面的值：前两处换成 3 和 4；第三处先把 3+4 算成 7 再换进去。
```

### 约定三：for 循环 = "对每个数做一遍"

高斯小时候被要求算 $1+2+\cdots+100$。我们不管技巧，直接暴力算。这也是你在本站遇到的**第一个滑块实验**：点「▶ 浮窗运行」，拖动 `top` 滑杆，代码每停一次就自动重跑一遍：

```python title="暴力但诚实：循环累加"
# sliders: top=100 [10:500:10]
total = 0
for n in range(1, top + 1):   # top 由滑块注入，代码里不用再赋值
    total = total + n
print(f"1 加到 {top} 的和是 {total}")
```

`range(1, top + 1)` 产生 $1,2,\dots,top$（注意：**含头不含尾**，想包含上限本身就要 +1）。变量 `total` 每轮把自己更新成"旧值 + 新数"，这叫**累加器**模式。把滑块从 10 一路拖到 500，观察和的增长速度——数字越大长得越快，这个"越滚越快"的感觉先记住，第 8 章见分晓。

### 约定四：def 函数 = "把一个想法装进盒子"

```python title="把'加到 n'封装成函数"
def add_up_to(n):
    total = 0
    for k in range(1, n + 1):
        total = total + k
    return total

print(add_up_to(100))
print(add_up_to(1000))
print(add_up_to(10000))
```

这三行会分别打印 `5050`、`500500`、`50005000`。先看清函数把哪件事封装住了，再进下一节。

写一次，到处问。注意 `range(1, n + 1)`：想包含 $n$ 本身，就要写到 $n+1$。

### 约定五：while 循环 = "只要还……，就再来一次"

for 循环适合"数得清要几轮"的活儿。可有些问题事先不知道要重复多少次——比如"从 1 开始往上加，加到总和第一次超过目标为止"。这就要请出 `while`：

```python title="while：不知道要几轮，看条件行事"
# sliders: target=200 [100:900:50]
total = 0                  # 累加器：从零起账
n = 1                      # 计数器：从 1 开始数
while total < target:      # while：只要 total 还没到目标，就重复缩进块里的活
    total = total + n      # 把 n 记进总账
    n = n + 1              # 计数器前进一步——忘了这行，total 就永远停在原地
print(f"加到 {n - 1} 时，总和 {total} 首次达到或越过 {target}")
```

读法：`while 条件:` 与 `if 条件:` 长得一样，脾气不同——`if` 只判断一次，成立就做一遍；`while` 做完一遍**回头再查条件**，还成立就再来一遍，直到条件不成立才放行。所以缩进块里必须有一件事在推动条件走向"不成立"（这里是 `n = n + 1` 让 total 一路涨），否则条件永远成立，就成了第 5 节警告的死循环（让 total 一路涨的正是 `total = total + n` 配合 `n = n + 1` 这对搭档）。拖动 `target` 滑杆试试：目标越大，轮数越多。

```quiz
while 循环的缩进块里如果什么都不改条件依赖的变量，会发生什么？
- Python 会自动停止
- 条件永远成立，循环停不下来（死循环） [*]
- 循环体只执行一次
? while 靠"条件最终不成立"收工。缩进块里必须推动条件变化（比如让计数器 +1），否则就是死循环——这正是第 5 节"别写死循环"警告的来历。
```

## 4. Python 验证：sum() 的诞生

上面那个"累加器"模式太常用了，Python 干脆把它做成了内置工具 `sum()`：

```python title="sum 就是那个循环的快捷方式"
numbers = [1, 2, 3, 4, 5]   # 方括号列表：把一组数按顺序装在一起
print(sum(numbers))

print(sum(range(1, 101)))
```

这两行分别输出 `15` 和 `5050`。

对比一下：`add_up_to(100)` 和 `sum(range(1, 101))` 结果一样。**`sum()` 不是天上掉下来的，它就是你刚写的那个 for 循环。** 本站后面每引入一个新工具，都会像这样先给你看"没有它会怎样"。

顺手验证一下高斯的答案为什么是 5050：

```python title="两种方法互相印证"
def add_up_to(n):
    total = 0
    for k in range(1, n + 1):
        total = total + k
    return total

for n in [10, 100, 1000]:
    print(f"n={n}: 循环算出 {add_up_to(n)}")
```

输出依次是 `55`、`5050`、`500500`。

三种规模的答案都可以随手再改大验证。至于"不用循环怎么一步算出来"，第 8 章《数列与归纳法》见分晓。

### 快问快答

```quiz
range(1, 101) 一共产生多少个数？
- 100 [*]
- 101
- 99
? 含头不含尾：从 1 开始数到 100 之前停下，共 100 个数。想含尾就多写一步：range(1, n + 1)。
```

:::warning[常见误区]

**误区一**：`range(1, 100)` 会数到 100。
实际上含头不含尾，只到 99。想包含 100 就写 `range(1, 101)`。

**误区二**：`print(total)` 写进循环里和写在循环外没区别。
写在循环内会打印每一轮的中间值（100 行）；写在循环外只打印最终值。看你想看过程还是结果。

**误区三**：`sum()` 是必须背下来的"魔法"。
你已经手写过它的逻辑了。本站所有工具都会这样先拆开给你看。

:::

## 5. 浏览器环境的特别说明

本课的滑块实验已经在第 3 节完成；下面只说明浏览器环境和本地 Python 的三点差别。

本站代码跑在你的浏览器里（不是你的电脑），有三点不同：

- **没有 `input()`**：需要"外部数据"时，直接给变量赋值；
- **别写死循环**：`while True:` 没有限制条件会让页面卡住（条件怎么推动、怎么收工，见约定五）；
- **画图自动显示**：用了 matplotlib 的代码，图会出现在输出区（下一课讲）。

## 6. 练习

**练习 1**：用 f-string 打印 `7 × 8 = 56`（× 用字符 `*` 还是真乘号都行，试试）。

<details>
<summary>点开查看逐步解答</summary>

```python
a = 7
b = 8
print(f"{a} * {b} = {a * b}")
```

要点：f-string 里 `{}` 放表达式即可，不必先存变量再引用。
</details>

**练习 2**：用循环算 $2+4+6+\cdots+100$（偶数和）。下面的代码算的是全部数的和，改成只加偶数，运行并通过检查：

```exercise
# @title: 练习：只加偶数
# @check: 2550
# @hint: range 的第三个参数是步长，range(2, 101, 2) 产生 2,4,...,100
total = 0
for n in range(1, 101):
    total = total + n
print(total)
```

**练习 3**：定义函数 `countdown(n)`，打印 n, n-1, ..., 1, 然后返回打印了几个数。

<details>
<summary>点开查看逐步解答</summary>

```python
def countdown(n):
    count = 0
    for k in range(n, 0, -1):
        print(k)
        count = count + 1
    return count

print(f"一共 {countdown(5)} 个数")
```

要点：步长为 -1 表示倒数；计数又是一个累加器（这次累加的是 1）。
</details>

## 7. 选读：为什么"暴力算"也是数学？

<details>
<summary>选读 · 数学家的工作流程</summary>

有人觉得"写循环硬算"不算数学。恰恰相反——**数学的核心是找到可信的规律，而可信来自反复验证**。你接下来会不断看到：先用代码暴力算出具体数字，再猜出规律，最后（选读部分）给出严格证明。暴力 → 猜想 → 证明，这正是数学家的工作流程，只是我们把第一步交给了机器。

</details>
