# 信道编码与差错控制回望

## 1. 从一个场景开始

付款二维码被钥匙刮掉一个角，手机照样把它扫了出来；内存条被宇宙射线打翻一个比特，服务器毫无察觉地继续跑着。它们的共同底气是一句话：**发送的时候多付一点冗余，接收的时候就有一双发现错误、甚至亲手纠正的眼睛**。本章讲调制、噪声、判决与同步，全都在回答「怎么把比特送到」；这一课回身处理最后一环——就算路上磕碰了，也要把消息完整收下来。

## 2. 直觉解释

香农 1948 年先给结论（85 号课正式拆他的公式）：只要传输速率低于信道容量，**必定存在**一套编码方案把误码压到任意低；但他只标出了天花板的高度，没有递上梯子——「存在」不等于「照着做」。梯子靠后来的工程师们一节一节造出来。

造梯子的原料只有一个：**精心安排的废话**。往真实比特里掺入按规则算出来的多余比特，使合法 codeword 之间保持距离；噪声想篡改一个字，得先把某个字挪近另一个合法字——挪动一格时看得出破绽（检错），挪动的位置本身还能出卖它（纠错）。信源编码那边挤水分，信道编码这边注结构，一来一回正好互补。

## 3. 正式定义

最朴素的两个玩具够本章使用：重复码与线性奇偶码。

| 名词 | 名字 | 玩法 |
| --- | --- | --- |
| $(n,k)$ 码 | 分组长 $n$、信息位 $k$ | 每 $k$ 个信息比特配发 $n-k$ 个校验比特 |
| $R = k/n$ | 码率 | 有效吞吐占发射比特的比例 |
| $d_{\min}$ | 最小汉明距离 | 最近两个合法字的差异位数 |
| 检错能力 | 发现异常 | $d_{\min} \geq e+1$ 时可检出 $e$ 位错 |
| 纠错能力 | 定位修复 | 可纠正 $t$ 位错，其中 $t$ 是 $\lfloor (d_{\min}-1)/2 \rfloor$ |

重复码 $(3,1)$ 把每比特喊三遍，最小距离 3，能纠 1 位错——表决不足 2 票不改口，代价是码率 $1/3$。校验型方案把校验位设计成若干组比特的「奇偶哨兵」，用远低于 $1/3$ 的代价换同样的纠错力，这就是接下来手算的那一族。

## 4. 分步例题

**例**：Hamming$(7,4)$ 码的账本——4 个信息比特发出去带 3 个哨兵。位次编号 1 到 7，编号恰为 2 的幂的位置放校验位：

1. 安排座次：位 1、2、4 是校验位 $p_1,p_2,p_4$，位 3、5、6、7 承载信息 $d_3,d_5,d_6,d_7$；
2. 取信息比特 $1011$ 落座：$d_3=1,\ d_5=0,\ d_6=1,\ d_7=1$；
3. 哨兵规则：让每组之和凑成偶数——$p_1$ 管住编号二进制里含 1 的位 $\lbrace 1,3,5,7\rbrace$，$p_2$ 管 $\lbrace 2,3,6,7\rbrace$，$p_4$ 管 $\lbrace 4,5,6,7\rbrace$；
4. 解方程：$p_1 = 1 \oplus 0 \oplus 1 = 0$，$p_2 = 1 \oplus 1 \oplus 1 = 1$，$p_4 = 0 \oplus 1 \oplus 1 = 0$（$\oplus$ 是模 2 加法：同得 0、异得 1，奇偶分析的专用符号）；
5. 发出：位序拼起来是 `0110011`。途中第 5 位被噪声掀翻，收到 `0110111`；
6. 接收端重算三个哨兵组的奇偶，得到综合征 $s_1=1,\ s_2=0,\ s_4=1$——这三位二进制 $s_4s_2s_1 = 101_2$ 直接读出十进制 **5**：出错的就是第 5 位。翻回去，数据原样取回 $d_3d_5d_6d_7 = 1011$。

注意这份魔法的价格表：7 个发送位搬 4 个信息位，码率 $4/7 \approx 57\%$，比重复码的 $33\%$ 体面得多；而纠错能力同为 1 位——同样是距离 3，巧妙的校验结构比蛮力复读省下近一半的开销。这就是「好的冗余」与「坏的冗余」的分水岭。

## 5. 动手实验

奇偶与表决都是离散比特操作，三件套渲染器没有对应形态——本课依旧交给 matplotlib 兜底，并用固定种子保证三档对决可复现。

### 实验 1（python）：三种码率的无声对决

```python title="重复 1/3/5 遍，误码率差出几个数量级"
import random                    # 随机数库
random.seed(2026)                # 固定随机种子：三个选手同一副骰子
import matplotlib.pyplot as plt

N_BITS = 2000                    # 每档准备发送的信息比特总数
P_FLIP = 0.08                    # 信道每比特翻转概率（二元对称信道）
names = []                       # 选手名
bers = []                        # 实测误码率
for k in [1, 3, 5]:              # 每个信息比特复读的份数，k=1 是裸奔对照组
    total = N_BITS // k          # 能打包多少个长度 k 的分组
    wrong = 0                    # 解码后仍不对的信息比特数
    for b in range(total):
        bit = random.randint(0, 1)             # randint：0 和 1 都可能取到
        copies = []
        for rep in range(k):
            got = bit
            if random.random() < P_FLIP:       # random()：抛一枚偏心硬币
                got = 1 - got                  # 被噪声翻面
            copies.append(got)
        ones = sum(copies)                     # sum：一张选票堆里的 1 票数
        guess = 1 if ones * 2 > k else 0       # 多数表决：过半才改判
        if guess != bit:
            wrong = wrong + 1
    names.append(f"重复 x{k}")
    bers.append(wrong / total)
    print(f"k={k}  误码 {wrong}/{total} = {round(wrong / total, 4)}，吞吐只剩 {round(100 / k)}%")

plt.figure(figsize=(6.4, 2.8))
plt.bar(names, bers, color=["tomato", "steelblue", "seagreen"])   # bar：柱状图逐位立起
```

三条柱一档比一档矮：本组实跑里裸奔翻车 157/2000，复述三遍掉到 10/666 ≈ 1.5%，复述五遍在整整 400 个分组里一次都没翻——与解析预告 $3p^2(1-p)+p^3$ 一类的多项式量级贴合（固定种子的同款对决人人复现）。但右边的价格牌同样醒目：吞吐 $100\%/33\%/20\%$ 断崖跳水。可靠性不是白送的，是用带宽换的。

### 快问快答

```quiz
既然复制五遍比三遍更稳，为什么真实系统不无限加码？
- 复制有上限，规范不允许更多
- 每加一遍都要吞掉吞吐量，码率跌破需求就白忙 [*]
- 复制太多会产生新的噪声
? 冗余购买可靠性付的是码率货币：预算定死时，寻找「同样开销下纠错更强」的结构（如 Hamming、LDPC）才是正路，盲目复读是最贵的保单。
```

:::warning[常见误区]

**误区一**：「校验位就是把数据再抄一遍。」
抄写是纯粹的备份，坏了哪份都不知道坏在哪；校验位是数据的**函数**（奇偶组合），它的取值空间跟数据绑定，任何一处翻转都会牵动整组哨兵的平账——正是这种耦合让错误自我暴露并报名坐标。

**误区二**：「加了纠错码就不会丢包。」
 Hamming 只担保单比特错误；两位同时中招就会指向第三个无辜位置（综合征仍非零），修出一串新错。更强的码提高免疫半径，但没有任何码保证绝对安全——这是「距离决定能力」的另一面。

**误区三**：「香农极限是编译器的一个优化选项。」
定理只保证好码的存在性；具体的长码构造（Turbo、LDPC、极化码）花了半个世纪才逼近天花板的十分之一分贝以内。下一站去 35 章，那些梯子的图纸才真正展开。

:::

## 6. 练习

**练习 1**：接住例题里那句悬念—— Syndrome 机位被实例化成代码，可惜两处登记笔误让它指鹿为马：

```exercise
# @title: 练习：让三位哨兵交出肇事坐标
# @check: 0110011
# @check: 1011
# @hint: s1 的首项下标写错了一位——三个哨兵的分组下标换成 Python 下标时都要减一；数据座是第 3、5、6、7 位，别从第 4 位起连取四格
r = "0110111"                    # 接收到的 7 位字（内藏一处翻转）

s1 = (int(r[1]) + int(r[2]) + int(r[4]) + int(r[6])) % 2   # ← 问题在这：第一组覆盖位 1,3,5,7，首项却取到了位 2
s2 = (int(r[1]) + int(r[2]) + int(r[5]) + int(r[6])) % 2   # 第二组位 2,3,6,7 无恙（下标统统减一）
s4 = (int(r[3]) + int(r[4]) + int(r[5]) + int(r[6])) % 2   # 第三组位 4,5,6,7 无恙

err_pos = s4 * 4 + s2 * 2 + s1   # 综合征从二进制翻回十进制：直接读出肇事位号

fixed = r                        # 若确有错位则动手翻正
if err_pos > 0:
    fixed = r[:err_pos - 1] + str(1 - int(r[err_pos - 1])) + r[err_pos:]   # 切片拼接：替换第 err_pos 个字符

data = fixed[3] + fixed[4] + fixed[5] + fixed[6]   # ← 问题在这：数据座位是 3,5,6,7，这里从位 4 连取了四格

print(fixed)
print(data)
```

修正两处后输出 `0110011` 与 `1011`：综合征 $101_2$ 直读第 5 位，翻正、对号入座取回四个信息位。注意 `int(r[索引])` 做的是「字符转整数」以便参与加法，切片的下标一律比位号小 1——这套账目的坐标翻译最容易在这里栽跟头。

## 7. 选读：这张地图的下一层

<details>
<summary>选读 · 从玩具到工业级的一页纸</summary>

本章的两个玩具各贡献一根支柱：重复码给出「表决判决」的原型，Hamming 码给出「 syndrome 即坐标」的原型。工业级码把两根支柱嫁接起来再推到极限——卷积码用移位寄存器把记忆织进序列（第 35 章的卷积码直观预告），LDPC 用一张稀疏的大奇偶图让成百上千个弱哨兵投票互证，迭代几轮就从噪声里捞出可靠的信念；Turbo 码干脆让两个弱码互相递纸条，1993 年首次把实刃架到距香农天花板半分贝处。Wi-Fi、5G、深空探测链路的 PHY 层清单里全是这些名字——本章学过的每一件兵器（星座、匹配滤波、同步、软判决）都在它们的系统表里持械上岗。

卷积码的译码也有可算的账本：把编码器画成**格图（Trellis）**——横轴是时刻，纵轴是寄存器状态，每个输入 bit 对应一条带两个输出 bit 的边。以两状态玩具码（状态 = 上一位输入；0 态发 0→00、1→11，1 态发 0→10、1→01）为例：发送 10 得到码序列 1110，信道翻坏第一位后收到 1010。**维特比算法**把四条候选路径的汉明距离各自累加：00→00 00 得 2、01→00 11 得 2、10→11 10 得 **1**、11→11 01 得 2——距离最小的幸存路径反推出 **10**，翻坏的比特当场抓回。逐格累加、逐格剪枝、每个状态只留一名幸存者，这就是最大似然序列译码的全部骨架；软判决把 0/1 距离换成幅度差，还能再多榨约 2 dB 增益。
</details>
