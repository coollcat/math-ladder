# QAM 星座图

## 1. 从一个场景开始

Wi-Fi 路由器的包装盒上印着一行小字：1024-QAM。三个旋钮课（ASK、FSK、PSK）里我们一次只拧一个旋钮，一个符号只驮一两个比特；可现代无线链路动辄一个符号驮十个比特——它们不是把某个旋钮拧得更狠，而是**同时拧幅度和相位两个旋钮**。旋钮组合无穷多，得有一张地图才不迷路——这张地图就叫星座图。

## 2. 直觉解释

把「当前幅度 $A$ 与当前相位 $\varphi$」这对组合画成平面上的一个点：横轴记同相分量（幅度乘相位的余弦），纵轴记正交分量（幅度乘相位的正弦）。每发一个符号，就在平面上点亮一颗星。

- 星星离原点的距离 = 该符号的幅度；
- 星星的角度方位 = 该符号的相位。

所有合法的星星排成一张图案（常见的是方正的点阵），这就是**星座图**。接收端的工作变成了看星星：收到的点离哪颗星最近，就判哪颗星。噪声是蒙在图上的雾——雾越浓，星星之间必须离得越开。ASK 是只会左右移动的一条线，PSK 是绕着圆圈走的一圈点，而 QAM 把整个平面都用上了：这就是方阵点阵比单旋钮高效得多的几何原因。

## 3. 正式定义

M-QAM 的第 $k$ 个符号期间发送 $s_k(t) = A_k \cos(2\pi f_c t + \varphi_k)$，把参数对 $(A_k, \varphi_k)$ 写成一个复数坐标：

$$s_k = I_k + \mathrm{j}Q_k, \qquad I_k, Q_k \in \lbrace -(m-1),\ \ldots,\ -3,\ -1,\ +1,\ +3,\ \ldots,\ +(m-1)\rbrace$$

| 符号 | 名字 | 含义 |
| --- | --- | --- |
| $M$ | 星座点数 | 每符号可取的状态总数 |
| $\log_2 M$ | 每符号比特数 | 一颗星驮多少比特 |
| $I$ / $Q$ | 同相/正交分量 | 点在平面上的横纵坐标 |
| $d_{\min}$ | 最小欧氏距离 | 最近两颗星的间距，判决安全余量 |

效率账一眼算清：16-QAM 每符号驮 $\log_2 16 = 4$ 比特，64-QAM 驮 6 比特，Wi-Fi 7 的 4096-QAM 驮 12 比特——同样是每秒一百万个符号，吞吐量差了三倍。代价同样写在图上：M 翻倍，同样的功率摊给更多的星，相邻间距 $d_{\min}$ 就缩水约一半，误码率随 SNR 恶化得极快。「一颗星多驮比特」与「星星之间的雾中余量」是一对永远在谈判的交易对手。

## 4. 分步例题

**例**：手算一个 16-QAM 映射。电平表每轴取 $\lbrace -3, -1, +1, +3\rbrace$，两位比特按格雷码查表转成电平（00→−3，01→−1，11→+1，10→+3，相邻电平只差一位）。

1. 取比特串 `1011`：前两位 `10` 决定横坐标 $I$，后两位 `11` 决定纵坐标 $Q$；
2. 查表：`10` → $I = +3$，`11` → $Q = +1$；
3. 星座点为 $(+3, +1)$，即幅度 $\sqrt{3^2+1^2}=\sqrt{10}\approx 3.16$、相位 $\arctan(1/3)\approx 18.4°$；
4. 顺带核一笔功率账：四个电平平方的平均值是 $(9+1+1+9)/4 = 5$，两个轴各贡献一份，平均符号能量为 10；
5. 反向演练一遍解码：收到噪声污染的点 $(2.8,\ 0.6)$，离哪颗合法星最近？逐一点比较后判定 $(+3,+1)$，还原出比特 `1011`——「最近邻判决」全程只用勾股定理。

### 实验 2（python）：画出 16-QAM 星座并撒上噪声

```python title="16-QAM 星座图：合法星位与噪声云"
import matplotlib.pyplot as plt   # 绘图库（本站浮窗标配）

lvls = [-3, -1, 1, 3]            # 每根轴上允许的四个电平
xs = []                          # 星座的横坐标集合
ys = []                          # 星座的纵坐标集合
for i in lvls:
    for j in lvls:
        xs.append(i)             # 外层循环固定横坐标
        ys.append(j)             # 内层循环铺满四行

plt.figure(figsize=(5.2, 5.2))
plt.scatter(xs, ys, s=260, color="steelblue", zorder=3)   # s=点的大小，zorder=图层次序（星压住雾）
for k in range(len(xs)):         # 给每颗星标注它驮的四位比特
    bits_x = "00" if xs[k] == -3 else ("01" if xs[k] == -1 else ("11" if xs[k] == 1 else "10"))
    bits_y = "00" if ys[k] == -3 else ("01" if ys[k] == -1 else ("11" if ys[k] == 1 else "10"))
    plt.annotate(bits_x + bits_y, (xs[k], ys[k]), ha="center", va="center",
                 color="white", fontsize=7)               # annotate：在指定坐标写字；ha/va=水平/垂直对齐锚点
plt.axis("equal")                # 两轴等比例，保证圆形轮廓不变形
```

每颗蓝星上的白字就是它驮的四位比特：横纵各分两位、各自查同一张格雷码表。相邻两星之间恰好只有一位不同——判错一颗星时通常只错一位比特，这是格雷映射送给误码率的礼物。

### 快问快答

```quiz
同为 64 符号，方形 8×8 的 64-QAM 和另一款八圈同心圆环排布的星座，为什么工程上几乎总是选方形？
- 方形排列在同等平均功率下最小间距更大 [*]
- 圆环更美观所以抗噪更强
- 方形能省电，圆环费电且不影响误码
? 把面积切成整齐方格，点与点贴得最宽松；同心圆挤在一起会互相贴脸。噪声余量看的是点间最近距离，不是图案好不好看。
```

:::warning[常见误区]

**误区一**：「星座图上的连线是信号轨迹。」
线上什么也没有：发送端一颗一颗地跳点，并不沿着线滑行。连线只是示意图习惯（或是某些特殊调制方案的跳变路径），判决只关心点位与距离。

**误区二**：「QAM 提高阶数是免费的提速。」
阶数翻倍，$d_{\min}$ 缩水近半，误码率对 SNR 的需求陡增几十分贝量级内的好几个台阶。128-QAM 只配出现在干净的电缆或近距离 Wi-Fi 里， LTE 小区边缘往往自动降到 QPSK——速率是按信道质量动态谈下来的。

**误区三**：「16-QAM 就是把 4 个 ASK 电平和 4 个 PSK 相位拼一起。」
若把两者直接串联，16 个点是分布在不同半径圆弧上的相位点，间距参差不齐。真正的 QAM 用两个正交载波分别承载 $I$ 与 $Q$ 分量，才会得到整齐的方格点阵——正交性是方形星座的前提。

:::

## 6. 练习

**练习 1**：一份 16-QAM 链路参数单需要补全效率账与安全账。代码能跑但四处都不对：

```exercise
# @title: 练习：16-QAM 的效率与距离账本
# @check: 16
# @check: 4
# @check: 4800
# @check: 2
# @hint: 星座点数 M 是每轴电平数的平方（横竖各挑一个才组成星位）；每符号比特数要问 log2；比特率得乘上它；d_min 用相邻电平直接相减
import math                      # math.log2：问 2 的几次方等于某数

levels = [-3, -1, 1, 3]          # 每根轴上的四个电平
symbol_rate = 1200               # 每秒发出的符号个数

M = len(levels)                  # ← 问题在这：只数了一根轴的电平
bits_per_symbol = round(M / 4)   # ← 问题在这：不是除以 4，是求 log2(M)
bit_rate = symbol_rate           # ← 问题在这：还没乘每符号比特数
d_min = levels[0] - levels[1]    # ← 问题在这：减出了负的距离

print(M)
print(bits_per_symbol)
print(bit_rate)
print(d_min)
```

修好后输出 16、4、4800、2：星座是两轴的组合（4 种 × 4 种），一颗星驮 $\log_2 16 = 4$ 比特，故比特率 $1200 \times 4 = 4800$ bit/s；而相邻电平相差 2，正是雾里最近的两颗星的安全间距。

**练习 2**：64-QAM 在同等发射功率下，$d_{\min}$ 大约是 16-QAM 的几分之几？粗略估算即可，说明理由。

<details>
<summary>点开查看逐步解答</summary>

16-QAM 电平取自 ±1±3，最外星到中心的距离是 $\sqrt{3^2+3^2}=\sqrt{18}$；64-QAM 电平要扩成 ±1±3±5±7 共八档，维持「最大幅度不暴涨」的口径时，点更密、间距从 2 缩到 2 再除以密度比——严格说在平均功率归一的条件下 $d_{\min}^2$ 与 $M$ 成反比量级：64-QAM 的间距约为 16-QAM 的一半上下（精确值取决于功率归一口径）。数量级结论最有用：**M 翻倍 ≈ 间距打七折到对折 ≈ 对噪声余量的预算砍一刀**。工程师据此在高阶 QAM 前先确保链路有充足的 SNR 富余。
</details>

## 7. 选读：为什么偏偏是方形

<details>
<summary>选读 · 圆与方的能效之辨</summary>

固定平均功率 $E_s$ 时，星座设计的自由度只剩「怎么摆这些点」。二维平面里，让任意多的点彼此尽量远离的最优解接近蜂窝六边形；但工程还要兼顾另一个硬约束——实现简单。方形点阵下，映射与判决都能退化成「两个轴各判各的一维问题」：解调器只需两次一维门限比较，硬件极其干净。方形因此成了性能与复杂度的黄金折中；六边形一类非规整星座只在理论上展示「还能再挤一点点」，实际链路（Wi-Fi、5G NR）清一色方形。另外，格雷映射的规范地位也值得一提：它是被判错概率加权的「单比特代价最小」标尺，任何偏离都要付出误比特率溢价。
</details>
