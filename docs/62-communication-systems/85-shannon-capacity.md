# 信道容量与香农极限

## 1. 从一个场景开始

1990 年代末，为了争夺「拨号上网谁更快」，两大调制解调器阵营打得头破血流：一派说能到 x2，另一派说 K56flex 才行，最后国际电信联盟出面调和出 V.90 标准——56 kbps 封顶，谁也再快不上去了。

为什么偏偏卡在 56k？不是厂商不努力，而是撞上了一堵 1948 年就砌好的墙：**香农容量**。香农证明，任何带宽为 $B$、信噪比为 $S/N$ 的信道，无差错传输的速率有一个铁顶——低于它，纠错编码可以做到万无一失；高于它，神仙编码也救不了。本课拆解这个二十世纪信息科学最重要的公式。

## 2. 直觉解释

把信道想成一条高速公路：

- **带宽 $B$** 是车道数——每秒能放行多少个独立的信号变化；
- **信噪比 $S/N$** 是天气能见度——灯光与背景亮度的对比；
- **容量 $C$** 是安全通行能力的极限车流。

雾天（低信噪比）想多运货只有两条路：加灯（提高功率）或减速降密度（降低每符号比特数）。香农公式精确给出了这场交易的兑换率——而且是对数的：**功率翻倍只换来固定的一小段提速**，加得越多越不划算。

还有一层深意：容量公式里的 $\log_2$ 与第 35 章熵的定义遥相呼应。熵 $H$ 说「信源最多能压多紧」，容量 $C$ 说「信道最多能扛多快」——压缩与纠错在同一把尺子下会师。

## 3. 正式定义

**香农–哈特利定理**：带宽 $B$、信噪比为 $S/N$（线性倍数，非分贝）的加性高斯噪声信道，容量为

$$C = B \log_2\left(1 + \frac{S}{N}\right)$$

| 符号 | 名字 | 含义 |
| --- | --- | --- |
| $C$ | 信道容量 | 无差错传输的速率上限（bps） |
| $B$ | 带宽 | 信道占用的频谱宽度（Hz） |
| $S/N$ | 线性信噪比 | 功率比；分贝值需先换算：$10^{\mathrm{dB}/10}$ |
| $\log_2(1+S/N)$ | 频谱效率 | 每赫兹每秒可承载的比特数 |

两条阅读须知：其一，公式里的信噪比是**线性功率比**——30 dB 是 1000 倍而不是 30 倍，这是第一大坑；其二，香农只说「存在这样一套编码」，没给编码本身（实用逼近要等 Turbo 与 LDPC 登场，那是第 35 章 LDPC 预告的后续剧情）。

## 4. 分步例题

**例 1**：教学取整的电话话音信道 $B = 3000$ Hz、SNR = 30 dB。求容量。

1. 分贝换线性：$10^{30/10} = 1000$；
2. 代入公式：$C = 3000 \times \log_2(1001)$；
3. 查对数：$\log_2(1001) \approx 9.967$；
4. $C \approx 29902$ bps ≈ **29.9 kbps**。

**例 2**（反向）：想在同一条信道跑 28800 bps，至少需要多少 dB？

1. 所需频谱效率：$28800 / 3000 = 9.6$ bps/Hz；
2. 反解线性信噪比：$S/N = 2^{9.6} - 1 \approx 775$；
3. 化回分贝：$10\log_{10}(775) \approx 28.9$ dB；
4. 对照例 1 的 30 dB：留了约 1 dB 余量——工程上这薄薄一层余量就是「能用」与「天天断线」的分界。

## 5. 动手实验

### 实验 1（viz）：对数墙的形状

```viz

  "type": "plot",
  "title": "单位带宽容量 C/B = log2(1+S/N)，横轴 SNR 取分贝",
  "expr": "log(1 + 10^(x/10))/log(2)",
  "xmin": 0,
  "xmax": 40,
  "sliders": []
}
```

读图方法：横轴是 SNR 的分贝值，纵轴是每赫兹能扛的比特率。0 dB 处只有 1 bps/Hz，到 10 dB 涨到约 3.5；此后每一格都越来越「贵」——SNR 翻一倍（+3 dB）至多换来 1 bps/Hz，而从 30 dB 爬到 40 dB 要把发射功率整整乘 10，频谱效率也只从约 10 涨到 13.3。功率线性地烧、速度对数地涨——这就是「对数墙」。想翻墙只能拓宽 $B$（换更大的车道）或压低噪声 $N$（降温、靠近）。

### 实验 2（python）：拨号时代的容量账本

```python title="话音信道 B=3400 Hz 在不同信噪比下的容量"
import math                      # 用 log10 与 log2

B = 3400                         # 电话话音信道带宽（约 300~3700 Hz）
for db in [10, 20, 30, 40]:      # 四档典型信噪比
    ratio = 10 ** (db / 10)      # 分贝换线性功率比
    c = B * math.log2(1 + ratio) # 香农公式
    print(f"SNR {db} dB -> 容量约 {int(round(c, 0))} bps")
```

典型输出：20 dB 约 22.6 kbps，30 dB 约 33.9 kbps，40 dB 约 45.1 kbps。对照史实：双向都过模数转换的老式调制解调器定格在 33.6 kbps——恰好贴着 30 dB 档的墙；56 k 版本靠局端数字化绕开半程转换，把极限顶到约 64 k 的量化栅栏再被功率法规压回 53 k 左右。**每一代产品都是这条对数墙上的刻度。**

### 快问快答

```quiz
香农定理说速率超过容量 C 会发生什么？
- 信号立刻完全消失
- 无论用什么编码，误码都无法压到任意低 [*]
- 只是延迟变大
? 超限传输的错误率存在不可逾越的下限：功率、带宽再怎么调度也压不下去。低于 C 时则相反——存在编码让误码率任意接近零，这是整个现代通信的合法性证书。
```

:::warning[常见误区]

**误区一**：「有噪声就一定出错。」
恰恰相反——香农第二定理说只要速率低于容量，噪声再大也能做到无差错传输（代价是编码复杂度）。噪声决定的是天花板高度，不是「必然出错」。

**误区二**：「加大发射功率就能线性提速。」
对数墙专治这种想法：SNR 从 1000 倍提到 2000 倍，频谱效率只从约 10.0 涨到 11.0 bps/Hz。无线厂商宁可挖带宽、挖天线数量也不硬堆功率。

**误区三**：「56k 调制解调器是厂商技术不行。」
它已把模拟电话线的香农账本用到了极限；剩余缺口是量化栅栏与发射功率法规，不是算法差距。理解极限的人不会苛责工程师。

:::

## 6. 练习

**练习 1**：补全香农账本的正反两问。代码能跑但答案不对：

```exercise
# @title: 练习：正算容量，反算所需信噪比
# @check: 29902
# @check: 28.9
# @hint: 分贝要先除以 10 再作 10 的幂换回线性倍数；反解时公式里底数是 2（2 的多少次方等于 1+信噪比）
import math

B = 3000                         # 带宽 Hz
snr_db = 30                      # 信噪比 dB

ratio = snr_db / 10              # ← 问题在这：这只是折半，还没变成线性倍数
c = B * math.log2(1 + ratio)
need = 10 ** 9.6 - 1             # ← 问题在这：底数应是 2 不是 10
print(int(round(c, 0)))
print(round(10 * math.log10(need), 1))
```

修正为 `ratio = 10 ** (snr_db / 10)` 与 `need = 2 ** 9.6 - 1` 后输出 29902 和 28.9——与例题逐步结果严丝合缝。

**练习 2**：Wi-Fi 想把频谱效率翻倍，香农公式指出的三条正路各是什么？

<details>
<summary>点开查看逐步解答</summary>

对 $C = B\log_2(1+S/N)$ 各动一刀：(a) 加带宽 $B$——Wi-Fi 从 20 MHz 信道扩到 160 MHz；(b) 提信噪比——多天线波束赋形把能量对准接收者；(c) 靠近或缩短距离让路径损耗变小。注意 (b)(c) 都是对数收益，所以标准演进的主旋律其实是 (a) 与空间维度（MIMO 把多条独立 $B$ 叠加）。单靠调制阶数加密刻度（64-QAM→1024-QAM）只在极高 SNR 下才兑现。
</details>

## 7. 选读：与二元对称信道握手

<details>
<summary>选读 · 连续与离散的两张容量脸</summary>

第 35 章的信道课见过它的离散亲戚：错误率 e 的二元对称信道容量 $C = 1 - h(e)$。两者是同一思想在连续与离散世界的投影——香农–哈特利公式取高斯噪声 + 带宽约束后解析可积，BSC 公式取硬判决比特翻转后只剩一个熵函数。工程上二者还能串成一条链：先在模拟层按香农–哈特利选好调制与码率，再到比特层用 LDPC 追赶那道 1 − h(e)。第 40 章信息论的互信息视角会把这两张脸统一成一个定义：容量 = 互信息对输入分布的最大值。

</details>
