# 扩频与跳频：蓝牙的抗干扰术

## 1. 从一个场景开始

2.4 GHz 频段是全世界最拥挤的「公共操场」：Wi-Fi、蓝牙、无线键鼠、Zigbee，甚至微波炉都在这里撒野。可你的蓝牙耳机在开着 Wi-Fi 热点的笔记本旁边照样稳稳放歌。

它的生存策略不是「打赢」任何一台干扰源，而是**根本不恋战**：每秒 1600 次，蓝牙把自己的信号从一个 1 MHz 小频道搬到另一个，搬去哪由一套双方约定的伪随机序列决定。干扰者守着几个频道狂轰滥炸，蓝牙早已转移到别处——这就是**跳频扩频（FHSS）**，本课的主角，也是最后一课：通信系统如何在不属于自己的地盘上打游击。

## 2. 直觉解释

正规军思维是「选一条最干净的频道，重兵把守」。游击队思维相反：

- **化整为零**：把信号拆成一串短促出击，每次只占一个窄频道 625 微秒；
- **行踪不定**：下一个频道由伪随机序列给出，干扰方无法预判；
- **伤而不溃**：某个频道被轰了？损失的只是那 1/79 时间片上的一个包，重传即可。

经典蓝牙的具体参数（蓝牙规范）：79 个 1 MHz 频道铺满 2.402–2.480 GHz，每秒跳 1600 次，每个频道停留 625 微秒。而**自适应跳频（AFH）**是这套游击战术的升级版——发现哪片「村子」被 Wi-Fi 占了，就把它从行动地图上划掉，以后只走干净频道。划掉谁，收发双方要同步更新同一张「黑名单」（信道图）。

## 3. 正式定义

**跳频扩频（FHSS）**：载波频率按伪随机序列 $h_k \in \lbrace 0, 1, \ldots, N-1\rbrace$ 在 N 个频道间周期切换，第 k 个时隙占用频道 $f = f_0 + h_k \times \Delta f$。

| 符号/术语 | 名字 | 蓝牙经典取值 |
| --- | --- | --- |
| $N$ | 频道总数 | 79（1 MHz 间隔） |
| 时隙 | dwell time | 625 μs（每秒 1600 跳） |
| $h_k$ | 跳频序列 | 由主设备地址与时钟驱动，双方预同步 |
| AFH | 自适应跳频 | 测量各频道误码 → 剔除坏频道 → 更新信道图 |

**处理增益**的直觉：宽带 Wi-Fi 占约 20 MHz ≈ 22 个蓝牙频道；不启用 AFH 时任一跳撞进敌区的概率约 $22/79 \approx 28\%$——七成以上时间安然无恙。启用 AFH 后这 22 个频道被整体除名，撞击概率归零，代价是可用频道缩到 57 个。扩频的本质是一笔香农式交易：**用带宽换稳健**——信号摊得越开，单位频点上的能量密度越低，越难被针对，也越少打扰别人。

## 4. 分步例题

**例**：一台微波炉在频道 30–51（共 22 个频道）制造持续干扰。

1. 无自适应时：每次跳频落入干扰区概率 $22/79 \approx 0.28$；每秒 1600 跳中期望约 $1600 \times 22/79 \approx 446$ 次撞枪口——靠重传硬扛，吞吐打折；
2. 启用 AFH：双方把这 22 个频道写入黑名单，行动池缩为 $79 - 22 = 57$ 个干净频道；
3. 每个干净频道平均每秒被光顾 $1600 / 57 \approx 28$ 次——流量均匀摊到幸存者头上；
4. 规范还要求保留足够多的可用频道以维持频率分集，所以黑名单不能无限扩张——游击队也得留根据地。

## 5. 动手实验

### 实验 1（python）：一台跳频模拟器

```python title="伪随机跳频 vs 固定干扰区：数一数挨了几枪"
import matplotlib.pyplot as plt  # 画图库（卷一已引入）

N = 79                           # 频道总数
busy_lo, busy_hi = 30, 51        # 干扰区：频道 30 到 51（含）
hops = []                        # 跳频序列（简化版伪随机）
for k in range(200):
    ch = (17 * k + 3) % N        # 线性同余风格：真实蓝牙用地址+时钟，思想相同
    hops.append(ch)

hits = 0                         # 撞进干扰区的次数
for ch in hops:
    if busy_lo <= ch <= busy_hi:
        hits = hits + 1
print(f"200 跳中撞入干扰区 {hits} 次")

afh_hops = []                    # AFH 版：撞进坏区的跳次折回下方干净池子
for ch in hops:
    if busy_lo <= ch <= busy_hi:
        ch = ch % busy_lo        # 对坏区下缘取余：折回 0~29 的干净频道
    afh_hops.append(ch)

plt.figure(figsize=(7, 2.6))
plt.plot(hops, marker="o", markersize=3, linestyle="", label="raw")
plt.plot(afh_hops, marker=".", markersize=3, linestyle="", color="tomato", label="AFH")
plt.axhspan(busy_lo, busy_hi, color="gray", alpha=0.2)   # axhspan：横向刷出干扰区
plt.legend()
```

灰带是微波炉的地盘。蓝点（原始跳频）有 56 个、近三成落进灰带；红点（AFH 重映射后）全部绕开——注意红点序列依然「乱」得像随机，只是乱在缩小的池子里。把 `busy` 区改宽再跑，观察 AFH 池子收缩的极限。

### 实验 2（python）：低功耗蓝牙的另一种跳法

```python title="BLE 数据信道：固定步长的圆周跳频"
current = 10                     # 当前数据信道（0~36 共 37 个）
inc = 7                          # 连接时协商的跳频增量（规范允许 5~16）
seq = []
for i in range(8):
    seq.append(current)
    current = (current + inc) % 37   # 圆周前进：模 37 回绕

print("BLE 跳频序列:", seq)
```

打印的序列像钟表指针一样步长恒定地绕圈。BLE 用这种简单算术代替经典蓝牙的复杂伪随机——因为它的对抗目标是「别长时间压在同一处」，而不是保密行踪；配合 AFH 黑名单照样能躲开 Wi-Fi。两种跳法，一种哲学。

### 快问快答

```quiz
与其跳来跳去，为什么不干脆固定在一条最干净的频道上通信？
- 固定频道信号更强
- 固定频率会被干扰源持续压制，且频段法规要求共享；跳频把干扰摊薄成小伤 [*]
- 跳频更省电
? 游击哲学的精髓：不与任何强敌正面争夺阵地。固定频率一旦被瞄准就全线瘫痪；跳频让每次损失只有 1/N 个时隙，重传即可恢复。AFH 更进一步——连「被瞄」的机会都不给。
```

:::warning[常见误区]

**误区一**：「跳频就是加密。」
跳频序列确实难以窃听，但它的设计目标是抗干扰与多址共存，密钥管理、帧加密另有专门机制（蓝牙的链路层加密）。把「行踪诡秘」当「通信保密」是危险的误解。

**误区二**：「AFH 需要干扰源配合或额外信令。」
黑名单完全靠收发双方自己测量：统计各频道的误包率，坏的就剔除，再通过常规控制消息同步信道图。Wi-Fi 对此毫不知情也无需知情。

**误区三**：「扩频浪费宝贵的带宽。」
香农视角下这是明码标价的交换：带宽换低功率密度与抗扰性，还顺带解决了多用户共享（不同跳频序列几乎互不碰撞）。在无人管制的公共频段，「能活」比「省」重要得多。

:::

## 6. 练习

**练习 1**：给一台蓝牙打印机算三笔账。代码能跑但答案不对：

```exercise
# @title: 练习：跳频系统的三个数字
# @check: 625
# @check: 40
# @check: 8
# @hint: 驻留时间 = 一秒的微秒数 / 每秒跳数；平均光顾 = 总跳数整除可用频道数；BLE 第 5 次值要把循环走满 5 步
usable = 79 - 39                 # AFH 后的干净频道数

dwell = 10000 // 160             # ← 问题在这：单位错了，一秒是 1000000 微秒
visits = 1600 // usable          # ← 问题在这：该按干净池子均摊，不是全频段
ch = 10                          # BLE 当前数据信道
for i in range(4):               # ← 问题在这：只走了 4 步，问的是第 5 次值
    ch = (ch + 7) % 37

print(dwell)
print(visits)
print(ch)
```

修正后输出 625、40、8：每频道停留 625 微秒；39 个频道被拉黑后剩下 40 个干净频道，每个每秒平均被光顾 40 次；BLE 从 10 号信道以步长 7 绕圈，第 5 站落在 8 号。

**练习 2**：若敌方干扰机恰好也在每秒切换 1600 次、且知道你的跳频序列，AFH 还救得了你吗？

<summary>点开查看逐步解答</summary>

序列泄露等于行踪暴露，AFH 的测量再快也只能事后躲避——对抗「全知的敌人」超出跳频的设计边界，那属于加密与物理层安全的领域。但现实威胁模型几乎从不如此强大：干扰方不知道地址与时钟就推不出序列。工程结论：安全分析永远先写清「对手知道什么」，跳频防的是不知情的蛮横，不是知情的狙击。

## 7. 选读：另一族扩频——直接序列

<details>
<summary>选读 · DSSS 与 GPS</summary>

扩频还有一条路线：不换频率，而是把每个比特乘上一串高速 ±1 的伪随机码片（如 11 片的巴克码），频谱被展宽 N 倍、幅度密度骤降——接收端用同一串码片做相关运算才能把能量重新聚焦，别人看来近乎噪声。GPS 是它最壮观的舞台：卫星信号落到地面时比噪声还弱一千倍仍可解调，靠的正是处理增益的聚焦魔法。跳频与直序殊途同归：都把「信号 vs 干扰」的对决从单点硬拼改写成统计意义上的整体优势。

</details>
