# K 近邻

## 1. 从一个场景开始

你搬进一个新城市，想知道附近哪家餐厅好吃。你没有看任何点评网站——你只是问了住得最近的五户邻居："你们平时去哪吃？"三户说"街角小面馆"，两户说"商场里的火锅"。你决定去小面馆。

这就是 K 近邻（K-Nearest Neighbors，KNN）的全部算法：**找到离你最近的 K 个样本，投票决定你的类别**。没有训练过程、没有参数学习、没有模型——它只是把训练数据原封不动地存起来，等新样本来了再现场投票。

## 2. 直觉解释

想象你在一张地图上，红点是苹果摊、蓝点是橘子摊。现在地图上出现了一个问号——你想知道这里该放苹果还是橘子。

最朴素的想法：以问号为圆心画一个圈，圈里红点多就放苹果，蓝点多就放橘子。圈画多大？那就看 K：K=3 就数最近的 3 个摊，K=10 就数最近的 10 个摊。

K 的选择决定了分类器的"性格"：

- **K=1**：完全信任最近的那个邻居——边界锯齿状、对噪声极度敏感（一个标错的样本就把边界扭曲）；
- **K 很大**：考虑很多邻居——边界平滑，但可能把远处的不相关样本也拉进来投票，模糊了真正的分界线；
- **K 适中**：在"过度信任"和"过度平均"之间找到平衡。

这个平衡就是偏差-方差权衡的又一个化身：K 小→低偏差高方差，K 大→高偏差低方差。

## 3. 正式定义

给定训练集 $\{(x_i,y_i)\}_{i=1}^{n}$，对新样本 $x$：

1. 计算 $x$ 到所有训练样本的距离 $d(x,x_i)$；
2. 找出距离最小的 K 个样本，记其下标集为 $\mathcal{N}_K(x)$；
3. 分类：$\hat{y}=\arg\max_c\;\sum_{i\in\mathcal{N}_K(x)}\mathbf{1}[y_i=c]$（多数投票）。

| 符号 | 名字 | 含义 |
| --- | --- | --- |
| $K$ | 近邻数 | 参与投票的邻居个数 |
| $d(x,x_i)$ | 距离度量 | 衡量两个样本有多"远" |
| $\mathcal{N}_K(x)$ | K 近邻集 | 离 $x$ 最近的 K 个训练样本 |
| $\mathbf{1}[\cdot]$ | 指示函数 | 条件为真时取 1，否则取 0 |

**常见距离度量**：

| 名称 | 公式 | 特点 |
| --- | --- | --- |
| 欧氏距离 | $d=\sqrt{\sum_j(x_j-x_j')^2}$ | 直线距离，最常用 |
| 曼哈顿距离 | $d=\sum_j\lvert x_j-x_j'\rvert$ | 网格距离，对异常值更鲁棒 |
| 闵可夫斯基 | $d=\left(\sum_j\lvert x_j-x_j'\rvert^p\right)^{1/p}$ | $p=2$ 欧氏，$p=1$ 曼哈顿 |

## 4. 分步例题

**例**：5 个训练样本，二维特征，判断新点 $(3,3)$ 的类别。

训练集：$A(1,1,\text{红})$、$B(2,2,\text{红})$、$C(4,4,\text{蓝})$、$D(5,5,\text{蓝})$、$E(1,5,\text{蓝})$。

1. 计算 $(3,3)$ 到各点的欧氏距离：
   - $d(A)=\sqrt{4+4}=2\sqrt{2}\approx2.83$
   - $d(B)=\sqrt{1+1}=\sqrt{2}\approx1.41$
   - $d(C)=\sqrt{1+1}=\sqrt{2}\approx1.41$
   - $d(D)=\sqrt{4+4}=2\sqrt{2}\approx2.83$
   - $d(E)=\sqrt{4+4}=2\sqrt{2}\approx2.83$
2. 排序：$B(1.41)$、$C(1.41)$、$A(2.83)$、$D(2.83)$、$E(2.83)$；
3. $K=3$：最近 3 个是 $B$(红)、$C$(蓝)、$A$(红)——红 2 票、蓝 1 票→判**红**；
4. $K=5$：全部邻居投票——红 2 票、蓝 3 票→判**蓝**；
5. 同一个点、同一个数据集，**K 不同答案相反**——K 的选择不是小事。

### 实验 2（python）：从零实现 KNN

```python title="KNN 分类器：计算距离、排序、投票"
import math

# 训练集：(x, y, 类别)
train = [(1,1,"红"), (2,2,"红"), (4,4,"蓝"), (5,5,"蓝"), (1,5,"蓝")]

def euclidean(a, b):
    """欧氏距离：sqrt((x1-x2)^2 + (y1-y2)^2)"""
    return math.sqrt((a[0]-b[0])**2 + (a[1]-b[1])**2)

def knn_predict(point, train_data, k):
    """KNN 预测：计算距离、取最近 k 个、投票"""
    # 第一步：计算到所有训练点的距离
    dists = [(euclidean(point, (x, y)), label) for x, y, label in train_data]
    # 第二步：按距离排序
    dists.sort(key=lambda t: t[0])             # lambda 定义排序依据
    # 第三步：取最近 k 个，统计票数
    votes = {}
    for _, label in dists[:k]:                 # 切片取前 k 个
        votes[label] = votes.get(label, 0) + 1 # dict.get 安全取值
    # 第四步：返回票数最多的类别
    return max(votes, key=votes.get)            # max 按票数取最大

test = (3, 3)
for k in [1, 3, 5]:
    result = knn_predict(test, train, k)
    print(f"K={k}: 判定为 {result}")
```

运行结果：$K=1$ 判红（最近的是 $B$），$K=3$ 判红（$B,C,A$ 中红多），$K=5$ 判蓝（全票中蓝多）。代码只有 20 行——KNN 的美在于它**几乎没有训练阶段**，所有计算都推迟到预测时。

### 快问快答

```quiz
KNN 为什么被称为"懒惰学习"？
- 因为它不需要选择超参数
- 因为它把所有计算推迟到预测时，训练阶段几乎不做任何事 [*]
- 因为它只能处理小数据集
? 训练阶段只是"把数据存起来"（$O(1)$ 时间），预测时才计算距离、排序、投票（$O(nd)$ 时间）。与之对比，朴素贝叶斯训练时要统计所有概率、逻辑回归训练时要迭代求解——它们是"急切学习"。
```

:::warning[常见误区]

**误区一**："K 越大越准确。" K 过大会引入远处的不相关邻居——他们可能是另一条街的餐厅，跟你的口味毫无关系。极端情况下 $K=n$（全部样本投票），分类器永远返回多数类，完全丧失区分能力。

**误区二**："KNN 不需要特征工程。" 距离度量对特征的尺度极度敏感：如果一个特征的范围是 0-10000、另一个是 0-1，前者会完全主导距离计算。KNN 几乎**必须**做特征标准化（z-score 或 min-max 归一化），否则效果会很差。

**误区三**："KNN 在高维数据上也管用。" 这是维度灾难的领地：在高维空间中，所有点之间的距离趋于相等——最近的邻居和最远的邻居差不多远。投票失去了意义。预告：维度灾难是 KNN 的天敌，下一课 K-means 也会遇到类似困境。

:::

## 6. 练习

**练习 1**（概念）：训练集有 100 个红点和 900 个蓝点，新样本的 10 个近邻里有 4 红 6 蓝。用 K=10 的多数投票判为蓝，但红点的真实比例是 10%——这个结果合理吗？如何改进？

<details>
<summary>点开查看逐步解答</summary>

10% 的红点在 10 个近邻中出现了 4 个（40%），远高于全局比例——说明这个区域确实红点密度更高。多数投票判蓝没有错，但如果业务上更关心红类（比如欺诈检测），可以：(1) 降低 K 让局部特征更突出；(2) 加权投票，按距离倒数加权（近邻话语权更大）；(3) 调整决策阈值，不以 50% 为界。
</details>

**练习 2**（判题）：下面的 KNN 代码在投票时用了错误的比较逻辑。修好它让 K=3 正确输出"红"。

```exercise
# @title: 练习：修好 KNN 的投票逻辑
# @check: 红
# @hint: max 函数的 key 参数应该按票数取最大，不是按类别名字典序。
import math

train = [(1,1,"红"), (2,2,"红"), (4,4,"蓝"), (5,5,"蓝"), (1,5,"蓝")]
test = (3, 3)
K = 3

dists = []
for x, y, label in train:
    d = math.sqrt((test[0]-x)**2 + (test[1]-y)**2)
    dists.append((d, label))
dists.sort()

votes = {}
for _, label in dists[:K]:
    votes[label] = votes.get(label, 0) + 1

result = max(votes)                            # ← 错了：这按字典序取最大键
print(result)
```

把 `max(votes)` 改成 `max(votes, key=votes.get)` 后，输出 `红`——按票数取最大而非按名字排序。

**练习 3**（选做）：如果用曼哈顿距离代替欧氏距离，例题中 $(3,3)$ 的 $K=3$ 结果会变吗？手算验证。

<details>
<summary>点开查看逐步解答</summary>

曼哈顿距离 $d=\lvert x_1-x_2\rvert+\lvert y_1-y_2\rvert$：
- $d(A)=2+2=4$，$d(B)=1+1=2$，$d(C)=1+1=2$，$d(D)=2+2=4$，$d(E)=2+2=4$。

排序：$B(2)$、$C(2)$、$A(4)$、$D(4)$、$E(4)$——$K=3$ 取 $B$(红)、$C$(蓝)、$A$(红)→判红。结果没变，因为在这个对称的例子里两种距离的排序一致。但在非对称的数据中，距离度量的选择会改变邻居的排序，进而改变分类结果。
</details>

## 7. 选读：维度灾难——为什么高维空间里距离失效

<details>
<summary>选读 · KNN 在高维空间的困境</summary>

设 $n$ 个点均匀分布在 $d$ 维单位超立方体 $[0,1]^d$ 中。最近邻到原点的距离 $r_{\min}$ 满足：

$$E[r_{\min}^d]\approx\frac{1}{n}\cdot\frac{1}{V_d}$$

其中 $V_d=\frac{\pi^{d/2}}{\Gamma(d/2+1)}$ 是 $d$ 维单位球的体积。当 $d$ 增大时 $V_d$ 急剧缩小（$d=20$ 时 $V_{20}\approx0.026$），导致 $r_{\min}$ 趋近 1——最近的邻居也住在超立方体的"对角"上。

更直觉的表述：$d=100$ 时，一个半径为 0.5 的球只包含不到 $10^{-29}$ 的空间体积。绝大多数体积都集中在"壳层"上。任何两个点之间的距离都差不多——"最近"和"最远"之间几乎没有区别。

这就是维度灾难（curse of dimensionality）：高维空间中，局部性假设崩溃，KNN 的"离得近就是同类"的直觉不再成立。解决思路包括降维（PCA）、特征选择、以及用核方法把数据映射到低维空间。
</details>
