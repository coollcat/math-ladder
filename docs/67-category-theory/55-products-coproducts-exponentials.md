# 积、余积与指数对象直觉

## 1. 从一个场景开始

电商仓库接到一笔怪订单：客户要"一把伞和一双雨靴"，但坚持**只收一个包裹**。仓库只能发明一件新商品——把伞与靴绑在一起的标准套装，并附上两条开箱说明（先取左袋是伞、右袋是靴）；此后任何相同诉求的订单，仓库都只回这一种套装。

与此同时，隔壁投诉处理部遇到了镜像问题：客户既可能寄回伞也可能寄回雨靴，处理台必须给两种来货各设一个受理口，并且在每个口子上都能按标准流程办结。仓库发"组合包"、处理台收"分拣件"——把这两张业务卡片再叠上一层"按型号定价"（每支伞各配一个价目响应），你就提前预定了本课三位主角的全部戏份。

## 2. 直觉解释

回到上一课的收编原则："不问内部，只看往来"。让它开工三次：

- **积 $A\times B$ 是标准套装**：它自带两支拆包箭头（称为投影 $\pi_1,\pi_2$），并且任何"同时想要两边信息"的对象都得经它的合同中转——条款保证中介方式唯一；
- **余积 $A+B$ 是分拣台**：方向对调，改为自带两支**投放箭头**把 $A$ 与 $B$ 的货各送上台面；下游任何处理站只需认得两种来源标签即可办结一切来货，同样"接线方式唯一"；
- **指数对象 $B^A$ 更进一步**：连"如何从 $A$ 走到 $B$"这件事本身都被做成一件商品上架——购物车里装的是一支支完整的路线图，配一支总评箭头，输入路线图与原料即可交付成品。

三个世界的落地样本：
- **Set 世界**：套装=笛卡尔积（大小相乘）、分拣台=不相交并（大小相加）、货架=全体函数（大小为 $|B|^{|A|}$）——数量语言和乘方口诀严丝合缝；
- **整除偏序世界**（$a\le b$ 读作"$a$ 整除 $b$"）：$\gcd$ 就是两数的积（最大公因数=同时整除二者的最大者），$\mathrm{lcm}$ 就是余积（最小公倍数）；例如 $6$ 与 $10$ 的套装是 $2$、分拣件是 $30$；
- **Python 世界**：元组打包对应套装、带来源标签的分类型列表对应分拣台、"以输入换输出的一级函数"对应货架商品。

## 3. 正式定义

**积**：候选 $P$ 配两支投影 $\pi_1:P\to A$、$\pi_2:P\to B$；若对任何 $X$ 及其两支箭头 $f:X\to A$、$g:X\to B$，存在唯一的中介箭头 $\langle f,g\rangle:X\to P$ 使两侧方程闭合：

$$\pi_1\circ\langle f,g\rangle=f\qquad \pi_2\circ\langle f,g\rangle=g$$

**余积**：对偶翻面——候选 $Q$ 配投放 $in_1:A\to Q$、$in_2:B\to Q$，任何处理者 $X$ 接到两条来路时有唯一的中转方案使其闭合：

$$h\circ in_1=p\qquad h\circ in_2=q$$

**指数对象**：候选 $E=B^A$ 配总评箭头 $ev:E\times A\to B$；对任意 $X$ 配一支探针 $t:X\times A\to B$，存在唯一派生箭头 $\tilde t:X\to E$ 使 $ev\circ(\tilde t\times id_A)=t$。

| 构件 | 角色 | 唯一条款查什么 |
| --- | --- | --- |
| $\pi_1,\pi_2$ | 投影 | 拆包两步各自对号 |
| $\langle f,g\rangle$ | 中介 | 一次性接管双诉求 |
| $in_1,in_2$ | 投放 | 分门别类上台 |
| $h$ | 处理方案的统一接口 | 两路来账一并结清 |

读法备忘：三个定义其实共用同一句台词——"给出候选与其引脚，任何外来需求都有唯一接法"。区别只在引脚朝向与需求形状。

## 4. 分步例题

用数字说话：$|A|=3$、$|B|=2$。

1. **积的订单量**：每个 $x\in A$ 都要挑一个搭档 $y\in B$，共 $3\times 2=6$ 组成套记录；
2. **余积的面单量**：两类货源并列登记且互不相扰，共 $3+2=5$ 条入库线；
3. **货架的商品量**：每件商品是一整张"三输入、两输出"的指派表——第一个输入有 2 种去向、第二个也有……合计 $2\times 2\times 2=2^3=8$ 件；
4. 联动上一课：单点站台的接待量公式 $k^{n}$ 在 $n=3,k=2$ 时同样报出 $8$——它数的是"探针发来的全部路线"，与货架商品一一对应，两门业务共享同一本台账；
5. 结论：大小账本等于逻辑账本——泛性质不仅定义结构，还自动送你一套算术恒等式。

### 实验 1：八件商品自己盘点

```viz

  "type": "set-mapper",

```

规则还是老规矩：每件原料必须恰好引出一支箭头，但**彼此互不商量**——于是配置总数就是 $2\times2\times2$。你的每一次点击都在世界上多注册一件"商品"；想让整套货架清零重来也是合规操作，因为资格判定只看当下这张表。

### 实验 2：三本大账当场对数

```python title="积、余积、指数的数量三条账"
A = ["a1", "a2", "a3"]
B = ["b1", "b2"]

pair_count = 0               # 积：成套记录
for x in A:
    for y in B:
        pair_count += 1      # += 表示自增累加
print(pair_count)

ledger = []                  # 余积：贴上来源标签的不相交并入账
for x in A:
    ledger.append(["L", x])
for y in B:
    ledger.append(["R", y])
print(len(ledger))           # len 数容器里有多少个成员

shelf = []                   # 指数：三层选择层层展开＝指派表全集
for c0 in B:
    for c1 in B:
        for c2 in B:
            shelf.append((c0, c1, c2))
print(len(shelf))
```

输出的三个整数正是 $6,5,8$——乘法、加法、幂运算三兄弟同框报到。此刻把哪一层循环改成遍历 `A` 都会当场露馅：算术表象的背后其实是箭头方向的严格分工。

## 常见误区

:::warning[常见误区]

**误区一**："积就是把两个东西塞进同一个袋子。"
袋子不带说明书不算积：必须随附两支合格的拆包箭头，并满足"任意双诉求对象有唯一中介"。少一支投影或允许多种中介，同一批货物就会摇身变成别的构造。

**误区二**："余积就是集合并集。"
普通并集会悄悄合并共同成员（$A\cup A=A$），而余积坚持"哪怕是同一件货，两路来货也分牌登记"。Set 世界需要贴来源标签正是为了防这次悄悄握手。

**误区三**："指数对象 $B^A$ 只是把 $B$ 写上去的好看记号。"
它是真家伙：货架本身是一个对象，大到可以整体参与后续焊接（下一课极限的信使），小到其内部几何决定了"参数化程序"能否被当值传递。名字里的幂次只是它在 Set 世界亮出的营业额。

:::

## 6. 练习

**练习 1**：仓库升级后原料多了一件（A 变成四个成员），程序却还留着旧档架的三层骨架，盘出的库存立刻缩水：

```exercise
# @title: 练习：把档架改造成逐层生长式，四件原料也照数清点
# @check: 16
# @check: True
# @hint: 别再多手写一层循环试试运气——换成在旧档案基础上"每人多一次去向选择"的生长模式：对已有档案逐条复制、再各自追加一种新去向。
def grow(stack, picks):
    fresh = []
    for card in stack:
        fresh.append(card)              # ← 问题在这：只保留了原样续摊
    return fresh

DOMAINS = 4
shelf = [()]
step = 0
while step < DOMAINS:                   # 这里的 while 有次数上限，安全
    shelf = grow(shelf, ["b1", "b2"])
    step += 1

reference = 0                           # 直接枚举兜底核对
for u in range(2):
    for v in range(2):
        for w in range(2):
            for t in range(2):
                reference += 1

print(len(shelf))
print(len(shelf) == reference)
```

修好后两行为 `16` 与 `True`：把 `grow` 内部补上内层去向循环（对 `card` 逐个加上 `picks` 里每一种选择生成新卡），生长式档架立刻恢复 $2^4$ 的全额库存，并与四重直排枚举完全对账。初始版本每层只保留旧记录不加枝叶，档架纹丝不动地停在一份空白档案上。

**练习 2**（口头推理）：在整除偏序的世界里解释：为什么 $\gcd$ 自动配备"两支进路"而 $\mathrm{lcm}$ 需要反过来配备"两支出路"？

<details>
<summary>点开查看逐步解答</summary>

该世界中箭头方向是"由小到大"（因指向倍数）。作为候选积，需要两支进入自身的投影箭头：$\gcd$ 既整除两数，正好各收一支（ $2\mid 6$、$2\mid 10$）；又因为凡能同时整除二者者必整除 $\gcd$，中介由"更小的那个公因数"的这笔关系直接顶替——收编成立。反观余积要求自身向两数发出箭头：$\mathrm{lcm}$ 同时是两者的倍数，恰好充当出发枢纽，"既是 $6$ 又是 $10$ 的公共倍数则必是 $\mathrm{lcm}$ 的倍数"完成唯一性。一句话总结：**方向感决定分工**，同族数论事实不过是泛性质在该小世界里的方言发音。
</details>

## 7. 选读：柯里化——货架的跨界魔术

<details>
<summary>选读 · 输入何时变成了中间件</summary>

把探针的定义再看一眼：一支两变量函数 $X\times A\to B$ 竟被唯一兑换成一支单变量函数 $X\to B^A$。这条往返通道就是柯里化——多参函数拆成"先记主菜、后添配料"的两段式下单。编程语言的日常红利由此铺开：固定一半参数立即得到一族定制函数，库调用链条因此可以像乐高一样逐段扣合。更有趣的反向通感发生在余积一侧：很多语言里的错误处理类型（成功值或失败原因，二选一）恰恰是标准的分拣台——每种路径都得提供各自的办结方案，缺一路都过不了编译。至此你会发现：类型系统只是替你在编译期跑了一遍今天的箭头审计而已。
</details>
