# 第 67 章专属组件规格

本文件只登记尚未实现的理想教具（自 index「计划交互形态」迁入统一维护）。正式课程当前只能使用既有通用 `viz`、浮窗 Python 与文字/ASCII 交换图；不得把下列名称写成已上线 `viz type`。

## 公共需求

1. 所有组件通过现有 `viz` JSON 围栏接入；解析失败显示中文错误且不影响页面水合。
2. 交换图布局一律从数据自动推导（节点/箭头数组 → 层次布局），不要求作者手写坐标；提供拖拽微调并允许一键复位。
3. 箭头必须有方向、标签与「同一支箭头」的稳定身份（拖动节点不改变箭头连接关系）。
4. 每个组件提供「重置 / 随机例 / 导出 JSON 快照」三键；连续动画遵守 `prefers-reduced-motion`。
5. 支持暗色模式、移动端纵排布局、路由切换重扫不重复绑定（dataset 守卫）；异步运行必须有重入守卫。

## morphism-puzzle（态射组合拼图 · 交换图补全）

- 目标：给出缺 1–2 支箭头的交换图，学生从候选池拖入正确箭头使整图交换。
- 配置：`objects`（节点数组）、`arrows`（已给箭头）、`candidates`（候选箭头池，含干扰项）、`commutesOn`（需验证的方块列表）。
- 必做：拖入后即时验证该方块是否交换（沿两条路径的合成逐点比对）；干扰项拖入时给出「为什么不可交换」的具体反例点；计数与身份律箭头支持开关显示。
- 课程落点：10、20（组合律与单位元）。

## functor-diff（函子作用前后对比器）

- 目标：左右双栏对照同一张小交换图在函子 $F$ 作用前后的样子——对象搬家、箭头搬家、焊缝（合成关系）不走样。
- 配置：`source`（源范畴小图）、`functor`（对象映射 + 箭头映射）、`highlight`（保恒等 / 保合成哪条被演示）。
- 必做：任选源图一支箭头，双栏联动高亮它的像；提供「故意写错的函子」开关（丢箭头或破坏合成），让学生找出哪条公理被违反；箭头映射必须与对象映射自洽校验。
- 课程落点：30（函子）、40（自然变换——支持两个函子并排作对比）。

## universal-receiver（泛性质万向接收器）

- 目标：学生把任意「候选对象 + 万箭汇聚的态射束」投进接收器，组件判定它是否满足所给泛性质（唯一性 + 存在性），并可视化分解出的唯一中介态射。
- 配置：`property`（initial/terminal/product/coproduct 预设之一）、`diagram`（形状图）、`attempts`（候选解数组，含唯一正解与若干近似解）。
- 必做：近似解必须给出「穿过它的两条路径在何处分岔」的具体失败点；唯一性用两条同色路径重合动画表达；预设间可一键切换（积 ⇄ 余积对偶翻转）。
- 课程落点：50（泛性质）、55（积余积）、60（极限余极限）。

## monad-pipeline（monad 管道串联演示）

- 目标：把 `unit → bind → bind → …` 画成一条集装箱流水线：装箱、拆装拍扁、传给下一段；直观呈现「多层包装被 bind 拍平」。
- 配置：`pipeline`（步骤数组，每步为 {name, body}）、`wrapper`（Maybe/List/函数容器三选一）、`nestedInput`（预置嵌套样例）。
- 必做：单步执行与连续播放双模式；每步同步显示容器层级的横剖面（嵌套深度计数）；提供「裸用 flatten 代替 bind」的反例开关，演示为什么必须由 bind 顺便拍扁。
- 课程落点：70（Monad）、80（应用出口）。
