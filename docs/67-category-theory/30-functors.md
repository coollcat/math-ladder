# 函子：结构之间的翻译官

## 1. 从一个场景开始

把一份中文菜谱整本译成英文：既要把**名词**翻译（"面粉"到 "flour"），也要把**动词**翻译（"搅拌"到 "stir"），而且动作关系不能走样——原文说"搅完再加热"，译文绝不能读成"加热完再搅"。漏搬动词、或者搬了却弄乱先后，这份译文就是废纸。

范畴之间的函子干的就是这活：把一个箭头世界整本搬到另一个箭头世界，搬点、搬箭头、还要焊缝原样。上一课立的两条公理，正是它在双方世界里都要遵守的合同范本。

## 2. 直觉解释

最亲切的样本就在你电脑里：**Python 世界自己就是一个小范畴**——点是类型（数字、字符串），箭头是函数。而 `list` 是一位随身翻译官：

- **对象层**：它把任何类型 T 送往"该类型的清单"，就像给每个名词都派了一个复数形式；
- **箭头层**：它把任何普通函数 f 抬升成"逐项处理版"，`fmap(f)` 扫一遍清单、每格套一次 f；
- **不走样条款**：先套 f 再套 g 跟一次性套上"g 接 f"，结果必须一模一样；恒等函数抬升后必须原样奉还。

数学家把这组要求写成两条等式（下节），你先用眼睛验收：右边这套"翻译流水线"走的每一步，左边都有对应的单程直达。

别的世界也有各自的表现形式：偏序世界里，函子是一条单调映射（有大小关系的两点，像也保持）；群的世界到集合的世界之间站着一位特别的翻译官——**遗忘函子** $U$，它把每个群送回"只是一堆元素"的底账集合、把同态送回普通函数——正是上一门课"涂黑内部"的那个操作被收编成了正规军。

## 3. 正式定义

设 $\mathcal C$ 与 $\mathcal D$ 是范畴。从 $\mathcal C$ 到 $\mathcal D$ 的函子 $F$ 由两层指派组成：

| 层 | 数据 | 要求 |
| --- | --- | --- |
| 对象层 | 每个对象 $A$ 配对象 $F(A)$ | 无附加条件 |
| 箭头层 | 每支 $f:A\to B$ 配 $F(f):F(A)\to F(B)$ | 见下 |

且必须满足两条**函子律**：

$$F(g\circ f)=F(g)\circ F(f)\qquad F(id_A)=id_{F(A)}$$

第一条是"焊缝不走样"；第二条是"白线翻译后还是白线"。对照范畴公理你会发现：**函子就是一种范畴层面的同态**——只是这次被映射的对象本身"是"上节课的产物。同构函子（两层都能互逆地翻译）呼应第 33 章"同构即完美翻译"；更细的忠实与满（faithful / full）分级议题，留作选读探索。

三条硬规则里最容易忽略的是箭头层的**首尾一致**：$f:A\to B$ 在译界必须是一支 $F(A)$ 到 $F(B)$ 的箭头。你上一课刚踩过"终点对不上起点"的 KeyError，这里就是同一个坑在双语世界里的复发。

## 4. 分步例题

验证容器翻译官确实合规：取基础清单 $\lbrack 2,\ 3\rbrack$、抬升函数"平方"与"加倍"。

1. 对象层设定：任何类型 $T$ 送到"清单版的 $T$"；
2. 箭头层示例：普通函数 $sq(v)=v^2$ 抬升为"逐项平方"：$\lbrack2,3\rbrack \mapsto \lbrack4,9\rbrack$；
3. **焊缝检查**：先加一（$v+1$）再平方得 $\lbrack9,16\rbrack$；直接套用合成函数 $(v+1)^2$ 也得 $\lbrack9,16\rbrack$，两路相合 ✓；
4. **白线检查**：抬升后的恒等处理让清单分毫不动 ✓；
5. 结论：list 容器合法上岗。反过来试想一位拙劣翻译只搬名词不搬动词——那两条等式当场爆雷，这正是下一节的实验器材。

## 5. 动手实验

### 实验 1：给三类对象登记翻译去向

```viz
{
  "type": "set-mapper",
  "title": "翻译官的对象层工作台：左侧三个源对象各该去往哪个目标",
  "left": ["整数", "字符串", "布尔"],
  "right": ["整数清单", "字符串清单", "布尔清单"]
}
```

点击中间圆点，为每个源对象接一支去路。这只是一个函子万里长征的第一步——**对象层本身毫无约束**（愿意的话你可以违宪地把整数也送去"字符串清单"试试，组件不会拦你），真正的合同全押在箭头层的两条律令上。

### 实验 2：两条函子律代码实测

```python title="容器翻译官的两条法条核对"
def fmap(f, xs):         # 箭头层：把普通函数 f 抬升为逐元素版本
    ys = []
    for x in xs:
        ys.append(f(x))
    return ys

base = [2, 3]

def add1(v):
    return v + 1
def square(v):
    return v * v
def stay(v):             # 白线的原型：什么都不做
    return v

stage2 = fmap(square, fmap(add1, base))    # 先加一再平方
onetrain = []
for v in base:                            # 直通车版：一次到位
    onetrain.append(square(add1(v)))
print(stage2)
print(stage2 == onetrain)
print(fmap(stay, base) == base)           # 白线律
```

首行打印 `[9, 16]`；第二行 `True` 是焊缝不走样的现场证据；末行 `True` 是白线原样奉还。逐元素运算天然保序保长，所以"清单翻译官"稳过审——换成会吞元素或乱重排的容器，这两条律就得重新验关。

## 常见误区

:::warning[常见误区]

**误区一**："函子就是个函数。"
普通函数连接的是**点**；函子连接的是**整个世界**，且以成对的方式同时搬运点与箭头。方向感的差别约等于"司机"和"搬家公司"。

**误区二**："函子律是冗余的，对象层对了就行。"
恰恰相反：大量貌似合理的对象层配上乱来的箭头层照样能跑——实验里如果把逐元素循环写成隔一个取一个，五步以内两条律就兵败如山倒。合同的全部牙齿都长在箭头层。

**误区三**："函子必须是可逆的。"
函子允许压缩甚至塌陷：常值函子把所有对象送去同一个目标、所有箭头送去同一支白线，两条律照样成立。有来有回才升级叫同构。

:::

## 6. 练习

**练习 1**：程序想证明"先加一再翻倍"的两段流水线等于一次直达（这正是保复合条款），但直达车装配时颠倒了工序：

```exercise
# @title: 练习：让直达车按字条上的工序发车
# @check: [2, 6]
# @check: [2, 6]
# @check: True
# @hint: 字条写的是"先加一再翻倍"。直达车一次进站就得走完全程：先坐加一站，再坐翻倍站——想想外层该套哪支函数。
def add1(v):
    return v + 1
def scale(v):
    return v * 2

def lift(f, xs):        # 翻译官的箭头层（正确）
    out = []
    for x in xs:
        out.append(f(x))
    return out

base = [0, 2]

stage_all = lift(scale, lift(add1, base))   # 两段式：先加一再翻倍
express = []
for v in base:                              # 想当一次到位的直达车
    express.append(add1(scale(v)))          # ← 问题在这：先翻倍再加一了
print(stage_all)
print(express)
print(stage_all == express)
```

修好后三行依次为 `[2, 6]`、`[2, 6]`、`True`：两段式的 `0→1→2`、`2→3→6` 与直达车殊途同归，保复合条款当场兑现。初始版直达车 `add1(scale(v))` 煮出的是 `[1, 5]`——工序颠倒让同一张字条跑出了两种菜。想加码的话，再定义白线函数 `stay(v)` 并核对 `lift(stay, base) == base`，把第二条函子律也纳入质检。

**练习 2**（口头推理）：遗忘函子 $U$ 把群连同乘法一并丢给集合世界。有人说"$U$ 忘得太狠，肯定违反白线律"。你怎么反驳？

<details>
<summary>点开查看逐步解答</summary>

$U$ 丢掉的是**结构信息**，不是**行为一致性**。$U(\mathrm{id}_G)$ 仍是恒等函数——元素的一个都不动；$g\circ f$ 复合后作为函数的逐点作用本来就和分开做无异。所以两条函子律双双安好。"忘性"体现在别处：许多本质不同的同态映射会被 $U$ 平反成看起来一样的普通函数——它是忠实的却不区分乘法好坏，丢了"保乘"这张心电图。
</details>

## 7. 选读：协变与逆变

<details>
<summary>选读 · 有一种翻译喜欢倒着搬箭头</summary>

约定俗成还有一种"反向翻译官"：对每支 $f:A\to B$，它配出的不是 $F(A)\to F(B)$ 而是 $F(B)\to F(A)$，并把 $F(g\circ f)=F(f)\circ F(g)$ 设为新契约。这类怪客称为逆变函子，典例是把线性空间 $V$ 送到它的对偶空间（全部线性泛函组成的空间）的操作。日常约定里不加前缀的"函子"专指本文的正向款（协变）。两者的分工在后续表示论路线会反复登场；眼下只需记住：**箭头的流向本身就是可挑选的翻译口径**——这是"看结构不看材料"哲学的又一次扩容。

</details>
