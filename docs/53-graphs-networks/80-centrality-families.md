# 中心性家族比较

## 1. 开场钩子

机场枢纽、急救站和谣言关键传播者的“重要”不是同一件事。有的要直连多，有的要到谁都近，有的要站在最短路上，有的要看邻居本身有多强。

中心性不是一个数字，而是一组问题的映射。

## 2. 直觉解释

| 家族 | 问的问题 | 擅长发现 |
| --- | --- | --- |
| 度中心性 | 谁直接连接多？ | 活跃枢纽 |
| 接近中心性 | 谁到所有人都快？ | 服务覆盖点 |
| 中介中心性 | 谁常出现在最短路上？ | 桥梁和瓶颈 |
| 特征向量/PageRank | 谁连接到重要的节点？ | 结构影响力 |

同一个社交图中，客服号可能接近所有人，但不是谣言桥；跨社区账号可能中介很高，但度不算最高。

## 3. 正式定义

无向图的接近中心性常用

$$C_C(v)=\frac{n-1}{\sum_u \text{dist}(v,u)},$$

其中距离按边数计算。中介中心性为

$$C_B(v)=\sum_{s\ne v\ne t}\frac{\sigma_{st}(v)}{\sigma_{st}},$$

$\sigma_{st}$ 是 $s$ 到 $t$ 最短路径数，分子表示其中经过 $v$ 的数量。

特征向量中心性解

$$A\vec x=\lambda \vec x.$$

## 4. 分步例题

星形图：中心 C 连着三个叶子 L1、L2、L3。

1. C 的度为 3，任一叶子度为 1；
2. C 到所有点的总距离是 $1+1+1=3$，接近中心性为 $3/3=1$；
3. 叶子到其他点的总距离是 $1+2+2=5$，接近中心性为 $3/5=0.6$；
4. 若没有跨叶子边，所有最短路都经过 C，所以 C 的中介也最大。

### 实验 1（lab）：同一张图，四种「重要」

课程里的对照表是手写的分数。下面这张卡把四个指标**在真图上现算**——不是查表，是 BFS 与 Brandes 现推出来的：

```lab

  "type": "g53-centrality-panel",
  "title": "四个指标同屏排榜：冠军会不会换人",
  "metric": "degree"
}
```

默认这张六节点图里，`枢纽` 连了三条边，度中心性第一；`守门人` 只连两条边、度只有 0.6，却**是通往外部顾问的唯一通道**。先切 `度中心性`，冠军是枢纽；再切 `中介中心性`，榜单整条重排，冠军换成守门人——0.400 对 0.350。这就是正文那句「真实系统不应只看一张榜单」。

切到 `接近中心性` 与 `特征向量中心性`：冠军又回到枢纽。**四个指标并不是四个互相独立的真相**，它们常常一致，分歧才是信息量所在——分歧出现时，要问的是「我在优化哪种重要」。

再点 `加一条捷径`：程序自动在两个还没有直连的节点之间连一条边。中介中心性对这条边最敏感——多一条替代路径，守门人的票立刻被别人分走；度中心性只动那两个端点。反复点几次，看两个指标的排名怎么越走越远。最后点 `换成星形`：四个冠军全落在中心——**没有分歧时，就不需要比较指标了**。

### 实验 2（python）：手写的对照表

下面的对照表故意让四个指标给出不同冠军。修改数值前先想：你在改变哪种“重要”？

```python title="四种中心性的语义差异"
metrics = {
    "degree":       {"客服": 9, "桥梁": 4, "明星": 8, "冷门专家": 2},
    "closeness":    {"客服": 0.91, "桥梁": 0.72, "明星": 0.65, "冷门专家": 0.31},
    "betweenness":  {"客服": 0.10, "桥梁": 0.88, "明星": 0.04, "冷门专家": 0.01},
    "eigenvector":  {"客服": 0.61, "桥梁": 0.44, "明星": 0.92, "冷门专家": 0.18},
}

for name, table in metrics.items():   # items 同时取指标名和分值表
    ranked = sorted(table, key=table.get, reverse=True)
    best = ranked[0]                  # 排序后的第一名就是最高分节点
    print(f"{name}: 第一名={best}, 排序={ranked}")
```

真实系统不应只看一张榜单；先定义要优化的风险或收益。

## 6. 常见误区

:::warning[常见误区]

**误区一**：你把中心性当成综合实力。它们回答的问题不同，不能直接相加。

**误区二**：你忽略有向性。入中心性和出中心性必须分开。

**误区三**：你以为高中介一定高 degree。两个大群体之间的小账号可能只有两条边却控制通道。

:::

## 8. 选型边界

选指标前先问失效模式：

1. 断开直连选 degree；
2. 缩短平均响应选 closeness;
3. 监控跨区通路选 betweenness;
4. 追踪长期影响选 PageRank 或特征向量版本。

若数据只是观测到的交互，缺失边会让所有榜单都有偏差。

## 9. 选读：四种"重要"能差多远

<details>
<summary>选读 · 一张小图上把四种中心性并排放</summary>

正文说"中心性是一组问题的映射，不是一个数字"。这句话最硬的证据是：同一张图，四种中心性可以给出**完全不同的排序**。

取五节点链 $1-2-3-4-5$ 与五节点星形（中心 $C$ 连四个叶子）：

| 图 | 度数中心性 | 接近中心性 | 中介中心性 | 特征向量中心性 |
| --- | --- | --- | --- | --- |
| 链 | $1,2,2,2,1$（归一后 $0.25,0.5,0.5,0.5,0.25$） | $0.4,\ 0.571,\ 0.667,\ 0.571,\ 0.4$ | $0,\ 3,\ 4,\ 3,\ 0$ | $0.134,\ 0.232,\ 0.268,\ 0.232,\ 0.134$ |
| 星 | 中心 $1.0$，叶子 $0.25$ | 中心 $1.0$，叶子 $0.571$ | 中心 $6$，叶子 $0$ | 中心 $0.333$，叶子 $0.167$ |

**链上最刺眼的一处**：度数中心性只给中间三位相等的 2，两端各 1——它说中间三位"一样重要"；中介中心性却把差距拉得更开：中间那位 4，次中间两位 3，两端 0（$4$ 对 $0$ 是**无穷多倍**）。差别在于问的问题：度数问"你有多少直接联系人"，中介问"多少对通讯必须经过你"。链的两端谁都不需要经过，尽管它们各有 1 个邻居。

**星上反过来的地方**：中介中心性给中心 $6$、叶子 $0$——差距是"绝对压倒"；特征向量中心性给中心 $0.333$、叶子 $0.167$，只有 **2 倍**。为什么？因为特征向量中心性解 $A\vec x=\lambda\vec x$ 时，叶子的分数来自中心的分数，而中心的分数是四片叶子之和，于是 $\lambda=\sqrt4=2$，比值正好 2。它衡量的是"你邻居有多重要"，不是"有多少对路径经过你"。

**取舍**：度数最便宜（$O(m)$）但只看一跳；接近要全源最短路（$O(nm)$）；中介要数所有最短路径（Brandes 算法 $O(nm)$）；特征向量要幂迭代（每轮 $O(m)$，轮数看谱隙）。信息量与成本同步上升——没有一个"更对"。

**边界**：四种都默认无权、无向、静态。加权图要把边数换成最短路长度；有向图的中介统计要区分方向；动态图上这四套全部要重算，没有增量公式可套。

</details>
