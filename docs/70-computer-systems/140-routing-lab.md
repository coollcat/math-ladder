## 1. 从一个场景开始
你从北京发一个包到洛杉矶的一台服务器。它经过十几个路由器，每一个都要做一个决定：**这个包该从哪个口出去？**
没有任何一台机器知道完整的地图。每台路由器只有邻居告诉它的那点信息，以及一张自己算出来的表。**它们凭什么能对所有目标达成一致？**
## 2. 直觉解释
问路有两种方式：
| 方式 | 做法 | 对应协议 | 优点 | 缺点 |
| --- | --- | --- | --- | --- |
| **拿整张地图自己算** | 每个节点把自己直连的链路广播给全网，于是大家都有同一张地图，各自跑一遍最短路 | **链路状态**（OSPF、IS-IS） | 收敛快、无环、支持按带宽设权重 | 要泛洪、要存整张图、计算量大 |
| **只问邻居** | 每个节点只知道"我到各处多远"，定期把整张表发给邻居，邻居据此更新 | **距离向量**（RIP、EIGRP） | 实现极简、消息小 | 收敛慢、**计数到无穷** |
第一种是"各自算同一道题"，第二种是"反复互相抄答案，抄到不再变化为止"。
## 3. 正式定义
网络建模为带权无向图 $G = (V, E, w)$，$w(e) \ge 0$ 是链路代价。
**链路状态（Dijkstra）**：维护 $d[v]$（当前已知最短距离）与集合 $S$（已确定的节点）。每轮：
1. 取 $u = \arg\min_{v \notin S} d[v]$；
2. 把 $u$ 加入 $S$，此时 $d[u]$ 即最终值；
3. **松弛** $u$ 的每条出边：若 $d[u] + w(u,v) < d[v]$，则 $d[v] \leftarrow d[u] + w(u,v)$。
**关键判据**：只有当**所有边权非负**时，"取最小者"这一步才安全——因为任何绕道都要先经过某个 $d$ 更大的节点，不可能更短。
**距离向量（分布式 Bellman-Ford）**：每个节点 $u$ 维护到所有目标的表 $D_u[v]$，反复执行
$D_u[v] \leftarrow \min_{x \in N(u)} \bigl(w(u,x) + D_x[v]\bigr)$
直到无人再更新。它收敛（边权非负时最多 $|V|-1$ 轮），但**坏消息传得极慢**。
**真实量级**：
| 协议 | 类型 | 度量 | 关键数字 |
| --- | --- | --- | --- |
| RIP | 距离向量 | 跳数 | **15 跳上限**（16 = 不可达），30 s 广播一次整表，180 s 无更新判失效 |
| OSPF | 链路状态 | cost $= \dfrac{100\ \text{Mbps}}{\text{接口带宽}}$ | Hello 10 s、Dead 40 s，按**区域**划分以限制泛洪范围 |
| BGP | 路径向量 | AS 跳数 + **策略** | 全球 IPv4 路由表接近 **百万条**前缀，收敛一次可达数分钟 |
## 4. 分步例题
**例**：图中 A 连 B(2)、C(5)，B 连 C(1)、D(3)，C 连 E(4)，D 连 E(2)、F(4)，E 连 F(3)、G(2)，F 连 G(5)。用 Dijkstra 求 A 到各点的最短距离。
1. 初始化：$d[A] = 0$，其余 $\infty$，$S = \varnothing$；
2. 取最小 $A$：$S = \lbraceA\rbrace$。松弛 A–B 得 $d[B] = 2$，A–C 得 $d[C] = 5$；
3. 取最小 $B$（2）：$S = \lbraceA,B\rbrace$。松弛 B–C：$2 + 1 = 3 < 5$ → $d[C] = 3$；B–D：$2+3 = 5$ → $d[D] = 5$；
4. 取最小 $C$（3）：松弛 C–E：$3 + 4 = 7$ → $d[E] = 7$；
5. 取最小 $D$（5）：松弛 D–E：$5+2 = 7$，不小于 7，不更新；D–F：$5+4=9$ → $d[F]=9$；
6. 取最小 $E$（7）：E–G：$7+2 = 9$ → $d[G] = 9$；E–F：$7+3=10$，不小于 9，不更新；
7. 结果：$A{=}0,\ B{=}2,\ C{=}3,\ D{=}5,\ E{=}7,\ F{=}9,\ G{=}9$。
**注意第 3 步**：$d[C]$ 从 5 被降到 3——**松弛就是"发现更短的路就改账"**。整个算法的正确性只依赖一件事：非负权下，全局最小的那个未确定节点的距离不可能再被改进。

**点一个节点**把它设为源点，**点一条边**选中它（可拖"权重"滑块改代价，或按"断开/恢复选中边"）。三种模式：
- **Dijkstra**：逐帧看"选出最小 → 松弛出边"两个动作，被松弛的边高亮，下方距离表同步更新；
- **距离向量**：每一帧是**所有节点同时**把整张表发给邻居。看它要几轮才收敛（本图约 5 轮）；
- **计数到无穷**：线型 A—B—C，断开 A—B 之后，B 与 C 互相引用对方的旧值，距离**交替上升**，直到撞上跳数上限 16 才停。
做两个实验：
- Dijkstra 模式下点节点 G 作为源点：距离表整体改变，但**树的结构是同一张图的最短路径树**；
- 把某条边的权重拖到 20：看最短路径树怎么"改道"，以及哪些节点的距离**完全没变**（不在这条路径上的那些）。
### 实验 2（python）：同一张图，两种算法
```python title="链路状态与距离向量：结果相同，过程完全不同"
INF = 10 ** 9
graph = {                    # 邻接表：节点 → [(邻居, 权重), ...]
    "A": [("B", 2), ("C", 5)],
    "B": [("A", 2), ("C", 1), ("D", 3)],
    "C": [("A", 5), ("B", 1), ("E", 4)],
    "D": [("B", 3), ("E", 2), ("F", 4)],
    "E": [("C", 4), ("D", 2), ("F", 3), ("G", 2)],
    "F": [("D", 4), ("E", 3), ("G", 5)],
    "G": [("E", 2), ("F", 5)],
}
src = "A"
def dijkstra(g, s):
    dist = {v: INF for v in g}      # 字典推导：所有节点先置无穷
    dist[s] = 0
    done = set()
    while len(done) < len(g):
        u = None
        for v in g:
            if v not in done and (u is None or dist[v] < dist[u]):
                u = v                        # 贪心：取未确定里距离最小的
        done.add(u)
        for w, c in g[u]:
            if dist[u] + c < dist[w]:        # 松弛：发现更短的路就改账
                dist[w] = dist[u] + c
    return dist
def distance_vector(g, s):
    dist = {v: (0 if v == s else INF) for v in g}
    for r in range(len(g) - 1):              # 边权非负时最多 |V|−1 轮收敛
        nd = dict(dist)                      # 本轮的新表（所有人同时更新）
        changed = False
        for u in g:
            for w, c in g[u]:
                if dist[w] + c < nd[u]:      # 经邻居 w 走到 s 要 dist[w] + c
                    nd[u] = dist[w] + c
                    changed = True
        dist = nd
        print(f"  第 {r + 1} 轮：", {k: dist[k] for k in sorted(dist)})
        if not changed:                      # 一整轮无人更新 → 收敛
            break
    return dist
d1 = dijkstra(graph, src)
print("Dijkstra（一次算完）：", {k: d1[k] for k in sorted(d1)})
print("距离向量（逐轮交换）：")
d2 = distance_vector(graph, src)
print("两者一致：", d1 == d2)
```
两种算法给出同一张表，但过程截然不同：Dijkstra 是**一个人拿着整张图做 $|V|$ 次贪心选择**；距离向量是**所有人同时抄邻居的作业，抄到没人再改**。后者的致命弱点在"计数到无穷"模式里——**好消息传得快，坏消息传得慢**。
### 快问快答
```quiz
链路 A—B 断开后，为什么距离向量协议要很久才能发现「到 A 不可达」？
- 因为要等邻居主动通知，而邻居不知道该怎么通知
- 因为 B 还会从 C 那里听说「C 能到 A」（用的是 C 的旧值），于是一轮一轮互相抬高，直到撞上跳数上限 [*]
- 因为链路断开的检测本身就要几分钟
? 距离向量只交换「距离数字」，不交换「路径」，所以无法判断邻居告诉你的那条路是不是正经过你自己。B 听 C 说「我到 A 是 2」，就记 3；C 听 B 说「我到 A 是 3」，就记 4 —— 循环放大。毒性逆转（告诉邻居「经我到 A 是无穷」）与触发更新能缓解，但根治要靠链路状态或路径向量（BGP 记录完整 AS 路径）。
```
:::warning[常见误区]
**误区一**："距离向量就是分布式的 Dijkstra。" 你以为它们是同一算法的两面——**不是**。Dijkstra 是"从已知最短的那点向外扩张"的贪心，它要求每个节点握有**全局拓扑**；距离向量是"反复用贝尔曼方程迭代"的不动点计算，节点只握有**邻居的距离表**。收敛速度、消息复杂度、对坏消息的反应全都不同。
**误区二**："路由就是求最短路，求出最短路就完事了。" 你以为互联网是一张求最短路的图——**域内路由（OSPF）确实在求最短路，域间路由（BGP）不是**。BGP 的核心不是"最短"，而是**策略**：谁是我的客户、谁是我的供应商、我愿不愿意为谁转发流量。一条 AS 路径更长但更"便宜"或更"可信"的路由，完全可能被优先选择。**把 BGP 当成最短路算法，是网络工程里最贵的误解。**
**误区三**："路由表收敛之后，网络里就没有环了。" 你以为收敛即无环——**收敛过程中**的瞬态环路是真实存在的：拓扑变化时，各节点更新有先后，某些瞬间 A 认为经 B 到 D 最近，B 认为经 A 到 D 最近，包就在两点间弹来弹去。IP 首部里的 **TTL**（每跳减一，归零即丢弃）就是为这种瞬态环准备的保险丝。
:::
## 6. 练习
**练习 1**：这台 Dijkstra 输出 999（等于最初的无穷大），说明它一次都没真正松弛。修到输出 `6`：
```exercise
# @title: 练习：选错了要扩展的节点
# @check: 6
# @hint: Dijkstra 的贪心是「取未确定节点里距离最小的那个」——只有选最小，才能保证它的距离不再被改进。代码选了最大的
INF = 999
edges = [(0, 1, 4), (0, 2, 2), (2, 1, 1), (1, 3, 3), (2, 3, 7)]   # (起点, 终点, 权重)
dist = [0, INF, INF, INF]     # 从节点 0 出发到各点的距离
done = [False] * 4
for _ in range(4):
    u = -1
    for i in range(4):
        if not done[i] and (u < 0 or dist[i] > dist[u]):   # ← 问题在这：应该选 dist 最小的
            u = i
    done[u] = True
    for a, b, w in edges:
        for x, y in [(a, b), (b, a)]:                      # 无向图：两个方向都要松弛
            if x == u and dist[u] + w < dist[y]:
                dist[y] = dist[u] + w
print(dist[3])
```
**练习 2**：线型拓扑 A—B—C，链路代价都是 1。断开 A—B 后，B 与 C 用距离向量反复更新。写出前 4 轮 B 与 C 各自记录的"到 A 的距离"，并说出为什么加跳数上限就能终止。
<details>
<summary>点开查看逐步解答</summary>
1. 断开前：$d_B(A) = 1$（直达），$d_C(A) = 2$（经 B）；
2. 断开后 B 的直达边没了，但 B 还记着旧值 1，C 记着 2；
3. 第 1 轮（B 问 C）：$d_B(A) = d_C(A) + 1 = 2 + 1 = 3$；
4. 第 2 轮（C 问 B）：$d_C(A) = 3 + 1 = 4$；
5. 第 3 轮：$d_B(A) = 4 + 1 = 5$；第 4 轮：$d_C(A) = 6$；
6. **每轮 +1，无限上升**——这就是计数到无穷。等 $d$ 超过 15（RIP 的上限），协议把它标记为 16 = 不可达，循环才停；
7. 上限的作用不是"算对了"，而是**给这个死循环一个出口**：把无限循环变成"最多 15 轮后必定收敛到不可达"。代价是收敛慢（几分钟），这也是 RIP 只适合小网络的原因。
</details>
## 7. 选读：毒性逆转、触发更新与 BGP 的路径向量
<details>
<summary>选读 · 三种给「坏消息」加速的办法</summary>
**水平分割（split horizon）**：绝不把"从某个邻居学来的路由"再告诉那个邻居。它解决了**两节点**之间的互相欺骗，但三人成环时无效。
**毒性逆转（poison reverse）**：把"从邻居学来的那条路"以**无穷大**的代价告诉该邻居——明说"经我到 A 是走不通的"。这是水平分割的加强版，代价是路由表变大。
**触发更新（triggered update）**：不等 30 秒的周期，一旦检测到链路断开就**立刻**发更新。它把"发现坏消息"的时间从分钟级压到秒级。
即便如此，距离向量在复杂拓扑下仍可能慢。**链路状态（OSPF）** 换了个思路：与其反复协商，不如让所有人都拿到同一张地图。泛洪的代价是带宽，收益是**收敛快且天然无环**（所有人都用同一份数据算最短路，而 Dijkstra 给出的树无环）。
到了自治系统之间，规模（近百万条前缀）和**商业策略**让两个方案都不适用，于是有了 **BGP 的路径向量**：路由通告里带上完整的 **AS 路径**（如 `65010 65020 3356`）。收到通告时先看有没有自己的 AS 号——**有就丢弃**，这条简单规则一举消灭了所有环路，而且让"我愿意为谁转发"这类策略有了可操作的字段。
**从"跳数"到"完整路径"，本质上是把"多少"换成了"经过谁"——信息多了一点点，能回答的问题多了很多。**
</details>
