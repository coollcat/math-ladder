# 积分：把无限个瞬间攒回总量

上一章我们学会了"瞬间"的语言：导数。但它只回答了一半的问题——知道每一刻的速度，**总共走了多远**？里程表不会自己长出来。把无数个"瞬间的变化"重新攒回一个"总变化"，这个动作就叫**积分**。

别以为这只是物理课的事。"曲线下的面积"其实是数学里最通用的语言：

- **概率**：身高在 170 到 180 厘米之间的概率，就是概率密度曲线下那一块的面积；
- **功**：推力一路变化时做的总功，是力-距离曲线下的面积；
- **流量**：水管流速忽快忽慢，一小时总送水量还是流速曲线下的面积。

只要问题长成"每一点的强度 × 无限细分的一小段，全部加起来"，它就是积分。

本章七课，一级一级往上爬：

1. [面积与黎曼和](./10-riemann.md)——把曲边图形切成矩形，用"分割→取样→求和→取极限"驯服弯曲；
2. [微积分基本定理](./20-ftc.md)——全数学最优雅的定理：面积问题原来是求导的逆问题；
3. [反常积分：对无穷做积分](./25-improper-integrals.md)——先截断再取极限，判决无穷区域面积的有穷与无底洞，旗舰交互是 b 翻倍巡逻的尾巴赛跑表（两条著名尾巴谁停谁疯）；
4. [不定积分与换元](./30-techniques.md)——把求导法则倒放，练出一套"反求导"手艺；
5. [分部积分：乘积法则的逆运算](./32-partial-integration.md)——乘积法则倒放成"转嫁公式"，选对 u 让难题降级，旗舰交互是拖系数的半成品检测器（只乘不减，欠账现形）；
6. [部分分式：拆开有理函数](./35-partial-fractions.md)——把复杂分数兑换成标准面额逐项收割，有理函数积分的万能钥匙，旗舰交互是拖系数配平、直到两张曲线严丝合缝；
7. [数值积分](./40-numeric.md)——没有公式的积分怎么办？让计算机把矩形切到足够细。

学完这章，微积分上下半场合龙：微分拆解变化，积分还原总量。而"无限过程如何得到确定结果"这件事本身，下一章还要用更纯粹的方式重讲一遍——无穷级数。

## 实战挑战 · 给电动测试车算里程

> 来源标注：改编自经典题型（高考物理 v-t 图像类问题——图线与时间轴围成的面积即位移），工程数据为情境原创。

某电动车测试场做续航标定：试车员驾驶车辆沿直线跑道加速再刹停，车载传感器每 **2 秒**记录一次车速，得到下表：

| 时刻（秒） | 0 | 2 | 4 | 6 | 8 |
| --- | --- | --- | --- | --- | --- |
| 车速（米/秒） | 0 | 18 | 42 | 30 | 0 |

物理课告诉你：速度-时间图线下的面积就是走过的路程。可图线是弯的，"面积"怎么算？这正是本章的黎曼和登场时刻。已知前 2 秒车辆做匀加速，速度满足 $v(t) = 9t$。

**(a)** 用梯形法则估计全程 8 秒的总里程（每一小段看作梯形：$\text{位移} = \frac{v_{前} + v_{后}}{2} \times \Delta t$）；
**(b)** 用牛顿-莱布尼茨公式算出前 2 秒的精确路程，并与 (a) 中这一段的梯形估计对照；
**(c)** 想一想：后 6 秒为什么不能用 (b) 的办法，只能老实数值积分？

```exercise
# @title: 实战挑战 · 给电动测试车算里程
# @check: 180.0
# @check: 18.0
# @hint: (a) 每段面积 = 两端速度平均 × 段宽 Δt=2——现在代码里漏乘了段宽；(b) v=9t 的原函数是 F(t)=4.5t²，代入端点相减
times = [0, 2, 4, 6, 8]                     # 采样时刻（秒）
speeds = [0, 18, 42, 30, 0]                 # 对应车速（米/秒）

total = 0.0
for k in range(len(speeds) - 1):            # 相邻采样点两两配对，共 4 段
    avg_speed = (speeds[k] + speeds[k + 1]) / 2   # 这段的平均速度猜想：两端取平均
    total = total + avg_speed               # ← 累加的是"高"，面积还缺什么？

print(round(total, 1))                      # (a) 全程里程的梯形估计

F_end = 9 * 2 ** 2                          # ← 这个"原函数猜想"求导后还等于 9t 吗？
F_start = 0
print(round(F_end - F_start, 1))            # (b) 前 2 秒精确路程
```

<details>
<summary>点开查看逐步解答</summary>

**(a)** 把四个时段各看成一块细长梯形，底宽都是 $\Delta t = 2$ 秒：

$$\tfrac{0+18}{2}\cdot 2 + \tfrac{18+42}{2}\cdot 2 + \tfrac{42+30}{2}\cdot 2 + \tfrac{30+0}{2}\cdot 2 = 18 + 60 + 72 + 30 = 180 \text{ 米}$$

初始代码把"高"当成了"面积"——它累加的每个窄条都只有 1 秒宽，所以得 90。补上 $\times\,\Delta t$ 后正好翻倍。

**(b)** 前 2 秒 $v(t)=9t$ 是匀加速，原函数 $F(t)=\frac{9}{2}t^2=4.5t^2$（回验：$(4.5t^2)'=9t$ ✓）。于是

$$s=\int_0^2 9t\,dt = 4.5\times 2^2 - 0 = 18 \text{ 米}$$

而 (a) 里这一段的梯形估计是 $\frac{0+18}{2}\times 2 = 18$ ——分毫不差！这不是巧合：直线速度的梯形替身就是它自己（40 号课选读的误差公式里 $f''=0$，误差恒为零）。

**(c)** 牛顿-莱布尼茨公式的门票是一张写得出的原函数；后 6 秒的车速没有公式，只剩五个孤零零的采样点——解析法无票可买，数值积分是唯一入口。真实车辆的每一次里程标定都是这么算的（40 号课误区二："数值方法是常态而非妥协"）。

验证代码：

```python
times = [0, 2, 4, 6, 8]
speeds = [0, 18, 42, 30, 0]
total = 0.0
for k in range(len(speeds) - 1):
    dt = times[k + 1] - times[k]
    total = total + (speeds[k] + speeds[k + 1]) / 2 * dt
print(round(total, 1))

exact = 4.5 * 2 ** 2 - 4.5 * 0 ** 2   # ∫₀² 9t dt 的精确值
print(round(exact, 1))
```
</details>

## 实战挑战 · 矩形法别忘了乘宽度

黎曼和的精髓：每个窄条的**面积** = 高度 × 宽度。下面用矩形法算 $\int_0^1 x^2\,dx$（真值 $\frac13 \approx 0.333$），却只累加了高度、漏乘了宽度 $dx$，修到输出 `0.333`：

```exercise
# @title: 实战挑战：矩形法别忘了乘宽度
# @check: 0.333
# @hint: 每根细矩形的面积 = f(x) × dx，只加 f(x) 得到的是高度之和。
def f(x):
    return x * x

n = 1000
a, b = 0, 1
dx = (b - a) / n          # 每根矩形的宽度
total = 0.0
for k in range(n):        # 切成 1000 根细矩形
    x = a + k * dx        # 第 k 根矩形的左端点
    total = total + f(x)  # ← 问题在这：漏乘了宽度 dx
print(round(total, 3))
```

<details>
<summary>点开查看逐步解答</summary>

每根矩形的面积是"高 × 宽"：

```python
total = total + f(x) * dx   # 高度 f(x) × 宽度 dx
print(round(total, 3))      # 0.333
```

改完：$1000$ 根矩形面积之和约 $0.3335$，`round` 到 3 位为 `0.333`，与真值 $\frac13$ 吻合。初始代码只加高度，得到约 $333$（把 1000 个 $\le1$ 的高度累加），差了整整一个 $dx=0.001$ 的数量级。积分是"高度 × 宽度"的求和，漏乘宽度就退化成"数高度"。

</details>
