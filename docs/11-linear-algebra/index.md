# 线性代数：会算术的几何

前十章里，数学一直是"一个数的故事"。这一章，我们让**一串数**一起登场——它们排成队，就有了方向；有了方向，就成了几何。线性代数的口号是：**把几何动作翻译成算术，再把算术结果翻译回几何**。翻译官当得好，图形学里的旋转缩放、机器学习里的相似度打分、傅里叶变换里的"换坐标系"，全是同一套基本功。

这门语言为什么值得学？三个事实：

- **游戏与动画**：屏幕上每个角色的每一次转身、跳跃、压扁，背后都是本章的矩阵在对整个画面"动手脚"；
- **机器学习**：判断两句话像不像，就是把它们变成向量再算点积——你天天听说的"向量"、"嵌入"，主角都在这章登场；
- **傅里叶变换**（第 16 章·卷一枢纽站）：它本质上是"换一组基来说话"，而"基"正是本章压轴概念。

本章七课，一步一个脚印：

1. [向量：既有大小又有方向的量](./10-vectors.md)——给箭头配上算术：加法与数乘；
2. [点积：两个向量合不合拍](./20-dot-product.md)——一个数说了算；
3. [矩阵：让整个平面动起来](./30-matrix.md)——对整个平面动手脚的配方；
4. [矩阵乘法：动作的接力](./35-matrix-multiplication.md)——两份配方合并成一份：行乘列的合账算术，AB ≠ BA 的现场证明；
5. [基与坐标：换一套语言说同一个点](./40-basis.md)——同一个向量，不同的语言；
6. [逆矩阵：撤销键的出生课](./45-inverse-matrix.md)——对角互换、副对角变号再除以行列式：动作世界的 Ctrl+Z；

学完这章你会发现：以前学的加减乘除没有作废——它们只是学会了在箭头、网格和坐标系上跳舞。

## 实战挑战 · 游戏引擎的精灵变形台

> 情境原创 · 图形学入门经典场景

你在给一款像素游戏写引擎。屏幕上的每个角色都是一堆顶点坐标，"放大""转身"这类动作，全靠矩阵一次搬运整个点集。美术提了个需求：把精灵**横向放大 2 倍、纵向放大 3 倍**（贴图适配宽屏），然后**整体左转 90°**。渲染管线里两个矩阵谁先谁后，结果差之毫厘谬以千里——今天你来当一回图形学工程师。

**(a)** 写出缩放矩阵 $S$ 与左转 90° 的旋转矩阵 $R$。提示：读列——$\hat{\imath}$ 和 $\hat{\jmath}$ 各被送到哪？再把角点 $\vec{p}=(1,2)$ 先后用 $S$、$R$ 各搬一次。

**(b)** 把两种顺序都算一遍：先 $S$ 后 $R$，与先 $R$ 后 $S$。同一个角点的落点一样吗？下面的代码能跑，但第二行是复制第一行改的懒——修到两个落点都正确：

```exercise
# @title: 实战挑战：先放大还是先转身
# @check: -6 2
# @check: -4 3
# @hint: "先旋转、后缩放"就是把 apply 的里外两层对调：apply(S, apply(R, p))。对照「矩阵」一课实验 3 的写法
S = [[2, 0], [0, 3]]    # 缩放配方：î -> (2,0)，ĵ -> (0,3)
R = [[0, -1], [1, 0]]   # 左转90度：î -> (0,1)，ĵ -> (-1,0)
p = [1, 2]              # 精灵的一个角点

def apply(M, v):
    # 矩阵乘向量：每个分量 = M 的一行与 v 对应相乘再相加（矩阵课的手艺）
    return [M[0][0] * v[0] + M[0][1] * v[1],
            M[1][0] * v[0] + M[1][1] * v[1]]

first = apply(R, apply(S, p))    # 先缩放、后左转
second = apply(R, apply(S, p))   # ← 这行抄错了顺序！应该是先旋转、后缩放
print(first[0], first[1])
print(second[0], second[1])
```

**(c)** 思考题：如果缩放是**均匀**的（横竖都放大同样的倍数），先后顺序还重要吗？

```quiz
把精灵先等比放大 3 倍再左转 90 度，和先左转 90 度再等比放大 3 倍，最终画面相同吗？
- 不同：矩阵动作永远不可交换
- 相同：均匀缩放和旋转谁前谁后都不改变落点 [*]
- 只有转 180 度时才相同
? 等比缩放只是把每支基箭头按同一倍率拉长，而旋转不碰任何长度——两种操作互不打架（可交换）。会打架的是横竖不等比的缩放，就像本题的 S。
```

<details>
<summary>点开查看逐步解答</summary>

**(a) 读列写出配方**：缩放把 $\hat{\imath}\to(2,0)$、$\hat{\jmath}\to(0,3)$，故 $S=\begin{pmatrix} 2 & 0 \\ 0 & 3 \end{pmatrix}$；左转 90° 把 $\hat{\imath}\to(0,1)$、$\hat{\jmath}\to(-1,0)$，故 $R=\begin{pmatrix} 0 & -1 \\ 1 & 0 \end{pmatrix}$。

**(b) 两种顺序分步搬运** $\vec{p}=(1,2)$：

- 先缩放后旋转：$S\vec{p} = (2,6)$，再左转：$R(2,6) = (-6,2)$；
- 先旋转后缩放：$R\vec{p} = (-2,1)$，再缩放：$S(-2,1) = (-4,3)$。

两个落点不同——这正是矩阵课实验 3 的"$AB \neq BA$"：变换是动作，动作先后不可随意调换。用代码验算：

```python
S = [[2, 0], [0, 3]]
R = [[0, -1], [1, 0]]
p = [1, 2]

def apply(M, v):
    return [M[0][0] * v[0] + M[0][1] * v[1],
            M[1][0] * v[0] + M[1][1] * v[1]]

print(apply(R, apply(S, p)))   # [-6, 2]
print(apply(S, apply(R, p)))   # [-4, 3]
```

**(c) 均匀缩放可交换**。横竖同乘 $k$ 的矩阵是 $\begin{pmatrix} k & 0 \\ 0 & k \end{pmatrix}$，它作用在任何向量上等于"整支箭头拉长 $k$ 倍"，而旋转不改变长度、只拧方向——两者一个管长短、一个管朝向，分工不重叠，所以谁先谁后落点一致。真正打架的只有"横竖不等比"的缩放：它会把圆揉成椭圆，揉的方向取决于先转还是先揉。

**附赠面积账**：本题合成变换把单位正方形的面积变成几倍？分步算即可——缩放贡献 $|\det S| = 6$ 倍，旋转贡献 $|\det R| = 1$ 倍（旋转不挤压面积），总共 6 倍。行列式的"面积倍率"身份在链式动作里照样好使。

</details>

## 实战挑战 · 三维点积别漏分量

点积是"对应分量相乘再求和"。三维向量 $[1,2,3]$ 与 $[4,5,6]$ 的点积应该遍历三个分量，下面这题只循环了两次，修到输出 `32`：

```exercise
# @title: 实战挑战：三维点积别漏分量
# @check: 32
# @hint: 两个向量各有 3 个分量，循环次数得是 3，不是 2。
u = [1, 2, 3]
v = [4, 5, 6]
dot = 0
for i in range(2):             # ← 问题在这：漏了第三个分量
    dot = dot + u[i] * v[i]
print(dot)
```

<details>
<summary>点开查看逐步解答</summary>

三维向量有三个分量，循环要跑满 3 次：

```python
for i in range(3):             # 0、1、2 三个下标
    dot = dot + u[i] * v[i]
print(dot)                     # 1*4 + 2*5 + 3*6 = 32
```

改完：$1\times4 + 2\times5 + 3\times6 = 4 + 10 + 18 = 32$。初始代码 `range(2)` 只算了前两个分量（$4+10=14$）。点积的"合拍程度"由**全部**分量共同决定，漏掉任何一维都会得出错误的相似度——这正是本章点积课"一个数说了算"的前提。

</details>
