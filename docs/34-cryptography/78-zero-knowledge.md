# 零知识证明：不说出秘密，却让你确信

## 1. 从一个场景开始

你要进一栋上了密码锁的楼，保安拦住你。你不能把密码告诉他（他会记住），但你必须让他相信你**确实知道**密码。

怎么办？让他背过身去，你输密码进门，他从门外看到门开了——**他确信你知道密码，却依然不知道密码是什么**。

这种"证明我知道，但不泄露我知道什么"的能力，在现代密码学里叫**零知识证明**。它是区块链隐私、身份认证、可验证计算背后的同一件工具。

## 2. 直觉解释

想象一个环形洞穴，只有一个入口，进去后分左右两条路，尽头在深处相通。

你想证明自己有打开深处那道门的钥匙。验证者在洞口等着，看不见里面。

每一轮：验证者随机喊"**从左边出来**"或"**从右边出来**"——你只要真有钥匙，无论从哪边进都能穿过门到指定出口，**百发百中**。

如果你没有钥匙呢？你从左边进去，只能在左边这条死路上等。验证者要是喊"右边出来"，你**只能原路返回**从左边出来，穿帮。

关键在于：你进去之前**不知道他会喊哪边**。所以每一轮你都只有一半的把握蒙对，连续 20 轮全蒙对的概率是 $2^{-20} \approx 0.0001\%$——**他确信了，但他从头到尾没见过钥匙，也不知道钥匙长什么样**。

这就是零知识证明的三个支柱：

- **完备性**：真有秘密的人，总能通过；
- **可靠性**：没秘密的人，骗不过去（概率可以压到任意小）；
- **零知识**：验证者除了"这是真的"之外，什么也没拿到。

## 3. 正式定义

把上面的话翻成协议语言。以**离散对数知识证明**（Schnorr 协议）为例：证明者 P 想让验证者 V 相信他知道 $x$，其中 $y = g^x \bmod p$ 是公开的。

| 符号 | 名字 | 说明 |
| --- | --- | --- |
| $p$ | 模数 | 大素数，公开 |
| $g$ | 生成元 | 公开的底数 |
| $x$ | **秘密** | 只有证明者知道 |
| $y$ | 公开值 | $y = g^x \bmod p$，人人可查 |
| $r$ | 随机数 | 每轮重新选的"掩码"，用一次就扔 |
| $t$ | 承诺 | $t = g^r \bmod p$ |
| $c$ | 挑战 | 验证者随机给的一个比特或整数 |
| $s$ | 应答 | $s = r + c\cdot x$（模 $p-1$） |

**协议三步（跑很多轮）**：

1. **承诺**：P 随机选 $r$，发 $t = g^r$；
2. **挑战**：V 随机给一个 $c$；
3. **应答**：P 回 $s = r + cx$。

验证者检查：$g^s \stackrel{?}{=} t\cdot y^{c}$。

为什么成立？$g^{r+cx} = g^r\cdot(g^x)^c = t\cdot y^c$——**等式两边天然相等，条件是真知道 $x$ 才能算出 $s$**。

## 4. 分步例题

**例 1**：取小参数 $p=23,\ g=5$，秘密 $x=6$。

1. 公开值 $y = 5^6 \bmod 23 = 15625 \bmod 23 = 8$；
2. 证明者随机取 $r=4$，承诺 $t = 5^4 \bmod 23 = 625 \bmod 23 = 4$；
3. 验证者挑战 $c=3$；
4. 应答 $s = r + cx = 4 + 18 = 22$；
5. 验证：$g^s = 5^{22} \bmod 23$，$t\cdot y^c = 4\times 8^3 \bmod 23 = 4\times 512 \bmod 23 = 2048 \bmod 23$。

两边都等于 $2$——**通过**。

**例 2（没秘密的人为什么过不了）**：假设攻击者不知道 $x$，他能怎么作弊？

- 他可以先选 $s$，**倒推** $t = g^s y^{-c}$——但 $t$ 必须在**看到 $c$ 之前**发出去，而他不知道 $c$ 是什么；
- 或者他先选 $c$ 再算 $s$——但 $c$ 是验证者随机给的，**不由他决定**。

**两个约束互相矛盾**：承诺在前、挑战随机，作弊者每次只有约 $1/2$ 的猜中率（挑战为单比特时）。跑 20 轮，成功率 $2^{-20}$。

**例 3（Fiat–Shamir：去掉交互）**：如果让挑战**由承诺的哈希值决定**，即 $c = H(t)$，就不需要验证者在线了——证明者自己算 $c$，把 $(t, s)$ 一起发出去，任何人重新算 $c=H(t)$ 再验一遍即可。**哈希函数扮演了"不可预测的随机源"**，这把交互式协议变成了可传播的签名（这正是数字签名第 75 课的思想）。

## 5. 动手实验

先跑一遍完整协议，看它如何通过：

```python title="Schnorr 协议：一轮完整交互"
import math                       # math.gcd：最大公约数，这里用来检查随机数合法性

p, g = 23, 5                      # 极小的教学参数：真实场景 p 有几百位
x = 6                             # 证明者的秘密
y = pow(g, x, p)                  # 公开值 y = g^x mod p（pow 的三参数形式直接做模幂）
print("公开值 y =", y)

r = 4                             # 每轮重新选的随机掩码
t = pow(g, r, p)                  # 承诺
c = 3                             # 验证者的随机挑战
s = r + c * x                     # 应答
print("承诺 t =", t, " 挑战 c =", c, " 应答 s =", s)

left = pow(g, s, p)               # 验证者算左边
right = (t * pow(y, c, p)) % p    # 验证者算右边
print("g^s mod p =", left, " t·y^c mod p =", right)
print("验证通过" if left == right else "验证失败")
```

输出两边都是 `2`，`验证通过`。

现在看关键的一点：**作弊者只能猜中约一半的挑战**。我们来数一数：

```python title="作弊者的通过率：20 轮能骗过几次"
import math

p, g = 23, 5
y = pow(g, 6, p)

# 作弊者不知道 x，只能先随便编一个 s，再看挑战 c 能不能蒙对
# 这里直接统计：在 p-1 个可能的挑战里，他能碰巧对上的比例
hit = 0
total = 0
for c in range(1, 11):            # 取 10 个可能的挑战值
    for s_fake in range(1, 6):    # 作弊者只有 5 个备选应答（真实场景是天文数字）
        r_guess = s_fake - c * 0  # 他没有 x，只能按 x=0 估：等价于纯猜
        if pow(g, s_fake, p) == (pow(g, r_guess, p) * pow(y, c, p)) % p:
            hit = hit + 1
        total = total + 1
print(f"盲猜命中率约 {hit}/{total} = {hit/total:.2%}")
```

命中率远低于 100%——**每一轮都在削弱作弊者**，连续多轮后他必然暴露。

再看去交互化是怎么做的：

```python title="Fiat–Shamir：把挑战换成哈希"
def toy_hash(n, mod):             # 教学用"哈希"：真实的哈希要雪崩性与抗碰撞
    return (n * 7919 + 12345) % mod   # 结果对输入极敏感，够演示"不可预测"了

p, g = 23, 5
x = 6
y = pow(g, x, p)
r = 4
t = pow(g, r, p)
c = toy_hash(t, p - 1) + 1        # 挑战由承诺自己决定，不再需要验证者在线
s = r + c * x
print("t =", t, " c = H(t) =", c, " s =", s)
print("验证：", pow(g, s, p) == (t * pow(y, c, p)) % p)
```

任何人拿到 $(t, s)$ 都能重算 $c=H(t)$ 并验证——**交互式证明就此变成了一张可以传递的凭证**。

### 快问快答

```quiz
零知识证明里的验证者，最后学到了什么？
- 秘密的具体内容
- 只知道"证明者确实掌握秘密"这一件事 [*]
- 秘密的哈希值
? 这正是零知识的定义：验证者除了命题为真，什么额外信息都得不到。秘密的内容不会以任何形式泄露，连它的哈希也不会。
```

:::warning[常见误区]

**误区一**："零知识证明就是加密传输秘密。" 
不是。加密是"把内容藏起来，让有钥匙的人还原"；零知识证明是**根本不传内容**——传的是"我知道内容"这件事的证据。加密通信里对方的服务器最终能解密看到明文，零知识证明里连对方都看不到。

**误区二**："一轮就够了。" 
单比特挑战的一轮通过率是 $1/2$，靠不住。必须**重复很多轮**把成功率压到 $2^{-n}$，或者用大的挑战空间一次到位。可靠性是概率性的，这是它和数学证明最大的区别。

**误区三**："零知识证明等于区块链。" 
区块链只是它的应用场地之一。身份认证（不泄露密码）、可验证计算（外包算力但能验算）、匿名凭证（证明你成年但不透露生日）都在用它。第 34 章讲的是密码学结构，落地形态可以有很多种。

:::

**练习 2**：算一算，如果挑战空间是 $0$ 到 $2^{20}-1$，作弊者蒙对一次的概率是多少？连续独立猜 10 次的成功率又是多少？

<details>
<summary>点开查看逐步解答</summary>

单次蒙对概率 $= 1/2^{20} \approx 9.5\times10^{-7}$。

连续 10 次全部蒙对：$(2^{-20})^{10} = 2^{-200} \approx 6.2\times10^{-61}$。

这个数量级比宇宙中的原子数还小得多——**这就是"概率性的可靠性"为什么够用**。

```python
p_single = 1 / 2 ** 20
p_all = p_single ** 10
print(f"单次：{p_single:.3e}")
print(f"十次全中：{p_all:.3e}")
```

## 7. 选读：模拟器为什么能说明"零知识"

<details>
<summary>选读 · 零知识的严格定义长什么样</summary>

"验证者什么也没学到"这句话怎么变成数学？答案是**模拟器论证**：

> 如果存在一个模拟器，在**不知道秘密**的情况下也能造出与真实交互**无法区分**的对话记录，那么验证者从真实交互里什么额外信息也得不到。

听起来反直觉——作弊者不是过不了验证吗？注意模拟器的特权：它可以**先看挑战 $c$，再倒推承诺 $t = g^s y^{-c}$**。真实协议里承诺必须在前，所以作弊者做不到；模拟器可以把顺序调过来，于是能造出完美对话。

这说明：**对话记录本身不含秘密信息**——因为不需要秘密就能生成一条一模一样的记录。验证者拿到的所有数据，都"可以凭空编出来"，因此零信息。

这套论证是零知识证明理论的基石（Goldwasser–Micali–Rackoff，1985），也是它敢叫"零"知识的原因。
</details>
