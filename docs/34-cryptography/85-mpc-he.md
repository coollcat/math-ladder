# 安全多方计算与同态加密：让密文自己算

## 1. 从一个场景开始

三家医院想联合统计"患同一种病的总人数"，好决定要不要扩建病房。可病历是敏感数据，谁也不想把自己的名单交给另外两家；退一步，连交给一个"可信第三方"都不放心。

问题是：**怎样在彼此都不亮底牌的情况下，算出底牌之和？**

同一个难题还换着面孔出现：两家公司想比谁的员工平均工资高，却都不想先亮工资条；银行之间想算出共有多少重叠客户；手机把照片传给云端修图，却不想让云端看见照片。它们的答案都指向近二十年最热的两个词——**安全多方计算**与**同态加密**。

## 2. 直觉解释

两条路线看着像，其实分工不同。

- **秘密分享**：把一个秘密拆成若干片，任何一片单独看都是纯噪声，合起来才拼回原值。三家医院各自把"人数"拆成三片，两两交换一片，最后每人手里的片子相加，恰好是所有人数之和——而谁也没见过别人的原始数字。
- **同态加密**：把数据锁进"盲盒"再送出去。**盲盒有个神奇性质：可以在不开盒的情况下把两个盲盒摞起来**——解开后得到的，正好是两个数之和。云端全程只见盲盒，不见内容。

一张对照表把两者钉住：

| | 安全多方计算（MPC） | 同态加密（HE） |
| --- | --- | --- |
| 谁持有数据 | 多方各持一份明文分享 | 一方加密，另一方计算 |
| 谁做计算 | 多方交互着算 | 单个计算方独立算 |
| 主要成本 | 通信轮数 | 密文体积与噪声预算 |
| 典型场景 | 隐私求交、联合统计、秘密竞价 | 云端加密查询、隐私推理 |

一句话记忆：**MPC 是"分着算"，HE 是"盲着算"。**

## 3. 正式定义

**定义一（加法秘密分享）**：把秘密 $s \in \mathbb{Z}_q$ 拆成 $n$ 份 $(s_1,\dots,s_n)$，满足

$$s_1 + s_2 + \cdots + s_n \equiv s \pmod q .$$

只要其中任意 $n-1$ 份在 $\mathbb{Z}_q$ 上均匀随机，少了一份就还原不出 $s$——这是它信息论安全（不依赖任何计算难度假设）的来源。

**定义二（加法同态加密）**：加解密算法满足

$$\mathrm{Dec}\bigl(\mathrm{Enc}(a) \oplus \mathrm{Enc}(b)\bigr) = a + b ,$$

其中 $\oplus$ 是**密文空间**上的运算，不需要解密就能做。若乘法也有对应运算 $\mathrm{Dec}(\mathrm{Enc}(a)\otimes\mathrm{Enc}(b)) = a\cdot b$，两者同时具备，就叫**全同态加密**（FHE）。

| 符号 | 名字 | 说明 |
| --- | --- | --- |
| $q$ | 模数 | 运算在一块"时钟"上进行，过格就绕圈 |
| $s_i$ | 第 $i$ 份分享 | 单独看是噪声，全体相加才还原秘密 |
| $\mathrm{Enc}(m)$ | 密文 | 加密后的数据，交给计算方 |
| $\oplus,\otimes$ | 密文运算 | 分别对应明文的 $+$ 与 $\times$ |
| 噪声 | 密文的"误差余量" | 每次运算都在长大，超预算就解错 |

**玩具方案（本课主角）**：私钥是一个大整数 $p$，加密

$$\mathrm{Enc}(m) = m + p\,r,\qquad r \text{ 随机取整数},$$

解密就是取余 $\mathrm{Dec}(c) = c \bmod p$。它是"整数上"全同态方案的极简版（真实方案还会再套一个公开的大模数）。

- 加法同态：$c_1 + c_2 = (m_1+m_2) + p(r_1+r_2)$，取余就得到 $m_1+m_2$；
- 乘法同态：$c_1\cdot c_2 = m_1 m_2 + p(\cdots)$，取余得到 $m_1 m_2$；
- **但明文本身也是噪声**：乘法让噪声迅速膨胀，一旦越过 $p/2$，取余就绕错圈——这正是 FHE 的核心难点。

## 4. 分步例题

**例 1（三份分享还原）**：取 $q=97$，秘密 $s=42$，拆成三份。

1. 随机取 $s_1 = 30$，$s_2 = 55$；
2. 第三份倒推：$s_3 \equiv s - s_1 - s_2 \pmod{97}$；
3. 算 $30+55=85$，于是 $s_3 \equiv 42-85 = -43 \equiv 54 \pmod{97}$；
4. 核对：$30+55+54 = 139$，$139 \bmod 97 = 42$ ✓。

任何一方拿着自己那一份（比如 54），看起来只是个普通数字，与 42 毫无可辨认的联系。

**例 2（两方掩码求和）**：A 有 $x=17$，B 有 $y=25$，模数 $q=97$，两人都不想泄露自己的数。

1. A 随机取掩码 $r=63$，把 $x+r \equiv 80 \pmod{97}$ 发给 B；
2. B 看到 80，但 $r$ 未知，他学不到 $x$；
3. B 加上自己的数：$80+25 = 105 \equiv 8 \pmod{97}$，发回给 A；
4. A 减去掩码：$8-63 = -55 \equiv 42 \pmod{97}$；
5. 核对 $x+y = 17+25 = 42$ ✓——**只交换了两条消息，谁也没泄露，和却算出来了**。

**例 3（玩具方案的加法同态手算）**：取 $p=97$。

1. 加密 $m_1=3$：取 $r_1=5$，得 $c_1 = 3 + 97\times5 = 488$；
2. 加密 $m_2=5$：取 $r_2=2$，得 $c_2 = 5 + 97\times2 = 199$；
3. 在密文上直接相加（全程不解密）：$c_1+c_2 = 687$；
4. 解密：$687 \bmod 97 = 687 - 7\times97 = 8 = 3+5$ ✓。

**关键**：第 3 步从头到尾没人看过 $m_1,m_2$ 的明文——云端只是把两个大整数加了一下。

## 5. 动手实验

先看"噪声预算"为什么是全同态加密的命门。横轴是乘法深度（连着乘了几次），曲线是噪声大小：只有噪声一直待在预算线以下，解密才不出错。

拖动 $B$（初始噪声）、$g$（每层乘法把噪声放大的倍数）与预算线：**一旦曲线穿出预算线，右边所有深度都不可用**。想算更深的电路，要么放大预算 $p$（密文跟着变长），要么用"自举"把噪声重新刷新（选读里讲）。

再看玩具方案真的能跑：加密 → 密文相加 → 解密，明文始终只在自己那一侧出现过。

```python title="玩具同态加密：密文相加，明文相加"
import random                      # 随机数库（第 0 章出生）：用来生成噪声因子 r

p = 97                             # 私钥：一个大整数，"噪声尺度"

def enc(m):
    """加密：m + p*r。r 随机，所以同一个 m 每次密文都不同"""
    r = random.randint(1, 10)      # randint(a, b)：返回 a~b 之间的随机整数（含两端）
    return m + p * r

def dec(c):
    """解密：对 p 取余，把 p*r 这一层整个甩掉"""
    return c % p

a, b = 3, 5                        # 两方各自的明文，谁也没告诉云端
ca, cb = enc(a), enc(b)            # 云端只拿到这两个大整数
print("密文 A =", ca, " 密文 B =", cb)

c_sum = ca + cb                    # 云端的全部工作：把两个密文加起来
print("密文之和 =", c_sum)
print("解密后 =", dec(c_sum), "（明文之和 =", a + b, "）")
```

因为 $r$ 每次随机，重跑会得到不同的密文，但最后一行永远是 `8`。**云端自始至终只看见两个随机的大整数。**

最后验证一件要命的事：乘法会让噪声爆炸。

```python title="噪声是怎么长大的：加法温和、乘法致命"
p = 97                             # 私钥；噪声预算大约是 p/2 = 48

noise = 3                          # 从一个"明文 3"的小噪声出发
for depth in range(1, 6):          # 连续做 5 层乘法
    noise = noise * noise          # 乘法同态下，噪声是相乘的，涨得飞快
    tag = "能解密" if noise < p // 2 else "超出预算，解不准了"
    print(f"深度 {depth}：噪声 {noise}，{tag}")
```

前两层还看得过去，第三层起噪声就把余数空间吃穿——**这就是"自举"要解决的问题**：趁密文还没失效，用加密的私钥把它重新"洗"一遍。

### 快问快答

```quiz
安全多方计算与同态加密，最本质的区别是什么？
- 前者不依赖计算困难性，后者依赖
- 前者由多方各持一份数据交互计算，后者由单方在密文上离线计算 [*]
- 前者只能求和，后者能做任意运算
? 两者的安全性都可以建立在计算困难性上；能做哪些运算取决于具体方案（本课的玩具方案就同时支持加与乘）。真正的分水岭是"数据在谁手里、计算由谁做"：MPC 把数据分散到多方、靠交互缝合结果，HE 让数据保持加密、由一方独立计算。
```

:::warning[常见误区]

**误区一**："同态加密就是把数据加密后存起来。"
加密存储是"保险箱"，同态加密是"**能在锁着的箱子里干活的机器人**"。前者只负责保密，后者允许计算方在完全不解密的前提下对密文直接运算——这是它区别于普通加密的全部价值。

**误区二**："安全多方计算需要一个可信的第三方来汇总。"
恰恰相反，MPC 的整个动机就是**去掉那个可信第三方**。秘密分享与掩码技术让参与方两两交互，就能在没有任何人看到完整明文的情况下算出结果；引入第三方反而是把安全假设又押回一个人身上。

**误区三**："全同态加密已经很快，可以随便上生产。"
慢得多。密文比明文大几个数量级，一次密文乘法可能比明文乘法慢上百万倍。今天它主要落在延迟不敏感的场景（加密数据库、隐私推理），"能用"和"划算"是两回事。

:::


**练习 2**：在玩具方案里，$p$ 一旦泄露会怎样？用自己的话解释"私钥 $p$ 泄露，密文立刻一文不值"。

<details>
<summary>点开查看逐步解答</summary>

密文是 $c = m + p\,r$。知道 $p$ 之后，一条取余运算就能剥掉整层 $p\,r$：$c \bmod p = m$——加密形同虚设。

```python
p = 97
c = 488          # 对应 3 + 97*5
print(c % p)     # 3：私钥一泄露，明文档场现形
```

所以真实方案里 $p$ 是**私钥**，必须严加保管；公开的只有"可以加密、可以算密文"这件事。这也解释了玩具方案与真实方案的分工：玩具把 $p$ 藏起来当安全来源，真实方案还要额外加上一个公开的大模数来掩盖 $p$ 的位置。

</details>

## 7. 选读：混淆电路、不经意传输与自举

<details>
<summary>选读 · MPC 的通用引擎与 FHE 的"刷噪声"</summary>

**不经意传输（OT）**。最基础的一块砖是"二选一不经意传输"：发送方手里有两个数 $m_0,m_1$，接收方只想要其中一个，但**发送方不知道他挑了哪个**，他也拿不到另一个。经典的 1-out-of-2 OT 借助 RSA 的"两个公钥里有一个解不开"实现，几行数论就够。

**混淆电路（Yao's Garbled Circuits）**。有了 OT，任意函数都能算：一方把电路的每条导线编码成一组随机标签，把每个逻辑门写成"用两把输入钥匙才能打开、里面装着输出钥匙"的乱码表；另一方只拿到自己那一侧的输入钥匙，走完电路只解出自己的输出，全程看不见对方的输入。

**自举（Bootstrapping）**。回到噪声问题：把"解密"这一小段电路**本身也加密**，用加密的私钥去"重新解密"一个快失效的密文——输出的是一个崭新、噪声归零的密文。Gentry 2009 年正是靠这一招第一次造出全同态加密：只要方案能"带着噪声同态地算一点点解密逻辑"，噪声就能被无限刷新。

代价是每一步都极其昂贵。所以后来的路线转向"层次化"方案（只支持有限深度、不做自举），在实用性与可证安全性之间找平衡——这也是今天加密数据库查询大多选择有限同态、而非全同态的原因。

</details>
