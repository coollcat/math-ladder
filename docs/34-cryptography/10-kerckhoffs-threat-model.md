# Kerckhoffs 原则与威胁模型

## 1. 从一个场景开始

1914 年，各国电台里飞着加密电报。有人提议：把加密方法藏得深一点，敌人就破解不了？历史给出的答案冰冷：密码本会被缴获、设备会被拆解、工程师会跳槽——**依赖"方法保密"的系统，寿命以月计**。

19 世纪荷兰语言学家 Auguste Kerckhoffs 早已立下军规：**密码系统必须假设敌人完全知道加解密原理，安全只能寄托在一把小小的密钥上。**现代密码学的整座大厦都盖在这条原则上。

## 2. 直觉解释

把密码系统想成一把门锁：锁芯结构是公开的专利图纸，真正保密的只有你手里的钥匙。

- 若安全靠"没人看得懂图纸"，那么图纸一泄，全盘皆输；
- 若安全只靠钥匙，丢了这把换一把就行，损失被锁死在最小范围；
- 公开还带来**同行审查**：全世界数学家帮你挑毛病，比自娱自乐的"祖传秘方"可靠得多。

设计前还要先回答另一个问题：**防谁？**窃听者只听不改；篡改者要改包；伪造者想冒名发信。对手清单 + 对手的资源（能算多少步、能截多少报文）合称**威胁模型**——不写清楚它，"安全"二字无从谈起。

## 3. 正式定义

一个对称密码系统由三元组构成：明文空间 $\mathcal{M}$、密文空间 $\mathcal{C}$、密钥空间 $\mathcal{K}$，以及一对算法

$$\text{Enc}_k : \mathcal{M} \to \mathcal{C}, \qquad \text{Dec}_k : \mathcal{C} \to \mathcal{M}$$

满足对每个 $k$ 与每条消息 $m$：$\text{Dec}_k(\text{Enc}_k(m)) = m$（可还原性）。

**Kerckhoffs 原则**：Enc 与 Dec 的全部细节公开已知；系统的安全性**仅**依赖于 $k$ 的保密。

**攻击者的算力预算**用密钥空间衡量：若 $\vert \mathcal{K}\vert = N$，穷举攻击平均需约 $N/2$ 次尝试。密钥每加 1 位，$N$ 翻倍——这就是"128 位密钥"背后的算术护城河。

## 4. 分步例题

**例**：比较两把"锁"的抗穷举能力。

1. 凯撒移位密码：26 个字母循环移位，$\vert\mathcal{K}\vert = 26$；攻击者哪怕一台计算器也能瞬间试完；
2. 12 位小写字母口令：每位 26 种选择，$\vert\mathcal{K}\vert = 26^{12} = 95428956661682176$，约 95429 万亿；
3. 倍数关系 $26^{12} / 26 = 26^{11}$——密钥多 11 个字符，穷举成本放大约 3670 万亿倍；
4. 结论：安全性来自**指数级的密钥空间**，而非算法的隐蔽性。这正是 Kerckhoffs 原则的定量版本。

### 实验 2：亲手感受穷举的成本

```python title="两种密钥空间的体量对比"
shift_keys = 26                    # 移位密码：只有 26 把钥匙
pwd_keys = 26 ** 12                # ** 已在乘方课登场：12 位小写口令的钥匙总数

print(f"移位密码钥匙数: {shift_keys}")
print(f"12 位小写口令钥匙数: {pwd_keys}")

ratio = pwd_keys // shift_keys     # // 整除：放大了多少倍
print(f"穷举成本放大倍数: {ratio}")

# 攻击者按每秒 100 亿次尝试估算，跑完 26^12 需要的天数：
days = pwd_keys // (10 ** 10 * 60 * 60 * 24)
print(f"每秒百亿次也要 {days} 天才能扫完")
```

第一行数字小到可怜——所以下一课你会看到凯撒密码在频率分析面前不堪一击；第二行已经把秒级穷举拖到百天量级，真实口令策略还会继续放大这个指数。

### 快问快答

```quiz
按照 Kerckhoffs 原则，下列哪件事可以公开而几乎不损害安全？
- 加密算法的完整流程 [*]
- 当前的会话密钥
- 随机数生成器的内部状态
? 算法公开正是原则的要求：安全只押注在密钥上。密钥本身或随机状态一旦泄露，一切归零。
```

:::warning[常见误区]

**误区一**："算法保密更安全。" 安全性无法靠隐藏获得稳定保障（业内戏称 security through obscurity），且封闭系统得不到公开审查的纠错红利。

**误区二**："威胁模型越全面越好，一律按最高防护设计。" 防护有成本；明确"防谁、预算多少"才有可交付的安全。家用 Wi-Fi 和银行金库的威胁模型理应不同。

**误区三**："密钥长就一定安全。" 密钥空间只是底线；实现漏洞、随机数质量差都能让长钥形同虚设。

:::

## 6. 练习

**练习 1**：某系统宣传"我们的加密算法从未公开，绝对安全"。用 Kerckhoffs 视角列出两条质疑。

<details>
<summary>点开查看逐步解答</summary>

其一：未公开意味着未经审查，历史上"自家保密"的算法屡屡被业余者攻破；其二：算法终将泄露（离职员工、逆向工程），届时无备用方案——安全应当假设算法已泄后依然成立。
</details>

## 7. 选读：从 Kerckhoffs 到现代开放标准

<details>
<summary>选读 · 一条原则的一百年</summary>

Shannon（1949）把它表述为"敌人知道系统"；互联网时代落地为 AES、TLS 等**开放标准**：算法全文公开、会议公开、实现开源，全球研究者持续攻击数十年而不破，才获得"信任"资格。反面教材是一战德军的 ADFGX 密码与二战日军的"紫密码"——方法保密撑了一时，一旦被缴获分析便全线崩塌。开放不是慷慨，是工程上唯一可持续的自信。

</details>
