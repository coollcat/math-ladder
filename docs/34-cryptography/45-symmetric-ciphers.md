# 对称加密：从一次一密到 AES 的距离

## 1. 从一个场景开始

你的手机此刻正用一把 128 位的钥匙（区区 16 个字节）给几个 GB 的流量加解密，一天经手的比特比一次一密一整年的钥匙消耗量还多。可第 30 课的香农定理明明白白写着：完美保密要求钥匙不比消息短——这台手机岂不是天天在违反数学？

并没有。它只是换了一份合同：放弃"无限算力也不可破"的信息论安全，改签"算力范围内不可破"的**计算安全**。这一课就看现代对称加密（AES 一族）如何用一把短钥匙搅动任意长的消息。先交底：本课是全书公钥主线的一块背景板，安全性论证走工程与密码分析的路；但它是实用世界里真正扛流量的主力，值得认真一看。

## 2. 直觉解释

一次一密像私人贵重品押运：每件货配一个独立保险箱，绝对安全，成本也是天文数字。现代对称加密像一座大型搅拌厂：机器（公开算法）固定不动，一把短钥匙决定搅拌的顺序和力度，任意长的货倒进去都被搅匀——钥匙不再是"保密材料的总量"，而是"搅动消息的说明书"。

两条技术路线：

- **流密码**：把短钥匙喂给伪随机数生成器，拉长成一串与消息等长的"伪随机钥匙"，再按一次一密的套路逐位异或。相当于给一次一密装了个省钥匙的仿真器，安全的代价从"信息论不可破"降为"生成器不可预测"。
- **分组密码**：把明文切成固定长度的块（AES 每块 128 位），用"代换 + 置换"的轮函数反复搅动。本课的主角。

搅动的原料早有家底：[古典密码与频率攻击](./20-classical-ciphers.md) 里的单表替换就是"代换"，移位就是"置换"——现代分组密码只是把它们搬进比特世界、叠上十几轮、再让密钥控制每一轮的细节。

## 3. 正式定义

**异或（XOR）**：比特世界的加法，规则"相同出 0、不同出 1"：$0 \oplus 0 = 0$、$0 \oplus 1 = 1$、$1 \oplus 0 = 1$、$1 \oplus 1 = 0$——正是模 2 的加法（第 10 章同余那只 2 号钟面）。它有三条好性质：$a \oplus a = 0$（自己消自己）、$a \oplus 0 = a$（谁都不动）、交换结合随便来。于是 $c = m \oplus k$ 的解密就是 $m = c \oplus k$——同一把钥匙再来一次。

**分组密码**：一族函数 $\lbrace E_k\rbrace$，每把钥匙 $k$ 对应一个双射 $E_k : \lbrace 0,1\rbrace^n \to \lbrace 0,1\rbrace^n$——$n$ 位明文块换成 $n$ 位密文块，且每个密文块都能唯一解回去。

| 符号 | 名字 | 含义 |
| --- | --- | --- |
| $n$ | 分组长度 | AES 取 128 位：一次搅动一块 |
| $k$ | 密钥 | AES 128/192/256 位：远短于消息 |
| $E_k, D_k$ | 加密 / 解密 | 互为反函数 |
| S 盒 | 代换盒 | 查表：把一小组比特整体换成另一组（单表替换的比特版） |
| P 盒 | 置换盒 | 挪位：把比特重新排队（位置乱了，指纹才散得开） |
| 轮 | 一轮 | 一次"代换 + 置换（± 钥匙异或）"；AES 主线 10 轮 |

**计算安全**：不承诺敌人算不出，只承诺穷举与密码分析的成本高到没有意义——128 位钥匙意味着 $2^{128}$ 次尝试，宇宙年龄也排不完。它与香农的信息论安全是两份不同的合同。

两大经典结构（各看一轮）：

$$\text{Feistel 一轮：} (L, R) \ \mapsto\ (R,\ L \oplus F(k, R))$$

$$\text{SPN 一轮：} x \ \mapsto\ P(S(x \oplus k))$$

Feistel 的妙处：不管轮函数 $F$ 长什么鬼样子，只要它会算，"换半 + 异或"天然可逆——加密解密共用同一套电路。SPN 则要求 S 盒自己可逆（解密要查逆表）。

## 4. 分步例题

用 4 位小玩具把两套结构各走一遍。S 盒用一张真实的 4 位双射表（下标 0~15 进，值出）：

$$S = (14, 4, 13, 1, 2, 15, 11, 8, 3, 10, 6, 12, 5, 9, 0, 7)$$

轮函数取 $F(k, r) = S[r \oplus k]$。

**例 1**：异或钥匙化。明文 $m = 1010$，钥匙 $k = 0110$：

1. 加密：$1010 \oplus 0110 = 1100$；
2. 解密：$1100 \oplus 0110 = 1010$ ✓——同一把钥匙进进出出。

**例 2**：Feistel 一轮往返。明文拆半 $(L, R) = (1101, 1001)$（十进制 13, 9），轮钥匙 $k = 0101$（十进制 5）：

1. 算影子：$F(5, 9)$：$1001 \oplus 0101 = 1100$（12），查表 $S[12] = 5$（即 0101）；
2. 加密一轮：$(L', R') = (R,\ L \oplus F) = (1001,\ 1101 \oplus 0101 = 1000)$，密文 $(9, 8)$；
3. 解密：手里是 $(L', R') = (1001, 1000)$。原来的右半就站在 $L'$ 位上：$R = 1001$；原来的左半被同一个影子盖过：$L = R' \oplus F(k, L') = 1000 \oplus 0101 = 1101$；
4. 恢复 $(1101, 1001)$ ✓——解密只用了加密的那个 $F$，方向反着走。

**例 3**：SPN 两轮。取明文 $x = 0110$，P 盒定义为"每个比特向左挪一格，最高位绕回最低位"：

1. 第一轮代换：$S[6] = 11$，即 $0110 \to 1011$；
2. 第一轮置换：$1011 \to 0111$；
3. 第二轮代换：$S[7] = 8$，即 $0111 \to 1000$；
4. 第二轮置换：$1000 \to 0001$。两轮后 $0110$ 变成 $0001$。
5. 雪崩抽查：翻转任何一个输入比特，输出的多个比特都会跟着变（§5 实验 5 的实测账：变化 1~3 个比特）——"改一格、烂一片"的方向有了，但两轮小玩具离"约一半翻转"的理想还很远；AES 用 10 轮、更大的 S 盒和列混合把雪崩做满。

### 实验 3：异或小课堂 + 固定密文的 16 把钥匙（python）

```python title="异或三性质 + 每个明文都有唯一钥匙解释"
a = 10                   # 二进制 1010（4 位小玩具，数字一律 0~15）
b = 6                    # 二进制 0110
print(a ^ b)             # ^ 是异或：按位"相同出 0、不同出 1"（模 2 加法）
print(a ^ a)             # 自己消自己：结果恒为 0
print(a ^ 0)             # 异或 0 原样通过：谁都不动

c = 6                                        # 截获的密文 0110
count = 0                                    # 钥匙计数器
for m in range(16):                          # 把 16 个候选明文逐个过堂
    k = m ^ c                                # 能把 c 解成 m 的那把唯一钥匙
    print(f"{m:04b} -> {k:04b}")             # 冒号后是格式规格：04b = 补零到 4 位、按二进制打印
    count = count + 1
print(f"共 {count} 把钥匙，一把对应一个明文——密文对明文零信息")
```

循环部分就是第 30 课"每个明文都有钥匙"的比特版：固定任何一个密文，16 个明文各配一把不同钥匙。完美保密的结构还在，只是钥匙从"每条消息一整串"换成了"每块 4 位一把"——流密码正是用生成器批量伪造这把钥匙的省钥匙方案。

### 实验 4：Feistel 一轮往返实测（python）

```python title="4 位 Feistel：4096 种组合全部往返成功"
S = [14, 4, 13, 1, 2, 15, 11, 8, 3, 10, 6, 12, 5, 9, 0, 7]   # 4 位 S 盒：下标进、值出

def F(k, r):
    return S[r ^ k]            # 轮函数（玩具版）：先异或轮钥匙，再查 S 盒

def enc(l, r, k):
    return r, l ^ F(k, r)      # 加密一轮：一次打包返回两个数（右半原样过，左半异或"右半的影子"）

def dec(l2, r2, k):
    return r2 ^ F(k, l2), l2   # 解密一轮：同一个影子再异或回去，顺手换回位置

bad = 0                        # 往返失败计数器
for l in range(16):
    for r in range(16):
        for k in range(16):
            cl, cr = enc(l, r, k)            # 加密得到密文两半
            if dec(cl, cr, k) != (l, r):     # 元组比较：两半都要对上才算复原
                bad = bad + 1
print(f"16×16×16 = 4096 组，失败 {bad} 组")

cl, cr = enc(13, 9, 5)
print(f"明文 (1101, 1001) -> 密文 ({cl}, {cr})")
print(dec(cl, cr, 5))          # 例 2 的手算对账
```

无论轮函数长什么样（哪怕它完全不可逆），"换半 + 异或"都自动可逆——4096 组零失败就是这句话的实验版。

### 实验 5：S 盒双射检验 + 两轮 SPN 雪崩实测（python）

```python title="S 盒必须是双射；两轮 SPN 的雪崩账本"
S = [14, 4, 13, 1, 2, 15, 11, 8, 3, 10, 6, 12, 5, 9, 0, 7]   # 4 位 S 盒
print(sorted(S))               # 排序后一个不重、正好 0~15：代换才可逆

def bit(x, i):
    return (x >> i) % 2        # >> 把 x 右移 i 格（相当于整除 2 的 i 次方），% 2 取出那一格比特

def permute(x):
    # 置换盒 P（挪格子）：每个比特向左挪一格，最高位绕回最低位
    return bit(x, 0) * 2 + bit(x, 1) * 4 + bit(x, 2) * 8 + bit(x, 3)

def spn2(x):
    return permute(S[permute(S[x])])   # 两轮：代换 → 置换 → 代换 → 置换

base = spn2(0)                 # 基准：明文 0000 的两轮输出
for i in range(4):
    flipped = 2 ** i           # 翻转第 i 位 = 加上 2 的 i 次方（0001 / 0010 / 0100 / 1000）
    y = spn2(flipped)
    changed = 0                # 输出差异比特计数
    for j in range(4):
        if bit(base, j) != bit(y, j):
            changed = changed + 1
    print(f"翻转 bit{i}: 输出 {y:04b}，变化 {changed} 个比特")
```

实验 2 图里的四个数字就是这里的实测输出。1~3 个比特的变化说明雪崩在发生但远未做满——AES 的答案是 10 轮、8×8 的大 S 盒和一行搅浑四字的列混合。

### 快问快答

```quiz
Feistel 结构最让工程师省心的一点是什么？
- 轮函数 F 越复杂，密文越乱
- 加密解密共用同一套轮函数电路，反着走一遍就是解密 [*]
- 密钥可以比明文短
? F 完全不需要可逆：解密只是把同一个 F 算出来的影子再异或回去。这省掉一整套解密电路——DES、SM4 用它用了几十年。
```

::::warning[常见误区]

**误区一**："短钥匙加密长消息违反了香农定理。" 香农的 $\vert\mathcal{K}\vert \ge \vert\mathcal{M}\vert$ 是信息论安全的门票；计算安全是另一份合同——只要穷举钥匙的成本高到宇宙尺度，钥匙就可以远短于消息。两份合同不要混着读。

**误区二**："S 盒随便挑一张花哨的表都行。" S 盒必须是双射，否则两个明文块挤进同一个密文块，解密当场失忆；真实设计还要抗差分与线性密码分析——AES 的 S 盒来自有限域求逆加仿射变换，每个数字都有数学出身的理由。

**误区三**："轮数多是浪费电。" 每一轮都在摊薄统计指纹：一两轮的小玩具雪崩残缺（实验 2 的账本），十几轮才把"改一格、烂一半"做满。现代 CPU 的 AES 专用指令一两个时钟周期跑完一轮——轮数是安全预算，不是浪费。

::::

**练习 1**：手算异或 OTP：$m = 1101$，$k = 1011$，求密文并把解密验算走一遍。

<summary>点开查看逐步解答</summary>

$c = 1101 \oplus 1011 = 0110$。解密：$0110 \oplus 1011 = 1101$ ✓。"自己消自己"保证异或往返必然成功——这也是它在密码学里无处不在的原因。

**练习 2**：补全 Feistel 的回程票。密文 $(L', R') = (9, 8)$、轮钥匙 $k = 5$，把明文两半解出来，改到通过：

```exercise
# @title: 练习：把 Feistel 的回程票补上
# @check: 13
# @check: 9
# @hint: 密文 (L', R') 里，L' 就是原来的右半——原样通过的那一半不用动；原来的左半被影子 F(k, L') 盖过，异或同一个影子就显形。
S = [14, 4, 13, 1, 2, 15, 11, 8, 3, 10, 6, 12, 5, 9, 0, 7]

def F(k, r):
    return S[r ^ k]        # 轮函数：先异或轮钥匙，再查 S 盒

cipher = (9, 8)            # 一轮加密后的密文 (L', R')
k = 5

L_new = cipher[0] ^ F(k, cipher[1])   # ← 影子吃错了对象：该拿哪一半去喂 F？
R_new = cipher[1]                     # ← 这一半真的需要"动手术"吗？

print(L_new)
print(R_new)
```

**练习 3**：AES 用 128 位钥匙加密几个 GB 的文件——香农不是说钥匙必须跟明文一样长吗？两句话讲清为什么不矛盾。

<details>
<summary>点开查看逐步解答</summary>

香农定理管的是**信息论安全**：想做到"密文对明文零信息"，钥匙必须与消息等长且真随机。AES 走的是**计算安全**：放弃零信息，只保证攻击者在现实算力内穷举不出那把 128 位钥匙（$2^{128}$ 次尝试）——密文其实留有指纹，只是没有任何算力能在宇宙冷却前把指纹读出来。
</details>

## 7. 选读：从 DES 到 AES 的军备竞赛

<details>
<summary>选读 · 轮数、钥长与一纸标准的三十年</summary>

DES（1977）：56 位钥匙、16 轮 Feistel，设计时是长城，1998 年电子前哨基金会用一台 25 万美元的机器 56 小时穷举穿墙——钥匙长度输给了摩尔定律。过渡方案 3DES 把 DES 跑三遍续命，真正接棒的是 AES（2001）：Rijndael 方案胜出，SPN 结构、128 位分组、10/12/14 轮（对应 128/192/256 位钥匙），S 盒定义为有限域 $\mathbb{F}_{2^8}$ 上求逆再仿射——每个部件都经得起差分与线性密码分析的放大镜。至于流密码这一支：把短钥匙与计数器一起喂给生成器拉出密钥流（TLS 常用的 ChaCha20 是当代代表），本质是"用生成器的不可预测性换钥匙长度"的一次一密仿真。两条路线合流于同一句合同：**计算安全**。背景板课到此交还主线——密钥有了着落点之后，下一课回到可证明安全的公钥世界。

</details>
