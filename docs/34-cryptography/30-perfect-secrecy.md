# 完美保密与一次一密

## 1. 从一个场景开始

冷战时期，莫斯科与华盛顿之间的红色电话用的是一种土到极致的加密：双方各持一本**完全相同的随机数字簿**，每发一个字母翻一页，用完作废。没有复杂轮函数、没有 S 盒，却被信息论证明**无条件不可破**——哪怕敌人拥有无限算力。

代价同样极端：密钥要和消息一样长、必须真随机、绝不复用。它就是一次一密（One-Time Pad）。这一课先弄清"完美"的精确含义，再看三条纪律为什么一条都不能少。

## 2. 直觉解释

凯撒密码死于频率轮廓：密文保留了明文的统计指纹。完美保密的目标是让密文**毫无指纹**——任何明文加密后，产出的每种密文都一样常见。

怎么做到？给每个字母配一个**独立均匀随机**的移位量：明文 a 加 0 是 a、加 13 是 n、加任意格都等概率。于是：

- 密文里每个字母出现的概率完全相同——频率分析失去靶子；
- 更强的结论：拿到密文 c，**任何**同长度的明文都可能是它的原文（各自对应一把不同的钥匙）——密文对明文零信息；
- 敌人算力再强也无济于事，因为他缺的不是计算，是**那串已经烧掉的随机数**。

反面教材是"偷懒复用"：两份消息共用同一页随机钥，$c_1 - c_2 = m_1 - m_2$——钥匙在差分里抵消了，两条明文的差异裸奔，历史情报机构多次栽在这上面。

## 3. 正式定义

**完美保密**（Shannon, 1949）：对密文空间中一切 $c$ 与明文空间中一切 $m$，

$$P(M = m \mid C = c) = P(M = m)$$

即看到密文后，对明文的判断不比没看到时多出任何信息（两个分布完全重合）。

**一次一密**：明文 $m_1 \dots m_n \in \mathbb{Z}_{26}^n$，密钥 $k_1 \dots k_n$ 独立均匀随机且只用于这一次；加密 $c_i = (m_i + k_i) \bmod 26$。Shannon 定理断言：完美保密必然要求 $\vert\mathcal{K}\vert \ge \vert\mathcal{M}\vert$——密钥数量至少要达到明文空间的大小；一次一密恰好取等号，是省无可省的最优解。

## 4. 分步例题

**例 1**：单字母 OTP。明文 m=7，钥匙 k=19。

1. 加密：$c = (7 + 19) \bmod 26 = 26 \bmod 26 = 0$；
2. 解密：$(0 - 19) \bmod 26 = -19 \bmod 26 = 7$ ✓（Python 的 % 对负数自动补圈）；
3. 保密检查：截获 c=0 的旁观者眼中，全部 26 个明文各有恰好一把钥匙能解释它，且这些解释机会均等——c 不偏袒任何一个 m。

**例 2**：复用泄密演示。同一把钥 k=5 加密 `ATTACKATDAWN`（m₁）与 `ABORTTHEPLAN`（m₂）：

1. 差分 $m_1 - m_2 \bmod 26$ 在第 1、12 位（A−A、N−N）给出 0——钥匙彻底消失；
2. 差分为 0 等价于"两位原文字母相同"：攻击者立刻得知两条命令的首字母相同、末字母也相同；
3. 英文差分还有大量可利用的规律（空格、高频词），配合"crib dragging"拖拽猜词足以逐位复原双明文。
4. 教训：钥匙复用一次，完美保密当场破产。

### 实验 2：模拟验证"密文均匀"

```python title="同一个明文字母，一万次随机加密的分布"
import random

samples = []
for _ in range(10000):
    message = 4                          # 明文固定为 e（编号 4）
    key = random.randint(0, 25)          # 每次独立抽一把新钥匙
    samples.append((message + key) % 26)

flat_check = []
for cipher_value in range(26):
    hits = len([s for s in samples if s == cipher_value])
    flat_check.append(hits)

print(f"26 种密文出现次数: {flat_check}")
print(f"最大 {max(flat_check)}，最小 {min(flat_check)}——差距只有抽样噪声")
```

无论明文固定成哪个字母，直方图都是同一条水平线：密文分布与明文无关——这就是完美保密的实验形态。

### 实验 3：钥匙复用的灾难现场

```python title="两次一密：差分让钥匙抵消"
import random

def otp(text, keys):
    out = ""
    for i in range(len(text)):
        p = ord(text[i]) - ord("A")
        out = out + chr(ord("A") + (p + keys[i]) % 26)
    return out

msg1 = "ATTACKATDAWN"
msg2 = "ABORTTHEPLAN"
keys = [random.randint(0, 25) for _ in range(12)]   # 同一串钥匙伺候两封电报

c1, c2 = otp(msg1, keys), otp(msg2, keys)
diff = ""
for i in range(12):
    d = (ord(c1[i]) - ord(c2[i])) % 26     # 密文差 = 明文差（钥匙抵消）
    diff = diff + ("_" if d == 0 else chr(ord("a") + d))

print(f"c1: {c1}")
print(f"c2: {c2}")
print(f"差分: {diff}   ← 下划线处两位明文相同，钥匙已蒸发")
```

运行几次：下划线的位置每次不同，但只要出现，就等于免费泄露"这两位字母相同"——对破译者是真金白银的线索。真实历史中，复用还叠加语言统计，足以整段复原。

### 快问快答

```quiz
完美保密要求的是下列哪件事？
- 加密函数足够复杂、轮数够多
- 密文分布与明文无关：看密文不改变对明文的判断 [*]
- 密钥至少 128 位且不可导出
? 定义比较的是条件分布 P(M=m|C=c) 与 P(M=m)：两者相等才叫完美。复杂度与位数都是手段，不是定义本身。
```

:::warning[常见误区]

**误区一**："OTP 用伪随机数生成器也行。" 伪随机序列终有周期与种子， Shannon 证明的前提是真随机；换成 PRNG 后只剩"计算安全"，无限算力面前会露馅。

**误区二**："密钥长一点就能复用两次。" 长度不是问题核心，**独立性与一次性**才是；复用瞬间差分攻击登场。

**误区三**："完美保密也保护长度和发送时间。" 它只藏内容；消息多长、何时发出，这些元数据照样可见——流量分析是另一条战线。

:::

**练习 3**：为什么说"$\vert\mathcal{K}\vert \ge \vert\mathcal{M}\vert$"排除了"短钥万能密码"？用计数直觉说明。

<details>
<summary>点开查看逐步解答</summary>

完美保密要求：给定任一密文 c，每条候选明文都必须至少有一把钥匙能把它解释成 c。若有 |M| 条明文而钥匙不足 |M| 把，鸽笼原理保证某条明文无钥匙可用——它在 c 下概率为零，与 P 相等的条件矛盾。钥匙不够，保密必有缺口。
</details>

## 7. 选读：香农如何证明"钥匙必须够长"

<details>
<summary>选读 · 计数论证三步走</summary>

固定任意 $(m, c)$。完美保密说 $P(C=c \mid M=m) = P(C=c)$ 与 $m$ 无关。把左边展开成 $\sum_k P(K=k)\,[\text{Enc}_k(m)=c]$：每条明文都需要"能到达 c"的一批钥匙支撑同样的总概率。数一数供给：全部钥匙要同时服务所有明文，总量不足就会顾此失彼——严格写出不等式即得 $|\mathcal{K}| \ge |\mathcal{M}|$。这是信息论少有的"不可能性定理"之一：它不给方案，直接划定宇宙规则。

</details>
