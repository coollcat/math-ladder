# 哈希、冲突与期望分析

## 1. 从一个场景开始

图书馆有百万本书，想"报书名、立刻取书"。逐个找是 $\Theta(n)$；按序二分要 $O(\log n)$ 还得维护顺序。理想答案是**直接知道位置**：书名一报，柜子编号脱口而出。

哈希表就是这台"报号机"：用一个小函数把任意键映射进固定数量的格子。但格子有限、键无限，两本书撞进同一格只是时间问题——**冲突**如何面对，决定了这张表的命运。

## 2. 直觉解释

最朴素的哈希：$h(k) = k \bmod m$——第 10 章"同余时钟"的直系后代。键被钟面扫射，均匀散进 $m$ 个格子里。

- 装了 $n$ 个键、$m$ 个格子，**装载因子** $\alpha = n/m$ 表示平均每格挤几个；
- 冲突不可消灭（鸽笼原理：$m+1$ 个键进 $m$ 格必撞），只能管理——常见策略是**拉链法**：每格里挂一条链表，撞进的元素排队；
- 妙处在于概率视角：只要散列够随机，每条链的期望长度就是 $\alpha$。查找代价从"看运气"变成"算平均"——这叫**期望分析**。

生日悖论的味道也来了：23 个人里两人同生日的概率已超一半。同理，往 365 个格子里扔几十个键，冲突就会不请自来——远比直觉来得早。

## 3. 正式定义

**哈希函数** $h : U \to \lbrace 0, 1, \dots, m-1\rbrace$ 把全域 $U$ 的键映入 $m$ 个槽位；简单均匀散列假设下每个键独立等概率落入各槽。

- 装载因子：$\alpha = n/m$；
- 拉链法下，一次**成功查找**的期望探测数为 $\Theta(1 + \alpha)$，插入为 $\Theta(1)$；
- 保持 $\alpha = O(1)$（随 $n$ 扩容翻倍 $m$），各项操作期望 $O(1)$——这就是"哈希表 $O(1)$"承诺的真实含义：**期望**意义、且均摊扩容之后。

若把 $n$ 个球独立均匀扔进 $m$ 格，某指定格恰装 $k$ 球的概率服从二项分布；最大负载约为 $\frac{\ln m}{\ln\ln m}$（当 $n = m$）——远超平均值却增长极慢。

## 4. 分步例题

**例**：哈希表 $m = 7$，$h(k) = k \bmod 7$，依次插入 12, 25, 38, 15, 40。

1. $h(12) = 12 \bmod 7 = 5$ → 进 5 号格；
2. $h(25) = 4$ → 进 4 号格；$h(38) = 3$ → 进 3 号格；
3. $h(15) = 1$ → 进 1 号格；$h(40) = 5$ → **与 12 撞车**！40 挂到 5 号格链表的第二位；
4. 此时 $n=5, m=7$，$\alpha = 5/7 < 1$：多数格子空着，但冲突照样发生；
5. 查 40 时先算 $h(40)=5$，再在 5 号链上走 2 步命中——总代价 = 定位 + 链长。

### 实验 2：先感受"没有冠军函数"的日子

想知道"最挤的格子装了几个"，没有现成工具时只能手动记擂台：

```python title="手动擂台赛：逐个比较记录最高纪录"
loads = [3, 0, 5, 2, 5, 1]      # 六个格子的占用数

champion = loads[0]             # 从第一个选手开始当临时冠军
for v in loads[1:]:
    if v > champion:            # 来了个更高的，就抢走冠军头衔
        champion = v

print(f"最挤的格子装 {champion} 个")
```

这个"边扫边记住最大值"的模式无处不在——Python 也把它做成了内置函数 `max`：`max(loads)` 一行顶七行。它接收一个可迭代对象，返回其中最大的元素；手写擂台与内置调用是同一语义的两副面孔。

### 实验 3：扔球模拟——冲突与最大负载

```python title="n 个球随机扔进 m 个格子"
import random

m = 50
n = 50
bins = []
for _ in range(m):
    bins.append(0)              # 先给每个格子清零

for _ in range(n):
    slot = random.randint(0, m - 1)   # randint(a, b)：闭区间内取随机整数（两端都可能）
    bins[slot] = bins[slot] + 1

collisions = n - len([x for x in bins if x > 0])   # 球数减去非空格子数 = 白挤的次数
busiest = max(bins)
print(f"{n} 个球进 {m} 格：发生 {collisions} 次挤压")
print(f"平均每格 {sum(bins) / m:.1f} 个，最挤的格子装 {busiest} 个")

empty = len([x for x in bins if x == 0])
print(f"空格子还有 {empty} 个")
```

$n = m$ 时平均每格 1 个，却总有格子挤四五个、而空格子成片——**波动比均值更真实**。多跑几次观察 busiest 的起伏，它大致在 $\frac{\ln m}{\ln \ln m} \approx 2.9$ 一带，叠加涨落实测常见 4~5。

### 快问快答

```quiz
拉链法哈希表中，一次失败查找的期望代价主要取决于？
- 表中键的具体数值大小
- 装载因子 alpha（每格平均挂几个） [*]
- 键插入的先后顺序
? 散列均匀时定位到格子只需常数步，之后沿链逐个比对，链长期望长度正是 alpha。
```

:::warning[常见误区]

**误区一**："选好哈希函数就不会冲突。" 键空间无限、槽位有限，鸽笼原理宣判冲突必然发生；好函数只能让冲突"均匀地少"。

**误区二**："哈希表操作就是 $O(1)$，写进论文不用加注。" 是**期望** $O(1)$，且以维持 $\alpha = O(1)$ 的扩容为前提；最坏情况（全员撞一格）仍是 $O(n)$。

**误区三**："装载因子小于 1 就不会撞。" 例题里 $\alpha = 5/7$ 照样撞——$\alpha$ 只管平均链长，不管个体命运。

:::

## 6. 练习

**练习 1**：$m=10$、$h(k)=k \bmod 10$，插入 17, 42, 9, 77 后列出每格内容并指出谁和谁冲突。

<details>
<summary>点开查看逐步解答</summary>

$h(17)=7$、$h(42)=2$、$h(9)=9$、$h(77)=7$——77 与 17 在 7 号格撞车，链上顺序 17→77。末位相同的十进制数天然同格：这也暴露了"取末位"式哈希对特定数据的偏科。
</details>

**练习 3**：为什么扩容通常选"格子数翻倍"？结合 $h(k)=k \bmod m$ 说明。

<details>
<summary>点开查看逐步解答</summary>

$m$ 变了所有键都要重哈希（rehash），成本 $O(n)$；翻倍使扩容间隔指数拉长，均摊到每次插入只有 $O(1)$。另外 $m$ 取 2 的幂时 $k \bmod m$ 等价于截取二进制末几位——快，但要求低位分布均匀，否则要混入更高位的扰动。
</details>

## 7. 选读：通用散列——让坏数据无计可施

<details>
<summary>选读 · 从函数族里现场抽签</summary>

固定的哈希函数再好，也怕针对性构造的数据（攻击者知道 $h$ 就能造一堆同格键）。通用散列的对策是准备一族函数 $H$，运行时**随机抽一个**：对任何两个不同键 $x \ne y$，族中让它们相撞的函数比例至多 $1/m$。于是无论对手怎么造数据，期望冲突率都被钉死在 $1/m$——把"防算法"升级成了"防预测"。34 章密码学的 Kerckhoffs 原则在这里提前回响：安全不能依赖敌人不知道你的选择。

</details>
