# 字符串算法：KMP 与 Trie 为什么能省时间

## 1. 从一个场景开始

你在编辑器里按下 Ctrl+F，输入 `ababac`，几毫秒后全文里的高亮全部跳出来。文本有一百万个字符，模式只有六个——如果程序真的"在每个位置从头对齐比一遍"，最坏要比一千多万次。可它并没有变慢。

更苛刻的场景在生物实验室：一段测序读长要在三十亿个碱基的人基因组里找位置，而 DNA 只有 A、T、C、G 四个字母，"碰巧开头一样"的概率比英文里高得多，朴素的比对会一次次空欢喜。搜索框的自动补全也一样：你敲下三个字母，它要从上千万个词里挑出所有以这三个字母开头的词。

这三个场景站着两位主角：**KMP**（在一段文本里找模式）和 **Trie**（在词表里按前缀找词）。它们省时间的办法都只有一句话：**不重复已经知道的信息**。

## 2. 直觉解释

朴素匹配像一位记性很差的校对员。拿模式 `ababac` 去比对文本 `abababac`：

```text
T: a b a b a b a c
P: a b a b a c
              ↑ 第 6 位失配：文本是 b，模式是 c
```

朴素做法的反应是"这段不对，换个位置重来"——把模式的脑袋重新对到文本的第 2 个字符。可它刚刚亲口读到了五个字符 `ababa`，而这个串的后三位 `aba` 恰好又是模式自己的开头。既然已经知道文本里这五位就是 `ababa`，最省力的选择是：把模式挪到"让 `aba` 对上刚才那三位"的位置，接着往下比，**不必重读文本**。

KMP 的全部魔法就在这里：把"模式自己和自己有多像"提前算好，失配时只挪模式、不挪文本。这份相似度档案叫**前缀函数**。

Trie 的直觉更直白。查纸质词典时，你不会为每个词从第一页翻起：`cat`、`car`、`cart` 共享开头 `ca`，那就让它们的查询路径**共用一段路**，到分岔口再各走各的。前缀越长，省下的重复走路越多。

## 3. 正式定义

**定义一（前缀函数）**：对模式串 $p$（长度 $m$），前缀函数是一个长度 $m$ 的数组 $\pi$，其中

$$\pi[i] = \max\lbrace\,k : k < i+1,\ \ p[0..k-1] = p[i-k+1..i]\,\rbrace$$

读作：子串 $p[0..i]$ 的**最长真前缀**，如果它同时又是这个子串的**真后缀**，长度就记为 $\pi[i]$。

| 符号 | 名字 | 说明 |
| --- | --- | --- |
| $p$ | 模式 | 要找的串，长度 $m$ |
| $T$ | 文本 | 被搜索的串，长度 $n$ |
| $i$ | 文本指针 | **只前进，从不后退**——这是线性的关键 |
| $k$ | 已匹配长度 | 模式指针，同时表示"已对上几位" |
| $\pi[i]$ | 前缀函数值 | 失配时 $k$ 该退回哪里 |
| 真前缀 | 不含自身的前缀 | 若允许等于自身，回退会原地打转 |

**KMP 的两条规则**：

1. 字符相等：$k \leftarrow k+1$，两边一起往前走；
2. 失配：$k \leftarrow \pi[k-1]$，文本指针 $i$ 原地不动，用新位置接着比。

**均摊复杂度**：$k$ 每匹配一次加一，全程最多加 $n$ 次，所以它最多也只能减 $n$ 次（$k$ 不会变成负数）。加减总数都是 $O(n)$，再加预处理 $O(m)$，总时间 $O(n+m)$。注意是**均摊**——某一步可能连着回退好几格，但把所有步骤加起来，回退的总账还不上前进的总账。

**定义二（Trie，前缀树）**：一棵树，每条边标一个字符；从根走到某个节点，一路上标边的字符依次拼出一个字符串，它就是该节点代表的**前缀**。节点上带一个"词尾"标记，表示这个前缀是一个完整的词。

| 操作 | 代价 | 说明 |
| --- | --- | --- |
| 插入或查询词 $w$（长 $L$） | $O(L)$ | 从根逐字符往下走 $L$ 步，与词表大小无关 |
| 前缀枚举 | $O(L+\text{输出量})$ | 走到前缀节点，再向下收集整棵子树 |
| 空间 | 与总字符数、分支数成正比 | 字母表越大，每个节点越"胖" |

## 4. 分步例题

**例 1（手算前缀函数）**：$p=$ `ababac`。

1. $\pi[0]=0$：单个字符没有真前缀；
2. `ab`：前缀 `a` 与后缀 `b` 不等，$\pi[1]=0$；
3. `aba`：前缀 `a` = 后缀 `a`，$\pi[2]=1$；
4. `abab`：前缀 `ab` = 后缀 `ab`，$\pi[3]=2$；
5. `ababa`：前缀 `aba` = 后缀 `aba`，$\pi[4]=3$；
6. `ababac`：`a`↔`c`、`ab`↔`ac`、`aba`↔`bac`……全不成立，$\pi[5]=0$。

得到 $\pi=[0,0,1,2,3,0]$。它既能连着涨（1、2、3），也能一次跌回 0——涨跌取决于串的自相似程度。

**例 2（KMP 跑一遍）**：在 $T=$ `abababac` 里找 `ababac`。

1. 前五次比较 `a b a b a` 全部命中，$k=5$；
2. 第六次：$T[5]=\texttt{b}$ 对 $p[5]=\texttt{c}$，失配；
3. 回退：$k \leftarrow \pi[4]=3$，文本指针仍停在 5；
4. 比 $T[5]=\texttt{b}$ 与 $p[3]=\texttt{b}$，命中，$k=4$；
5. 比 $T[6]=\texttt{a}$ 与 $p[4]=\texttt{a}$，命中，$k=5$；
6. 比 $T[7]=\texttt{c}$ 与 $p[5]=\texttt{c}$，命中，$k=6=m$：在文本下标 2 处找到一次匹配。

总共 9 次比较。朴素做法走完同一条路要 13 次（第 1 次对齐比 6 次，第 2 位对齐白比 1 次，第 3 位对齐再比 6 次）。省下的 4 次就是"不重读文本"的收益。模式越长、自相似结构越多，省得越狠。

**例 3（Trie 长什么样）**：依次插入 `cat`、`car`、`cart`、`dog`。

1. `cat` 走出路径 c-a-t，在 t 上打词尾；
2. `car` 复用 c-a，在 a 下新开 r 分支，在 r 上打词尾；
3. `cart` 复用 c-a-r，只在 r 下再挂一个 t——r 上原来的词尾要留着，因为 `car` 和 `cart` 都是词；
4. `dog` 另起 d-o-g 一路。
查询 `car`：根 → c → a → r，三步到位。词表里有一万个词还是一万零一个词，这一步都是三步。

## 5. 动手实验

### 实验 1（viz）：KMP 自动机就是一台 DFA

把模式的每个"已匹配长度"当成一个状态，失配回退写进转移表，KMP 就成了一台只读一遍文本的自动机：

```viz

  "type": "dfa-runner",
  "title": "模式 ababac 的 KMP 自动机",
  "states": ["0", "1", "2", "3", "4", "5", "6"],
  "alphabet": ["a", "b", "c"],
  "transitions": [["0", "a", "1"], ["0", "b", "0"], ["0", "c", "0"], ["1", "a", "1"], ["1", "b", "2"], ["1", "c", "0"], ["2", "a", "3"], ["2", "b", "0"], ["2", "c", "0"], ["3", "a", "1"], ["3", "b", "4"], ["3", "c", "0"], ["4", "a", "5"], ["4", "b", "0"], ["4", "c", "0"], ["5", "a", "1"], ["5", "b", "4"], ["5", "c", "6"], ["6", "a", "1"], ["6", "b", "0"], ["6", "c", "0"]],
  "start": "0",
  "accepting": ["6"],
  "input": "abababac"
}
```

状态编号就是"已匹配几位"，走到 6 就是整个模式都对上了。把输入串换一换再看：读完 `abababac` 的最后一跳是从 5 落到 4 再补到 6——**文本一位都没退，只有状态在回退**，这就是 KMP 比朴素匹配快的全部原因。

### 实验 2（python）：前缀函数与 KMP 搜索

```python title="KMP：前缀函数 + 一次线性扫描"
def prefix_function(p):
    # 返回列表 pi，pi[i] 是 p[0..i] 的最长「真前缀 = 真后缀」长度
    pi = [0] * len(p)                     # [0] * len(p)：造一个等长、全填 0 的列表
    k = 0                                 # k：当前已经接上的前缀长度
    for i in range(1, len(p)):            # 从第二个字符开始逐位推进
        while k > 0 and p[i] != p[k]:     # 接不上就连着回退，退到能接或退到 0
            k = pi[k - 1]
        if p[i] == p[k]:                  # 接上了：已匹配长度加一
            k = k + 1
        pi[i] = k                         # 把这一位的答案记进表里
    return pi

def kmp_search(text, pattern):
    pi = prefix_function(pattern)
    k = 0
    hits = []
    for i in range(len(text)):
        while k > 0 and text[i] != pattern[k]:
            k = pi[k - 1]                 # 只有模式指针回退，文本指针 i 原地不动
        if text[i] == pattern[k]:
            k = k + 1
        if k == len(pattern):             # 走满整个模式：命中一次
            hits.append(i - len(pattern) + 1)   # append：把命中的起始下标追加到队尾
            k = pi[k - 1]                 # 接着找下一处，回退而非清零
    return hits

print(prefix_function("ababac"))
print(kmp_search("abababac", "ababac"))
```

输出 `[0, 0, 1, 2, 3, 0]` 与 `[2]`：前缀函数与例 1 手算的完全一致，KMP 在文本下标 2 处报出命中。

### 实验 3（python）：Trie 做词频统计与自动补全

```python title="Trie：字典套字典，边查边计数"
END = "#"                     # 词尾暗号：一个不会出现在真实单词里的字符
root = {}                     # 每个节点就是一个字典，键是字符，值是下一层节点

def insert(word):
    node = root
    for ch in word:           # 逐字符往下走，缺一条路就现开一条
        if ch not in node:    # not in：这个键还不存在（字典的成员检查看的是键）
            node[ch] = {}
        node = node[ch]
    node[END] = node.get(END, 0) + 1   # get(键, 默认值)：取旧计数，没有就按 0 算，再加一

def count(word):
    node = root
    for ch in word:
        if ch not in node:
            return 0          # 半路断了：这个词压根没进过树
        node = node[ch]
    return node.get(END, 0)

def collect(node, path, out):
    # 从当前节点往下把所有完整单词收齐：先记自己（若是词尾），再递归每个孩子
    if END in node:
        out.append(path)
    for ch in node:
        if ch != END:
            collect(node[ch], path + ch, out)   # 递归：带着新字符继续往下走

def starts_with(prefix):
    node = root
    for ch in prefix:
        if ch not in node:
            return []         # 没有任何词以这个前缀开头
        node = node[ch]
    out = []
    collect(node, prefix, out)
    return out

for w in ["cat", "car", "cart", "dog", "car"]:
    insert(w)

print(count("car"))               # car 插入过两次
print(starts_with("car"))         # 以 car 开头的所有词
print(starts_with("ca"))
```

输出 `2`、`['car', 'cart']`、`['cat', 'car', 'cart']`。注意 `car` 与 `cart` 共用同一条查路，前缀 `ca` 之下挂着的整棵子树就是自动补全的候选清单——**共享前缀，就是 Trie 的省时间方式**。

## 6. 常见误区

:::warning[常见误区]

**误区一**："KMP 是 O(n+m)，所以每个字符只比一次、从不回退。" 其实 k 会回退，某一步甚至能连着退好几格。不回退的只有**文本指针 i**。复杂度是**均摊**的：k 总共最多前进 n 次，因此也最多回退 n 次，把账合起来才是线性。单看某一步，KMP 可能比朴素还啰嗦。

**误区二**："前缀函数里的前后缀可以包含整段。" 必须是**真**前缀、**真**后缀（长度严格小于 $i+1$）。一旦允许等于自身，失配回退时 k 会原地不动，搜索陷入死循环。这也是代码里回退用 `pi[k-1]`（退到**前一位**的历史答案）而不是 `pi[k]` 的原因。

**误区三**："Trie 又快又省，什么字符串问题都能上。" 它只共享**前缀**：找"所有以 ing 结尾的词"它帮不上忙（那是反向 Trie 或后缀树的地盘）。空间上，每个节点要为字母表留分支，直接开固定大小数组在 Unicode 上会爆炸，工程里改用哈希表或双数组实现。更常见的变体是给节点存子树词数，让排名、前缀计数变成 $O(L)$。

:::

## 7. 练习

**练习 1**：下面的前缀函数能跑，但对 `aabaaac` 算错了一位。把它改到判题通过：

```exercise
# @title: 练习：把前缀函数的一次回退改成连续回退
# @check: [0, 1, 0, 1, 2, 2, 0]
# @hint: 失配时模式可能得连着回退好几步。检查 while 与 if：只退一次是接不住"接不上就继续退"这条规则的。
def prefix_function(p):
    pi = [0] * len(p)
    k = 0
    for i in range(1, len(p)):
        if k > 0 and p[i] != p[k]:     # ← 问题在这：这里只能回退一次
            k = pi[k - 1]
        if p[i] == p[k]:
            k = k + 1
        pi[i] = k
    return pi

print(prefix_function("aabaaac"))
```

<details>
<summary>点开查看逐步解答</summary>

把 `if` 改成 `while`：

```py
while k > 0 and p[i] != p[k]:
    k = pi[k - 1]          # 退一步，若还接不上就继续退
```

对照看差异出在 `aabaaac` 的最后一位 c：此时 $k=2$，字符 c 与 $p[2]=\texttt{b}$ 不匹配。正确的做法是连退两步——先退到 $\pi[1]=1$，发现 $\texttt{c}$ 与 $p[1]=\texttt{a}$ 还是不匹配，再退到 $\pi[0]=0$，最终 $\pi[6]=0$。只退一次的程序在退到 1 后就收工，把 $\pi[6]$ 记成了 1，于是 $\pi=[0,1,0,1,2,2,1]$。这一位的错值会让 KMP 在后续失配时回退得不够深，从而漏掉真正可能重叠的匹配。**回退是一段 while 循环，不是一次判断**——这是前缀函数最容易写错的地方。

</details>

**练习 2**：为什么前缀函数算的是"真前缀 = 真后缀"的最大长度，而不是"最长相同前缀后缀"（允许前缀覆盖整段）？用手算 $p=$ `aaa` 举反例说明。

<details>
<summary>点开查看逐步解答</summary>

若允许取整段，$p=$ `aaa` 时 $\pi[2]$ 会等于 3（整段）。设想在一次搜索中 $k=3$ 时失配，代码执行 `k = pi[k-1]`；但若别处出现 $\pi[k]$ 且允许整段，回退就会落在 3 上——状态原地不动，程序停在同一个字符上无限循环。取"真"前缀之后，`aaa` 的答案变成 $[0,1,2]$：$\pi[2]=2$ 意味着"失配时可以承认前两个字符仍然对得上"，回退严格变小，循环必然终止。**真前缀不是抠字眼，它是终止性的保证。**

</details>

## 8. 选读：把 KMP 请上 Trie —— AC 自动机

<details>
<summary>选读 · 两个工具合体，就是多模式匹配</summary>

KMP 解决"一个模式在一段文本里出现几次"。如果手上有**一万个敏感词**要一次扫完呢？一万次 KMP 当然可以，但每遍都要重读文本一遍。把两件工具叠起来就是答案。

**第一步**：把一万个词插进一棵 Trie——这就是第 5 节实验 3 的那棵树。
**第二步**：给 Trie 的每个节点配一条"失配指针"，指向"当我在这里接不上时，该退到哪个节点继续"。这条指针的构造，就是 BFS 序遍历 Trie，并对每个节点求**最长真后缀**——和前缀函数是一回事，只不过是在树上做。
**第三步**：拿文本在自动机上跑一遍：每读一个字符，沿转移走；走不动就沿失配指针退。命中一个词尾标记时，把沿失配链上所有词尾也一并报出（因为它们的后缀也出现在这里）。

结果是：预处理 $O(\text{词表总长})$，扫描 $O(n+\text{命中数})$——**扫一遍文本，报出所有词**。这就是 Aho–Corasick 自动机（1975），也是 grep、IDS/IPS 的规则匹配、词典分词的底座。

回头看本课的两条主线，它们在这里合流：前缀函数提供"失配时往哪退"的知识，Trie 提供"把大量模式共享掉的公共前缀"。第 31 章的 DFA 视角则告诉我们，这两件事合起来不过是一台带记忆的状态机——**字符串算法的极限，就是自动机能记住多少信息**。

</details>
