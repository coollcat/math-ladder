# 监控、审计与失败模式清单

## 1. 从一个场景开始

模型上线那天往往是它状态最好的一天：数据最新鲜、口径刚对齐、所有人都盯着它。此后它独自面对促销季、改版、羊毛党和新法规——没有哪份测试集预演过这三年。

航空业的答案不是造一架永不坏的飞机，而是把**维护体系**和飞机一起交付：黑匣子、仪表盘、检查单、塔台和无指责的事故复盘。可信 AI 的最后一块拼图一样：把每一类翻车提前写进剧本。

## 2. 直觉解释

先把"上线后会坏"分门别类。本章一路走来其实已经踩了满地的坑：

| 代号 | 失败模式 | 一句话画像 | 出身 |
| --- | --- | --- | --- |
| A | 直接危害与滥用 | 有人故意惹它、用它伤人 | 打印眼镜（对抗样本） |
| B | 置信腐坏 | 嘴上还是九成，实际只剩七成 | 校准虚价 + 分布偏移 |
| C | 差别对待 | 各组判别力相同，待遇却劈叉 | 公平性不可能三角 |
| D | 反馈回路放大偏见 | 它的输出变成下一轮教材，越教越歪 | 推荐极化、再训练污染 |
| E | 泄露与合规翻车 | 从统计公告里抠出某个人 | 需要为隐私计价 |

**监控就是给每一类配一个便宜、可解释、有人接手的警报器**：

- **输入侧**：特征均值漂移率、缺失率、字典外词汇占比——上一课的热身图就是它们；
- **输出侧**：分数分布稳定性、拒绝率、自报置信度直方图——虚价复发会最先在这里露馅；
- **效果侧**：延迟到达的真实标签抽样复核、人工抽检小样本——唯一能直接回答"还准吗"的一路。

审计的人和流程版图也一样分层：构建者自检卡在发布前（gate），内部红队专门使坏，外部独立审计按年度出报告，值班工程师盯告警，事故后全员做无指责复盘——五个角色一个都不能由同一个人兼任。

## 3. 正式定义

把上表上升为**故障剧本**：每条告警对应一个病灶和一个动作，不许凭感觉临场发挥。

| 警报信号 | 最可能的病灶 | 第一动作 | 关联课 |
| --- | --- | --- | --- |
| 自报置信度直方图右移 | 校准腐坏（B） | 加急复检可靠性图、重做温度缩放 | 校准课 |
| 一批"合法输入"连续骗过模型 | 直接危害（A） | 上线对抗检测、收紧边界监控 | 对抗课 |
| 组间通过率/误伤率劈叉 | 差别对待（C） | 冻结阈值、跑三口径公平体检 | 公平课 |
| 同一问题的解释件前后矛盾 | 归因不可靠 | 换工具交叉验证、回查基线选择 | 解释课 |
| 特征均值与词表整体搬家 | 分布偏移 | 触发 OOD 报警、安排补采样 | 漂移课 |
| 新样本接连跌出署名区间 | 可交换性失效 | 收窄保证书适用范围并公示 | conformal 课 |
| 用户称能从公告反推个体 | 隐私预算失守 | 暂停发布、核查台账超支记录 | 隐私课 |
| 输出回流成为新训练数据 | 反馈放大（D） | 断开回流管道，人审后再入库 | 本课 |

规则只有两条：每条警报必须**有名有姓地映射**到一类病灶；每个病灶必须预先写好第一动作，别在凌晨三点发明流程。

## 4. 分步例题

一家电商平台做了周年促销，风控小组照例跑一遍上下线对比：

| 特征 | 训练期均值 | 三个月后均值 | 相对漂移 | 定级 |
| --- | --- | --- | --- | --- |
| 人均消费 | 120 | 178 | 48% | 观察 |
| 登录频次 | 4.0 | 4.6 | 15% | 正常 |
| 退款率 | 6.0 | 15.0 | 150% | 观察 |

1. 先算相对漂移 $|179 - 120|/120$ 式的比值：绝对元数没有可比性，波动尺度才是公分母；
2. 登录频次只挪了一成五，划入正常带（约定阈值为两成）；
3. 人均消费与退款率双双越过红线，且方向一致——高消费高退款同时出现，剧情指向"促销引来的薅羊毛人群"，而不是自然增长；
4. 按剧本行动：触发 B 类加急复检（这批人的分数分布换了天下）＋ 输入侧补采样；
5. 结论归档：这次演练本身也要写进下周的复盘会，剧本就这样一版版长厚。

### 实验 2：漂移率自查脚本

```python title="上线前后三个特征的漂移率定级"
rows = [
    ("人均消费", 120.0, 178.0),   # 每行：特征名, 训练期均值, 本周均值
    ("登录频次", 4.0, 4.6),
    ("退款率", 6.0, 15.0),
]
alarm = 0.2                        # 观察名单门槛：相对漂移超过两成

for name, before, now in rows:     # 元组解包：一轮循环同时取三个量
    rate = abs(now - before) / before
    flag = "观察" if rate > alarm else "正常"   # 条件表达式：成立取前值，否则取后值
    print(name, round(rate, 2), flag)
```

输出与分步例题的表格逐位一致。注意用的是**相对值**：把 6 升到 15 的惊悚程度远大于 120 到 178，虽然后者多涨了 43 个单位。

## 常见误区

:::warning[常见误区]

**误区一**："监控嘛，盯着准确率曲线就行。"
效果侧指标常常**延迟数周到数月**才到货，等它报警时损失已经结算完毕。输入侧与输出侧指标便宜、即时、不依赖真标签，必须配上——三条腿缺一不可。

**误区二**："告警响了很多次都没事，以后调成静音吧。"
没人响应的告警等于没有告警，还附赠狼来了效应。工程纪律是每次告警必须有处置记录（哪怕结论是"确认无害"），并且定期修剪既扰民又不顶事的指标。

**误区三**："合规评审都过了，不会有问题。"
合规是入场券不是终身保险：它检验的是提交那一刻的材料，而偏见、漂移和反馈回路都是**时间的朋友**。审计因此必须是周期性活动，外加重大变更触发的临时抽检。

:::

**练习 3**：概念辨析：为什么审计要求"内部红队与构建者分属不同汇报线"？

<details>
<summary>点开查看逐步解答</summary>

同一根汇报线会让"发现问题的成本"压在发现问题的人头上：指标压力、排期压力都会转化成"这个告警应该没事吧"的自由裁量。独立汇报线把这两件事拆开——第 30 课的不可能性定理同样提醒我们，任何单一视角都有结构性盲区，分权是制度的冗余设计。
</details>

## 7. 选读：无指责复盘的四问模板

<details>
<summary>选读 · blameless postmortem</summary>

事故处理完不是终点，一周内要在复盘会上过一遍固定四问：**发生了什么**（时间线按分钟排，只描述不评价）；**当时为什么看起来合理**（每个人基于他当时掌握的信息做出局部合理的决定，找到那些信息为何缺失或误导）；**哪一层防线最划算**（同因不同果的小改动往往比大重构有效）；**谁负责跟到关闭**（每条改进项有姓名有期限）。它继承自可靠性工程的精髓：把追责换成修复，人才愿意把黑匣子的真实数据交出来——模型时代这条人性定律原样生效。
</details>
