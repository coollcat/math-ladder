# ADMM 与分布式优化

## 1. 从一个场景开始

你管理一个广告推荐系统：十亿用户的行为数据分散在五十台服务器上，每台只存了五十分之一的用户画像。你想学一个全局模型，但把十亿行数据搬到一台机器上训练——网络带宽会先于模型崩溃。

EM 算法（第 96 课）教过"拆子问题轮流做"的思路，但它是串行的：每个子步需要上一步的完整结果。有没有一种方法，让五十台机器**同时**算自己的那一份，然后只交换一小段汇总信息就拼回全局解？

ADMM（Alternating Direction Method of Multipliers，交替方向乘子法）就是为此而生的。它把"大问题拆小"和"小问题对齐"交替进行，每一步都可以并行。

## 2. 直觉解释

想象你在组织一场五十人的合唱。每个人只能听到自己的声部，但你们要唱出和声。

- **每轮练习**（x 更新）：每个人各自按自己的理解唱一遍——这是"各算各的子问题"；
- **指挥调音**（z 更新）：指挥收集所有人的版本，取一个折中版本——这是"全局一致性"；
- **反馈纠正**（u 更新）：指挥把折中版本和个人版本的偏差告诉每个人——这是"乘子更新"，拉大家往共识靠拢。

三步循环往复。重点在于：每个人**只需要交出自己的版本、收到一个偏差值**，不需要听其他四十九个人的独唱。带宽开销极小，这就是 ADMM 能分布式的核心原因。

数学上，它把一个带约束的优化拆成两步极小化——每步都比原问题简单得多，但通过拉格朗日乘子的"传话"保持全局一致。

## 3. 正式定义

考虑可分离的凸优化问题：

$$\min_{x,z}\; f(x)+g(z) \quad \text{s.t.}\; Ax+Bz=c$$

| 符号 | 名字 | 本例 |
| --- | --- | --- |
| $x$ | 原始变量 | 各机器上的局部模型参数 |
| $z$ | 共享变量 | 全局一致的模型参数 |
| $f(x)$ | 局部目标 | 各机器的局部损失之和 |
| $g(z)$ | 全局正则项 | 防止过拟合的惩罚 |
| $A, B, c$ | 约束矩阵与向量 | 强制局部与全局对齐 |
| $\rho$ | 惩罚参数 | 控制一致性的"拉力"强度 |
| $u$ | 缩放乘子 | 偏差的累积度量 |

**增广拉格朗日**：在标准拉格朗日上加一个二次罚项

$$L_\rho(x,z,u)=f(x)+g(z)+u^{\mathsf T}(Ax+Bz-c)+\frac{\rho}{2}\|Ax+Bz-c\|^2$$

**ADMM 迭代格式**（三步循环）：

$$\begin{aligned}
x^{k+1}&=\arg\min_x\; L_\rho(x,z^k,u^k) \\
z^{k+1}&=\arg\min_z\; L_\rho(x^{k+1},z,u^k) \\
u^{k+1}&=u^k+\rho(Ax^{k+1}+Bz^{k+1}-c)
\end{aligned}$$

每步极小化只涉及一半变量——交替方向之名由此而来。

## 4. 分步例题

最简单的 ADMM 实例：$\min\;\frac12\|Ax-b\|^2$ 等价于

$$\min_{x,z}\;\frac12\|z-b\|^2 \quad \text{s.t.}\; x-z=0$$

取 $A=I$（单位阵），$f(x)=0$，$g(z)=\frac12\|z-b\|^2$。

1. **x 更新**：$\min_x\; u^{\mathsf T}(x-z^k)+\frac\rho2\|x-z^k\|^2$，求导得 $x^{k+1}=z^k-u^k/\rho$；
2. **z 更新**：$\min_z\;\frac12\|z-b\|^2+\frac\rho2\|x^{k+1}-z+u^k/\rho\|^2$，求导得 $z^{k+1}=\frac{b+\rho(x^{k+1}+u^k/\rho)}{1+\rho}$；
3. **u 更新**：$u^{k+1}=u^k+\rho(x^{k+1}-z^{k+1})$；
4. 迭代三步看看：取 $b=3$，$\rho=1$，$x^0=z^0=u^0=0$——
   - $x^1=0-0=0$，$z^1=(3+1\cdot0)/1=3$？不对，$z^1=(3+1\cdot(0+0))/(1+1)=1.5$，$u^1=0+1\cdot(0-1.5)=-1.5$；
   - 几步后 $x,z$ 都收敛到 3，$u$ 收敛到 0——偏差消失，全局一致达成。

### 实验 2（python）：两台"机器"的分布式求解

```python title="ADMM 求解 min (x1-2)^2 + (x2-3)^2，约束 x1=x2"
import math

rho = 1.0          # 惩罚参数
x1, x2 = 0.0, 0.0 # 两台机器各自的局部变量
z = 0.0            # 共享的全局变量
u1, u2 = 0.0, 0.0 # 各自的缩放乘子

history = []
for k in range(20):
    # x 更新（各机器独立求解，可并行）
    x1 = (2 + rho * (z - u1/rho)) / (1 + rho)  # 机器 1 的局部解
    x2 = (3 + rho * (z - u2/rho)) / (1 + rho)  # 机器 2 的局部解

    # z 更新（收集两台机器的结果取均值）
    z = (x1 + u1/rho + x2 + u2/rho) / 2        # 全局一致性步

    # u 更新（把偏差反馈给各机器）
    u1 = u1 + rho * (x1 - z)                     # 乘子 1 更新
    u2 = u2 + rho * (x2 - z)                     # 乘子 2 更新

    residual = math.sqrt((x1 - z)**2 + (x2 - z)**2)
    history.append(residual)

print(f"x1={x1:.4f}, x2={x2:.4f}, z={z:.4f}")
print(f"最终残差: {history[-1]:.6f}")
print(f"目标函数值: {(x1-2)**2 + (x2-3)**2:.6f}")
```

运行结果：$x_1\to2$，$x_2\to3$，$z\to2.5$——全局均值。残差从大到小收敛到零。两台机器各自求解简单的一元二次问题，只交换一个标量 $z$，完全不需要共享原始数据。

### 快问快答

```quiz
ADMM 为什么特别适合分布式计算？
- 因为它用的矩阵运算比梯度下降快
- 因为每个子问题只涉及局部变量，只需交换全局变量 z 和乘子 u [*]
- 因为它不需要选择学习率
? ADMM 的 x 更新可以拆成多台机器各自独立做，每台只交出自己的 x_i 和 u_i，全局的 z 更新是简单的加权平均。通信量与机器数线性相关，与数据量无关——这正是分布式场景的核心优势。
```

:::warning[常见误区]

**误区一**："ADMM 比梯度下降收敛更快。" 不一定。ADMM 的每步涉及两个极小化子问题，计算量通常比一次梯度步大。它的优势不在单步速度，而在**可分解性**——能并行、能分布式、能利用问题结构。对于不可分的问题，ADMM 可能没有梯度下降快。

**误区二**："ρ 越大收敛越快。" 过大的 $\rho$ 让增广项主导目标，子问题的条件数恶化，反而拖慢收敛。实践中 $\rho$ 的选择是一门艺术：太小一致性差、太大子问题难解。有些实现做自适应 $\rho$ 调整。

**误区三**："ADMM 只能解凸问题。" 理论收敛保证确实需要凸性，但实践中 ADMM 在非凸问题（如深度学习的分布式训练）上也常用——只是不再保证全局最优，可能收敛到局部解或鞍点。

:::

## 6. 练习

**练习 1**（概念）：ADMM 的 x 更新和 z 更新为什么可以并行化？如果把两步合并成一步同时更新 $x$ 和 $z$，还叫 ADMM 吗？

<details>
<summary>点开查看逐步解答</summary>

x 更新用的是 $z^k$ 和 $u^k$（上一轮的值），z 更新用的是 $x^{k+1}$ 和 $u^k$——所以 z 必须等 x 做完，两者是串行的。但如果有多个 x 变量（比如 $x_1,\ldots,x_N$ 分布在不同机器上），它们的更新**互相独立**，这才是并行的地方。合并更新就变成了标准的增广拉格朗日方法，失去了"交替方向"把大问题拆小的能力。
</details>

**练习 2**（判题）：下面的 ADMM 代码在 z 更新时用了错误的公式。修好它让残差收敛到零。

```exercise
# @title: 练习：修好 ADMM 的 z 更新步
# @check: 2.5000
# @check: 0.000000
# @hint: z 更新应该是两个 x 的加权平均（加上各自的 u/rho 偏移），再除以 2。
rho = 1.0
x1, x2 = 0.0, 0.0
z = 0.0
u1, u2 = 0.0, 0.0

for k in range(30):
    x1 = (2 + rho * (z - u1/rho)) / (1 + rho)
    x2 = (3 + rho * (z - u2/rho)) / (1 + rho)
    z = (x1 + x2) / 2            # ← 错了：忘了加 u/rho 的偏移项
    u1 = u1 + rho * (x1 - z)
    u2 = u2 + rho * (x2 - z)

residual = math.sqrt((x1 - z)**2 + (x2 - z)**2)
print(round(z, 4))
print(round(residual, 6))
```

修好 z 更新为 `(x1 + u1/rho + x2 + u2/rho) / 2` 后，输出 `2.5000` 和 `0.000000`：共享变量收敛到两台机器解的均值，残差归零。

**练习 3**（选做）：如果把 ADMM 用于 Lasso 回归 $\min\frac12\|Ax-b\|^2+\lambda\|z\|_1$（约束 $x=z$），z 更新步变成了什么？提示：L1 正则项的近端算子是软阈值。

<details>
<summary>点开查看逐步解答</summary>

z 更新是 $\min_z\;\lambda\|z\|_1+\frac\rho2\|x^{k+1}-z+u^k/\rho\|^2$。这是 L1 正则项加二次项的复合，解析解就是**软阈值算子**：$z^{k+1}=S_{\lambda/\rho}(x^{k+1}+u^k/\rho)$，其中 $S_\kappa(v)=\operatorname{sign}(v)\max(|v|-\kappa,0)$。这正是第 55 课 L1 正则化的老朋友——ADMM 把不可分的 Lasso 拆成了可分的二次子问题加软阈值，两者都有闭式解。
</details>

## 7. 选读：ADMM 的收敛性保证

<details>
<summary>选读 · 为什么交替做也能对齐</summary>

ADMM 的收敛性依赖三个条件：(1) $f$ 和 $g$ 是凸函数；(2) 增广拉格朗日有鞍点；(3) $\rho>0$。满足这些条件时，ADMM 保证：

- **残差收敛**：$\|Ax^k+Bz^k-c\|\to0$（可行性）
- **目标收敛**：$f(x^k)+g(z^k)\to f^\ast+g^\ast$（最优性）
- **乘子收敛**：$u^k\to u^\ast$（对偶变量稳定）

收敛速率是 $O(1/k)$——比梯度下降的 $O(1/k)$ 在常数因子上可能更好（因为利用了可分离结构），但比牛顿法的二次收敛慢。实践中通常 20-100 步就能达到工程精度，瓶颈往往在通信而非迭代次数。

与 EM 的对比：EM 也是交替优化，但它的 M 步需要在给定隐变量下求完整参数的条件期望——是"轮到谁谁就全做一遍"。ADMM 则把问题按变量维度切开，每步只做半边——刀法不同，但"拆了再拼"的精神一脉相承。
</details>
