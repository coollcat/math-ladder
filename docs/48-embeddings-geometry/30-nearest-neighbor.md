# 最近邻检索

## 1. 从一个场景开始

你听完一首冷门爵士，App 立刻推来三首"气质相近"的歌。它的曲库有一亿首，每首要几十维特征——逐首算一遍距离再挑最小，一亿次的乘法加法，手机得算到明天。

可它响应只花了几十毫秒。秘密不是算得快，而是**少算**：先粗分格子，只在可疑的格子里精查。这一课研究"在一亿个点里找最近的一个"如何从不可能变成日常。

## 2. 直觉解释

去图书馆找一本具体的书，你不会把几百万册全翻一遍——你按索书号走到对应楼层、对应书架。**分类索引把"全局大海捞针"缩小成"局部仔细看"。**

检索问题同构：

- **暴力法**：和每个点都算一次距离，谁最小选谁。绝对准确，代价 $O(N)$ 次——$N$ 是曲库大小；
- **分区法**：先把空间切成若干区域（按风格粗分、按哈希桶装），查询时只访问少数几个候选区。可能漏掉真最近邻（它在隔壁格子），但快了成百上千倍。

愿意用一点点准确率换巨大速度的交易，就叫**近似最近邻**（ANN, Approximate Nearest Neighbor）。第 30 章的哈希思想在这里复活：普通的哈希表要"一模一样才进同一个桶"，而这里反过来设计——**越相似的向量越容易落进同一个桶**。

## 3. 正式定义

给定查询点 $q$ 和数据集 $D$，**最近邻查询**定义为

$$\text{nn}(q) = \arg\min_{x \in D} \; d(q, x)$$

| 符号 | 名字 | 含义 |
| --- | --- | --- |
| $d(q,x)$ | 距离函数 | 欧氏距离或余弦距离等，选定后不可中途更换 |
| $\arg\min$ | 最小值的位置 | 让距离最小的那个 $x$，注意是"哪个点"不是"多小" |
| ANN | 近似最近邻 | 允许以概率 $(1-\varepsilon)$ 返回真正近邻，换数量级加速 |

ANN 的两个基本指标像天平两端：**召回率**（找到的真是前几名吗）与**速度/内存**（查一次碰几个桶）。工程系统（如各类向量数据库）就在这条天平上调参。

## 4. 分步例题

四首歌的特征为（节奏, 能量）：A $[3,8]$、B $[7,4]$、C $[2,9]$、D $[6,5]$。你在听 $q=[3,9]$，找最近邻。

1. 列出全部候选：A、B、C、D 共四次比较；
2. 逐一算平方距离（不必开方，比大小开不开方一样）：
   - A：$(3{-}3)^2+(8{-}9)^2 = 1$
   - B：$(7{-}3)^2+(4{-}9)^2 = 41$
   - C：$(2{-}3)^2+(9{-}9)^2 = 1$……等等，C 也是 $1$？
   - D：$(6{-}3)^2+(5{-}9)^2 = 25$
3. 出现并列！A 与 C 同为 1。规则说取其一即可，但工程上这提示我们：**该把两首都推出去**——"top-k 最近邻"才是真实产品里的形态；
4. 若加了分区线 $x=5$ 把空间切成左右两半，查询落在左半区：只需检查 A、C 两次，比较次数从 4 降到 2，且这个例子里没漏掉任何近邻。

### 实验 2（python）：画一张带分区的星图

```python title="十二首歌的曲库与一条分区线"
import matplotlib.pyplot as plt

songs = [[3, 8], [7, 4], [2, 9], [6, 5], [1, 2], [8, 8],
         [5, 1], [9, 6], [4, 3], [2, 5], [7, 9], [6, 8]]
query = [3, 9]

xs = []   # 收集横坐标
ys = []
for s in songs:
    xs.append(s[0])
    ys.append(s[1])

plt.scatter(xs, ys, s=70, label="songs")
plt.scatter([query[0]], [query[1]], marker="*", s=300, color="tomato", label="you")  # marker="*"：五角星记号
```

星星在左上格。左上格里只有 A、C、J 三位候选——查询时先定位格子，再在格子内精查。

### 实验 3（python）：数一数各自比了多少次

```python title="暴力法 vs 分桶法的工作量对比"
songs = [[3, 8], [7, 4], [2, 9], [6, 5], [1, 2], [8, 8],
         [5, 1], [9, 6], [4, 3], [2, 5], [7, 9], [6, 8]]
query = [3, 9]

brute_count = 0                 # 暴力法计数器
best = None                     # 目前最近的歌
best_d2 = None                  # 它的距离平方
for s in songs:
    brute_count += 1            # += ：累加简写，等价于 brute_count = brute_count + 1
    d2 = (s[0] - query[0])**2 + (s[1] - query[1])**2
    if best_d2 is None or d2 < best_d2:   # is None：还没存过任何候选；or：两者任一成立
        best_d2 = d2
        best = s

bucket_count = 0                # 只查左上格（x < 5 且 y >= 5）
for s in songs:
    if s[0] < 5 and s[1] >= 5:
        bucket_count += 1

print(f"暴力法比较 {brute_count} 次, 找到 {[best[0], best[1]]}")
print(f"分桶法只需精查 {bucket_count} 个候选")
```

本例中两种方法答案一致（都是 A），但工作量是 12 对 3。真实系统里格子不止四个，而是递归细分或哈希成千上万桶——省下的倍率随之指数级放大。

### 快问快答

```quiz
ANN 敢于"近似"，它用什么东西换速度？
- 把所有向量的维度砍到 1 维
- 牺牲少量召回率：偶尔漏掉真最近邻，换取百倍千倍的查询加速 [*]
- 提前把用户想听的歌算好缓存起来
? 分区/哈希类方法让查询只访问极少数桶；代价是目标恰好躺在别的桶里时会漏报。调好参数后漏报率很低而加速极大。
```

:::warning[常见误区]

**误区一**："你以为 ANN 是有 bug 的 KNN。" 漏报是被设计、被量化、可调节的属性（召回率指标管着它），不是程序错误。要绝对精确也有纯精确算法，只是付不起那个时间。

**误区二**："你以为换了距离度量结果不变。" 欧氏距离下的最近邻，换成余弦度量后可能完全换人（长度权重变了）。建索引之前必须锁定度量，索引结构本身往往就绑定了一种度量。

**误区三**："你以为二维直觉能直接搬到一千维。" 平面上画格子很直观，但下一课你会看到：维度一高，"格子"会集体失灵——这正是高维检索需要专门技术的原因。

:::

## 6. 练习

**练习 1**：修好这个最近邻函数——它现在总返回离你最远的那首：

```exercise
# @title: 练习：找回真正的最近邻
# @check: 歌曲A
# @check: 1.0
# @hint: argmin 要的是"更小者胜"。盯着循环里那个 if 的比较方向看。
songs = [[3, 8, "歌曲A"], [7, 4, "歌曲B"], [2, 9, "歌曲C"], [6, 5, "歌曲D"]]
query = [3, 9]

def dist(p, q):
    return ((p[0] - q[0])**2 + (p[1] - q[1])**2) ** 0.5

best = songs[0]
best_d = dist(best, query)
for s in songs:
    d = dist(s, query)
    if d > best_d:        # ← 问题在这：方向反了
        best = s
        best_d = d

print(best[2])
print(round(best_d, 1))
```

**练习 2**：为什么计算平方距离后可以不开方就直接比大小？什么时候必须真的开方？

<details>
<summary>点开查看逐步解答</summary>

开方函数 $y=\sqrt{x}$ 在 $x>0$ 上单调递增：$a<b$ 当且仅当 $\sqrt{a}<\sqrt{b}$。所以"谁的平方距离小"与"谁的距离小"结论永远一致，比较环节省掉开方，一亿次查询就是省一亿次开方。需要**具体数值**时才开方：比如"距离小于 3 才推荐"这种阈值判断，或者向用户展示"相似度分数"。
</details>

**练习 3**：把实验 3 的分区线改成十字（$x=5$ 与 $y=5$ 四象限），查询仍只查自己所在象限，会不会漏掉某个比当前答案更近的点？

<details>
<summary>点开查看逐步解答</summary>

会。构造反例：查询 $q=[4.9, 4.9]$ 在右上象限，右上象限里最近的点距离可能是 5，但左上象限一个点 $[4.8, 5.0]$ 距离约 $0.22$——被边界切掉了。这就是 ANN 漏报的微观机制。补救办法是**回查相邻桶**（查 4 或 9 个邻居格子），漏报率骤降、代价略升。真实系统的多层递归分区 + 邻桶回查，就是把这套朴素想法做到极致。
</details>

## 7. 选读：桶的两条路线

<details>
<summary>选读 · 哈希派与分区派</summary>

把相似向量聚到一起有两大门派：

- **哈希派（LSH）**：设计一族随机切平面，让两个点在所有切法下落进同一桶的概率随相似度升高。查询时用同一套切法定位候选。理论保证漂亮：存在 $(c, r)$ 近似下多项式时间的次线性方案。
- **分区派（IVF 类）**：先用聚类（k-means 思想）把空间划成几千个质心区域；查询先找最近的几个质心，再进入对应区域细查。工程中最常见，配合**乘积量化**（PQ，把向量切段分别压缩编码）能把一亿条 128 维向量压进几 GB 内存。

两条路都体现同一句话：**先粗后精，用可控的错换可控的快**。至于为什么高维里这件事格外难，下一课给出几何层面的解释。

</details>
