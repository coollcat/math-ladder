# 近似最近邻：十亿向量里毫秒级找邻居

## 1. 从一个场景开始

上一课我们让检索"少算"了：先分格子，只查可疑的格子。可真实向量数据库面对的是**十亿条 128 维向量**——即便只算乘法，一次全量扫描也是 $10^9\times128\approx1.3\times10^{11}$ 次运算，毫秒级根本不可能。

它靠的不是更快的芯片，而是三件套：**倒排索引**把候选锁进少数几个桶、**乘积量化**把内存压到原来的几十分之一、**分层图**让查询沿"高速公路"一路跳到最近邻门口。这一课把这三样拆开，并亲手做一次量化误差分析。

## 2. 直觉解释

把"在十亿个点里找最近"想成在一个巨型城市里找最近的一家便利店：

- **IVF（倒排索引）**：先按片区划出几千个"街道"，每栋楼上只挂一个门牌。查的时候先看你在哪个片区，只走进邻近的几条街，别处一律不逛。
- **PQ（乘积量化）**：每栋楼的门牌只记"大概位置"（比如"东三栋"），不记精确坐标。房子从 128 个浮点数缩成几个字节，代价是门牌与实际位置之间有一点点偏移。
- **HNSW（分层可导航小世界图）**：每栋楼都连向几个邻居，还额外修了一层"高速路"。查询先沿高速路跳大步，跳不动了再退到小路微调——像查地图先放大到省、再放大到街道。

前两者省的是"查多少"和"存多少"，第三者省的是"跳几步"。**它们都拿一点点准确率换数量级的速度**，这就是近似最近邻（ANN）的全部交易。

## 3. 正式定义

精确检索要把查询 $q$ 与库里每个 $x$ 都算一遍：

$$\hat{x}=\arg\min_{x\in D}\ \lVert q-x\rVert_2,\qquad \text{代价 } O(Nd).$$

**IVF**：先用聚类把 $D$ 划成 $n_{\text{list}}$ 个簇，簇心 $c_1,\dots,c_{n_{\text{list}}}$；每个簇是一个"倒排表"。查询时只访问离 $q$ 最近的 $n_{\text{probe}}$ 个簇内的向量。

**PQ（乘积量化）**：把 $d$ 维向量切成 $m$ 段（每段 $d/m$ 维），第 $j$ 段配一个含 $2^{b}$ 个码字的码本 $C_j$。一个向量被压成 $m$ 个编号，第 $j$ 段的**量化误差**为

$$\lVert x_j-\tilde x_j\rVert^2=\min_{c\in C_j}\lVert x_j-c\rVert^2 .$$

内存从每向量 $4d$ 字节（float32）降到 $m$ 字节（$b=8$）；代价是距离用的是 $\lVert q-\tilde x\rVert$ 而非 $\lVert q-x\rVert$。

**HNSW**：构造多层近邻图，第 0 层含全部点、越往上越稀疏。查询自顶层贪心——每步走向比当前更近的邻居，够不到更近的就下降一层。

| 符号 | 名字 | 含义 |
| --- | --- | --- |
| $N,\ d$ | 库大小、维度 | 精确检索的复杂度 $O(Nd)$ 里的两个因子 |
| $n_{\text{list}},n_{\text{probe}}$ | 簇数、探测簇数 | IVF 的两个旋钮：桶越多每桶越小，探得越多越准越慢 |
| $m,\ b$ | 段数、每段码字位数 | PQ 的内存 = $m$ 字节（$b=8$）；$m$ 越大误差越小、编码越长 |
| 召回率 | recall@k | 返回的 $k$ 个里有多少是真正的 $k$ 近邻——ANN 的质量指标 |
| $\rho$ | 压缩比 | 原始字节 ÷ 编码字节，PQ 常用 $4d/m$ |

**三方权衡**（记住这张三角）：**召回率、延迟、内存**三者不可兼得。调 IVF 的 $n_{\text{probe}}$ 换召回—延迟，调 PQ 的 $m$ 换召回—内存。

## 4. 分步例题

**量化误差分析**。取一个小库（$d=2$，便于手算），PQ 每个维度配一本码本：

| 段 | 码本 |
| --- | --- |
| 第 1 维 | $\lbrace-1.0,\ 0.0,\ 1.0\rbrace$ |
| 第 2 维 | $\lbrace-2.0,\ -1.0,\ 0.0\rbrace$ |

库中四个向量 $A=[0.8,-1.9]$、$B=[-0.9,-0.1]$、$C=[0.4,-1.6]$、$D=[1.2,-0.3]$，查询 $q=[1.0,-2.0]$。

1. **逐维选最近码字**：$A$ 的第 1 维 $0.8\to1.0$、第 2 维 $-1.9\to-2.0$，得 $\tilde A=[1.0,-2.0]$。
2. **算每段平方误差**：$A$ 为 $(0.8-1.0)^2+( -1.9+2.0)^2=0.04+0.01=0.05$；同理 $B=0.01+0.01=0.02$、$C=0.16+0.16=0.32$、$D=0.04+0.09=0.13$。平均误差 $=0.13$——**这就是 PQ 的"谎言账单"**。
3. **真实平方距离**：$A=0.05$、$B=7.22$、$C=0.52$、$D=2.93$。
4. **量化后平方距离**（用 $\tilde A=[1,-2]$ 等）：$A=0$、$B=8$、$C=1$、$D=4$。
5. **对比排序**：真实 $A<C<D<B$，量化后仍是 $A<C<D<B$——**误差让所有距离整体变大，却保住了近邻次序**。这正是 ANN 敢用量化距离做粗筛的底气；但当两个候选挨得极近时，误差也可能把它们的顺序翻过来，那才是漏报的来源。

### 实验 2（python）：亲手复核上文的量化误差

```python title="PQ 量化误差 + 真实距离 vs 量化距离"
vectors = {"A": [0.8, -1.9], "B": [-0.9, -0.1], "C": [0.4, -1.6], "D": [1.2, -0.3]}
codebooks = [                     # 每维一本码本（PQ 逐段各配一本）
    [-1.0, 0.0, 1.0],             # 第 1 维的码字
    [-2.0, -1.0, 0.0],            # 第 2 维的码字
]
query = [1.0, -2.0]

def d2(u, w):                     # 平方欧氏距离：逐维作差、平方、求和
    return sum((u[i] - w[i]) ** 2 for i in range(len(u)))

def quantize(vec):                # 返回量化后的坐标与平方误差
    out, err = [], 0.0
    for d, cb in enumerate(codebooks):        # enumerate：同时拿到维下标 d 与对应码本
        best = min(cb, key=lambda c: abs(c - vec[d]))   # 取离该维最近的码字
        out.append(best)
        err += (best - vec[d]) ** 2
    return out, err

for name in vectors:
    code, err = quantize(vectors[name])
    real = d2(query, vectors[name])            # 真实距离
    approx = d2(query, code)                   # 量化后的近似距离
    print(name, "码字", code, "误差", round(err, 2),
          "真实", round(real, 2), "近似", round(approx, 2))
```

四行输出与例题逐格对应：$A$ 的误差只有 $0.02\!\sim\!0.05$，$C$ 却高达 $0.32$——**码本覆盖不到的空白区永远是误差重灾区**，这也是实战里码本要用真实数据（k-means）训练出来、而非拍脑袋定的原因。

### 实验 3（python）：IVF 粗筛的召回率与省下的访问量

```python title="两个粗聚类心 + 四个查询：数一数召回率"
pts = {"A": [0.8, -1.9], "B": [-0.9, -0.1], "C": [0.4, -1.6], "D": [1.2, -0.3]}
centroids = {"L": [-1.0, -1.0], "R": [1.0, -1.0]}    # 两个质心（教学用固定值）

def d2(u, w):
    return sum((u[i] - w[i]) ** 2 for i in range(len(u)))

lists = {"L": [], "R": []}                             # 倒排表：簇心名 → 成员
for name in pts:
    c = min(centroids, key=lambda k: d2(pts[name], centroids[k]))   # 归入最近的簇
    lists[c].append(name)
print("倒排表", lists)

queries = [[1.0, -2.0], [-1.0, 0.0], [0.6, -1.0], [-0.5, -1.5]]
hits, scanned = 0, 0
for q in queries:
    exact = min(pts, key=lambda n: d2(q, pts[n]))              # 暴力：全库比一遍
    probe = min(centroids, key=lambda k: d2(q, centroids[k]))  # 只探最近的 1 个桶
    ann = min(lists[probe], key=lambda n: d2(q, pts[n]))       # 桶内取最近
    scanned += len(lists[probe])                               # 统计实际访问了几个向量
    if ann == exact:
        hits += 1
    print("查询", q, "精确", exact, "IVF", ann)
print("召回", hits, "/", len(queries), " 访问", scanned, "次（暴力需", len(pts) * len(queries), "次）")
```

前三个查询全中，第四个 $[-0.5,-1.5]$ 的真近邻 $C$ 住在右边那条街，而查询自己落在左边——**只探一个桶就漏了**。访问量从 $16$ 次降到 $8$ 次，代价是 $75\%$ 的召回率。把 $n_{\text{probe}}$ 调到 $2$ 当然能补上这个漏，但这套玩具库里一共只有两个桶，全探就等于退回全库扫描——真实系统桶数成千上万，多探一两个桶既能救回漏报，又远不至于扫全库，那才是 $n_{\text{probe}}$ 这个旋钮真正值钱的地方。

## 6. 常见误区

:::warning[常见误区]

**误区一**："你以为 ANN 就一定不准。" 它是**可调的**近似：把 $n_{\text{probe}}$、图搜索深度调大，召回率能上 95% 甚至 99%，只是延迟跟着涨。生产系统常常在 98% 召回下仍快几十倍——这远比"精确但超时"有用。

**误区二**："你以为 PQ 只省内存、不影响精度。" PQ 的误差会**直接进入距离**：查询用 $\lVert q-\tilde x\rVert$ 代替 $\lVert q-x\rVert$。近邻序号不一定变，但两个挨得很近的候选可能被误差换了位。所以"PQ + 重排序"是标配：PQ 粗筛出一批候选，再用原始向量精确重排。

**误区三**："你以为 HNSW 是"精确图加了个捷径"。" HNSW 是**启发式构造**的近似图：连边规则、层次高度都是人为设的，既没有精确性保证，内存占用还比 IVF 高（每个点要存一批邻居指针）。它强在查询快、召回高，弱在构建慢、更新贵。

:::

## 7. 练习

**练习 1**（判题）：下面的近似距离只算了第一个维度，$B$ 的距离被算小了——修到通过：

```exercise
# @title: 练习：把量化距离算全
# @check: 0.0
# @check: 1.0
# @check: 8.0
# @hint: 查询与码字都是二维；平方距离要把每一维作差、平方，最后求和。现在少了第二个维度。
query = [1.0, -2.0]
codes = {                      # 每个向量 PQ 量化后的码字坐标
    "A": [1.0, -2.0],
    "C": [0.0, -2.0],
    "B": [-1.0, 0.0],
}
for name in ["A", "C", "B"]:
    c = codes[name]
    d2 = (c[0] - query[0]) ** 2        # ← 问题在这：漏了第 2 维的平方项
    print(round(d2, 1))
```

修好后依次输出 $0.0,\ 1.0,\ 8.0$：$B$ 的两个维度各差 2，平方和为 $4+4=8$。少算一维会让远处的向量"看起来很近"，粗筛直接把真近邻挤掉。

**练习 2**（概念）：为什么 IVF 的 $n_{\text{probe}}$ 调大以后召回率上升、但延迟也上升？

<details>
<summary>点开查看逐步解答</summary>

$n_{\text{probe}}$ 就是"允许走进几条街"。多探一个桶，就多一次"真近邻可能藏在那里"的机会，漏报率随之下降——这正是实验 1 那条指数衰减曲线。但每多一个桶，就要对桶里**全部**向量算一遍距离：延迟正比于被访问的向量总数。所以召回与延迟是同一条旋钮的两端，工程上通常先定一个延迟预算（如 5 ms），再在这个预算内把 $n_{\text{probe}}$ 顶到最大。

</details>

**练习 3**（概念）：为什么实战里几乎总是"IVF/PQ 粗筛 + 原始向量重排序"两步走？

<details>
<summary>点开查看逐步解答</summary>

因为两者擅长的事不同：IVF/PQ 用**近似**换来"把候选从十亿压到几百"，快是关键（这一步根本不需要精确）；重排序时只需要对这几百个候选拿**原始向量**算真实距离，贵但小。于是总成本被拆成"便宜的粗筛 + 昂贵的精排"，精确度回到几乎无损，速度却保留了数量级优势。"先粗后精、用可控的错换可控的快"，和上一课分桶法一脉相承。

</details>

## 8. 选读：为什么高维让"格子"格外难

<details>
<summary>选读 · 维度灾难与 HNSW 的分层跳表</summary>

**一、格子的失效。** 分桶法在二维很直观，到了几百维会失灵：要让每个维度只切 $s$ 格，总格子数是 $s^d$。$d=128$、$s=2$ 时就已经是 $2^{128}$ 个格子，而库里只有 $10^9$ 个点——**绝大多数格子空着，少数格子挤着**。想让每格都有点，格子数必须与 $N$ 同级，于是"分桶"退化成"每个点一桶"，一点没省。这就是高维检索必须靠**量化（把连续空间压成有限码字）与图（用局部邻居代替全局划分）** 的原因。

**二、HNSW 的分层跳表。** HNSW 借鉴了跳表（skip list）：底层是稠密图（每个点连约 $M$ 个邻居），每往上一层，点以固定概率被"抽签"保留，最顶层只剩极少数点。查询从顶层的一个入口出发，贪心地走向更近的邻居；在当前层再也走不动时，下降到下一层继续。直觉上：**顶层负责大跨度跳跃，底层负责精细靠拢**，平均只走 $O(\log N)$ 步。

**三、可导航小世界。** HNSW 的连边不是随机的，而是刻意造出"长边 + 短边"混合的结构，让任意两点之间都能靠少数几步连上——这就是"可导航小世界"（NSW）的由来。它的代价是构建：每插入一个点都要搜一遍它的邻居并双向连边，建库比 IVF 慢得多，且删除点会破坏图的连通性，通常只能"标记删除"。

</details>
