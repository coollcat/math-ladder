# RAG：先查资料再开口

## 1. 从一个场景开始

问大模型"我们公司年假几天"，它张口就答"十五天"——编的。模型的参数冻结在训练那一刻，你公司的考勤制度它压根没读过；硬答，就只能编。**RAG**（Retrieval-Augmented Generation，检索增强生成）的解法朴素得像考试策略：**开卷考试**——先把问题拿去资料库里查出最相关的几段原文，把原文塞进题目里，再让模型"根据以下资料回答"。答不答得对先不论，至少它终于**看得到**资料了。

## 2. 直觉解释

RAG 是两门老课的串联：

- **检索**：把资料库切成小段，每段用嵌入模型压成向量（第 10 课的坐标卡）；问题同样压成向量，用第 30 课的最近邻检索找出语义最近的几段——"海边的狗"能搜到照片，靠的就是这套几何；
- **生成**：把问题与查到的段落**拼进提示词**，交给 Transformer 生成（第 47 章）——语言模型本来就擅长"照着上下文说话"，现在上下文里有真材实料。

一句话：**把"模型记不记得住"换成"模型找不找得到"**。知识更新了？改资料库就行，模型一个参数都不用动——检索是活的账本，参数是死的记忆。

## 3. 正式定义

一条 RAG 流水线的五步：

| 步骤 | 做什么 | 关键参数 |
| --- | --- | --- |
| 1. 分块 | 文档切成小段（chunk） | 块太大→检索不准；太小→上下文破碎 |
| 2. 嵌入 | 每块压成向量入库 | 嵌入模型决定语义分辨率 |
| 3. 检索 | 问题嵌入 → 最近邻 top-$k$ | $k$ 常取 3~10 |
| 4. 拼接 | 问题 + 查得段落 → 提示词 | 段落要带出处，便于核查 |
| 5. 生成 | 模型照上下文作答 | 提示词要求"只依据资料" |

用条件概率说清"增强"二字：普通生成答 $p(a \mid q)$——只靠问题 $q$ 与参数记忆；RAG 答 $p(a \mid q, d_1, \dots, d_k)$——**答案以检索到的资料为条件**。条件变了，分布就变：模型的任务从"回忆"降级成"阅读理解"，幻觉的地基被抽掉一大块。

## 4. 分步例题

玩具资料库三段，嵌入压成二维（真实系统几百上千维，几何不变）：

- 文档 A（"年假 15 天"）：$[2, 3]$；文档 B（"报销流程"）：$[0, 5]$；文档 C（"会议室预定"）：$[4, 1]$。

问题"年假有几天"嵌成 $q = [2, 2]$，用平方距离检索：

1. 到 A：$(2-2)^2 + (2-3)^2 = 1$；
2. 到 B：$(2-0)^2 + (2-5)^2 = 13$；
3. 到 C：$(2-4)^2 + (2-1)^2 = 5$；
4. 最小的是 A（距离 1）→ 把"年假 15 天"那段塞进提示词，模型照着答"15 天"。

三笔减法、两笔平方，检索就完成了判决——语义检索的内核就是这么便宜。

## 5. 动手实验

### 实验（python）：一座词袋玩具 RAG

```python title="玩具 RAG：嵌入、检索、拼提示"
import math

def embed(text):                                # 词袋嵌入：数每个关键词出现次数
    vocab = ["年假", "报销", "会议室", "天", "流程"]
    v = []
    for w in vocab:
        v.append(text.count(w))                 # count：子串出现次数
    return v

corpus = {                                      # 迷你资料库：三段原文
    "文档A": "员工年假十五天，未休天数不跨年。",
    "文档B": "报销流程：先填单，后附发票，五日审批。",
    "文档C": "会议室预定需提前一天，超时自动释放。",
}

lib = {}                                        # 向量库：每段一列坐标
for name, text in corpus.items():
    lib[name] = embed(text)
    print(name, "嵌入 =", lib[name])

query = "年假有几天"                            # 用户问题
qv = embed(query)

def d2(u, v):                                   # 平方距离：不开方也能比大小
    s = 0.0
    for i in range(len(u)):
        s = s + (u[i] - v[i]) ** 2
    return s

scores = []
for name, vec in lib.items():
    scores.append((d2(qv, vec), name))
scores.sort()                                   # 距离小在前
print("检索排序 =", [(name, d) for d, name in scores])

top = scores[0][1]                              # 取第一名
prompt = f"资料【{top}】：{corpus[top]}\n问题：{query}\n请只依据资料回答。"   # 拼提示词
print("---- 拼出的提示词 ----")
print(prompt)
```

怎么玩：排序第一的必是文档 A——"年假""天"两个词都命中（词袋是嵌入的最简影子；真实嵌入用第 55 课之前讲过的语义向量，能跨过"假期"与"年假"的同义沟）。把 `query` 改成"报销怎么走"再跑：冠军换成文档 B——检索雷达自动转向。注意最后一步：模型要答对，前提是**这一步拼对了**；下一课的误区卡会告诉你，检索错时生成只会错得更自信。

```quiz
RAG 相比"把资料微调进模型"，最大的优势是？
- 生成速度更快
- 资料更新只需改库，模型参数不动，且答案可溯源到原文 [*]
- 不需要任何嵌入模型
? 检索是外挂的活账本：知识常改、要求出处、多套权限隔离的场景，RAG 都比"把知识炼进参数"省事得多。微调更擅长改风格与技能，不擅长当实时百科。
```

::::warning[常见误区]

**误区一**："你以为有了 RAG 就不会幻觉。" 检索是给模型的上下文，不是给模型的手铐——提示词不严，它照样绕开资料自由发挥；更危险的是**检索错了**：塞进一段似是而非的资料，模型会把它复述得头头是道。RAG 把幻觉从"无中生有"降级成"材料解读偏差"，但没清零。

**误区二**："你以为分块越小越准。" 块太小，一句话被拦腰斩断，嵌出来的向量丢了上下文语义，检索命中率反而崩；块太大，一段里混进多个话题，向量变成"平均值"，谁都不像。分块是 RAG 工程里最见手感的旋钮。

**误区三**："你以为检索第一名永远该信。" top-1 也可能是不相关的高分项——工程上常用 top-$k$ 召回后再精排（rerank）、或给检索分设门槛："都不够像就老实说不知道"，比硬编强得多。

::::

## 6. 练习

```exercise
# @title: 练习：给问题找出最近的资料段
# @check: 文档1
# @check: 42
# @hint: 平方距离要"先作差、再平方、后求和"——漏了平方，正负误差会互相抵消，最近邻就指错人。
docs = {                                        # 迷你资料库（二维嵌入）
    "文档1": [2, 0],
    "文档2": [3, 2],
    "文档3": [0, 4],
}
facts = {"文档1": "13", "文档2": "42", "文档3": "7"}   # 各段里写的答案

query = [2, 2]                                  # 问题嵌入

best = None
best_d = None
for name in docs:
    p = docs[name]
    d = (p[0] - query[0]) + (p[1] - query[1])   # ← 问题在这：差值直接相加，忘了平方
    if best_d is None or d < best_d:
        best_d = d
        best = name

print(best)
print(facts[best])
```

<details>
<summary>点开查看逐步解答</summary>

补上平方：

```python
    d = (p[0] - query[0]) ** 2 + (p[1] - query[1]) ** 2
```

三段距离：文档 1 是 $1$，文档 2 是 $8$，文档 3 是 $2$ → 最近的是**文档 1**，取出的答案是 `42`。初始代码不平方：到文档 2 的"距离"是 $(1-3) + (3-1) = 0$——一正一负两个误差**互相抵消**，把最不相干的段落顶上了冠军。这正是不开方就不能比大小的反面教材：距离是"误差面积"，不是"误差代数和"。
</details>

**练习 2**：库里 100 万段资料，逐段算距离太慢。回忆第 30 课：近邻检索的加速思路叫什么？一句话说明它为什么能快。

<details>
<summary>点开查看逐步解答</summary>

近似最近邻（ANN）：先建分区/图索引（粗格、层次图等），查询时只扫描"可能藏有近邻"的一小撮区域，牺牲一点点准确率换几个数量级的加速。第 30 课的粗格检索就是最小样本：100 万段只需先比几个桶、再桶内细比——RAG 的毫秒级响应全靠这类索引撑腰。
</details>

## 7. 选读：让检索更像样的三板斧

工业级 RAG 在"五步"之外常见三件增强：**混合检索**——关键词检索（BM25）与向量检索各出一榜、融合排序，专治嵌入漏掉的精确匹配（型号名、错误码）；**重排**——先粗召回 top-50，再用更重的交叉编码器逐对打分精选 top-5，两段式"先广后精"；**查询改写**——用户问得含糊时先让模型把问题改写/拆解成利于检索的样子。三件套的共同哲学：检索这一步的质量上限，就是整个 RAG 的质量上限——生成端再强，也强不过喂进来的材料。
