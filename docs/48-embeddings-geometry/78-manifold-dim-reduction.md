# 流形假设与降维观察

## 1. 从一个场景开始

把地球摊成一张平面地图，永远要付一种代价：要么把极地扯得巨大（墨卡托投影），要么把大陆剪开裂缝。原因无它——**球面根本不是平面**，再聪明的摊法也只能保住一部分性质。

嵌入空间里的数据面临同款困境。第 40 章说高维宇宙空旷又寒冷，可真实数据并不均匀撒满整个空间：同一只杯子旋转拍摄的几百张照片，在编码空间里沿着一条一维曲线排队；人脸随表情与光照的变化，撑开的维度屈指可数。**数据像住在一层弯曲的薄膜上，而不是充满整个房间。**这一课给这个信念定名、验货，并检查两件最常用的"摊平工具"各自保住了什么。

## 2. 直觉解释

把高维数据想象成飘在房间里的一张纸（或一张被揉过又半展开的纸）。这就是**流形假设**：样本数虽多，但生成它们的自由度很少——旋转角、光照角、身份类别……每个自由度给薄膜添一点长度或褶皱。

为什么要关心它？因为观测工具只有三维眼睛。想知道一千维的云团长什么样，就得把它压回二维白纸上。压法有两大家族：

- **PCA 保方差**：找数据抖动最猛的方向拉直铺开。数学快、稳、可解释，但它眼里只有"总方差"，不认识"邻居"；
- **邻域法保邻居**（t-SNE、UMAP 一类）：目标是让原本挨着的点压缩后仍挨着、疏远的仍疏远——牺牲全局距离与方向，换取局部社群的诚实呈现。

两者的分歧在弯曲薄膜上会爆发：沿薄膜量距离要顺着曲面爬行，直线抄近路会横穿隔壁房间。PCA 恰恰是那个抄近路的。

## 3. 正式定义

**流形假设**：高维样本近似分布于低维流形上

$$\mathcal{M} \subset \mathbb{R}^{D}, \quad \text{内在维数 } d \ll D$$

| 符号 | 名字 | 含义 |
| --- | --- | --- |
| $D$ | 环境维数 | 编码向量的标称维数，如 512 |
| $d$ | 内在维数 | 薄膜本身有几个自由度，如 6 |
| $\pi_\theta(z)$ | 投影/映射 | 把样本 $z$ 压到低维坐标的降维方法 |
| $N_i$ | 近邻集合 | 原空间里离 $z_i$ 最近的若干个样本 |

两类方法的目标函数气质完全不同：

$$\text{PCA：} \max_{\theta} \; \operatorname{Var}\bigl(\pi_\theta(Z)\bigr) \qquad \text{邻域法：} \min \sum_i \sum_{j \in N_i} \bigl\lVert \pi(z_i) - \pi(z_j) \rVert^2 \text{ 的加权变形}$$

一句话读表：PCA 收的是**能量税**（抖得多者优先占用低维坐标），邻域法收的是**关系税**（谁跟谁熟必须登记在册）。当薄膜平坦时两者一致；一旦弯曲，账就分家了。

## 4. 分步例题

构造教科书级的最小流形：同心双环。内环半径 $1$、外环半径 $3$，共圆心；样本分布在两个环上（各带微小噪声）。这是一个内在维数为 $1$ 的流形——知道角度 $\theta$ 和环编号就能复原一切，却弯成了圈。

1. **PCA 的账本**：两环同心的点集是完美旋转对称的，$\operatorname{Var}(x) = \operatorname{Var}(y)$，主成分方向悬而未决（哪个方向都一样"最优"）；
2. **投下去看**：随便选个方向（比如水平轴），投影值就是横坐标 $r\cos\theta$。外环样本投出 $[-3, 3]$ 的连续带，内环投出 $[-1, 1]$——**整段落在前者的中间地带里**；
3. **灾难现场**：横坐标同为 $0.8$ 处，既有外环的样本也有内环的样本；"这条样本来自哪个环"的信息全部蒸发，剩下一堆无法区分的点；
4. **顺藤摸瓜**：换成沿薄膜走——先认出邻居连成环，再按弧长把每圈展开成一维线段：内环占一段、外环占另一段，两个"环"变成两条整齐分离的轨道。半径信息原封不动地回来了。

这就是本课的钥匙与陷阱：同样的二维数据、同样的目标（降到一维），PCA 与邻域法的答卷天差地别。

### 实验 2（python）：PCA 压扁 vs 邻域展开的正面对照

左图是原始双环；中图是 PCA 式的一维条带（内环样本全混进外环带子里）；右图先沿薄膜认领邻居、按圆周展开（教学用的是理想化的上帝视角——真实 t-SNE/UMAP 不知道极坐标，但致力于逼近这种效果）：

```python title="双环对照实验：同一批数据，两种降维两种命运"
import math                      # 数学库：用 cos 与 sin 计算圆周坐标
import matplotlib.pyplot as plt
import random                    # 随机库：固定种子保证每次结果一致

random.seed(5)                   # seed：锁定随机序列起点

def ring(r):
    pts = []
    for k in range(14):
        ang = 6.28318 * k / 14                  # 把一圈等分成 14 个方位
        rr = r + (random.random() - 0.5) * 0.08 # 实际半径带一点噪声（薄膜的厚薄）
        pts.append([rr * math.cos(ang), rr * math.sin(ang)])
    return pts

inner = ring(1.0)
outer = ring(3.0)

# --- 方法一：PCA 式投影。数据旋转对称，主方向任意，取水平轴为代表
pca_inner = [p[0] for p in inner]               # 列表推导：抽取横坐标作一维值
pca_outer = [p[0] for p in outer]

# --- 方法二：沿薄膜展开（上帝视角：直接读出每点的真实参数）
unw_inner = [[k / 14, 1.0] for k in range(14)]  # 低维坐标取（方位, 环层）
unw_outer = [[k / 14 + 0.02, 3.0] for k in range(14)]

fig, axes = plt.subplots(1, 3, figsize=(11, 3))   # subplots：一行三张子图；figsize 指定画布尺寸
xs_in = [p[0] for p in inner]
ys_in = [p[1] for p in inner]
xs_out = [p[0] for p in outer]
ys_out = [p[1] for p in outer]

axes[0].scatter(xs_in, ys_in, s=24, label="inner")
axes[0].scatter(xs_out, ys_out, s=24, label="outer")
axes[0].set_title("raw two rings")    # set_title：给子图起标题
axes[0].legend()

axes[1].scatter(pca_inner, [0]*14, s=24, label="inner")     # 一维结果画在同一条横线上
axes[1].scatter(pca_outer, [0.06]*14, s=24, label="outer")  # 轻微抬高错开，方便看清重叠带
axes[1].set_title("PCA to 1D: rings overlap")

xi = [u[0] for u in unw_inner]
yi = [u[1] for u in unw_inner]
xo = [u[0] for u in unw_outer]
yo = [u[1] for u in unw_outer]
axes[2].scatter(xi, yi, s=24, label="inner")
axes[2].scatter(xo, yo, s=24, label="outer")
axes[2].set_title("unfold along manifold"); axes[2].legend()
```

中间那张图直观呈现第 4 步例题的预言：内环的一维取值密密地嵌在外环的取值带正中央，大部分位置同时属于两环；右边那张图则干净利落分出两层。同样一批数据，降维方式的哲学不同，能回答的问题就不同。

### 快问快答

```quiz
拿到一张漂亮的二维嵌入图，聚类肉眼分明——第一步应该警惕什么？
- 图太漂亮说明算法一定错了
- 二维图保住的往往只是局部邻域排序，跨簇距离与簇的大小可能严重失真 [*]
- 应该直接按图上的视觉边界给数据打标签入库
? 邻域法的代价函数奖励"近处贴紧"，从不担保远处的关系与大尺度形状。画图用于提出假设，验证还得回到原始空间算指标。
```

:::warning[常见误区]

**误区一**："你以为二维图上的洞和孤岛就是数据的结构。" 低维呈现受制于权衡参数与随机初始化，不同种子能画出相当不同的拓扑形状。**观察手段会重塑所见**——图是望远镜的成像，不是天空本身。

**误区二**："你以为流形假设包治百病。" 离散类别数据、稀疏矩阵、强尖刺分布未必住在光滑薄膜上。硬套降维常常制造幻觉结构。先用上一章的密度体检确认"薄膜"存在，再用工具。

**误区三**："你以为 PCA 已经是老古董。" 保方差恰恰是压缩、去噪、检索预处理的正牌武器（第 21 章）；它输掉的只是"展示弯曲结构"这场比赛。顺手、快速、线性、有解析解——工程第一件该试的工具仍然是它。

:::

## 6. 练习

**练习 1**：展开圆环时绕不开的尺子问题——从方位 $350^\circ$ 走到 $356^\circ$ 是走了 $6$ 度，可从 $356^\circ$ 继续走到 $2^\circ$ 呢？代码现在给出的答案荒唐至极，修好它：

```exercise
# @title: 练习：接回被 360 度线剪开的圆周
# @check: 6.0
# @check: 6.0
# @check: 7.0
# @check: 5.0
# @hint: 先用对 360 取余把步长折回 0 到 359，若超过 180 就减去 360 表示"往反方向也算短"。abs 放在最后。
angles = [350.0, 356.0, 2.0, 9.0, 14.0]

def step(a, b):
    return abs(b - a)           # ← 问题在这：没处理越过 360 回卷的情形

for k in range(len(angles) - 1):
    print(round(step(angles[k], angles[k+1]), 1))
```

改对后四行输出依次是 $6, 6, 7, 5$——那格 $354$ 变回了诚实的 $6$。任何要把环形坐标摊直的算法（去余弦空间的周期方向、时钟数据、螺旋纹理）都得先过这道坎。

**练习 2**：有人断言："既然 PCA 会把双环压成一锅粥，说明 PCA 在流形上完全没用。"请用"保什么"的语言反驳或修正这句话。

<details>
<summary>点开查看逐步解答</summary>

该断言混淆了两份合同。PCA 的合同是**最大化保留方差**：双环数据方差最大的方向确实是水平的 $r\cos\theta$ 型分量，而"环半径"在方差预算里几乎为零，自然第一批被裁掉——这不是执行失误，而是合同的正确履行，并且换来了计算便宜、无超参、可逆重构。邻域法的合同是**保局部近邻关系**：它识别得出两个环是彼此不通的细管，代价是把全局距离搅乱。结论应修正为："PCA 不适合以可视化为主的弯曲流形探查，但在方差主导的任务（压缩、去噪、监督前预处理）仍是首选起手式。"选工具先签清楚合同。
</details>

## 7. 选读：t-SNE 与 UMAP 各自保留了什么

<details>
<summary>选读 · 只讲直觉，不进推导</summary>

两者共享一个配方骨架：**在原空间定义"亲近程度"，在低维空间再造一份"亲近程度"，然后让后者的分布尽量像前者。**

- t-SNE 把亲近度做成概率分布（高斯软化的近邻投票 → 低维换学生 t 分布的长尾巴），再最小化两个分布的 KL 散度。长尾专门负责中远距离：不纠结具体多远，只要"足够远就行"。副作用：簇间距离、簇大小、簇密度全都不可直接比较，常造成"簇越散越亲密"的错觉。
- UMAP 从图形视角出发：先把数据建成一张模糊的加权邻居图（纯数学地把邻居关系织成网），再优化低维图的布局使加权边尽量保真。相对更敢于伸展整体形状，跑得也快，但仍不承诺度量保真。

使用共识三条： perplexity / n_neighbors 相当于"视野旋钮"，扫多档比信单图可靠；跨运行重复几次防随机假象；关键结论回到原始空间检验。记住本课主旨——它们是把钥匙：为你打开新角度的门，但门外风景是否真实，要靠你回去走一趟才作数。
</details>
