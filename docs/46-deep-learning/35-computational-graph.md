# 计算图与自动微分

## 1. 从一个场景开始

会计核账有两种流派。**手工派**把每一笔账倒背如流，直接心算出最终错差如何分摊到每个账户；**系统派**则维护一张"账目流水图"——谁来自谁、按什么规则合并——想查任何一笔的来龙去脉，就沿图反着走一遍：规则统一、永不遗漏。

训练神经网络的梯度计算也有这两派。上一课（反向传播）是手推派的艺术品；本课介绍工程界的系统派——计算图 + 自动微分。你每天用的每一个深度学习框架，内核都是这套机制。

## 2. 直觉解释

**核心直觉：程序就是一张有向图，求导只是给每条边配一个局部系数。**

把任何一段计算拆成原子操作，画成节点：

```
x ──┐
    ├─→[ × ]──u──→[ + ]──v──→[ 平方 ]──L
w ──┘                ↑
b ───────────────────┘
```

每个节点只干一件小事（乘/加），并自带一本"局部导数小册子"：

| 节点 | 正向计算 | 局部导数 |
| --- | --- | --- |
| `×` | $u=x\cdot w$ | $\partial u/\partial x=w$，$\partial u/\partial w=x$ |
| `+` | $v=u+b$ | 都是 1（加法不改标度） |
| `平方` | $L=v^{2}$ | $\partial L/\partial v=2v$ |

**自动微分的全部秘密一句话：链式法则不是人脑独门绝技，它可以按图机械执行。** 从输出端出发，沿途把各条边的局部导数相乘、分支处累加汇聚——这就是反向模式自动微分。上一课的手工推导，就是把这张表填出来的过程；框架不过是替你填了。

## 3. 正式定义

计算图是有向无环图（DAG）：叶节点是输入/参数，内部节点是一次运算，边表示数据流向。

- **前向传播** = 按拓扑顺序算出每个节点的值；
- **反向模式自动微分** = 逆序为每个节点维护伴随值 $\bar v=\dfrac{\partial L}{\partial v}$，从根部的 1 出发，沿入边回灌：

$$\bar{x} \mathrel{+}= \bar{u}\cdot \frac{\partial u}{\partial x} .$$

注意那个 **"+="**：当一个参数同时出现在多条边上时（比如权重在两层被复用），每条支流的贡献都要累加进来——这是多元链式法则（第 13 章）的机器化形态，也是实践里梯度 bug 的头号产地。

两种模式的分工：反向模式一次回扫拿到损失对**所有**参数的偏导，适合"输入多、输出少"的训练；前向模式（对偶数实现）一次扫描得到对一个输入的方向导数，适合"输入少、输出多"。框架两者都内置。

## 4. 分步例题

用对偶数亲手跑一遍前向模式：目标 $f(x)=x^{2}\cdot(1+x)$ 在 $x=2$ 处求值并求导。

1. 种子注入：$x=2$ 写作 $(2,\,1)$ —— 第二位是该点的方向导数；
2. 常数不带方向：$1=(1,\,0)$；
3. 加法逐位相加：$1+x=(3,\,1)$；
4. 乘法"值乘值，交叉导数相加"：$x^{2}=(2,1)\times(2,1)=(4,\,2+2)=(4,\,4)$；
5. 再来一次乘法：
$$f=(4,4)\times(3,1)=\bigl(12,\;4\times1+4\times3\bigr)=(12,\,16).$$

所以 $f(2)=12$，$f'(2)=16$。手算验证：展开 $f=x^2+x^3$，$f'=2x+3x^2$，代入得 $4+12=16$ ✓。图上没有任何一步需要"灵感"，答案却和手推完全一致。

## 5. 动手实验

亲眼看一遍反向模式的最小内核：$L=(x w+b)^{2}$ 在 $x=3,w=2,b=1$ 处的三枚伴随值：

```python title="迷你反向模式"
x, w, b = 3.0, 2.0, 1.0      # 叶节点的取值

u = x * w                    # 节点 u = x·w（正向前进第一步）
v = u + b                    # 节点 v = u + b
L = v * v                    # 根节点 L = v²

Lv = 2 * v                   # 根伴随为 1，经平方边传给 v：∂L/∂v = 2v
Lu = Lv                      # 加法边不改变标度：uv 两支同额下传
Lb = Lu                      # 另一支同理（+= 累加的第一例）
Lx = Lu * w                  # 乘法边 ∂u/∂x = w
Lw = Lu * x                  # 乘法边 ∂u/∂w = x

print(L)                                  # (6+1)² = 49
print(round(Lx, 2), round(Lw, 2), round(Lb, 2))
```

输出 `49.0` 与 `28.0 84.0 14.0`。对照解析式验证：$\partial_x L=2vw=28$、$\partial_w=2vx=84$、$\partial_b=2v=14$ ✓。

看清楚那段代码的结构了吗？框架的"魔法"拆开就是这几行赋值的循环版：先按拓扑序正向存值，再逆序做同样的几行乘加——仅此而已。

## 6. 常见误区

:::warning[常见误区]

- **"自动微分 = 数值近似"** —— 不是差商估分。它给出与手推完全一致的精确导数（浮点范围内），数值近似的截断误差一概不存在。
- **"同一参数用到两次就乘两次"** —— 是**累加**。漏掉任何一条支路，梯度系统性偏小、网络照样往下走——最阴险的一类静默错误。
- **"有自动微分就不用懂链式法则"** —— 图是你搭的：节点切得太粗（整层黑盒化）、或在某节点原地修改变量（in-place 操作），反向流就会断或算错。

:::

## 7. 练习

下面的函数前向正确，但两条支流的伴随各漏了一份——初始代码能跑、结果明显不对。修到三条检查全部通过：

```exercise
# @title: 找出伴随意外的漏加
# @check: 40
# @check: 16
# @check: 4
# @hint: ∂(x²w)/∂x = 2x·w 走上支路、∂(xw)/∂x = w 走下支路，两份都要累加；对 w 同理是 x² 与 x
def grads_at_4_2():
    x = 4.0
    w = 2.0
    t1 = x * x * w             # 上支路：x²·w
    t2 = x * w                 # 下支路：x·w
    L = t1 + t2                # 根节点求和

    gx = 2 * x * w             # ← 只回了上支路，下支路那份 w 还欠着
    gw = x                     # ← 只回了下支路，上支路那份 x² 还欠着
    return L, gx, gw

L, gx, gw = grads_at_4_2()
print(int(L))                  # 先确认前向没抄错数
print(int(gx))                 # 解析值应为 2x·w + w = 16 + 4
print(int(gw))                 # 解析值应为 x² + x = 16 + 4
```

初始输出三行是 `40`、`16`、`4`——前向分毫无误，两个梯度各缺一条支流。修正：

```python
gx = 2 * x * w            # 经 t1 的贡献 ∂t1/∂x = 2x·w
gx = gx + w               # 经 t2 的贡献 ∂t2/∂x = w        ← += 在报警
gw = x * x                # 经 t1 的贡献 ∂t1/∂w = x²
gw = gw + x               # 经 t2 的贡献 ∂t2/∂w = x        ← += 在报警
```

三条检查变为 `40`、`20`、`20`。真实框架里你不会手写这些求和——但每次你改出"梯度静默偏小"的 bug，本质都是这里某一行 `+=` 被漏掉。

<details>
<summary>顺手验一遍解析解</summary>

$L(x,w)=x^{2}w+xw$，在 $(4,2)$ 处：

$$\frac{\partial L}{\partial x}=2xw+w=16+4=20,\qquad \frac{\partial L}{\partial w}=x^{2}+x=16+4=20 .$$

两个梯度相等纯属这组数字的巧合（$2xw=w$ 与 $x^2=x$ 同时成立要求 $w=x/2=x\Rightarrow x=0$——并不满足）；真正的公共因子是两个修正后都含"两项"，这就是分支累加的直接痕迹。
</details>

## 8. 选读证明：为什么反向模式回扫一次就够了

<details>
<summary>选读：复杂度会计</summary>

设图含 $N$ 个节点、$E$ 条边、$P$ 个参数。反向模式取齐全部 $P$ 枚偏导的代价：

- 前向一遍：每节点常数次运算，$O(N+E)$；
- 反向一遍：每条边读一次局部导数并乘加入对应伴随，$O(E)$。

合计两次线性扫描。朴素替代方案"逐个参数扰动估计导数"要 $O(P)$ 次全图前向。神经网络动辄百万参数——百万次全图扫描与两次线性扫描之间的鸿沟，就是深度学习工程可行性的全部秘密。

顺带解释为什么回扫必须严格逆拓扑序：某节点伴随被使用的前提是其下游伴随已全部就绪，否则任一支路晚到都得重算子树，代价瞬间劣化（这种"记忆化换指数"的把戏，第 08 章斐波那契处已经预演过一次）。
</details>
