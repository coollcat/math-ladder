# 困惑度与信道容量：语言模型和通信的共同标尺

## 1. 从一个场景开始

大模型评测榜上有两个常客：一边是语言模型的**困惑度**（perplexity），声称度量"模型面对下一个词有多迷茫"；另一边是本章反复露面的**信道容量**，量的是"一条水路最多运多少真货"。乍看风马牛不相及——一个管 AI 的脑子，一个管无线电的波——但它们其实是同一把标尺的两面：都从熵出发，都以比特计价。

这一课是本章的收官篇（也适合作为选学）：先给困惑度验明正身——它的出生证明上写的正是 $2^{H}$；再带它去信道的码头，与香农容量碰头。你将看到，语言的迷茫和链路的风浪，最终记在同一本账上。

## 2. 直觉解释

困惑度回答一个问题：**模型每走一步，实际上在几个选项里抓阄？**

- 完美的预言家（下一步只有一个确定走向）：抓阄面数为 1，毫无悬念；
- 公平硬币的世界：面数 2；公平的六面骰子：面数 6；
- 一团浆糊的均匀大词表：五万个字随便蹦，面数五万。

所以困惑度天然是"等效骰子面数"：数字是 20，意味着模型心里的犹豫相当于挥一只 20 面骰。注意这是一把**指数尺上的量**：交叉熵每降 1 比特，面数减半；降 2 比特，只剩四分之一——排行榜上"从 40 优化到 20"和"从 20 到 10"的含金量相同，都是省下 1 比特。

## 3. 正式定义

设语言模型的预测分布为 $q$，测试数据的真实频率为 $p$，先在数据上取平均算出交叉熵 $H(p,q)$（单位比特/词），然后：

$$\text{PPL}=2^{H(p,q)}$$

| 符号 | 名字 | 含义 |
| --- | --- | --- |
| $H(p,q)$ | 测试集交叉熵 | 模型给现实记账的日均账单 |
| PPL | 困惑度 | $2^{H}$：账单折算成"等效抓阄面数" |
| $\text{PPL}=2^{H(p)}$ | 理论下限 | 连真实分布都背下来的预测家的成绩 |
| 均匀词表特例 | 速算口诀 | $q$ 在 $n$ 个词上均匀时 $H=\log_2 n$、PPL 恰等于 $n$ |

码头另一侧的老朋友同时领回正式户口：信道噪声课的 $C=1-h(e)$ 只是二元对称信道的巧合版，通用身份是互信息对输入分布取最大值——互信息课的选读已经铺好了台阶。至此两条定理拼成完整回合：**信源编码定理说压到熵为止不丢真信息，信道编码定理说到容量为止传输不出真错误**。一头管文件的最小体积，一头管水路的最高运力。

## 4. 分步例题

**例 1（速算热身）**：某玩具模型对四个字一视同仁（各 $\frac14$）。交叉熵恰为 $\log_2 4=2$ 比特，困惑度 $2^2=4$——模型嘴里的"四个候选"与世界的四个真选项严丝合缝。

**例 2（读懂排行榜）**：甲作诗机困惑度 20，乙作诗机 5。每生成一步，甲在等效 20 个候选里翻来覆去，乙只面对 5 个；差距折成比特是 $\log_2 20-\log_2 5=2$ 比特/步——乙替甲方每次省出两比特犹豫金。另注意 $\frac{20}{5}=4$ 是倍数的错觉，真正的进步幅度要用比特差来量。

**例 3（码头碰头）**：一条蓝牙式链路翻转概率 $e=0.1$，容量 $C=1-h(0.1)\approx0.531$ 比特/符号。想把困惑度 4（每词恰 2 比特）的密文送过去，每词至少要占用 $2\div0.531\approx3.77$ 个发送符号——工程表格里的"码率"一栏，装的永远是这道除法。发射端越迷茫（PPL 大）字节越多，链路越颠簸（$e$ 大）每个符号越亏，两头的账一起涨。

### 实验 2（python）：同一个四字世界，三种人生

```python title="三种模型对账"
import math   # 数学函数库

world = [0.25, 0.25, 0.25, 0.25]          # 诗的真实频率：四个字轮流做庄

def cross_entropy(p, q):
    total = 0
    for i in range(len(p)):
        if p[i] > 0 and q[i] > 0:
            total = total - p[i] * math.log2(q[i])
    return total

def perplexity(p, q):
    return 2 ** cross_entropy(p, q)       # **：幂运算符，2 ** 3 就是 8

honest = [0.25, 0.25, 0.25, 0.25]         # 诚实模型：背下了真实气候
dumb = [0.125, 0.125, 0.125, 0.125]       # 糊涂模型：坚信有八个字（把窗外标语也算上了）
cocky = [0.7, 0.1, 0.1, 0.1]              # 抖机灵模型：七成身家押在第一个字上

for name, q in [("糊涂模型", dumb), ("诚实模型", honest), ("抖机灵模型", cocky)]:
    ce = cross_entropy(world, q)
    print(f"{name}: 交叉熵 {round(ce, 2)} 比特 -> 困惑度 {round(perplexity(world, q), 2)}")
```

三条成绩单演出一幕反转剧：抖机灵模型的 PPL 约 6.15，确实好过彻底瞎猜的 8——毕竟重注偶尔蒙对；却稳稳输给诚实的 4。**不许装懂，也不许装傻，实话实说永远是最优策略**——50 号课的那条谷底，换了一把尺又现形一次。

### 快问快答

```quiz
榜单显示：A 模型基于五万词表得到困惑度 30，B 模型基于八千词表得到困惑度 12。谁的语言学得更好？
- A 的数字大，显然 B 更好
- B 更好，12 很小
- 无法直接比较 [*]
? 分词口径不同，"每词多少比特"的基准本身就在漂移：粗粒度切分的每词负担天然更重。要在同一把尺上比，先把两者放进同一套分词器和同一份测试集重新称重。
```

:::warning[常见误区]

**误区一**："你以为困惑度低就代表会说话。" 老式 n-gram 计数器不懂语法不懂逻辑，照样能把新闻体语料的 PPL 刷得很低；换一种文风立刻原形毕露。它是灵敏度很高的温度计，不是智力证书。

**误区二**："你以为任何两个 PPL 数字都能摆在一起比大小。" 语种、领域、分词粒度换掉任何一个，比特基准就换一套；跨表排名前先查口径。实验室发布成绩必附测试集配置，原因正在于此。

**误区三**："你以为容量 C 是运营商承诺的网速下限。" 方向反了：C 是天花板。超过 C，可靠传输被数学禁止；低于 C 也只保证"存在某种编码能做到"，具体设备的时延抖动另有合同。把 C 当最低保证印进广告时，请想起本课。

:::

```python
import math   # 数学函数库

world = [0.25, 0.25, 0.25, 0.25]
truth_model = [0.25, 0.25, 0.25, 0.25]
dumb_model = [0.125, 0.125, 0.125, 0.125]

def cross_entropy(p, q):
    total = 0
    for i in range(len(p)):
        if p[i] > 0 and q[i] > 0:
            total = total - p[i] * math.log2(q[i])
    return total

ce_truth = cross_entropy(world, truth_model)
print(2 ** ce_dumb)
print(2 ** ce_truth)
```

糊涂模型的账单 3 比特对应八面骰，真模型的 2 比特对应四面骰——指数结算干净利落，全程整数落点。（对照正文速算口诀："q 均匀铺满 n 格时 PPL 恰等于表长"的活标本。）

**练习 2**：有人宣称训练出了困惑度 1.0000001 的汉语模型。不动用超算，你能凭概念判断这事的可疑之处吗？

<details>
<summary>点开查看逐步解答</summary>

PPL 无限接近 1，意味着交叉熵无限接近 0：每个位置都近乎唯一注定。而自然语言充满真实的可选性（同一个意思有多种说法、下一词从未被历史完全锁死），其分布的熵必然明显大于零——除非模型过拟合到了背诵训练集的程度。困惑度逼近 1 不是奇迹而是病历：评估集泄漏的经典症状。

</details>

**练习 3**：某信源实测困惑度 64（即每词 6 比特），拟经翻转概率 0.1 的信道传输。每词最少占几个发送符号？再把这道题翻译成一句日常比喻。

<details>
<summary>点开查看逐步解答</summary>

$6\div(1-h(0.1))\approx6\div0.531\approx11.3$，规划时向上取整按 12 个符号/词留足裕量。比喻：想说一句内涵 6 招的哑谜，走廊里每一招都有约一半"税"被打掉（简化耳朵模型只放行 0.531 折的真货），于是同一句得用近十二条嗓子编码齐喊、靠冗余投票还原。源头越迷茫、走廊越吵闹，预算垒得越高——压缩端努力压低 PPL、信道端努力抬高 C，两边各自省钱，中间这份预算单就是香农两大定理的握手处。

</details>

## 7. 选读：一本资产负债表的两种读法

<details>
<summary>选读 · 1948 年论文里的双引擎</summary>

翻开香农 1948 年那篇奠基论文会发现，信源编码与信道编码不是相邻的两章笔记，而是一枚硬币的两面：前者问"真实分布 $p$ 的消息流，最紧凑的无损记法平均每符号几位"，答案是逼近 $H(p)$；后者问"容量 $C$ 的管道里，信息能以多大速率完好通过"，答案是任何低于 $C$ 的速率都存在可用之码。设想一个理想中继站把两者接驳：信源端极限压缩出的每一比特，都被信道端的互信息窄门全额放行——两个定理的交接处没有损耗，损耗只发生在我们还没造出那么好的码的时候。半个多世纪以来，从 ZIP 到 LDPC 的每一次工程刷新，都是在向这张理论资产负债表的原价逼近。

</details>
