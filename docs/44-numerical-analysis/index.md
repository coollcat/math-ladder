# 数值分析

纸上的精确公式进入有限位浮点数后会出现舍入、放大误差和不稳定算法。数值分析教我们既算得快，也知道结果还能信多少。

这一章按下面的路线图推进：

1. [浮点表示与机器精度](./10-floating-point.md)——打开任何一种编程语言，输入 0.1 + 0.2，再问它"等于 0.3 吗"，它会冷静地回答：不等于；
2. [舍入误差与算法稳定性](./20-roundoff-stability.md)——会计对账时最怕的不是大额差错，而是"收入 1,000,001.33 元"对上"支出 1,000,00…；
3. [迭代法与收敛速度](./30-fixed-point-iteration.md)——拿起计算器，输入随便一个数（比如 5），然后反复按 cos 键：5 → 0.2837 → 0.960…；
4. [插值：用几个点造一条曲线](./40-interpolation.md)——桥梁健康监测系统只在梁的四个位置装了位移传感器，其余位置的挠度全靠推算；
5. [条件数与敏感问题](./50-conditioning.md)——两条几乎平行的直线会把交点顶上天：输入端不到百分之一的挪动，解沿着杠杆飞出十六个数量级；
6. [直接法：LU 分解与 Cholesky](./60-lu-cholesky.md)——把对称正定矩阵拆成 L·Lᵀ 之后，解方程只剩两次顺藤摸瓜的代入，而规模每翻一倍苦头恰好八倍；
7. [正交化：QR 分解与最小二乘](./70-qr-least-squares.md)——四个传感器点想拟合成一条直线，法方程与正交化两条路线殊途同归，那把叫 Gram–Schmidt 的剪刀是更稳的一台机器；
8. [迭代法与谱半径](./75-spectral-radius-iterative.md)——把求解拆成"猜一步改一步"的循环后，谱半径一个数字就能提前判决谁收敛、谁发散、每轮削掉几位数字；
9. [数值微分与数值积分](./85-numdiff-integration.md)——步长不是越小越好：中心差分在 V 形谷底附近拿到十位小数，换屋顶的辛普森一步跨进万分之一门槛；
10. [蒙特卡洛方法与方差缩减](./92-monte-carlo-variance.md)——往木板上撒豆子就能称出圆周率，误差却按 1/√N 收缩得像守财奴；对偶变量和控制变量教每一颗豆子变得更聪明。

## 实战挑战 · 桥梁挠度监测

真实场景：一座步行桥的健康监测系统在主梁上每 4 米装一个位移传感器，某次静载试验的读数如下（情境原创，经典的一次插值题型）：

| 位置 $x$（米） | 0 | 4 | 8 | 12 | 16 |
| --- | --- | --- | --- | --- | --- |
| 挠度 $y$（毫米） | 0 | 7 | 10 | 7 | 0 |

工程师需要知道**测点之间**的下沉量。约定相邻测点之间用一次（线性）插值：区间 $[x_i,x_{i+1}]$ 上取

$$y \;=\; y_i + \frac{y_{i+1}-y_i}{x_{i+1}-x_i}\,(x-x_i)$$

**(a)** 估计 $x=6$ 米处（第 2、3 号传感器正中偏左）的挠度；**(b)** 估计对称位置 $x=14$ 米处的挠度；**(c)** 数据入库彩蛋——传感器标定程序里有一句 `0.1 + 0.2 == 0.3` 的自检，它返回真还是假？

```exercise
# @title: 实战挑战：测点之间梁沉了多少
# @check: 8.5
# @check: 3.5
# @check: False
# @hint: (a) 区间斜率 (10-7)/(8-4)=0.75，从 7 出发走 2 米；(b) 对称地算右端区间；(c) 本章第 10 课讲过 0.1 在二进制里的命运。
# 测点数据（单位：米, 毫米）
slope_a = (10 - 7) / (8 - 4)      # 4~8 米区间的斜率，已示范
y_a = 7 + slope_a * (6 - 4)
print(y_a)                        # (a) x=6 处的挠度估计

print()                           # (b) x=14 处的挠度估计（12~16 米区间）

print()                           # (c) 自检表达式 0.1 + 0.2 == 0.3 的返回值
```

<details>
<summary>点开查看逐步解答</summary>

**(a)** 斜率 $(10-7)/(8-4)=0.75$ 毫米/米，$y(6)=7+0.75\times2=8.5$ 毫米。

**(b)** 右端区间斜率 $(0-7)/(16-12)=-1.75$，$y(14)=7+(-1.75)\times2=3.5$ 毫米。

**(c)** `False`。0.1 与 0.2 的二进制展开都无限循环，各自舍入存储后再相加，结果停在 0.3 旁边一个刻度上（差约 $5.55\times10^{-17}$）。桥梁数据无恙——毫米级的测量误差远大于浮点尘埃；但若哪天要比较"理论挠度 = 计算挠度"是否严格相等，就该改成容差比较：

```python
slope_a = (10 - 7) / (8 - 4)
y_a = 7 + slope_a * (6 - 4)
print(y_a)

slope_b = (0 - 7) / (16 - 12)
y_b = 7 + slope_b * (14 - 12)
print(y_b)

print(0.1 + 0.2 == 0.3)
print(abs((0.1 + 0.2) - 0.3) < 1e-12)   # 工程上正确的问法
```

工程复核：全梁最大挠度出现在跨中附近（8.5 毫米 < 跨度的 1/1000），且曲线关于跨中近似对称——线性插值的两个估值互相印证了这一点。
</details>

## 实战挑战 · 浮点相等要用容差

计算机里 `0.1 + 0.2` 并不精确等于 `0.3`，而是 `0.30000000000000004`。判断浮点"相等"要用容差 $|a-b|<\varepsilon$。下面这题用 `==` 直接比，修到输出 `True`：

```exercise
# @title: 实战挑战：浮点相等要用容差
# @check: True
# @hint: 别用 == 比浮点；改用 abs(a - b) < eps 的容差判断。
a = 0.1 + 0.2
b = 0.3
eps = 1e-9
same = (a - b) == 0      # ← 问题在这：浮点误差下这个等式不成立
print(same)
```

<details>
<summary>点开查看逐步解答</summary>

浮点数判等要用容差：

```python
same = abs(a - b) < eps   # |0.30000000000000004 - 0.3| = 5.55e-17 < 1e-9
print(same)               # True
```

改完：$0.1+0.2$ 与 $0.3$ 的差只有约 $5.55\times10^{-17}$，远小于容差 $10^{-9}$，判 `True`。初始代码 `== 0` 因浮点舍入永远为 `False`。二进制无法精确表示 $0.1$，这是机器精度的根本事实——本章浮点课的"彩蛋"就在这一行里。

</details>
