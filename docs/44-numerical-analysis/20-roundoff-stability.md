# 舍入误差与算法稳定性

## 1. 从一个场景开始

会计对账时最怕的不是大额差错，而是"收入 1,000,001.33 元"对上"支出 1,000,001.31 元"——两笔几乎相等的数一减，剩下 2 分钱，而这 2 分钱里混着两张单据各自的全部舍入噪声。

数值计算里同样的戏码天天上演：**两个相近的数相减，有效数字瞬间蒸发**。这一课看误差如何被算法放大，以及怎样设计算法让它老实待在笼子里。

## 2. 直觉解释

上一课说过：每个浮点数都带着约 $10^{-16}$ 的相对误差，像每张钞票都可能有半根头发丝的磨损。

- 加减一大一小两个数：小数的误差被淹没，无伤大雅；
- **相减两个几乎相等的数**：前导的相同数字互相抵消，留下的是两者"尾巴"上的误差——好比两根各长 1 米、各歪了 0.1 毫米的尺子相减，差值的相对误差可能是百分之几十。这叫**灾难性相消（catastrophic cancellation）**；
- 连加一万个 0.1：每次舍入一点点，顺序不同、结果就不同——误差会累积，但**怎么累积是可以设计的**。

一个**稳定算法**承诺：输入数据的微小扰动只引起输出的微小扰动。不稳定算法则是雪球制造机。

## 3. 正式定义

设真值运算为 $\tilde{y}=fl(f(x))$（$fl$ 表示舍入到最近浮点数）。

| 概念 | 含义 |
| --- | --- |
| 灾难性相消 | $a\approx b$ 时计算 $a-b$，结果的相对误差远大于操作数自身的相对误差 |
| 数值稳定性 | 算法输出误差被输入误差与舍入误差的适度倍数所控制 |
| 放大因子 | 输出误差与输入误差之比；条件问题（下一站）研究它的下限 |

**设计原则**（本课的两板斧）：

1. **换公式**：代数等价的公式可以天差地别。对 $x^2-bx+c=0$，两个根可写成：
$$x_1=\frac{b+\sqrt{b^2-4c}}{2},\qquad x_2=\frac{2c}{b+\sqrt{b^2-4c}}$$
第二个由韦达定理变形得到，避开了一次相近数相减；
2. **管住求和顺序**：把小数先加（升序相加）、或用成对求和，能显著压低累积误差。

## 4. 分步例题

**例**：解 $x^2-bx+1=0$，取 $b=10^{9}$。韦达定理说两根之积为 1，所以真值是 $x_1=10^{9}$、$x_2=10^{-9}$。

1. 判别式 $\Delta=b^2-4\approx 10^{18}$；
2. 大根没问题：$x_1=\dfrac{b+\sqrt{\Delta}}{2}\approx\dfrac{10^{9}+10^{9}}{2}=10^{9}$ ✓；
3. 小根用原始公式：$\dfrac{b-\sqrt{\Delta}}{2}$——两个约 $10^{9}$ 的数相减！机器上 $\sqrt{\Delta}$ 舍入后与 $b$ 一模一样，相减得零，小根直接塌成 $0$——真值 $10^{-9}$ 被吃得无影无踪；
4. 稳定变形：由韦达定理 $x_1x_2=1$ 得 $x_2=\dfrac{1}{x_1}=\dfrac{2}{b+\sqrt{\Delta}}$；
5. 结果：$x_2=\dfrac{2}{2\times10^{9}}=10^{-9}$ ✓，一位有效数字都没丢。**同一道题，公式选错答案就报废。**

## 5. 动手实验

### 实验 0：大数吃小数的放大镜

下图把数学上的恒等式 $a+x-a=x$ 放进机器，蓝线是机器算出的结果，橙色虚线是真值 $x$。先把 a 拉满到十亿量级：蓝线整条趴在零线上——大数把小数整个吞掉，减回去什么也没剩下；再把 a 退回到一千上下（比如 1024 附近）：蓝线变成一格一格的台阶——小数没被吃光，却只能踩着大数的刻度挪动：

### 实验 1：亲眼看见相消

```python title="灾难性相消现场"
b = 1e9
delta = (b * b - 4) ** 0.5          # **0.5 即开平方
root_naive = (b - delta) / 2        # 相减的两个数几乎相等 → 危险
root_stable = 2 / (b + delta)       # 稳定变形：只做加法和除法

print(root_naive == 0)              # 原始公式的小根直接塌成 0？
print(root_stable == 0)
print(abs(root_stable - 1e-9) < 1e-15)   # 稳定版是否足够接近真值 1e-9
```

第一行 `True` 是本案的铁证：真值 $10^{-9}$ 被原始公式算成了**零**。稳定公式则把小根完好救回。

### 实验 2：求和顺序的误差账本

```python title="一万次累加 0.1：三种顺序三种结局"
import math
import matplotlib.pyplot as plt

n = 10000
target = n * 0.1                     # 数学上的期望和（它自己也有微误差，仅作参照）

total_up = 0.0                       # 从小往大逐个加
for k in range(1, n + 1):
    total_up = total_up + 0.1

total_block = 0.0                    # 每 100 个打包成一块，再对块求和
for start in range(0, n, 100):
    block = sum(0.1 for _ in range(100))   # sum：内置求和函数；_ 是"用不到的循环变量"
    total_block = total_block + block

print("朴素连加误差:", total_up - target)
print("分块求和误差:", total_block - target)
print("math.fsum 误差:", math.fsum([0.1] * n) - target)   # fsum：精确补偿求和

errors = [abs(total_up - target), abs(total_block - target),
          abs(math.fsum([0.1] * n) - target)]
labels = ["naive", "block", "fsum"]
plt.bar(labels, errors, color=["tomato", "orange", "seagreen"])   # bar：条形图
plt.ylabel("abs error")
plt.yscale("log")
```

三条柱子依次变矮：朴素连加的误差最大，分块明显改善，`fsum` 干净到几乎为零。**求和不是无序的自由动作，而是有代价核算的操作。**

### 快问快答

```quiz
灾难性相消最容易发生在哪种运算里？
- 两个很大的数相乘
- 两个非常接近的数相减 [*]
- 一个数除以很大的数
? 相近数相减时前导有效数字互相抵消，剩下的差主要由两者的舍入尾巴组成，相对误差急剧放大。
```

:::warning[常见误区]

**误区一**："公式在数学上等价，所以随便用哪个。" 纸上等价不等于机器等价：分步例题里两个公式一个报废一个小数点后 15 位全对。**数值分析研究的就是这个差距。**

**误区二**："误差累积无法控制，听天由命。" 求和顺序、公式变形、成对合并……都是可设计的。稳定与不稳定算法的差距可以是"能用"与"不能用"。

**误区三**："只要最终结果看起来合理就行。" 灾难性相消的输出往往**长得完全正常**（比如一个漂亮的 0），不会报警。识别危险模式要靠知识，不靠肉眼。

:::

## 6. 练习

**练习 1**（概念）：下列操作哪些危险？(a) $(1+10^{-15})-1$；(b) $10^{10}+0.01$；(c) $\sqrt{10^{20}}-10^{10}$。

<details>
<summary>点开查看逐步解答</summary>

(a) 危险——$1$ 附近的刻度间距约 $10^{-16}$，加上去再减回来只剩零星几格，信息大半丢失；(b) 安全方向的大数吃小数：$0.01$ 直接被吞（这本身也是警示，但不算相消）；(c) 极度危险——$\sqrt{10^{20}}=10^{10}$，两数全同，结果恒为 0。判断口诀：**先看相减的两数是否接近，再看差的量级与操作数量级之比**。
</details>

**练习 3**：把实验 2 的 `n` 改成 100000 再跑，观察朴素误差是否大约放大 10 倍（随机游走式增长），而 `fsum` 是否依旧干净。

<details>
<summary>点开查看逐步解答</summary>

舍入误差近似随机游走，$n$ 步累计典型规模按 $\sqrt{n}$ 到 $n$ 之间增长；十倍步数下朴素误差通常涨到 $10^{-11}$ 上下，而 `fsum` 用精确补偿技术始终保持数学意义上的正确舍入。**误差预算要随规模重估**——这是工程上"先估精度再上线"的原因。
</details>

## 7. 选读：谁该背锅——算法还是问题本身

<details>
<summary>选读 · 稳定性与条件数分工表</summary>

同样的小根问题，换个角度看：即使使用完美算法，输入 $b$ 若有 $10^{-16}$ 的相对扰动，小根 $x_2\approx1/b$ 就会有同量级甚至更大的相对变化——这是**问题本身敏感**（病态），任何算法都救不了；而本课的相消是**算法敏感**（良态问题配了烂算法），换公式就能救。区分两者靠**条件数**：第 21 章《条件数与敏感问题》已经给过矩阵版的正式定义——条件数刻画问题的固有敏感度，稳定性刻画算法的保真度。诊断顺序永远是：先问问题病不病，再怪算法烂不烂。

</details>
