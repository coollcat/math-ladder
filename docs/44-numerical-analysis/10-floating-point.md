# 浮点表示与机器精度

## 1. 从一个场景开始

打开任何一种编程语言，输入 `0.1 + 0.2`，再问它"等于 0.3 吗"，它会冷静地回答：**不等于**。不是语言出了 bug，是所有遵守 IEEE 754 标准的计算机都这样——包括银行、飞机和游戏机里的那颗芯片。

数学里的实数是连续的绸缎，计算机里只有一把**刻度有限的尺子**。这一课我们看清这把尺子的刻度怎么排、缝隙有多宽，以及什么时候缝隙会咬人。

## 2. 直觉解释

科学记数法你已经会了：$6.022\times10^{23}$ 把数拆成"有效数字 × 10 的幂"。浮点数是同一个主意，只是底数换成 2：

$$\text{数值} = \pm\,1.\text{一串二进制小数}\times 2^{\text{指数}}$$

64 位浮点数（双精度）把这串信息装进 64 个格子：1 格放正负号，11 格放指数，52 格放尾数（有效数字）。

关键后果有两条：

1. **刻度是"相对"的**：尾数只有 52 格，所以数越大、缝隙越宽——在 1 附近缝隙约 $2^{-52}$，在十亿附近缝隙就涨到 $2^{-52}\times 2^{30}$。尺子在放大镜下看，永远只有那 52 个刻度；
2. **十进制的"整齐"在二进制里可能无限循环**：$0.5=2^{-1}$ 是精确的，但 $0.1$ 换成二进制是 $0.000110011001100\ldots$ 无限循环——塞不进 52 格，只能四舍五入存个近似值。

## 3. 正式定义

规格化浮点数：$x=\pm(1.b_1b_2\ldots b_{52})_2\times 2^{e}$，其中尾数首位恒为 1（省掉一格），$e$ 是带偏置的指数。

| 名词 | 含义 |
| --- | --- |
| 机器精度 $\varepsilon_{mach}$ | $1$ 与"下一个可表示的数"的间隙，双精度为 $2^{-52}\approx 2.22\times10^{-16}$ |
| 舍入 | 真值落进缝隙时，取相邻刻度里最近的一个 |
| 相对误差 | $\lvert x-\hat{x}\rvert/\lvert x\rvert$；舍入保证它不超过 $\varepsilon_{mach}/2$ |
| 上溢 / 下溢 | 指数超界：数太大爆成 inf，太小缩成 0 |

核心心法：**浮点运算的每个结果都只是"真结果附近的某个刻度"**。单次误差微小如尘埃，但误差会传播、会被算法放大——那是下一课的主题。

## 4. 分步例题

**例**：把 $0.1$ 写成二进制，看清它为什么存不下。

1. $0.1\times2=0.2$ → 整数部分 $0$；
2. $0.2\times2=0.4$ → 取 $0$；
3. $0.4\times2=0.8$ → 取 $0$；
4. $0.8\times2=1.6$ → 取 $1$，留下 $0.6$；
5. $0.6\times2=1.2$ → 取 $1$，留下 $0.2$——**回到第 2 步的情形**，开始循环；

所以 $0.1_{(10)}=0.000\overline{1100}_{(2)}$，循环节 4 位，永无止境。计算机截到 52 位尾数处舍入，存下的其实是

$$0.1000000000000000055511151231257827\ldots$$

这个"比 0.1 略胖一点点的数"。两个这样的近似数相加，误差就现出原形。

## 5. 动手实验

### 实验 1：亲手抓出机器精度

```python title="不断减半，直到 1 + eps 不再变化"
eps = 1.0
while 1.0 + eps != 1.0:      # 只要加完还能被察觉，就一直减半
    eps = eps / 2            # 减半：往更小的缝隙探
print("单位舍入误差约为:", eps)
print("对照 2 的 -53 次方:", 2 ** -53)

x = 0.1 + 0.2
print(x == 0.3)              # 经典惊吓：不相等
print(x)                     # 打印出来看看真身
```

第一行输出约 $1.11\times10^{-16}$：这是“1 加不上之前”的最后一步，也就是机器精度的一半（单位舍入误差）。完整刻度间隙是它的两倍，约 $2.22\times10^{-16}$。第三行的 `False` 与第四行的一长串 `0.30000000000000004` 就是引子里那个场景。

### 实验 2：浮点间隙显微镜——刻度随数量级变宽

先用网页组件感受全局：横轴是二进制指数，纵轴是该数量级附近的标准间隙（ulp）；precision 滑块相当于换一把尾数位数不同的尺子。你会发现曲线几乎全程贴着零线趴着，直到指数逼近 precision 才猛地竖起——这本身就是结论的一半：**缝隙在日常视野里小到看不见，却随数量级疯狂生长**。要逐档看清 $2^{x-\text{precision}}$ 怎么翻倍，跑下面的 Python 实验：它打印具体数值，并换成对数轴作图。

```viz
{
  "type": "plot",
  "title": "浮点间隙：二进制指数越大，绝对缝隙越宽",
  "expr": "2^(x - precision)",
  "label": "ulp",
  "xmin": 1,
  "xmax": 64,

    { "name": "precision", "min": 10, "max": 56, "step": 2, "value": 52 }
  ]

```

```python title="不同数量级上，相邻两个浮点数的间距"
import matplotlib.pyplot as plt

magnitudes = [0, 16, 32, 48]             # 指数：从 2^0 到 2^48
gaps = []
for e in magnitudes:
    base = float(2 ** e)                 # float() 把整数转成浮点数
    gap = base * 2.0 ** -52              # 刻度间距 = 尾数最小步进 × 数量级
    gaps.append(gap)
    print(f"2^{e} 附近相邻浮点数的间隙 = {gap}")

plt.semilogy(magnitudes, gaps, marker="o")   # 对数图：指数增长画出来是直线
plt.xlabel("magnitude exponent")
plt.ylabel("gap between adjacent floats")
plt.grid(True)
```

四个点连成一条上升直线：二进制指数每加 16，数值放大约 $65{,}536$ 倍，刻度间距也同步放宽。**绝对间隙在变，相对间隙（除以该数量级）却恒定**——这正是"浮点"二字中"浮动小数点"的含义。

### 快问快答

```quiz
为什么 0.1 在计算机里存不准？
- 因为内存不够大
- 因为 0.1 的二进制展开是无限循环小数，52 位尾数只能四舍五入 [*]
- 因为 0.1 不是有理数
? 0.1 = 1/10，而分母 10 含因子 5，与二的幂互质，化成二进制小数必然无限循环；0.5、0.25 这类分母为 2 的幂的数反而能精确存储。
```

:::warning[常见误区]

**误区一**："浮点误差是程序员的 bug。" 它是表示系统的固有属性：只要用有限刻度量连续世界，误差就在。工程要做的不是消灭它，而是不让它被放大（下一课）。

**误区二**："判断两个浮点数是否相等可以用 `==`。" 计算路径不同的两个"本应相等"的结果往往差一个刻度。应当比较差的绝对值是否小于容差。

**误区三**："小数点后位数越多越准。" 双精度只有约 15~16 位十进制有效数字；打印出的更多位数只是近似值的忠实展示，不代表精度。

:::

## 6. 练习

**练习 1**（概念）：下列哪些数十进制看似普通、二进制却能精确存储？$0.5$、$0.25$、$0.75$、$0.2$。

<details>
<summary>点开查看逐步解答</summary>

前三个都能：分母分别是 $2$、$2^2$、$2^2$（$0.75=\frac{3}{4}=0.11_2$）。$0.2=\frac{1}{5}$ 分母含 5，二进制无限循环，只能近似。口诀：**分母只含质因数 2 的小数才是二进制世界的"原住民"**。
</details>

**练习 2**（判题）：初始代码声称浮点世界一切精确。请改成探测真实情况：相等判断、差值与大数吃小数三个实验各一行：

```exercise
# @title: 练习：浮点世界的三连问
# @check: False
# @check: 5.551115123125783e-17
# @check: True
# @hint: 第二行直接打印 (0.1 + 0.2) - 0.3 的差；第三行问 1e16 == 1e16 + 1。
x = 0.1 + 0.2
print(x == 0.3)      # 第一问：加出来的数等于 0.3 吗？
diff = 0             # ← 学生任务：把 diff 改成 x - 0.3，看看误差有多大
print(diff)

print(1e16 == 1e16 + 1)   # 第三问：巨大的数旁边还站得下 1 吗？
```

第二问的答案 $5.55\times10^{-17}$ 恰好是机器精度量级——误差没有消失，只是藏在第 17 位有效数字里；第三问的 `True` 说明在 $10^{16}$ 附近刻度间距已涨到 2，"+1" 直接被舍没了。

**练习 3**：实验 2 里若把数量级换成 52 和 53，预测间隙变成多少？运行验证。

<details>
<summary>点开查看逐步解答</summary>

$2^{52}$ 附近整数已占满全部尾数格，间隙恰为 $1$；$2^{53}$ 处间隙跳到 $2$——这就是练习 2 第三问的原理：$2^{53}=9007199254740992$ 之后，连整数都开始"挤不下"了。
</details>

## 7. 选读：为什么是 52 与 2046

<details>
<summary>选读 · 64 位的分工账本</summary>

双精度 64 位分配：符号 1 位、指数 11 位、尾数 52 位。指数 11 位给出 $2^{11}=2048$ 种状态，扣除全 0（表示非规格化小数与零）与全 1（表示无穷与 NaN），正常数的指数共 2046 档，配合偏置 1023 覆盖约 $10^{-308}$ 到 $10^{308}$。尾数 52 位加上隐含首 1 等于 53 位有效位，$2^{-53}\approx 1.11\times10^{-16}$ 就是实验 1 抓到的数字——**一格一格都是预算**：想多存范围就要牺牲精度，反之亦然。半精度（16 位）、单精度（32 位）只是换了张预算表。

</details>
