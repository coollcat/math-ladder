## 实战挑战 · 旅行者号的深空保险单

1977 年发射的旅行者一号、二号探测器最初只靠内层卷积码保护数据。当扩展任务决定启用图像压缩——压缩后的数据对误码率苛刻得多——工程师在编码流水线外层又加了一道保险：里德-所罗门码 RS(255,223)，与内层约束长度 7、码率 1/2 的卷积码级联使用。这套"外码 + 内码"的组合经受住了几十亿公里的考验，后来成为深空通信 CCSDS 标准的基石。

它的参数恰好是本章每个概念的活教材：每个码块 255 个字节符号，其中 223 个装科学数据，剩下的是校验字节；单个符号就是 8 位，所以一个字节内翻几个位也只算一个符号错误——这正是它擅长扛突发错误的原因。

**题目**

设 $n=255$，$k=223$：

**(a)** 每个码块有多少个校验字节？

**(b)** 这套码最多能纠正每块多少个字节错误？（提示：第 55 课的最小距离账本——纠错半径不超过冗余量的一半。）

**(c)** 码率折合成整数百分比是多少？（先乘 100 再整除，别用小数。）

**(d)** 深空的一次宇宙射线事件在同一块里打翻了 12 个字节，译码器能保证救回来吗？打印比较结果。

第一问已示范方向，把其余三处补齐：

```exercise
# @title: 实战挑战：旅行者号的深空保险单
# @check: 32
# @check: 16
# @check: 87
# @check: True
# @hint: 校验字节数 = 总长 − 数据数；可纠错误数 = 校验数整除 2；百分比先乘 100 再整除；最后一问拿破坏量与可纠上限比大小。
n = 255        # 每个码块的总字节数（旅行者号 RS 码）
k = 223        # 其中真正的数据字节数

burst = 12     # 一次宇宙射线事件打翻的字节数

parity = n + k          # (a) 冗余字节数：方向反了，请改
t = parity // 3         # (b) 可纠正的字节错误上限：对半才对
percent = k // n        # (c) 码率的整数百分比：整数相除会得 0
rescued = burst > t     # (d) 这块还救得回来吗：想想大于号该不该换

print(parity)
print(t)
print(percent)
print(rescued)
```

<details>
<summary>点开查看逐步解答</summary>

**(a)** 校验字节 $= n - k = 255 - 223 = 32$。

**(b)** RS 码的最小距离是 $n-k+1 = 33$，于是纠错半径 $t=\lfloor 32/2 \rfloor = 16$：每块最多纠正 16 个字节错误。这与真实参数完全一致——旅行者号的 Reed-Solomon 码正是按"255 字节一块、最多纠 16 个字节错"设计的。

**(c)** 码率 $\frac{223}{255}\approx 0.875$；用整数运算 $223 \times 100 // 255 = 87$，即约 87%。换句话说，每传 100 个字节，只有约 87 个是科学数据，其余是为可靠性付的保险费。

**(d)** $12 \le t = 16$，打印 `True`：能救回来。若是 17 个字节，就超出了理论保证——未必无法恢复，但不再有任何承诺，只能听天由命。

正确代码：

```python
n = 255
k = 223
burst = 12

parity = n - k          # 32
t = parity // 2         # 16：整除自动向下取整
percent = k * 100 // n  # 22300 整除 255 得 87
rescued = burst <= t    # 12 <= 16 → True

print(parity)
print(t)
print(percent)
print(rescued)
```

顺带一提：手机扫码时那道被钥匙划花的二维码还能扫出来，用的是同一族 Reed-Solomon 码——L/M/Q/H 四档容错大约对应总码字的 7%、15%、25%、30%。深空与掌心，共享同一份代数保险单。

</details>

## 实战挑战 · 汉明距离：数不同，不是数相同

两个码字的汉明距离是它们**不同位**的个数。码字 `10101` 与 `11011` 的汉明距离是 3。下面这题数成了相同位，修到输出 `3`：

```exercise
# @title: 实战挑战：汉明距离数不同位
# @check: 3
# @hint: 汉明距离 = 不同的位数，比较时该用 !=。
a = "10101"
b = "11011"
dist = 0
for i in range(len(a)):
    if a[i] == b[i]:     # ← 问题在这：数成了相同位
        dist = dist + 1
print(dist)
```

<details>
<summary>点开查看逐步解答</summary>

汉明距离统计的是**不同**的位：

```python
if a[i] != b[i]:     # 这一位不同才计数
    dist = dist + 1
print(dist)          # 3
```

改完：`10101` 与 `11011` 在第 2、3、4 位不同，汉明距离 $3$。初始代码用 `==`，数的是相同位（$2$）。汉明距离是纠错码的度量尺：码字之间离得越远（最小距离越大），越能纠正错误——"数不同"而不是"数相同"，是这把尺子的起点。

</details>
