# Polar 码与 Turbo 码：靠迭代逼近香农极限

## 1. 从一个场景开始

2016 年，5G 标准的编码方案之争尘埃落定：数据信道交给 LDPC，**控制信道交给 Polar 码**。而上一代的 4G 用的是 Turbo 码。三代标准，三种码——它们不是随手挑的，每一种都在某个"码长 × 延迟"的格子里最划算。

要理解这场换血，得回到 1948 年香农留下的那句话：**只要码率低于信道容量，就存在一种编码，让错误率任意小。**

这句话最让人不舒服的地方是：它只说了"存在"，没说"怎么造"。于是接下来半个世纪，编码理论几乎都在回答同一个追问——**那个逼近极限的码，到底长什么样？**

## 2. 直觉解释

香农定理是一张"存在性支票"，兑现它花了 50 年。中间最好的实用码，离理论上限还差 2~3 dB（分贝是信噪比的对数单位，差 3 dB 相当于噪声功率要减半——这是巨大的差距）。

三个里程碑一层层把差距磨掉：

- **Turbo 码（1993）**：两个卷积码并行级联，中间插一个**交织器**把比特顺序打乱。译码时两个译码器像两个对答案的人，轮流把自己"对每一位的判断信心"传给对方——**迭代**。一轮不够，就来十几轮。
- **LDPC（1962 提出、1996 复活）**：稀疏校验矩阵 + 置信传播，本质也是"来回传信心"。
- **Polar 码（2008）**：第一个**被证明**随码长增长真正达到信道容量的构造，靠的是一个叫**信道极化**的现象。

一句话记住胜负手：**"迭代"**。一次译不准没关系，软信息来回传几十次，判断会被逐步放大；这比"一步到位地做硬判决"强得多。

## 3. 正式定义

**码率** $R = k/n$：$k$ 个信息位配上 $n-k$ 个校验位，信息占的比例。

**香农极限**：对 BPSK 加性高斯白噪声（AWGN）信道，容量（每维比特数）为

$$C = \tfrac12\log_2\bigl(1 + 2R\,\gamma\bigr),\qquad \gamma = \frac{E_b}{N_0}.$$

可靠传输要求 $R \le C$。令 $R\to 0$，可解出 $\gamma \ge \ln 2 \approx 0.693$，换成 dB 就是 $10\log_{10}0.693 \approx -1.59$ dB——**所有实用码的 BER 曲线只能无限逼近这条竖线，永远不能越过**。

**Turbo 码（并行级联卷积码）**：两个相同的递归系统卷积码（RSC）编码器，第二个前接交织器 $\pi$。译码器 A 与 B 各输出一份**外信息**（extrinsic information，即"除了本次输入之外我对该位的信心"），互相喂给对方，迭代 $10\sim20$ 轮。

**Polar 码（信道极化）**：用核矩阵 $F=\begin{pmatrix}1&0\\1&1\end{pmatrix}$ 构造 $G=F^{\otimes \log_2 N}$，把 $N$ 个相同的信道 $W$ 合成后再分裂成 $N$ 个"极化"信道。以擦除信道（BEC）为例，分裂规则是

$$I(W^-) = I(W)^2,\qquad I(W^+) = 2I(W) - I(W)^2 .$$

反复分裂，信道会朝两个极端跑：一半趋近容量 1（无差错），一半趋近 0（全废）。**把信息位放进好的那些，坏的做冻结位（固定填 0）**，就得到一个能逼近容量的码。

| 符号 | 名字 | 说明 |
| --- | --- | --- |
| $R=k/n$ | 码率 | 信息位占总位的比例，越高效越"省带宽" |
| $\gamma=E_b/N_0$ | 每比特信噪比 | 曲线横轴的常用单位是它的 dB 值 |
| $I(W)$ | 信道容量（BEC） | 取值 0~1；传输"一个符号"最多能带回多少信息 |
| $W^-,W^+$ | 分裂出的坏/好信道 | 只能通过递归定义，不能单独取出 |
| $\pi$ | 交织器 | 打乱比特顺序，让两个译码器的错误不相关 |
| 外信息 | 迭代译码的"货币" | 两个译码器之间交换的就是它 |

## 4. 分步例题

**例 1（BEC 上的极化，手算三层）**：取擦除率 0.5 的 BEC，单个信道容量 $I(W)=0.5$。

1. 第一层：坏支 $0.5^2 = 0.25$，好支 $2(0.5)-0.25 = 0.75$；
2. 第二层：$0.25$ 分裂成 $0.0625$ 与 $0.4375$；$0.75$ 分裂成 $0.5625$ 与 $0.9375$；
3. 第三层继续劈，得到 8 个数：$0.0039,\ 0.1211,\ 0.1914,\ 0.6836,\ 0.3164,\ 0.8086,\ 0.8789,\ 0.9961$；
4. 校验：每层总和守恒——第三层八个相加恰为 $8\times0.5 = 4$ ✓。

**关键现象在数值里**：最小的已经掉到 0.0039，最大的冲到 0.9961，中间地带越来越空。**信道正在"两极分化"。**

**例 2（Polar 的码率账）**：接着例 1，$N=8$ 的 Polar 码要码率 $R=1/2$。

1. $R=1/2$ 意味着 8 个位置里挑 4 个放信息位、其余 4 个冻结；
2. 按例 1 的容量排序，挑最大的 4 个：$0.9961,\ 0.8789,\ 0.8086,\ 0.6836$；
3. 这 4 条合计容量约 $3.37$ bit，理论上限是 $N\cdot I(W)=4$ bit；
4. 差的那一点是**短码的代价**：$N$ 越大，好信道占比越接近 $I(W)=0.5$，差距随之消失。

**例 3（码率 1/2 的香农极限）**：把 $R=1/2$ 代入容量公式。

1. 临界时 $R = C$，即 $1/2 = \tfrac12\log_2(1+2\cdot\tfrac12\cdot\gamma)$；
2. 右边化简约去 $1/2$：$1 = \log_2(1+\gamma)$；
3. 反解得 $1+\gamma = 2$，即 $\gamma = 1$（线性值）；
4. 换成 dB：$10\log_{10}1 = 0$ dB。

所以**码率 1/2 的理论门槛是 0 dB**（$-1.59$ dB 是码率趋近 0 时的绝对极限）。今天最好的 Turbo/LDPC/Polar 在 0.2~0.5 dB 附近就能把 BER 压到 $10^{-5}$，离这条线只差零点几 dB——这就是"逼近极限"四个字的分量。

再看真实的 BER 对比。下面的蒙特卡洛模拟做了件容易踩坑的事：在**同样的** $E_b/N_0$ 下比较"无编码"与"硬判决重复码"。

```python title="BER 曲线对比：同样的 Eb/N0，硬判决重复码反而更差"
import random                      # 随机数库（第 0 章出生）
import math                        # math.sqrt：给噪声算标准差

random.seed(74)                    # 固定种子：让每次运行的数字都一样

def simulate(scheme, gamma_db, trials=40000):
    """在 AWGN 信道上跑 BPSK；gamma_db = Eb/N0（分贝），scheme 取 uncoded 或 repeat3"""
    gamma = 10 ** (gamma_db / 10)              # 分贝换线性功率比：10 的 (dB/10) 次方
    sigma = math.sqrt(1 / (2 * gamma))         # 噪声标准差（沿用 Eb 归一为 1 的口径）
    amp = 1.0 if scheme == "uncoded" else math.sqrt(1 / 3)  # 重复三遍，每个码元只摊到 1/3 能量
    errors = 0
    for _ in range(trials):        # range(n)：重复 n 次；这里跑 trials 轮独立试验，_ 表示不关心是第几轮
        bit = random.getrandbits(1)            # getrandbits(1)：随机取一个二进制位（0 或 1）
        sent = amp if bit == 0 else -amp       # 映射：0 → +amp，1 → −amp
        shots = 3 if scheme == "repeat3" else 1
        votes = 0                              # 硬判决中判成"1"的票数
        for _ in range(shots):
            r = sent + random.gauss(0, sigma)  # gauss(均值, 标准差)：叠加高斯噪声
            if r < 0:                          # 硬判决：收到负值就判 1
                votes += 1
        decided = 1 if votes * 2 > shots else 0   # 重复码取多数票；无编码就那一票
        if decided != bit:
            errors += 1                        # 判错，记一笔
    return errors / trials

print("Eb/N0(dB)    无编码      重复3（硬判决）")
for db in [0, 2, 4, 6]:
    a = simulate("uncoded", db)
    b = simulate("repeat3", db)
    print(f"{db:>6}      {a:.4f}       {b:.4f}")
```

结论可能出乎意料：**每一行里，重复码的误码率都更高**。原因是能量守恒——同样的 $E_b/N_0$ 下，重复三遍就把每个码元的能量砍到 1/3，硬判决先把这一步的损失吃了进去，多数表决补不回来。（把三票按软信息直接累加再判号，最多只能追平无编码，重复码本身没有编码增益。）真正的增益来自**结构更好的码 + 迭代软判决译码**——那正是 Turbo/LDPC/Polar 做的事。

最后看 Polar 码的地基：信道极化到底长什么样。

```python title="信道极化：分裂出来的信道开始两极分化"
caps = [0.5]                              # 从一个容量 0.5 的擦除信道出发
for level in range(1, 11):                # 递归 10 层 → 2^10 = 1024 个分裂信道
    nxt = []
    for I in caps:
        nxt.append(I * I)                 # 坏分裂信道：容量 = I²，越劈越差
        nxt.append(2 * I - I * I)         # 好分裂信道：容量 = 2I − I²，越劈越好
    caps = nxt
    if level in (4, 6, 8, 10):
        good = 0
        for I in caps:
            if I > 0.9:
                good += 1
        print(f"层数 {level}（{len(caps)} 条信道）：容量超过 0.9 的占 {good / len(caps):.3f}")
print("好信道与坏信道两条极端都在变多，占比一路朝容量 0.5 爬")
```

四行占比依次是 $0.250,\ 0.344,\ 0.398,\ 0.435$——**单调朝 0.5 爬，但爬得很慢**。这就是 Polar 的处境：它被证明能达容量，却是在码长非常长的时候；短码下反而吃亏，得靠第 7 节的列表译码把性能补回来——5G 的控制信道恰好多是短块、低延迟的信息，配上补丁的 Polar 在那里够用，长数据块要的高吞吐并行译码则留给了 LDPC。

### 快问快答

```quiz
Polar 码达到信道容量的机制是哪一个？
- 把同一批比特重复发送多遍做多数表决
- 把 N 个相同信道合成分裂成 N 个极化信道，好信道放信息位、坏信道做冻结位 [*]
- 用多项式在有限域上求值
? 极化让一部分子信道容量趋近 1、另一部分趋近 0；把信息位放在好信道上，就等于用"挑出来的好信道"去逼近整条信道的容量。重复表决是重复码的思路，有限域多项式求值是 Reed-Solomon 的思路。
```

:::warning[常见误区]

**误区一**："Turbo 和 Polar 打破了香农极限。"
没有，也做不到。它们做的只是把曲线**尽量往左推**，离极限越来越近（今天只差零点几 dB），但从没有越过。香农定理是"存在性"与"上界"的双重结论，谁也绕不开。

**误区二**："在相同的信号能量下，重复码一定比不编码强。"
不一定。**按相同的 $E_b/N_0$ 算，硬判决重复码反而更差**——能量被摊薄，硬判决先丢一截。这个反直觉的事实正说明：编码增益不是"多传几遍"换来的，而是"用更聪明的结构"换来的。

**误区三**："Polar 赢了 5G 之争，所以它处处最好。"
不是。三种码各有地盘：长码高速数据 LDPC 更划算，短块低延迟控制信息 Polar 更合适，Turbo 在上一代里已经够用。工程选码从来是"短板 × 延迟 × 复杂度"的三角权衡，不存在通吃。

:::

**练习 2**：接着例 3，算一算码率 $R=1/4$ 时的香农极限是多少 dB，并说明为什么它比 $R=1/2$ 时更低。

<details>
<summary>点开查看逐步解答</summary>

令 $R=C$：$\tfrac14 = \tfrac12\log_2(1+2\cdot\tfrac14\gamma)$，两边乘 2 得 $\tfrac12 = \log_2(1+\tfrac{\gamma}{2})$，即 $1+\tfrac\gamma2 = \sqrt 2$，解出 $\gamma = 2(\sqrt2-1) \approx 0.828$。换成 dB：$10\log_{10}0.828 \approx -0.82$ dB。

比 $R=1/2$ 的 0 dB 更低。道理很直白：**码率越低，每个信息比特摊到的信道能量越多**，门槛自然越低；$R\to0$ 时趋近 $-1.59$ dB 的绝对极限。代价是带宽与吞吐——"更省能量"和"更省带宽"是同一枚硬币的两面。

```python
import math
for R in [1/2, 1/4]:
    gamma = (2 ** (2 * R) - 1) / (2 * R)      # 由 R = ½log2(1+2Rγ) 反解
    print(R, round(10 * math.log10(gamma), 2), "dB")
```

</details>

## 7. 选读：外信息、迭代增益与 Polar 的列表译码

<details>
<summary>选读 · "软信息"为什么比硬判决强</summary>

硬判决把每个接收符号压成一个比特（正还是负），丢掉了"离判决线有多远"这一层信息。**软判决留着这个距离当作信心值**：一个明显偏向 +1 的符号，比一个勉强落在 +1 侧的符号更可信。迭代译码的全部能量都来自这份信心账。

**外信息**是其中的关键约定：译码器 A 传给 B 的，必须是"**排除掉 B 已经提供的证据**之后，我自己新看到的那部分信心"。否则 B 会把 A 用过的旧证据当成新证据，信心被反复放大、越迭代越错——这叫**正反馈发散**，设计时必须避免。

**怎么知道迭代有效**？工程上有张 EXIT 图：横轴是输入外信息的质量，纵轴是输出外信息的质量。两条曲线只要不接触、形成一条越迭代越靠上的阶梯，就说明这套迭代能收敛。这套工具既是设计表，也是"这个码能不能逼近容量"的判据——它让"逼近极限"从口号变成了可计算的目标。

**Polar 的实战补丁**：纯粹按容量排序挑信道，短码下性能一般。5G 采用的是 **CRC 辅助的串行抵消列表（CA-SCL）译码**：同时保留 $L$ 条候选路径，用几个 CRC 校验位在最后帮它挑出正确的那条。这个小机关让 Polar 在短块控制信息上真正够用，也解释了标准为什么把它放在控制信道而不是数据信道。

</details>
