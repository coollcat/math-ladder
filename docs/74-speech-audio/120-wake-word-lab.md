# 关键词唤醒与端点检测

## 1. 从一个场景开始

智能音箱插着电待机一整天，续航和隐私都不允许它时刻运行庞大的识别模型。它真正的常态是：用一个极小的模型整夜守门，只回答一个问题——「刚才那句话，像不像『小爱同学』？」像，才把大模型叫醒。

这道闸门分两步：第 70 课的 VAD 端点检测先回答「**有人在说话吗**」（省电），本课的模板匹配再回答「**说的是不是那几个字**」（省算力）。两步都过了，才轮到后面几课的识别登场。

## 2. 直觉解释

把关键词检测想成「**拿关键词当印章，在时间轴上滚**」：

1. 每 20 ms 切一帧，每帧算一组 MFCC（第 50 课）——把人耳不敏感的细节压缩掉；
2. 拿一段固定长度的关键词模板（几十帧 MFCC），在整条音频流上逐点滑动比对，每滑到一个起点就打一个「相似度分」；
3. 于是「时间 → 得分」成了一条曲线：背景处贴地爬行，关键词处耸起一座峰；
4. 得分过阈值就唤醒。

一切的本事都在第 4 步那条**阈值线**上：调低，误报变多（锅铲声也被当成唤醒词）；调高，漏报变多（你喊了三遍它装睡）。**中间只有很窄一段是两头都干净的**——这是所有二分类判决的宿命，不是工程没做好。

还有一个隐藏难关：同一个人说同一个词，每次语速都不一样。模板是死的，快慢一变，得分就掉——第二次出现的关键词被放慢 6%，峰就明显矮一截。

## 3. 正式定义

**帧特征**：$x_t \in \mathbb{R}^{12}$，第 $t$ 帧的 MFCC（去能量维）。

**模板匹配得分**：模板 $M = \{m_1,\dots,m_L\}$（$L$ 帧），对齐起点 $t$ 的得分为逐帧余弦相似度的平均：

$$S(t) = \frac{1}{L}\sum_{k=1}^{L} \cos(x_{t+k},\, m_k)$$

比对前先做 **CMS**（减倒谱均值）：把每个维度的长期平均值减掉，不然声学通道（麦克风、距离）会让第一维能量一家独大。

**得分标准化**：打完分还要把曲线折成「比背景高出几个 σ」——用全体得分的中位数 $\tilde S$ 与绝对中位差 MAD 归一：

$$S'(t) = \frac{S(t) - \tilde S}{\mathrm{MAD}}$$

不做这一步，两个关键词窗口会自己抬高曲线的尺度、压平峰值，阈值就没法定了。归一之后，阈值有了物理量纲：**比背景高出几个 σ 才唤醒**。

**判决**：$S'(t) > \theta$ 记一次触发；连续过线的帧合并为一段。**漏报**（miss）：有关键词没触发；**误报**（false alarm）：没关键词却触发。**平滑**：得分过 $w$ 帧滑动平均再判决，能压毛刺，代价是峰值变矮、响应迟钝。

## 4. 分步例题

一条得分曲线里有三个候选事件：一声孤立的毛刺（3.2σ）、标准语速的关键词（峰 4.6σ，持续三帧）、被拖慢 6% 的第二次关键词（峰 2.8σ）。取阈值 $\theta = 3\sigma$：

1. 毛刺 3.2 > 3，单帧过线 → **误报**一次；
2. 关键词峰 4.6，三帧连续过线 → 合并为一段 → **命中**；
3. 慢速词峰 2.8 < 3 → 整段没过线 → **漏报**。

现在加 3 帧平滑再判：毛刺被两侧的 0.4、0.3 稀释成 $(0.4+3.2+0.3)/3 = 1.3$，**误报消失**；关键词峰稀释成 $(0.3+4.6+4.4)/3 = 3.1$，**保住了**；慢速词峰只有 2.6，**依然漏**。

结论一览无余：**平滑治得了毛刺，治不了语速**。语速要靠动态对齐（DTW）或神经网络打分（46 章），不是阈值能救的。

图上：上半是音频流与真值区间，中间是得分曲线与阈值线，下面实时统计触发段。做三件事：

- 把阈值从 3 拖到 1.5——第二次（放慢的）关键词被捞回来了，但毛刺和背景起伏也跟着过线：**误报先恶化**；
- 把阈值拖到 5——世界清净了，可你喊破喉咙它也不理：**漏报接管**；
- 把「平滑窗长」从 9 拖到 25——毛刺被抹平，但峰被削矮、检测整体变迟钝；
- 切到「嘈杂」环境——得分整体下沉，同样的阈值立刻漏报：**噪声移动的是整条曲线，不是某座峰**。

### 实验 2（python）：阈值两侧都是代价

```python title="同一份得分，两个阈值两份账"
scores = [0.4, 0.3, 0.5, 0.2, 0.4, 3.2, 0.3, 0.4, 0.5, 0.2,
          0.3, 4.6, 4.4, 4.2, 0.3, 0.4, 2.8, 2.6, 2.4, 0.3]
# 0.2~0.5 是背景，3.2 是一声孤立的毛刺，
# 4.2~4.6 是标准语速的关键词，2.4~2.8 是被拖慢 6% 的第二次关键词

def episodes(xs, th):
    hits, on = [], False
    for i, s in enumerate(xs):
        if s > th and not on:
            hits.append(i)          # 记下触发段的起点
            on = True
        elif s <= th:
            on = False
    return hits

for th in (2.0, 3.0):
    n_frames = sum(s > th for s in scores)
    print(f"阈值 {th}σ：超阈帧 {n_frames}，触发段起点 {episodes(scores, th)}")
```

阈值 2σ 把慢速关键词（段 16）捞回来了，但毛刺段 5 也在过线；阈值 3σ 好像干净些，其实毛刺 3.2 还是过了，反倒丢了慢速关键词。**阈值挪来挪去，只是在两类错误之间搬账**。

### 实验 3（python）：平滑能治什么

```python title="3 帧滑动平均前后的对比"
def smooth(xs, w=3):
    h = w // 2
    out = []
    for i in range(len(xs)):
        lo, hi = max(0, i - h), min(len(xs), i + h + 1)
        out.append(sum(xs[lo:hi]) / (hi - lo))
    return out

sm = smooth(scores)
print("毛刺处  ", [round(x, 2) for x in sm[4:7]])    # 3.2 被抹到 1.3
print("关键词处", [round(x, 2) for x in sm[10:13]])   # 峰还在（3.1 / 4.4）
print("慢速词处", [round(x, 2) for x in sm[15:18]])   # 还是够不着 3
```

平滑后按 3σ 判决：毛刺消失、标准关键词保留、慢速关键词依旧差一口气。**平滑是免费的午餐只有半份**——毛刺白送，语速得另点菜（DTW 或神经网络）。

### 快问快答

```quiz
厨房噪声变大、得分曲线整体下沉，运维把阈值从 3σ 调到 1.5σ 来「保唤醒率」。最先恶化的指标是？
- 漏报变多
- 误报变多：锅铲声、电视里的相似音节都会被当成唤醒词 [*]
- 响应变慢
? 阈值下调让判决线去迁就下沉的得分，背景毛刺也更容易过线——漏报少了，误报多了。这正是二分类判决的宿命：两侧都是代价，能做的只是把错误挪到自己更能承受的那一边（唤醒场景宁可疑神疑鬼）。
```

::::warning[常见误区]

**误区一**："阈值越低越灵敏，产品越好用。"
你以为灵敏是优点——唤醒产品里误报比漏报烦人得多：半夜自己亮灯说话的音箱，一天就会被用户拔电。**误报的代价是不对称的**，所以消费级产品宁可把阈值定得偏高。

**误区二**："模板匹配能对付所有语速。"
你以为同样的词得分都一样高——固定起点对齐天生怕语速变化，放慢 6% 得分就掉一截。真实系统要么用 DTW 动态对齐，要么直接上神经网络打分（第 46 章的序列模型正是为此而生）。

**误区三**："唤醒词识别就是小型 ASR。"
你以为唤醒是「识别得差一点的语音识别」——它俩任务不同：唤醒只要判「像不像」，不用懂内容，所以 $10^5$ 量级参数的小模型就够；ASR 要输出任意文本，算力差几个数量级。**把唤醒做重了，功耗预算首先不答应。**

::::

**练习 1**：下面的触发统计漏了第二次唤醒，补上被遗忘的那一步：

```exercise
# @title: 练习：第二次唤醒为什么没有触发
# @check: ['wake', 'wake']
# @hint: 关键词的得分会落回背景，这时要把「已触发」的旗子放下来，下一段关键词才有机会再次触发
scores = [0.4, 0.3, 4.6, 4.4, 0.3, 2.8, 2.6, 0.3, 0.4]
# 4.6/4.4 是第一次关键词，2.8/2.6 是第二次（背景都低于 0.5）

def episodes(xs, th):
    hits, on = [], False
    for s in xs:
        if s > th and not on:
            hits.append("wake")
            on = True
        # ← 问题在这：关键词过去之后，on 再也没被放回 False
    return hits

print(episodes(scores, 2.0))
```

**练习 2**：平滑窗 9 帧、帧移 10 ms 的唤醒系统，从「用户说完」到「触发判决」平均要多等多久？

<details>
<summary>点开查看逐步解答</summary>

1. 9 帧滑动平均要看满窗口：当前帧的得分要等它后面 $(w-1)/2 = 4$ 帧到齐才定稿；
2. 4 帧 × 10 ms = **40 ms** 的固定延迟；
3. 加上关键词本身约 0.8 s 的长度与一帧 32 ms 的窗长，端到端响应约 0.9 s——商品宣传里的「秒醒」，预算大头其实是关键词长度，不是算法延迟。

**工程含义**：平滑窗越长误报越少、延迟越长。窗长是体验参数，不是精度参数。

</details>

## 7. 选读：DTW 与 ROC

<details>
<summary>选读 · 两件对付「不确定性」的武器</summary>

**DTW（动态时间规整）**：模板与待测段不许逐帧硬对齐，而是允许「这帧对两帧、那帧跳一帧」——用动态规划找**累计距离最小**的对齐路径。语速变化被路径的伸缩吸收，慢 6% 的关键词得分就掉不下来了。代价是从 $O(L)$ 涨到 $O(L^2)$，好在关键词短、算得起。

**ROC（受试者工作特性）**：把阈值从低到高扫一遍，每个阈值记一对（误报率，召回率），画成曲线。曲线越靠左上越好；**斜率就是这一段里挪动阈值时两类错误的兑换率**。换特征、换模型，比较的就是整条 ROC，而不是某一个阈值的得失——本课实验里「拖阈值」看到的此消彼长，就是 ROC 逐点生成的过程。

</details>
