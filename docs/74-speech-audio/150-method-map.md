# 语音与音频智能方法地图

## 1. 从一个场景开始

14 门课学完了，工具箱里塞满了：源-滤波器、短时分析、语谱图、梅尔刻度、MFCC、基频检测、VAD、LPC、声码器参数、掩蔽阈值、码率分配、唤醒阈值、CTC 坍缩、注意力对齐、F0 与时长……

产品经理拿着三句话进来了：**「让它省电」「让它省流量」「把录音变成能搜的文字」**。先动用哪门课？

学完一章工具最大的风险不是忘了公式，而是「拿着锤子看什么都是钉子」。本课不添任何新东西，只做三件事：把全章排成一张**分诊地图**、演练一遍**分诊顺序**、把最容易踩的坑一次性列队展览。

## 2. 直觉解释

语音智能的问题分四个科室。分诊前先连问两个问题：

**第一问——你想解决什么？**

| 科室 | 管什么 | 典型症状 |
| --- | --- | --- |
| **特征** | 把声音变成机器好啃的表示 | 特征不对，后面全白搭 |
| **检测** | 回答「有没有 / 是不是」的判决题 | 漏报、误报、响应慢 |
| **编码** | 在保真的前提下把数据变小 | 存不下、传不动、音质差 |
| **识别合成** | 声音 ↔ 文字的双向翻译 | 听错、念错、机器人味 |

**第二问——代价落在哪？**

- **算力**：帧率 × 模型大小。唤醒端宁可 $10^5$ 参数，转写端才谈 $10^9$；
- **码率**：每秒多少 bit 能塞进信道。掩蔽阈值以下的，一分钱都别花；
- **体验**：漏报误报的兑换率与延迟。平滑窗长、阈值、模型大小都在这条线上讨价还价。

两问答案往表上一对，科室基本锁定。剩下的分歧多半发生在「多种工具都能凑合」的地带——那时先排**闸门顺序**：把不花钱的活挡掉（没人说话就别算），再谈怎么干得又快又省。

## 4. 分步例题

**题 A**：录音笔续航从一天提到一周。

1. 第一问：**检测**；第二问：算力（耗电的不是算法贵，是「一直在算」）；
2. 定位：先把没人说话的时段整段挡掉——[VAD](./70-vad-lab.md) 当第一道闸，[唤醒](./120-wake-word-lab.md)当第二道；
3. 处方：待机只跑 VAD（能量门槛，微瓦级），说话才上特征与模型。**闸门先于优化**。

**题 B**：播客 App 的流量账单告急。

1. 第一问：**编码**；第二问：码率（42 MB 一集传不动）；
2. 逐层排查：素材的掩蔽阈值在哪（[掩蔽](./100-masking-lab.md)）→ 按需付费分码率（[编码](./110-audio-codec-lab.md)）→ 语音为主的素材甚至可降到 16 kHz 采样；
3. 处方：1411 kbps 的母带压到 96 kbps，一集 42 MB → 2.9 MB，**先问透明阈值，再定码率**。

**题 C**：两小时会议录音要变成可搜索的文字稿。

1. 第一问：**识别**；第二问：算力（10⁸–10⁹ 参数的模型）+ 体验（同音字错别字）；
2. 定位：核心困难是帧与字的对齐——三代路线怎么选看场景：离线转写可上端到端大模型，边说边出字要流式（RNN-T）；
3. 处方：[分帧](./20-frame-window.md) → [MFCC](./50-mfcc-lab.md) → [识别](./130-asr-overview.md)，后处理再加语言模型纠错。**特征仍是三代共同的前端。**

## 5. 动手实验

### 实验 1（python）：给需求自动挂号

```python title="按需求开具科室单"
def route(silent, tight, want_text):
    # 闸门顺序：先把不花钱的活挡掉，再谈怎么干
    if silent:
        return "vad"      # 没人说话：后面全部不用跑
    if tight:
        return "codec"    # 要传出去：先压码率
    if want_text:
        return "asr"      # 要文字：上识别
    return "mfcc"         # 只要存特征：别贪全量波形

cases = [
    ("深夜待机：没人说话", True,  False, False),
    ("移动网络：流量告急", False, True,  False),
    ("会议纪要：要文字",   False, False, True),
    ("只存证据不要全文",   False, False, False),
]
for note, a, b, c in cases:
    print(f"{note} → {route(a, b, c)}")
```

四张挂号单对应四个科室。**if 台阶的顺序本身就是知识**：没人说话排第一——这一道闸门一分钱不花却省下后面全部算力；省流量排第二——传不出去一切白搭；最后才轮到「把话说完」。

### 实验 2（python）：一张表把量级钉住

```python title="语音工程师脑内必备的数量级"
print("── 时间 ─────────────")
for name, t in [("一帧语音（16 kHz/512 点）", 32e-3), ("帧移", 10e-3),
                ("男声基音周期（120 Hz）", 1 / 120), ("唤醒词四个音节", 0.8)]:
    print(f"{name}: {t * 1000:8.1f} ms")

print("── 码率 ─────────────")
for name, r in [("CD 立体声", 1411.2), ("MP3 高码率", 320),
                ("MP3 常用", 128), ("16 kHz 单声道 16 bit", 256)]:
    print(f"{name}: {r:7.1f} kbps")
```

时间一栏全部挤在 8–800 ms 之间——**语音是「一眨眼」尺度的信号**，所以一切都要分帧、都要快；码率一栏相差 9 倍，全靠心理声学把它们抹成「听起来差不多」。

### 快问快答

```quiz
要给录音笔把续航从一天提到一周，最先动用哪门课的工具？
- MFCC 特征压缩
- VAD 端点检测：没人说话就别烧电 [*]
- 神经声码器
? 续航的大头不是「算得贵」，而是「一直在算」。先把没人说话的时段整段挡掉（VAD），识别与编码才有资格谈效率——闸门先于优化。
```

::::warning[常见误区]

**误区一**："特征是老古董，端到端之后直接喂波形。"
你以为 MFCC 已经退役——三代 ASR 共享同一套前端（分帧、加窗、梅尔），端到端「端到」的是特征之后的部分。**对信号的理解没有过时，只是换了雇主。**

**误区二**："参数越多识别越准，无脑上大模型。"
你以为 $10^9$ 碾压 $10^6$——参数量与延迟、功耗、内存成正比，唤醒端跑 $10^9$ 模型电都不够。**每个场景有自己的参数预算**，地图的意义就是把「多大算够」钉在数量级上。

**误区三**："方法地图是一条通关路线。"
它是按需查阅的工具书，不是进度条。真实项目只摘用其中两三页——这张表真正想教的是**闸门顺序**：先挡掉不花钱的活（VAD / 掩蔽），再省着干（编码 / 小模型），最后才是干得好（大模型）。**顺序错了，越干越贵。**

::::

## 6. 练习

**练习 1**：分诊台的分支顺序被人调乱了，导致双重症状的需求开错科室。请扶正顺序，使输出依次是 `vad`、`vad`、`codec`：

```exercise
# @title: 练习：谁的科室单开错了
# @check: vad
# @check: vad
# @check: codec
# @hint: 没人说话时，后面所有重活都不该开工——这道闸门必须排在最前面
def route(silent, tight, want_text):
    if want_text:
        return "asr"
    if tight:
        return "codec"
    if silent:
        return "vad"
    return "mfcc"

print(route(True, False, True))    # 没人说话 + 又想要文字
print(route(True, True, False))    # 没人说话 + 流量告急
print(route(False, True, True))    # 流量告急 + 想要文字
```

**练习 2**：把一台「语音助手」端到端串起来：从你开口说「今天天气」到它回答「晴，26 度」，中间要经过哪些工序？每道工序各花多少时间预算？

<details>
<summary>点开查看逐步解答</summary>

1. **VAD**（70 课）：判断你开始说话——毫秒级，常驻；
2. **唤醒确认**（120 课）：确认是对着它说的——约 1 s 的得分窗，与说话并行；
3. **ASR**（130 课）：音频 → 文字——流式识别，边说边出字，延迟贴着说话长度走；
4. **语义处理**（LLM，不在本章）：文字 → 回答文字——大头，几百 ms 到几秒；
5. **TTS**（140 课）：文字 → 梅尔谱 → 波形——声学模型几十 ms，声码器是历史包袱（自回归 16k 次/秒前向）；
6. **延迟预算**：从「说完」到「听到回答」的体验红线约 1 s，超出就有「它死机了」的感觉。**每一道工序的时间账都要在这个红线里分。**

**这道题的价值**：语音产品不是任何一门课的胜利，是**流水线的接力**——而接力的每一棒都欠着前一棒的时间债。

</details>

## 7. 选读：三条游览路线

<details>
<summary>选读 · 不同胃口的吃法</summary>

**产品速通线**（最快做出东西）：分帧 → MFCC → VAD → 唤醒 → ASR → TTS。沿这条走完，你已经能给一台设备装上「听得见、听得懂、答得上」的最小闭环。

**信号纵深线**（语音算法工程师首选）：语谱图 → 梅尔滤波组 → MFCC → 基频 → LPC → 声码器。吃透「从波形到参数」的每一层表示，这条线直通第 61 章数字信号处理与第 49 章生成模型。

**传输纵深线**（音频平台向）：掩蔽 → 编码 → 语谱图/特征。重点不在「听懂」，而在「存得下、传得动、听着差不多」——这条线与第 35 章编码理论、第 40 章信息论汇合。

**三条线最后都汇入同一句话**：语音智能的本质不是某个模型，而是**在「算力、码率、体验」三条约束之间做取舍**——地图帮你找到工具，取舍只能靠你自己拍板。

</details>
