# 语音与音频智能

上一章让数学接上了耳朵；这一章让它接上**机器**。语音是流动的空气压强，机器只认数字特征——中间隔着一条完整的流水线：切片、拍照、按人耳加权、压成十几维系数；再往回走一遍，就是合成。这条流水线的每一站都是前五卷数学的会师点：DFT（16/61）、梅尔刻度、信息论（第 40 章）、线性预测（11）、维特比（37）、Transformer（47）、生成模型（49）。

## 方法主线

**建模 → 切片 → 拍照 → 加权 → 压缩 → 检测 → 参数化 → 编码 → 智能。**

前五课把模拟语音改造成特征：源-滤波给物理模型，分帧给分析单元，语谱图给时频照片，梅尔给人类分辨率，MFCC 给机器食物。六十到九十课提取与反转：音高、清浊、声道参数能从信号里"解"出来，也能合成回去——参数化的语音是可以双向走的。一百到一百四十课把感知与统计请上台：掩蔽决定编码策略，滑窗决定唤醒延迟，三代识别架构是同一个任务的数学化之争。

## 实战挑战 · 这段音频切出多少帧

MFCC 的第一问永远是"切多少帧"：16 kHz 采样、1.6 秒语音、帧长 25 ms、帧移 10 ms。下面这段代码把帧数算多了，修到输出 `158`：

```exercise
# @title: 实战挑战：分帧的帧数账
# @check: 158
# @hint: 最后一帧要完整放下，所以总采样数要先减去一个帧长再除以帧移；别忘了最后一帧本身要 +1
fs = 16000
dur = 1.6
frame_len = int(fs * 0.025)    # 帧长 400 个采样
frame_step = int(fs * 0.010)   # 帧移 160 个采样

n_frames = int(fs * dur / frame_step)   # ← 问题在这：没扣掉最后一帧自己的长度
print(n_frames)
```

<details>
<summary>点开查看逐步解答</summary>

1. 总采样数：$16000 \times 1.6 = 25600$；帧长 400，帧移 160；
2. 第一帧占 $[0, 400)$，下一帧从 160 起——帧起点每 160 个采样前进一次，但**最后一帧必须完整**，所以起点最远到 $25600 - 400 = 25200$；
3. 帧数 $= \lfloor 25200 / 160 \rfloor + 1 = 157 + 1 = $ **158**；
4. 验算：第 158 帧占 $[157 \times 160, 157 \times 160 + 400) = [25120, 25520)$，没有越界 ✓；第 159 帧占 $[25280, 25680)$，越界 ✗。

初始代码直接用总长除以帧移得 160——多出的两帧越过了信号末尾。分帧的"减帧长再加一"是所有短时分析（语谱图、MFCC、VAD）共同的账。

</details>
