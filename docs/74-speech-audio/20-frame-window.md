# 分帧与短时分析

## 1. 从一个场景开始

一句"今天天气不错"，按 16 kHz 采样录一秒，手里就有 16000 个数。上一课的源-滤波器模型说：谱 = 源谱 × 声道响应。可"今天天气不错"里有六七个音，每个音的声道形状都不一样——你要是对**整段**做一次傅里叶变换，得到的是这七八个音的谱**平均**：/s/ 的高频噪声和 /a/ 的共振峰搅成一锅粥，谁的形状也看不出来。

问题出在哪？源-滤波器模型有个没写出来的前提：分析期间声道形状**不变**。可人说话时舌头一直在动。

## 2. 直觉解释

办法和看电影一样。整部电影没有"一个剧情"，但**每一帧里剧情近似静止**。语音也一样：

- 声道是肉长的，从动念头到挪到位需要时间——**10 到 30 毫秒内，声道形状来不及变**；
- 所以把长信号切成 20~30 ms 的**帧**，在每一帧内部，"源×滤波器"的假设近似成立，可以放心做频谱分析；
- 帧与帧之间留重叠，保证不漏掉跨在两帧之间的变化。

这个动作叫**分帧**，这套"切短了再分析"的思想叫**短时分析**。它是语音处理（以及一切非平稳信号处理）的第一道工序。

## 3. 正式定义

对采样率为 $f_s$ 的信号 $x[n]$：

- **帧长** $N$：一帧包含的样点数，折成时长 $N/f_s$。语音常用 20~32 ms；
- **帧移** $H$：相邻帧起点相隔的样点数。常取帧长的一半（50% 重叠）或 10 ms；
- **帧数**：时长 $T$ 秒、共 $S = Tf_s$ 个样点的信号，能切出

$$K = 1 + \left\lfloor \frac{S - N}{H} \right\rfloor$$

个完整帧（起点 0 就是第 1 帧，往后每挪 $H$ 摆一帧，最后一帧必须装得下）；
- **加窗**：每帧乘上汉宁窗 $w[n]$ 等窗函数再变换——61 章讲过，不乘窗（矩形窗）旁瓣高、泄漏重。窗两端归零，这就是为什么帧与帧要重叠：单独一帧的两端信息被窗削没了，靠相邻帧补回来。

每帧做一次 DFT，就得到**短时傅里叶变换（STFT）**的第 $m$ 帧：

$$X_m(k) = \sum_{n=0}^{N-1} x[mH + n]\, w[n]\, e^{-j 2\pi k n / N}$$

两个互相牵制的分辨率：

| 量 | 公式 | 16 kHz、$N = 512$ 时 |
| --- | --- | --- |
| 频率分辨率 $\Delta f$ | $f_s / N$ | 31.25 Hz |
| 时间分辨率 | $N / f_s$ | 32 ms |

典型工作配置（16 kHz）：帧长 512 样点（32 ms）、帧移 160 样点（10 ms）——每秒 100 帧，相邻帧重叠 352 个样点（约 69%）。

## 4. 分步例题

**例 1**：1 秒 16 kHz 语音，帧长 512、帧移 160。切多少帧？

1. 总样点 $S = 16000$；
2. $K = 1 + \lfloor (16000 - 512)/160 \rfloor = 1 + \lfloor 96.8 \rfloor = 97$ 帧；
3. 每帧分辨率 $\Delta f = 16000/512 = 31.25$ Hz——足够分开 /a/ 的 $F_1 = 730$ 和 $F_2 = 1090$。

**例 2（反例）**：300 Hz 和 340 Hz 的双音，差 40 Hz。若用帧长 128 样点（@8 kHz，即 16 ms）去切，$\Delta f = 8000/128 = 62.5$ Hz > 40 Hz——**两条谱线在频谱上糊成一根**。帧长加到 512（64 ms），$\Delta f = 15.6$ Hz < 40 Hz，分开了；但 64 ms 里扫频信号已经滑出去老远，时间的细节没了。这就是窗函数那课"主瓣换旁瓣"谈判的续集：**帧长是时间分辨率与频率分辨率之间的交换券**。

## 5. 动手实验

### 实验 1（lab）：窗框拖短，双音糊死

```lab
{
  "type": "frame-window",
  "title": "拖窗框改帧长：帧太短，300 和 340 Hz 就分不开了",
  "kind": "beats",
  "frameLen": 256
}
```

上行是整段波形加可拖的窗框（灰虚线是其余帧的起点），中行是被窗掐出来的这一帧，下行是这一帧的频谱（灰虚线是矩形窗、实线是当前窗）。做三件事：

- 把帧长拖到 128 样点：下行谱上 300 和 340 Hz 糊成一根——分辨率 62.5 Hz 追不上 40 Hz 的间距；
- 拖回 512：两根谱线分开，但注意帧框已经盖住了波形里一大段——扫频信号在帧内已经"变了脸"；
- 切换窗函数看读数：矩形窗旁瓣 −13 dB、汉宁窗 −31 dB——61 章的谈判桌搬到了语音现场。

### 实验 2（python）：三套配置的帧数账

```python title="同一秒语音，三套分帧配置各切出多少帧"
fs = 16000
configs = [(512, 160), (256, 128), (1024, 512)]   # (帧长, 帧移)
for frame, hop in configs:
    n = 1 + (fs - frame) // hop        # 1 秒信号的帧数
    res = fs / frame                   # 频率分辨率（Hz）
    ms = frame / fs * 1000             # 帧长折成毫秒
    print(f"帧长{frame:>5}（{ms:4.1f} ms） 帧移{hop:>4} → 1 秒 {n:>3} 帧,"
          f" 分辨率 {res} Hz")
```

三行输出摆在一起看：帧长翻倍，分辨率减半（62.5 → 31.25 → 15.625 Hz），帧数变少、每帧时间变"钝"。工程上没有全赢的配置，只有按场景的取舍：做音高检测想要细频率就加长帧，抓爆破音的瞬间就缩短帧——30 课你会看到这两张"照片"各有名字。

::::warning[常见误区]

**误区一**："帧越长信息越多，效果一定越好。"
你以为加长帧稳赚——频率是细了，但两件事跟着坏：时间上糊掉（30 ms 里共鸣峰都滑过一轮了），且"帧内声道不变"的短时平稳假设直接崩盘。元音分析常用 32 ms，抓爆破音却要压到 5~10 ms。

**误区二**："帧移等于帧长、不重叠最省算力。"
你以为不重叠不浪费——汉宁窗两端严格为零，一帧的头尾信息被窗亲手削掉；不重叠就等于每帧两端各丢一小段。重叠 50% 以上，让每处信号都被"窗腰"（权重最高的中段）至少覆盖一次，才是省算力的正确姿势。

**误区三**："频率不够细就补零凑。"
你以为 FFT 点数越多分辨率越高——补零只是给现有谱线做插值，曲线变光滑但**真分辨率仍由真实窗长决定**（61 章的老结论）。想细就加长窗，别造假。

::::

## 6. 练习

**练习 1**：帧长 400、帧移 160，16 kHz 采 1 秒。求完整帧数，输出应为 `98`。这段代码漏了第一帧：

```exercise
# @title: 练习：一秒语音切几帧
# @check: 98
# @hint: 起点为 0 的那一帧不需要先跳一次帧移才出现——别忘了把它数进去
samples = 16000   # 1 秒 @ 16 kHz
frame = 400       # 帧长（样点）
hop = 160         # 帧移（样点）
frames = (samples - frame) // hop    # ← 问题在这：只数了"跳"出来的帧
print(frames)
```

起点 0 的帧是凭空就有的第 1 帧，之后每挪 160 样点多一帧：`frames = 1 + (samples - frame) // hop = 98`。这个"加一"是分帧计算最常见的 off-by-one。

**练习 2**：帧长 400、帧移 160 的配置，相邻两帧重叠多少样点？重叠率（占帧长的比例）是多少？若改帧长 512、帧移 160 呢？

<details>
<summary>点开查看逐步解答</summary>

1. 重叠样点 = 帧长 − 帧移：$400 - 160 = 240$，重叠率 $240/400 = 60\%$；
2. 换 512/160：重叠 $512 - 160 = 352$，重叠率 $352/512 = 68.75\%$；
3. 两套配置帧移都是 160（10 ms 一步）：每 10 ms 出一帧分析结果，这是实时语音识别的常见节拍——帧移定**出结果的节奏**，帧长定**每次往回看多远**。

</details>

## 7. 选读：为什么帧移取半窗长"刚刚好"

<details>
<summary>选读 · COLA 条件与无损合成的预告</summary>

把分帧加窗的帧重新叠回去能还原原信号吗？汉宁窗 $w[n] = 0.5 - 0.5\cos(2\pi n/(N-1))$ 有个漂亮的性质：**帧移取半窗长时，相邻窗错位相加，处处约等于 1**（严格等于 1 要把窗按周期化约定稍作修正，即 COLA 条件——overlap-add 的缩写）。

于是"加窗 → 分析 → 逆变换 → 逐帧错位相加"可以近似无损地走一个来回。这件事现在是语音增强、降噪的常规套路（STFT 域处理），而它成立的前提就藏在今天的分帧参数里：**帧移不能超过半窗长太多**。第 90 课的声码器把语音拆成参数再合成，走的也是这条路。

</details>
