# 语音识别概貌：从 HMM 到端到端

## 1. 从一个场景开始

两小时的会议录音，要变成一份可以搜索的文字稿。唤醒词那套「像不像」的判卷不够用了——识别要回答「**是哪个字、按什么顺序**」。

同一个任务，三代人用三种完全不同的数学化方式啃过它：1990s 的 HMM+GMM、2015s 的 CTC+深度网络、2020s 的端到端 Transformer。本课不讲技术史，而是把三代摆在同一张解剖台上问一个问题：**它们各自把「对齐」这个难题藏在了哪里？**

## 2. 直觉解释

先看清难题本身。语音每 10 ms 一帧，1 秒就是 100 帧；「你好」只有 2 个字。识别要从 100 帧里读出 2 个字——**帧和字对不上号**：哪几帧属于「你」，哪几帧属于「好」，没有现成答案。

穷举一下就知道为什么必须巧干：假设每帧有 6 种 token 可选，1 秒就有 $6^{100} \approx 6.5\times10^{77}$ 条候选路径——比可观测宇宙的原子还多。三代的分野，就是三种「不枚举」的解法：

- **一代（HMM）**：把对齐交给**隐状态**——每个音素是一串必须从左往右走的状态，维特比算法在状态图上找最优路径（第 37 章的数学原封不动搬过来）；
- **二代（CTC）**：干脆不做显式对齐——让网络逐帧分类，再发明一个**空白符**把「帧级答案」坍缩成字；
- **三代（端到端）**：把对齐交给**注意力**——帧与字直接互相「看对眼」，软对齐由数据自己学出来。

三种数学化，同一个任务。工具换了三代，**问题的骨架没变**。

## 3. 正式定义

三代流水线（参数量级是数量级感知，不是精确值）：

| 代 | 流程 | 对齐机制 | 参数量级 | 哲学 |
| --- | --- | --- | --- | --- |
| ① HMM+GMM（1990s） | 分帧+MFCC → GMM 逐帧打分 → 维特比对齐 → 词典+语言模型 | 隐状态路径 | 约 10⁶ | 生成式：算 $P(\text{音频}\mid\text{音素串})$ |
| ② CTC/RNN-T（2015s） | 分帧+FBank → 深度网络逐帧出 token 分布 → CTC 坍缩 | 空白符坍缩 | 约 10⁸ | 判别式：直接学 $P(\text{token}\mid\text{帧})$ |
| ③ 端到端 Transformer（2020s） | 特征 → 编码器自注意力 → 解码器逐 token 生成 | 注意力软对齐 | 约 10⁹ | 直接学 $P(\text{文本}\mid\text{音频})$ |

**CTC 坍缩规则**（本课的主角）：贪心取每帧概率最大的 token，得到一串帧级答案，然后两步坍缩：

1. **合并相邻重复**——同一个 token 连占多帧只算一个；
2. **删掉空白符 ⊔**——它表示「这一帧什么都不是」。

空白符一符两用：既给「说不清的帧」一个去处，又给**真重复**留活口——想输出两个 l，中间必须夹至少一帧 ⊔，否则合并步会把它们吞成一个。

## 4. 分步例题

**例 A**：贪心解码得到帧序列 `n n ⊔ i ⊔ h h h a a ⊔ o`，坍缩成什么？

1. 合并相邻重复：`n ⊔ i ⊔ h a ⊔ o`；
2. 删空白符：`nihao`。

注意第 1 步删掉的三个 h 里的两个——它们是「一帧一个 h」被拉长成了三帧，正是对齐不精确的正常表现。

**例 B**：帧序列 `m a a` 想输出「maa」，坍缩得什么？

1. 合并相邻重复：`m a`——**重复的 a 被吞了**；
2. 正确姿势：`m a ⊔ a` → 合并（无相邻重复）→ 删空白 → `maa`。

空白符不是可有可无的填充物，它是重复字母与「帧拉长」之间唯一的裁判。

- 一代点「GMM 打分」：看每帧对每个音素的似然曲线——这就是维特比要吃的输入；
- 一代点「HMM 对齐」：看状态路径怎么把 100 帧切成 5 段音素；
- 二代点「CTC 坍缩」：看概率热图上贪心路径怎么穿过空白符墙，去重删空白后变成 `nihao`；
- 三代点「注意力」：看帧与字的对角亮带——对齐不再是一条硬路径，而是一片软软的权重。

拖时间光标（波形条上左右拖），每一级视图同步高亮当前帧正在发生什么。

### 实验 2（python）：把 CTC 坍缩写成代码

```python title="坍缩两步：合并相邻重复、删空白符"
def collapse(frames):
    out, prev = '', ''
    for t in frames:
        if t != prev and t != '⊔':
            out += t
        prev = t
    return out

# 例 1：贪心帧序列 → 「你好」的拼音
print(collapse(['⊔', 'n', 'n', '⊔', 'i', '⊔', '⊔', 'h', 'a', 'a', '⊔', 'o']))
# 例 2：真重复必须靠空白符隔开
print(collapse(['m', 'a', 'a']))          # 想要 maa，重复的 a 被吞掉一个
print(collapse(['m', 'a', '⊔', 'a']))     # 空白符隔开，maa 保住了
```

三行输出依次是 `nihao`、`ma`、`maa`——例 2 就是空白符存在意义的自证。真实系统的解码远比贪心讲究（束搜索 + 语言模型打分），但**坍缩这两步是所有 CTC 解码共享的内核**。

### 快问快答

```quiz
CTC 坍缩会合并相邻重复的 token。要识别英文单词 hello 里连续的两个 l，靠什么？
- 没办法，CTC 天生识别不了重复字母
- 在两个 l 之间插入至少一帧空白符 ⊔ [*]
- 把单词表里所有含重复字母的词删掉
? 坍缩规则是「合并相邻重复、删掉空白」两步，所以空白符兼任分隔符：l l 中间夹一帧 ⊔，合并后恰好剩下两个 l。空白符一符两用——既表示「这帧什么都不是」，又给真重复留活口。
```

::::warning[常见误区]

**误区一**："端到端 = 什么都不用懂，特征是老古董。"
你以为三代抛弃了 MFCC——其实 FBank/MFCC 至今是三代共同的前端，变的不是「要不要特征」，而是「特征之后交给谁」。对语音信号的理解（分帧、加窗、梅尔刻度）没有过时。

**误区二**："贪心解码就是 CTC。"
你以为每帧取最大概率就完事——贪心只是教学捷径。真实解码用束搜索保留多条候选，再用语言模型给整句打分，才能纠出「同音不同字」的错误。**局部最优拼不出全局最优**，这句话在语音里同样成立。

**误区三**："三代是简单的取代关系，老的没用。"
你以为参数量决定一切——低功耗端 HMM 家族的小模型至今在服役：参数量与延迟、功耗、内存成正比，唤醒端 10⁶ 参数刚刚好。**不是越新越好，是越合适越好。**

::::

**练习 1**：下面的坍缩只做对了一半，把它补完整：

```exercise
# @title: 练习：坍缩只做了一半
# @check: nihao
# @hint: CTC 的坍缩是两步：合并相邻重复、删掉空白符。初版只做了第一步
frames = ['n', 'n', '⊔', 'i', '⊔', 'h', 'h', 'h', 'a', 'a', '⊔', 'o']
# 贪心解码：每帧取概率最大的 token，得到上面这串

out = ''
prev = ''
for t in frames:
    if t != prev:
        out += t        # ← 相邻重复合并了，但空白符 ⊔ 还混在里面
    prev = t

print(out)
```

**练习 2**：一代识别把「shì shì」两个音节翻成文字时，为什么必须有语言模型？

<details>
<summary>点开查看逐步解答</summary>

1. 声学层面（GMM + HMM）只能告诉你「这串帧像哪些音素」，音素串 shì-shì 对应**几十个候选词**：试试、世事、逝世、史诗……声学模型分不出胜负；
2. 语言模型按**词序列概率**排序：「试试看」在语料里远比「逝世看」常见，于是挑出「试试」；
3. 这就是一代流水线最后一格「词典 + 3-gram 语言模型」的全部职责——**声学管「像什么音」，语言模型管「像不像人话」**；
4. 三代端到端没有独立的语言模型格子，但注意力解码器在训练中自己「读」过了海量文本，把这一职责内化了——职责没有消失，只是搬了家。

</details>

## 7. 选读：流式识别为什么要 RNN-T

<details>
<summary>选读 · CTC 的短板与 RNN-T 的补丁</summary>

CTC 有个隐藏假设：**给定音频，各帧输出条件独立**。这带来一个尴尬——它天生不会「边听边想」：输出每一帧 token 时，看不到自己前几帧说了什么。离线转写无所谓（整段听完结完），但**流式识别**（边说边出字幕）必须记住上文。

RNN-T（RNN Transducer）在 CTC 的编码器旁边加了一个**预测网络**：每出一帧答案，先「回忆」自己刚说过什么，再联合编码器的声学信息决定这一帧输出 token、空白符还是沉默。代价是解码状态空间变成「声学帧 × 已输出 token」的二维网格，计算更贵——**用算力买「记住上文」的能力**，这笔交换在实时字幕、语音输入法上是划算的。

</details>
