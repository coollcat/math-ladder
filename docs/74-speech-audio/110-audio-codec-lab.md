# 音频编码：MP3/AAC 的取舍

## 1. 从一个场景开始

一首 4 分钟的歌，按 CD 规格存下来是 42 MB；换成 128 kbps 的 MP3，只剩 3.8 MB——砍掉了 90% 以上，绝大多数人却听不出差别。

省下来的 90% 不是靠「算得更聪明」，而是把上一课的心理声学变成了产品逻辑，一句话：**凡是落在掩蔽阈值以下的东西，丢了也听不出来——那就别编码它。** 这就是「感知编码」的全部灵魂。

## 2. 直觉解释

把编码器想成一个**分预算的会计**。CD 时代的会计很笨：每个样本都发 16 bit，安静的段落和激烈的段落一个价。感知编码的会计聪明在两件事：

- **按需付费**：每个临界频带（上一课的 Bark 刻度）单独报价。被强音掩蔽的频带，噪声可以放得很高，几乎不花钱；花钱的是强音两侧的「裙边」——那里听得到噪声，必须压到阈值以下。
- **不够就砍**：预算花不完皆大欢喜；预算不够时，编码器**从高频往低频砍**——先牺牲带宽（20 kHz 的上限一路退到几 kHz，声音「发闷」），实在不够才让临界带里冒出可听噪声。

量化精度的账很好算：每 1 bit 约买来 6 dB 信噪比（6.02 dB/bit）。

## 3. 正式定义

**码率**（bitrate）：每秒花掉多少比特。CD 未压缩的码率是三个数的乘积：

$$\text{码率} = \text{位深} \times \text{采样率} \times \text{声道数} = 16 \times 44100 \times 2 = 1411.2\ \text{kbps}$$

**量化信噪比**：给一个样本 $n$ bit，理想量化噪声下的信噪比约为

$$\text{SNR} \approx 6.02\,n \ \text{dB} \qquad \Longleftrightarrow \qquad n = \frac{\text{SNR}}{6.02}$$

**频带开销**：一条带宽 $B$（Hz）的临界频带，若需把噪声压到阈值以下 $\text{SNR}$ 分贝，每秒要付

$$\text{开销} = B \times \frac{\text{SNR}}{6.02} \ \text{bit/s}$$

**安全余量**（margin）：掩蔽阈值是**估**出来的，估错一点噪声就露馅。真实编码器把噪声压到阈值以下再多压几个 dB（常用 6 dB），这就是余量。

**文件体积**：码率 × 时长 ÷ 8。128 kbps 存 240 秒：$128000 \times 240 / 8 = 3.84$ MB。

## 4. 分步例题

**例 A**：同一首 4 分钟的歌，CD 与 MP3 各占多少地方？压缩比多少？

1. CD：$1411.2\ \text{kbps} \times 240\ \text{s} \div 8 = 42.34$ MB；
2. MP3：$128\ \text{kbps} \times 240\ \text{s} \div 8 = 3.84$ MB；
3. 压缩比 $1411.2 / 128 \approx 11$ 倍——省下的 90% 全部来自「阈值以下的样本不付费」。

**例 B**：一条 700 Hz 宽的临界频带，强音掩蔽前需要 48 dB 信噪比，掩蔽后只需要 12 dB。开销省了多少？

1. 掩蔽前：$700 \times 48 / 6.02 \approx 5581$ bit/s；
2. 掩蔽后：$700 \times 12 / 6.02 \approx 1395$ bit/s；
3. **省了 4 倍**——而耳朵听不出任何差别。掩蔽每抬高 6 dB，这条带就省 1 bit。

## 5. 动手实验

### 实验 1（lab）：把码率拖到 64 kbps，看高频怎么被整片砍掉

```lab
{
  "type": "audio-codec-lab",
  "title": "左右拖码率尺，看预算不够时高频是怎么被整片划掉的",
  "bitrate": 128,
  "complexity": 0.45,
  "margin": 6
}
```

图上有三条线：素材自己的频谱、掩蔽阈值 $T(f)$、以及当前码率下的量化噪声。做三件事：

- 把码率从 320 拖到 64 kbps——看噪声台阶整体上抬，右侧高频**先整片被划掉**（带宽牺牲），再不够才在带内冒出可听噪声；
- 拖「素材复杂度」到 0.8（交响、摇滚那类）——高频内容变多，同样的码率立刻捉襟见肘：**复杂段落比独奏难压**；
- 把「安全余量」拖到 0——码率省下一大截，但读数会提醒你：阈值是估出来的，估错就露馅。

### 实验 2（python）：码率与体积的换算尺

```python title="同一首歌，五档码率"
for kbps in [1411.2, 320, 128, 64, 32]:
    mb = kbps * 1000 * 240 / 8 / 1e6    # 4 分钟 = 240 秒
    print(f"{kbps:>7.1f} kbps → 4 分钟 {mb:6.2f} MB")
```

第一行与最后一行差 44 倍——从「母带级」到「电话音质」全在这条尺上。注意 128 与 64 之间只差一倍码率，听感却常常天差地别：**64 kbps 时高频已经被砍光了**。

### 实验 3（python）：给五条频带分预算

```python title="按需付费：每条临界频带的开销"
bands = [
    ("强音所在带",  100,  8),     # (带宽 Hz, 需要的 SNR dB)
    ("强音下裙边",  160, 48),     # 裙边听得到噪声，最贵
    ("中频主体",    700, 42),
    ("高频裙边",   2000, 18),
    ("空气感高频", 8000,  6),     # 阈值本来就低，随便糊
]
budget = 64000                       # 单声道预算：128 kbps 立体声对半
total = 0
for name, b, snr in bands:
    cost = b * snr / 6.02
    total += cost
    print(f"{name}: {b:>5} Hz × {snr:>2} dB → {cost:7.0f} bit/s")
print(f"合计 {total:7.0f} bit/s，预算 {budget} bit/s")
```

合计约 2 万 bit/s，远低于 64 kbps 的单声道预算——这个素材在这种模型下是「便宜」的。但别高兴太早：**带宽 8000 Hz 的「空气感」频带一条就吃掉 7973 bit/s**，是强音所在带的约 60 倍。预算一紧，第一个被砍的就是它。真实编码器算出的「透明码率」比这个玩具模型高（约 128–160 kbps），因为它还要付立体声冗余、瞬态、边信息这些本模型没算的账。

### 快问快答

```quiz
把码率从 320 kbps 一路拖到 64 kbps，最先牺牲的是什么？
- 音量变小
- 高频带宽：20 kHz 的上限一路退到几 kHz，声音「发闷」 [*]
- 左右声道合并成单声道
? 编码器的刀法是「先砍带宽、再冒噪声」：预算不足时从高频往低频整片划掉，截止频率从 20 kHz 退到 5 kHz。这就是低码率 MP3「发闷 + 高频嘶声」的来历——闷在先，噪声在后。
```

::::warning[常见误区]

**误区一**："MP3 是把声音「压缩」得小声了。"
你以为压缩就是衰减——其实 MP3 **丢的是信息**：把掩蔽阈值以下的频谱成分直接量化成噪声，音量一格没变，变的是「保真度」。这也是 MP3 无法「还原」的原因：丢掉的东西没存。

**误区二**："码率越高一定越好听。"
你以为 320 kbps 全面碾压 128——过了**透明阈值**之后，码率涨上去耳朵已经收不到差别了，多付的全是钱。工程上的正确问法是「这个场景的透明阈值在哪」，而不是「越高越好」。

**误区三**："掩蔽阈值是精确算出来的科学。"
你以为编码器算出的 $T(f)$ 分毫不差——它依赖人耳模型的近似（临界带宽度、扩展函数、监听音量）。所以才有安全余量：**余量是给「模型不准」买的保险**，调到 0 省码率等于裸奔。

::::

**练习 2**：一张 700 MB 的 CD，如果只按 128 kbps 存 MP3，能装多少分钟的歌？

<details>
<summary>点开查看逐步解答</summary>

1. 总比特数：$700\times10^6\ \text{字节} \times 8 = 5.6\times10^9$ bit；
2. 时长：$5.6\times10^9 / 128000 = 43750$ 秒；
3. 换成分钟：$43750 / 60 \approx 729$ 分钟 ≈ **12 小时**。

对比未压缩：$5.6\times10^9 / 1411200 \approx 3968$ 秒 ≈ 66 分钟——**一张 CD 的容量从一张专辑变成一个有声书专柜**，这就是 MP3 革命的全部数学。

</details>

## 7. 选读：真实编码器还付哪三笔账

<details>
<summary>选读 · 玩具模型与真实 MP3 之间的距离</summary>

本课的模型只算了「每条带的量化开销」，真实编码器还有三笔大开销：

- **立体声联合编码**：左右声道高度相似，改存「中置 + 侧向」（M/S）通常比存两份省一半——只在相似时才这么干，所以叫「联合」；
- **瞬态处理**：鼓点一响，长窗里的量化噪声会**提前**漏出来（预回声），编码器得临时切换到短窗，边信息随之变贵；
- **熵编码**：分好配额的量化值还要再压一遍——哈夫曼编码给高频出现的值发短码。这一手在第 35 章的[编码理论](../35-coding-theory/index.md)里有整套数学。

三笔账加起来，才把「透明码率」从玩具模型的几十 kbps 推到工程实际的 128–160 kbps。**模型省略的每一项，都是真实世界的一张账单。**

</details>
