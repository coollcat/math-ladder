# 张量与 einsum

## 1. 从一个场景开始

一个图像识别模型一次要吞下 100 张彩色照片。每张照片宽 224 像素、高 224 像素、每像素有红绿蓝三个格子——于是这批数据是一个四层的嵌套盒子：100 个文件夹 × 每个文件夹 224 行 × 224 列 × 3 格颜色，足足一千五百万个数排成规整的阵列。向量只够描述一条线上的队列，矩阵只够铺一张平面表格；面对这种"盒子套盒子再套盒子"的数据家族，我们需要一套通用的**命名、运算与记账语言**——这门语言叫张量，而它的速记笔法叫 einsum。

## 2. 直觉解释

先沿着熟悉的台阶往上爬：

- **0 阶**：单独一个数，比如今天的气温 31 度；
- **1 阶**：一串数排成队，比如一天 24 小时的温度记录；
- **2 阶**：数排成表格，就是矩阵——你已经跟它打了很久交道；
- **3 阶**：一沓表格摞起来，像一叠发票；
- **4 阶以上**：整箱发票、整个档案室……每加一阶就多一层"第几号"的索引。

所以从机器学习的日常角度说：**张量就是"随便多少维的规则数组"这个名字**。矩阵是它的二阶特例——在下面的实验里你会先跟这位老朋友重逢。

但真正让它们区别于普通数表的，是另一件事：张量自带"变身协议"——当基向量换了坐标系，它的分量按确定的规则跟着换装（向量换个坐标系分量会变，数值本身的含义不变）。本章主战场放在数组的实际操作上，变身规则的严格叙述留给选读与后续课程。

至于 einsum，它不是新运算，而是**一种下标记账法**：写下每个维度的名字，让重复的名字自动求和、剩下的名字留在答案上。矩阵乘法、内积、转置、批量相似度……全是同一支笔写出的不同句子。

## 3. 正式定义

| 记号 | 含义 |
| --- | --- |
| $A_{ij}$ | 二阶张量的元素：第 $i$ 行第 $j$ 列 |
| $T_{ijk}$ | 三阶张量的元素：三层编号 $\times$ 行 $\times$ 列 |
| 求和指标 | 在乘积里**出现两次**的下标（如 $j$），按约定自动对它求和 |
| 自由指标 | 只出现一次的下标，原样保留到结果 |

爱因斯坦求和约定：同一项里重复出现的下标自动求和，记号省略 $\Sigma$。比如

$$C_{ik}=\sum_j A_{ij}B_{jk}\quad\text{简写作}\quad C_{ik}=A_{ij}B_{jk}.$$

einsum 把这套约定搬进代码，读法只有三条：

1. **逗号分 ingredients**：`'ij,jk->ik'` 表示拿两个张量，各轴贴好字母标签；
2. **重复标签=压缩**：两侧共同出现的 `j` 被沿该轴求和，尺寸必须相等；
3. **箭头后=输出的形**：没被压掉的标签按箭头后的顺序排好；完全不写的自由下标也照样留下（省略模式）。

于是全部常见操作被统一成一张便签：

| 操作 | einsum | 形状变化 |
| --- | --- | --- |
| 内积 | `i,i->` | $(n)\times(n)\to()$ |
| 迹 | `ii->` | $(n,n)\to()$ |
| 外积 | `i,j->ij` | $(m)\times(n)\to(m,n)$ |
| 矩阵乘 | `ij,jk->ik` | $(m,n)\times(n,p)\to(m,p)$ |
| 批量逐行点积 | `ij,ij->i` | $(b,n)\times(b,n)\to(b)$ |

## 4. 分步例题

手算一遍矩阵乘法的"记账全过程"。取

$$A=\begin{pmatrix}1&2&0\\0&1&1\end{pmatrix},\qquad B=\begin{pmatrix}2&1\\0&1\\1&0\end{pmatrix}.$$

1. 写出记号 `'ij,jk->ik'`：$j$ 重复 → 沿 $A$ 的列、$B$ 的行求和；
2. $C_{11}=a_{11}b_{11}+a_{12}b_{21}+a_{13}b_{31}=1\times2+2\times0+0\times1=2$；
3. $C_{12}=1\times1+2\times1+0\times0=3$；
4. $C_{21}=0\times2+1\times0+1\times1=1$，$C_{22}=0\times1+1\times1+1\times0=1$；
5. 所以 $C=\begin{pmatrix}2&3\\1&1\end{pmatrix}$——这就是稍后代码将打印的结果。

### 实验 2 · 一支笔写出五种运算

```python title="einsum 五连击"
import numpy as np                       # 数值计算库，np 是惯用别名

A = np.array([[1, 2, 0], [0, 1, 1]])     # 造一个 2x3 矩阵
B = np.array([[2, 1], [0, 1], [1, 0]])   # 造一个 3x2 矩阵
C = np.einsum('ij,jk->ik', A, B)         # 矩阵乘：j 被压缩求和
print(C.tolist())                        # tolist 把数组转成普通列表方便打印

v = np.array([3, 4])                     # 向量 v
w = np.array([2, 1])                     # 向量 w
print(int(np.einsum('i,i->', v, w)))     # 内积：i,i 相乘后全压掉，剩标量

M = np.array([[2, 0], [0, 5]])           # 对角阵
print(int(np.einsum('ii->', M)))         # 迹：对角线自己配对自己求和
```

三次输出分别是 `[[2, 3], [1, 1]]`、`10`、`7`——与例题的手算完全咬合，内积 $3\times2+4\times1=10$、迹 $2+5=7$ 也当场验讫。注意这三行代码调用的是**同一个函数** `np.einsum`，变的只是那串下标字符串：这就是"通用语言"的含义。

## 6. 常见误区

:::warning[常见误区]
- **你以为张量只是花哨的多维数组，其实名字里有承诺**：物理学里的张量额外携带坐标变换规则，换基时分量照协议变装；工程语境下"多维数组"是它的数据载体这一面。两者是同一枚硬币的字与面，别混成一枚空壳。
- **你以为 einsum 是某种黑魔法函数，其实它只是把双循环摊开给你看**：`'ij,jk->ik'` 展开就是三重循环——外两层填 $i,k$，最内层沿 $j$ 累加。读懂这一点，任何离谱的长句都能人肉展开。
- **你以为标签字母有意义，其实只有位置和重复情况有意义**：把 `'ij,jk->ik'` 改写成 `'ab,bc->ac'` 语义一字不差。标签就像局部变量名，唯一的硬约束是"重复的对齐要对得上、尺寸要相等"。
:::

## 7. 练习

注意力机制里最关键的一步是把查询组 Q 与键组 K 做逐行互点：得分表第 $i$ 行第 $k$ 列等于 Q 的第 $i$ 行与 K 的第 $k$ 行的点积（相当于 einsum `'ij,kj->ik'`）。下面的实现却把它写成了普通矩阵乘积 Q·K（即 `'ij,jk->ik'`），请修正累加那一行的下标：

```exercise
# @title: 修好注意力得分表的下标
# @check: [5, 4]
# @check: [1, 2]
# @hint: 目标是"Q 的行 × K 的行"互相点积；每个 K 参与的乘积应当取 K[k][j]——第二个下标是行号 k，而不是循环列 j。
Q = [[1, 2],
     [0, 1]]        # 两行查询向量：两个词 × 2 维
K = [[3, 1],
     [0, 2]]        # 两行键向量

S = []                      # 得分表：2x2
for i in range(2):          # i：Q 的第几行
    row = []
    for k in range(2):      # k：K 的第几行
        s = 0
        for j in range(2):  # j：沿维度逐格累加
            s = s + Q[i][j] * K[j][k]   # ← 这是 Q·K，不是逐行互点
        row.append(s)       # s 收进行尾
    S.append(row)           # 整行收进 S
print(S[0])
print(S[1])
```

<details>
<summary>点开查看逐步解答</summary>

错误版本走的是 `'ij,jk->ik'`：累加的是 `Q[i][j]*K[j][k]`，K 以**列身份**参与——等价于 Q·K。逐格核账：第一行得 $1\times3+2\times0=3$、$1\times1+2\times2=5$，凑出 [[3, 5], …]，恰好不是想要的表。

目标语义 `'ij,kj->ik'` 要求 K 的两个下标顺序反过来：累加 `Q[i][j]*K[k][j]`——让 K 以**行身份**参与，`k` 出现两次、落在压缩位之外的自由位置上。修改一行：

```python
s = s + Q[i][j] * K[k][j]   # 'ij,kj->ik'：Q 第 i 行点积 K 第 k 行
```

修好后输出 `[5, 4]` 与 `[1, 2]`。手验第一行：Q 第一行 (1,2) 点 K 第一行 (3,1) 得 $3+2=5$，点 K 第二行 (0,2) 得 $0+4=4$ ✓。这张 2×2 的迷你得分表，正是大模型里注意力打分的原子动作——千卡并行算的张量巨阵，跑的就是这条三重循环。

</details>

```quiz
把矩阵乘法写成 einsum 'ij,jk->ik' 时，下标 j 同时出现在两个输入里，它在数学上表示什么？
- 把 A 与 B 中 j 位置的元素直接相减
- 沿 j 这个公共轴做加权求和，把它压缩成单个数 [*]
- j 只是装饰，可以随意删去
? j 重复出现触发爱因斯坦求和约定：对 A 的列方向与 B 的行方向同时扫过并累加，这正是矩阵乘法定义里那个 Sigma。
```

## 8. 边界与选读

本课立起的是**数据视角**的张量地基：多维数组 + einsum 记账。尚未登场的部分也要认得出边界：真正的张量分析（应力张量、黎曼曲率）关心的是坐标变换下的完整变身规则与协变导数，那是更深一层楼的课程；张量积这种"从两个空间合成一个大空间"的结构在第 59 章有自己的专座；卷积层内部的黑科技（im2col、稠密分块）也只是本课记号的下游应用，不在本课展开。

<details>
<summary>选读 · "变身协议"是什么意思</summary>

同一个物理向量 $\vec v$ 在旧基下写成 $(v_1,v_2)$，换一套新基后分量普遍会变成另外两个数——但所指的箭头从未改变。分量值会随基旋转，而"哪个下标平着变、哪个下标跟着基反向变"有严格分工：向量的分量随基**逆变**（新基短了分量就得变长），线性泛函的分量随基**协变**。协变下标习惯写在下方、逆变下标写在上方，$g_{ij}$ 这类带双侧指标的机器因此得名"张量"。einsum 里 `'ij,jk->ik'` 触发的压缩，在正统记号里正是"上下同标相消"（一对逆变接一对协变），于是不同分支学科的书页在这一刻悄悄打通。深度学习框架不区分上下标（大家默认用的是标准正交基，两种变装长得一模一样），这也是实战教材干脆只用 ASCII 小写字母的原因。

</details>
