# A/B 测试实战：从分组到决策

## 1. 从一个场景开始

2007 年 12 月，奥巴马竞选团队的总部分成两派：顾问们坚信首页放上竞选演讲视频最能打动访客；数据分析负责人西罗克（Dan Siroker）坚持让数据说话。他们把访客**随机**分成两组，各看一个版本的页面——这就是 A/B 测试。结果：视频版比原图差了三成，而最终胜出的组合把注册率提升了四成。

A/B 测试就是把假设检验装进生产线：随机分组保证公平比较，统计检验防止把噪音当成战果。这一课走完它的全流程。

## 2. 直觉解释

一次合格的 A/B 测试像一场双盲临床试验：

- **随机分组**是灵魂。老访客看 A、新访客看 B？那测的是新旧，不是版本好坏。抛硬币分组才能让两组人除版本外"平均而言一模一样"；
- **提前定样本量**是纪律。比较两个比例时，能探测到的最小差距随 $\sqrt{n}$ 缩小（又是平方根律）——样本太小，再大的提升也会淹没在噪音里；
- **一次测一个改动**是卫生习惯。同时改按钮和配色，赢了不知道该谢谁；
- **跑完再看结果**是底线。每偷看一次就多掷一次骰子，假阳性概率一路膨胀（详见本课误区三）。

流程五步：**定指标 → 算样本量 → 随机分流 → 收满数据 → 检验裁决**。

## 3. 正式定义

比较两组转化率 $p_A$ 与 $p_B$（各 $n$ 人）：

$$\hat{p}_{pool}=\frac{x_A+x_B}{n_A+n_B}, \qquad \mathrm{SE}=\sqrt{\hat{p}_{pool}(1-\hat{p}_{pool})\left(\frac{1}{n_A}+\frac{1}{n_B}\right)}, \qquad z=\frac{\hat{p}_B-\hat{p}_A}{\mathrm{SE}}$$

| 符号 | 名字 | 含义 |
| --- | --- | --- |
| $\hat{p}_A,\hat{p}_B$ | 两组观测转化率 | 各自的成功人数除以各自人数 |
| $\hat{p}_{pool}$ | 合并转化率 | 假设两版无差别时，对共同转化率的最佳估计 |
| $\mathrm{SE}$ | 差值的标准误 | 差距的抖动幅度 |
| **功效** $1-\beta$ | 统计功效 | 效应真存在时能被检出的概率（常取 80%） |

**样本量经验公式**（80% 功效、95% 显著性下的速算）：每组人数

$$n \approx \frac{16 \times \bar{p}(1-\bar{p})}{\delta^2}$$

其中 $\bar{p}$ 是大致的基线转化率、$\delta$ 是你想可靠探测的提升幅度。系数 16 来自 $(1.96+0.84)^2\times 2\approx15.7$ 的工程取整：前一项管 95% 显著性，后一项管 80% 功效，乘 2 计入两组各自的噪音。

## 4. 分步例题

**例**：现有按钮转化率约 15%，团队想检测出 7 个百分点的提升（$\delta=0.07$），每组要多少人？

1. 基线项：$\bar{p}(1-\bar{p})=0.15\times 0.85=0.1275$；
2. 分子：$16 \times 0.1275=2.04$；
3. 除以效应量平方：$2.04/0.07^2=2.04/0.0049\approx 416$；
4. 结论：每组约 420 人，共约 840 人。若只想检测 3.5 个百分点（减半），人数要乘 4——约 1660 人一组。**想看清更小的差异，代价按平方反比暴涨。**

### 实验 2（python）：置换检验——不查表也能算 p 值

A 组 100 人成交 12 单，B 组 100 人成交 23 单，提升 11 个百分点。这是真效果还是运气？把"标签不重要"的世界模拟五千遍：

```python title="打乱标签五千次：纯运气能造出多大差距"
import random                     # 随机库

outcomes = [1] * 12 + [0] * 88    # 列表乘法：[1]*12 是把 1 重复 12 次（首见写法）
outcomes = outcomes + [1] * 23 + [0] * 77   # 再接上 B 组名单，合并成一池

diffs = []                        # 存每次打乱后算出的组间差
for trial in range(5000):
    shuffled = outcomes[:]        # 切片 [:] 不带数字 = 复制整个列表，避免改动原名单
    random.shuffle(shuffled)      # shuffle：原地打乱列表顺序（首见），模拟重新随机分组
    group_a = shuffled[:100]      # 切片：前 100 个当 A 组
    group_b = shuffled[100:]      # 后 100 个当 B 组
    rate_a = sum(group_a) / 100   # sum 对 0/1 列表求和 = 成交数
    rate_b = sum(group_b) / 100
    diffs.append(rate_b - rate_a)

count_ge = 0                      # 数出运气差距不低于实测 0.11 的次数
for d in diffs:
    if d >= 0.11:
        count_ge = count_ge + 1

print(f"经验 p 值 = {count_ge / 5000}")
```

p 值约 0.03：纯运气大约只有百分之三的概率造出这么大的差距。注意这套**置换检验**完全没用到正态近似和查表——靠"重新洗牌"直接生成零假设世界，是小样本场景的好帮手。

### 快问快答

```quiz
实验跑到第 3 天，B 版领先 8 个百分点，p 值 0.03。正确的做法是？
- 立刻停止实验，宣布 B 获胜
- 按原计划收满预定样本量后再裁决 [*]
- 立刻停止实验并反向押注 A
? 提前偷看等于反复掷骰子取最好成绩：检验的红线是按「只裁一次」设计的，多次偷看会让假阳性率远超 5%。要么事先定好序贯规则，要么忍到收满。
```

:::warning[常见误区]

**误区一**："你以为提升 40% 就一定很惊人。" 相对提升要看基数：注册率从 8.26% 到 11.6% 是 40% 的相对提升，但绝对差距只有 3.3 个百分点。汇报时两个数都要给，否则极易夸大。

**误区二**："你以为随机分组可有可无。" 分流不随机，一切白搭：时段不同、渠道不同、新老用户比例不同，都会制造出比真实效应更大的偏差。A/B 测试九成的翻车事故在分组环节就已注定。

**误区三**："你以为随时看结果不花任何成本。" 每多看一次就多一次踩中假阳性的机会：若每天偷看并见好就停，实际假阳性率可以从 5% 膨胀到百分之几十。纪律不是仪式感，是统计性质本身的要求。

:::

## 6. 练习

**练习 1**：A 版 100 位访客 12 位注册，B 版 100 位访客 23 位注册。求提升的百分点数与合并注册人数，并用简化判据（差距是否超过 $1.96 \times \mathrm{SE}$，SE 用本课公式）判断显著性。下面的代码能跑但输出不对——改到通过：

```exercise
# @title: 练习：A/B 结果裁决
# @check: 11
# @check: True
# @hint: 提升百分点 = B 的注册数 - A 的注册数；显著判据是 diff > 1.96 * se（大于，不是小于）
import math   # 开方用

xa, na = 12, 100    # A 版：注册数与访客数
xb, nb = 23, 100    # B 版

ppool = (xa + xb) / (na + nb)                       # 合并转化率
se = math.sqrt(ppool * (1 - ppool) * (1/na + 1/nb)) # 差值的标准误

lift_pp = xa - xb                 # ← 第一处问题：谁减谁？
print(lift_pp)
sig = lift_pp / 100 < 1.96 * se   # ← 第二处问题：显著应该是「差距大」还是「差距小」？
print(sig)
```

**练习 2**：基线转化率 5%，想检测 1 个百分点的提升，每组约需多少人？

<details>
<summary>点开查看逐步解答</summary>

$n\approx 16\times 0.05\times 0.95/0.01^2=0.76/0.0001=7600$ 人每组。基线越低，同样的百分点提升相对越难确认——低流量产品做转化实验前先做这道算术，避免跑两周发现样本量差一个数量级。

</details>

**练习 3**：产品经理提议"同时上三个新设计，哪个数据好就用哪个"。从多重比较角度指出风险并给出补救方案。

<details>
<summary>点开查看逐步解答</summary>

做三次 5% 水平的检验，至少一次误报的概率约为 $1-0.95^3\approx 14\%$——近三倍膨胀。补救：一是事先声明这是探索性筛选，胜出者必须用全新流量复测一遍才上线；二是用更苛刻的显著性红线（如 Bonferroni 校正：0.05/3≈0.017）。原则一句话：**看的次数越多，单次的门槛就该越高。**

</details>

## 7. 选读：为什么"偷看"会膨胀假阳性

<details>
<summary>选读 · 停止规则的统计学</summary>

设想真实无差异的场景里每天做一次检验。单次假阳性率 5%，但只要某一天踩线就停止并宣布胜利——事件"至少一天踩线"的概率随天数增长：10 天约 $1-0.95^{10}\approx 40\%$。检验的红线是在"只裁决一次"的前提下标定的；改变停止规则就改变了错误率的计算方式。正规解法叫序贯检验（如 alpha spending、贝叶斯监控），它们从一开始就把"会多次查看"写进配方，而不是事后找补。下一章的贝叶斯视角对此格外友好——信念随数据连续更新，不存在"偷看"的原罪。

</details>
