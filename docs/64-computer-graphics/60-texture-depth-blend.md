# 纹理采样、深度测试与混合

## 1. 从一个场景开始

上一课结束时，每个像素都拿到了自己的重心配方；再往前一课，Phong 公式给它算出了明暗。但此刻它们还是一身纯色的塑料：砖墙没有砖纹，玻璃透不出后面的街景，两堵相交的墙也没定谁挡住谁。

GPU 在把片元写入屏幕前，要替每个像素结清三笔账：**表面穿什么衣服**（纹理采样）、**谁有资格占这个像素**（深度测试）、**半透明的东西怎么叠**（混合）。这三件事合起来，就是光栅化管线的最后一公里。

## 2. 直觉解释

**给三角形穿上图片**。纹理就是一张普通图片。给三角形的每个顶点别一枚图钉，钉在图片上的某个位置——位置用两个 0 到 1 的分数坐标记，横的叫 u、竖的叫 v，合称 **UV 坐标**。三角形内部的像素该穿哪块图？上一课的重心配方直接复用：三个顶点的 UV 按权重一勾兑，就得到像素自己的 UV；拿它去纹理图上查颜色，这一步叫**采样**。

采样有两种记账法。**最近邻**：四舍五入，直接查离得最近的那个格子——省事，但放大后一块一块的马赛克。**双线性**：周围四个格子按远近比例加权——平滑柔和。它的全部秘密只是"线性插值用两次"：先横着插一遍，再竖着插一遍。

**谁挡谁**。屏幕背后跟着一本同样大小的**深度账本**（z-buffer）：每个像素格里记着"目前画上去的东西离相机多远"。新片元来报到，比账本里记录更近才准它上色、并更新账本——注意这是**按片元逐像素记账**，一个斜插进画面的三角形，近的一半和远的一半在账本里是两个数。

**透明怎么叠**。玻璃片元不是全凭自己上色，而是和账本里已有的背景色调酒：新颜色占 alpha 成，旧颜色占剩下的。既然是"往旧账上叠"，**先画谁后画谁就变得要命**——调酒不满足交换律。

## 3. 正式定义

**UV 插值**（重心配方的照搬）：设三个顶点的纹理坐标为 $(u_A,v_A)$ 等，像素 P 的重心坐标 $(\alpha,\beta,\gamma)$ 来自上一课，则

$$ (u_P,\ v_P) = \alpha\,(u_A,\ v_A) + \beta\,(u_B,\ v_B) + \gamma\,(u_C,\ v_C) $$

**双线性采样**：把 $u,v$ 乘以纹理的宽高后落进四个相邻 texel（纹素）之间，设横向分数为 $u$、纵向分数为 $v$（均在 0 到 1 之间），四个角的颜色按面积反比加权：

$$c = (1-u)(1-v)\,c_{00} + u(1-v)\,c_{10} + (1-u)v\,c_{01} + uv\,c_{11}$$

| 符号 | 含义 |
| --- | --- |
| $c_{00}, c_{10}$ | 左下、右下两个 texel 的颜色 |
| $c_{01}, c_{11}$ | 左上、右上两个 texel 的颜色 |
| $u, v$ | 采样点到左下 texel 的横向、纵向分数距离 |
| 权重和 | 四个权重相加恒等于 1，权重大小 = 与该角的"亲近程度" |

**深度测试**：设本次片元深度为 $z_{new}$（约定越小越近），账本当前值为 $z_{buf}$。通过条件 $z_{new} < z_{buf}$：通过则写入颜色并更新账本，否则该片元被丢弃。

**alpha 混合**：

$$c_{out} = \alpha\,c_{src} + (1-\alpha)\,c_{dst}$$

| 符号 | 含义 |
| --- | --- |
| $c_{src}$ | 新片元自带的颜色 |
| $c_{dst}$ | 账本（帧缓冲）里已有的背景颜色 |
| $\alpha$ | 不透明度，0 全透、1 实心 |

## 4. 分步例题

**例**：一张 2×2 的纹理，四个 texel 颜色为左下 10、右下 30、左上 50、右上 70。采样点落在 $u=0.25,\ v=0.25$。求双线性采样的结果。

1. 定位：点落在四个 texel 围成的正方形内，横向分数 $u=0.25$，纵向分数 $v=0.25$；
2. 横向插下排：$(1-0.25)\times 10 + 0.25\times 30 = 15$；
3. 横向插上排：$(1-0.25)\times 50 + 0.25\times 70 = 55$；
4. 纵向收账：$0.75\times 15 + 0.25\times 55 = 25$；
5. 验算：四个权重依次为 $\frac{9}{16}, \frac{3}{16}, \frac{3}{16}, \frac{1}{16}$，和为 1，加权同色 $10\times\frac{9}{16}+30\times\frac{3}{16}+50\times\frac{3}{16}+70\times\frac{1}{16} = 25$ ✓。

先横后竖、或四权重一次性加权——两次 lerp 和对称公式是同一件事的两种写法。

## 5. 动手实验

### 实验 1（viz）：lerp 是双线性的内层积木

```viz

  "expr": "a*(1-x)+b*x",

    { "name": "b", "min": 0, "max": 100, "step": 5, "value": 70 }
  ]
}
```

怎么玩：横轴 x 是采样点在两个 texel 之间的位置分数，曲线高度就是采到的颜色——这就是"线性插值（lerp）"。双线性采样没有新数学：把这条曲线先沿横坐标跑一遍（下排两个 texel），再沿纵坐标跑一遍（上下排结果之间），两次 lerp 套起来就是"双线性"里的那个"双"字。

### 实验 2（python）：最近邻与双线性同屏对比

```python title="把一张 4×4 纹理铺到 12×12 的屏幕上"
import matplotlib.pyplot as plt

tex = [
    [10.0, 60.0, 10.0, 60.0],
    [60.0, 110.0, 60.0, 110.0],
    [10.0, 60.0, 10.0, 60.0],
    [60.0, 110.0, 60.0, 110.0],
]                                     # 4×4 纹理：数字当灰度值

N = 12                                # 屏幕每个方向的像素数
near = []                             # 最近邻的画布
biline = []                           # 双线性的画布
for j in range(N):
    row_n = []
    row_b = []
    for i in range(N):
        u = i / (N - 1) * 3           # 屏幕坐标换算到纹理坐标 0~3
        v = j / (N - 1) * 3
        iu = int(u)                   # int()：向零取整，得左下 texel 的列号
        iv = int(v)
        fu = u - iu                   # 到左下 texel 的横向分数
        fv = v - iv
        c00 = tex[iv][iu]             # 双下标：先取行再取列
        c10 = tex[iv][min(iu + 1, 3)]           # min()：防止查到纹理外
        c01 = tex[min(iv + 1, 3)][iu]
        c11 = tex[min(iv + 1, 3)][min(iu + 1, 3)]
        row_n.append(c00)             # 最近邻：直接抄左下那格
        bottom = (1 - fu) * c00 + fu * c10      # 横向 lerp 下排
        top = (1 - fu) * c01 + fu * c11         # 横向 lerp 上排
        row_b.append((1 - fv) * bottom + fv * top)   # 纵向 lerp 收账
    near.append(row_n)
    biline.append(row_b)

plt.subplot(1, 2, 1)                  # 画布切成 1 行 2 列，用第 1 格
plt.imshow(near, origin="lower", cmap="gray")
plt.title("nearest: blocky")
plt.subplot(1, 2, 2)                  # 第 2 格
plt.imshow(biline, origin="lower", cmap="gray")
plt.title("bilinear: smooth")
```

怎么玩：左图大色块边缘生硬（马赛克），右图渐变柔和。把 N 改成 40 再跑：两者差距缩小——分辨率越高，采样方式的差别越藏进细节；而低分辨率贴图被放大时，正是最近邻的重灾区（老游戏的像素风就是这么来的）。

### 实验 3（python）：深度账本让近处的三角形赢

```python title="两个三角形抢同一块屏幕"
import matplotlib.pyplot as plt

W = 16                                # 屏幕边长（像素数）
INF = 999.0                           # 表示"还没有人画过"的极远深度
color_buf = []                        # 颜色画布
depth_buf = []                        # 深度账本：每格记当前最近深度
for j in range(W):
    color_buf.append([0] * W)         # [0]*W：把 0 重复 W 次拼成一行
    depth_buf.append([INF] * W)

tri_near = [(3.0, 3.0), (15.0, 3.0), (9.0, 14.0)]    # 近处三角形：深度 5
tri_far = [(1.0, 1.0), (14.0, 1.0), (7.0, 13.0)]     # 远处三角形：深度 9

def edge(p1, p2, q):                  # 上一课的边函数：叉积判内外
    return (p2[0] - p1[0]) * (q[1] - p1[1]) - (p2[1] - p1[1]) * (q[0] - p1[0])

def draw(tri, depth, shade):          # 送去深度测试：赢了上色，输了记一笔
    rejected = 0
    xs = [p[0] for p in tri]          # 列表推导：抽出每个顶点的 x
    ys = [p[1] for p in tri]
    for j in range(W):
        for i in range(W):
            px = i + 0.5              # 像素中心采样（上一课的约定）
            py = j + 0.5
            if px < min(xs) or px > max(xs) or py < min(ys) or py > max(ys):
                continue              # 包围盒粗筛：盒外像素直接跳过
            a = edge(tri[1], tri[2], [px, py])
            b = edge(tri[2], tri[0], [px, py])
            g = edge(tri[0], tri[1], [px, py])
            if a >= 0 and b >= 0 and g >= 0:      # 像素在三角形内
                if depth < depth_buf[j][i]:
                    depth_buf[j][i] = depth       # 赢了：更新深度账本
                    color_buf[j][i] = shade
                else:
                    rejected = rejected + 1       # 输了：被更近的记录挡下
    return rejected

draw(tri_near, 5.0, 220)              # 先画近的
lost = draw(tri_far, 9.0, 90)         # 再画远的：重叠区被账本挡下
plt.imshow(color_buf, origin="lower", cmap="gray")
plt.title("z-buffer: nearer fragment wins")
print(f"远三角形有 {lost} 个像素被深度测试拒之门外")
```

怎么玩：重叠区最后是亮色——近的三角形赢了，尽管远的是后来者。默认先近后远，输掉 43 个像素；把最后两行的调用顺序对调（先远后近）再跑：结果画面一模一样，但拒之门外数变成 0——**深度测试让绘制顺序不再要命**，这正是它存在的意义。

### 快问快答

```quiz
深度缓冲为什么给每个像素各存一个深度值，而不是给每个三角形只记一个平均深度？
- 省显存，画面效果完全一样
- 三角形内部各像素到相机的远近不同，只有逐片元比较才能分对遮挡 [*]
- 为了让远处的三角形画得更快
? 一个斜插进画面的三角形，一半离相机近、一半远；只记一个值，重叠区域会整体判错。显存里那张逐像素的 z-buffer 就是为此存在的账本。
```

:::warning[常见误区]

**误区一**："你以为纹理坐标越界就是 bug。" $u,v$ 超出 0 到 1 时，管线按约定的环绕模式处理：clamp 截到边缘，或 repeat 平铺——地板瓷砖无限延伸正是故意越界平铺出来的。

**误区二**："你以为深度是按三角形记的。" z-buffer 按**片元**（每个候选像素）记账。一个三角形扫过 50 万个像素，账本就被试探更新 50 万次；"按三角形记一个值"在斜面上必然判错遮挡。

**误区三**："你以为透明物体先画后画无所谓。" alpha 混合不满足交换律：先红后白和先白后红得到不同颜色。行业标准是透明物体按从远到近排序绘制，且不再写深度账本（否则会挡住后面的透明物）。

:::

## 6. 练习

**练习 1**：2×2 纹理四角颜色 10、30、50、70，采样点 $u=0.25, v=0.25$。求双线性采样值。代码能跑但只干了一半活：

```exercise
# @title: 练习：给 2×2 纹理算一次双线性采样
# @check: 25.0
# @hint: 双线性是两次 lerp——先横向把 u 用完，再纵向把 v 用完；现在 v 还没参与
c00 = 10.0   # 左下 texel 颜色
c10 = 30.0   # 右下
c01 = 50.0   # 左上
c11 = 70.0   # 右上
u = 0.25     # 采样点横向分数
v = 0.25     # 纵向分数

value = (1 - u) * c00 + u * c10    # ← 问题在这：只插了下排，上排和纵向收账都没做
print(value)
```

改对后输出 25.0：下排 lerp 得 15、上排 lerp 得 55，纵向 $0.75\times15+0.25\times55=25$。只改一行前的代码时，常见修法是补出 `top` 再纵向收账。

**练习 2**：背景色 40。先画红色片元（颜色 100，α=0.5），再画白色片元（颜色 200，α=0.5），最终颜色是多少？调换绘制顺序呢？

<details>
<summary>点开查看逐步解答</summary>

先红后白：

1. 红叠上背景：$0.5\times100+0.5\times40 = 70$；
2. 白叠上 70：$0.5\times200+0.5\times70 = 135$。

先白后红：

1. 白叠上背景：$0.5\times200+0.5\times40 = 120$；
2. 红叠上 120：$0.5\times100+0.5\times120 = 110$。

135 对 110——同一组片元，顺序不同结果不同。这就是透明物体必须按深度排序的原因：离相机近的玻璃要**最后**叠上来，才算"最上面那一层酒"。
</details>

**练习 3**：两块共面的贴合多边形（比如贴在墙上的海报和墙本身）深度几乎相等，画面上出现闪烁的碎斑。这是什么现象？一句话给出演管方案。

<details>
<summary>点开查看逐步解答</summary>

**z-fighting**：两块片元深度过于接近，浮点舍入让深度测试的结果在不同像素、不同帧之间来回翻转。工程对策是给两者留出深度间隔（把海报沿法线挪出几个毫米），或用多边形偏移（polygon offset）在比较时人为垫高一方。
</details>

## 7. 边界与适用条件

- 本课的双线性是"放大镜"方案；纹理被**缩小**时四个点不够用（会闪摩尔纹），管线改用 mipmap 三线性或各向异性过滤，见选读。
- 屏幕空间线性插值 UV 在透视相机下有系统误差，深度与纹理坐标须做**透视校正插值**（上一课误区三的同源问题）。
- 深度值存进账本前通常非线性压缩（近密远疏）以照顾近处的精度；两块深度过近的片元会打出 z-fighting。
- 透明排序是 O(n log n) 的额外开销，且对凹形物体自身前后重叠无解——电影级渲染干脆把这个难题留给光线追踪。

## 8. 选读：Mipmap 给纹理配一副"远视眼镜"

<details>
<summary>选读 · 为什么远处会闪烁，金字塔怎么救</summary>

一块 1024×1024 的地板纹理铺向地平线：近处一个像素只对应纹理的一小块，远处一个像素却要"代表"成百上千个 texel。这时只采 4 个点等于抽样抽奖——画面远处出现闪烁的摩尔纹。

mipmap 的办法是预先把纹理按 2 的幂逐级平均缩小：1024→512→256→…→1，一套金字塔。采样时按像素实际"管辖"的 texel 范围选合适层级，在相邻两级之间再插值一次（三线性）。远处的像素自动戴上度数合适的远视眼镜——平均掉了高频细节，闪烁消失。代价仅是约三分之一的额外显存。

</details>
