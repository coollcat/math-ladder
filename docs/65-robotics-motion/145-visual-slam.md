# 视觉 SLAM：把相机当成主传感器

## 1. 从一个场景开始

扫地机器人钻进卧室：GNSS 在室内没信号，激光雷达要加钱，可**相机几十块钱还白送一整幅画面**。视觉 SLAM（vSLAM）的赌注就是：只用一只（或一对）相机，边走边回答"我在哪、房间长什么样"。它与上一课 SfM 共享同一套视差几何，但工程重心不同：SfM 离线慢慢炖一锅照片，vSLAM 要**实时**——每帧十几毫秒内完成"这帧相机挪了多少、看见了哪些新点"，再交给第 140 课的位姿图后端慢慢精修。

## 2. 直觉解释

vSLAM 的架构像一家分了前后台的餐厅：

- **前端（前台，快）**：每来一帧，赶紧回答"这帧相对上一帧挪了多少"。两条门派：
  - **特征点法**：先从画面里挑出"好认的地标"（角点、纹理块——桌角、插座），给每个地标发一张**描述子**"身份证"，两帧之间对身份证配对，几何一算，位姿就出来了。稳，但挑地标要花时间；
  - **直接法**：不挑地标，赌"同一面墙的灰度不变"——直接调位姿，让上一帧的像素搬到这一帧后灰度对得上。快、不挑场景纹理，但怕光照突变。
- **后端（后厨，慢而准）**：前端产出的位姿与点全都进第 140 课的弹簧网；回环检测（选读）发现"这是刚才那个门口"，整体优化把漂移摊掉。

前端管"跟得住"，后端管"没错账"——SfM 是只开后厨的餐厅，vSLAM 前后厨连轴转。

## 3. 正式定义

**特征匹配**：特征 $i$ 的描述子是向量 $d_i$，两帧特征按描述子距离配对：

$$\mathrm{match}(q) = \arg\min_i \lVert q - d_i \rVert, \quad \text{且} \quad \lVert q - d_i \rVert < \tau$$

阈值 $\tau$ 之外的"最像"也不认——**没有像样的匹配，好过自信的错配**。

**运动视差与深度**（两帧之间的三角测量，第 135 课的实时版）：已知平移 $t$ 的相机看深度 $Z$ 的点，其图像位移为

$$\Delta s = \frac{f \cdot t}{Z}$$

| 符号 | 名字 | 含义 |
| --- | --- | --- |
| $d_i$ | 描述子 | 特征的"身份证"向量（灰度模式的高维摘要） |
| $\tau$ | 匹配阈值 | 距离超过它的配对一律作废 |
| $f$ | 焦距（像素单位） | 针孔模型的缩放系数 |
| $\Delta s$ | 视差位移 | 同一点在两帧图像里的像素位移 |

这条公式就是前端的钱袋子：反着用（已知位移求深度）叫三角化新点，正着用（已知点深度读位移）叫解位姿——**一个公式，双向收费**。

## 4. 分步例题

**从位移读深度**：相机焦距 $f = 1$（像素单位）、真实横向平移 $t \cdot f = 12$（"平移 × 焦距"合成一个量）。画面里三个匹配点的位移：6、4、3 像素。

1. 深度 $Z = \dfrac{t f}{\Delta s}$：三点分别是 $\dfrac{12}{6} = 2$、$\dfrac{12}{4} = 3$、$\dfrac{12}{3} = 4$——近的动得快、远的动得慢，与直觉一致；
2. 反过来校平移：若已知某点深 2 米、量到位移 5.5 像素，$t f = 5.5 \times 2 = 11$——多个点各报一个估计，第 21 章最小二乘把它们的矛盾摊平，就同时得到位姿与全部深度；
3. 这正是 vSLAM 前端每一帧在做的代数：**谁动得快谁就近**——几百对匹配点，一锅最小二乘端出位姿与新点云。

## 5. 动手实验

### 实验（python）：描述子匹配与阈值拒绝

```python title="特征匹配：最近邻 + 阈值把关"
import math

feats = [                                        # 参考帧的两个特征描述子
    [0.8, 0.2],
    [0.2, 0.9],
]
queries = [                                      # 当前帧的三个特征描述子
    [0.9, 0.1],
    [0.3, 0.7],
    [1.0, 0.9],
]
thr = 0.5                                        # 匹配阈值：距离超过它一律拒绝

def dist(a, b):                                  # 描述子距离（欧氏）
    s = 0.0
    for i in range(len(a)):
        s = s + (a[i] - b[i]) ** 2
    return math.sqrt(s)

for qi, q in enumerate(queries):
    best_i = -1                                  # -1 = 没有像样的匹配
    best_d = None
    for i, f in enumerate(feats):
        d = dist(q, f)
        if best_d is None or d < best_d:
            best_d = d
            best_i = i
    if best_d > thr:                             # 阈值把关：最像的也不够像
        best_i = -1
    print("query", qi, " 匹配 =", best_i, " 距离 =", round(best_d, 3))
```

怎么玩：前两个查询稳稳配上 0 号、1 号特征（距离 0.141、0.224）；第三个查询离谁都远（最近 0.728），被阈值拒成 $-1$——它多半是噪声或新出现的物体，**宁可缺匹配，不要错匹配**：错配会顺着 SfM 的方程污染整帧位姿。把 `thr` 调到 1.0 再跑：第三个查询被"接纳"，虚假的自信进了账本；调到 0.2：第二匹配也没了——阈值是把"跟得住"与"不认错"放进同一个旋钮的杠杆，工程调试就调它。

```quiz
特征点法与直接法最本质的分歧是？
- 一个用相机一个用雷达
- 一个先挑"地标"再配对，一个直接拿像素灰度当约束 [*]
- 一个在白天用一个在晚上用
? 特征法把"哪里好认"显式挑出来（描述子配对），直接法赌"灰度搬运前后不变"逐像素优化。前者稳、后者快，场景纹理与光照决定选谁。
```

::::warning[常见误区]

**误区一**："你以为匹配上的就是同一个点。" 描述子最近≠同一物体：瓷砖墙、 repeating 纹理上一片特征长得一模一样。除阈值外还要加**比率测试**（最好的距离要远好于第二好的才认）与几何验证（RANSAC 用"多数点同意的位姿"投票，少数错配直接出局）。

**误区二**："你以为相机怎么走都有信息。" 与第 135 课同款警告：纯旋转没有平移视差，$\Delta s = \frac{f t}{Z}$ 里 $t = 0$ 时位移恒零，新点的深度永远量不出来。视觉 SLAM 的运动设计（横移、绕圈）本质上是在喂养视差。

**误区三**："你以为前端跟丢了可以慢慢找。" 前端丢帧（快速转身、剧烈晃动）后，特征匹配无从下手，位姿链断裂——此刻唯一能救场的是**不靠视觉的惯性推算**：IMU 短时积分顶几十毫秒（第 120 课的卡尔曼融合在这里接手），等画面恢复再重新锚定。视觉 + 惯性 = VIO，是无人机与 AR 眼镜的标配组合。

::::

## 6. 练习

```exercise
# @title: 练习：给匹配器装上正确的阈值闸门
# @check: 0
# @check: 1
# @check: -1
# @hint: 逻辑别装反：距离"超过"阈值才拒绝，没超过才保留匹配。
import math

feats = [[0.8, 0.2], [0.2, 0.9]]                 # 参考帧特征
queries = [[0.9, 0.1], [0.3, 0.7], [1.0, 0.9]]   # 当前帧查询
thr = 0.5                                        # 匹配阈值

def dist(a, b):
    s = 0.0
    for i in range(len(a)):
        s = s + (a[i] - b[i]) ** 2
    return math.sqrt(s)

for q in queries:
    best_i = -1
    best_d = None
    for i, f in enumerate(feats):
        d = dist(q, f)
        if best_d is None or d < best_d:
            best_d = d
            best_i = i
    if best_d <= thr:                            # ← 问题在这：条件写反了
        best_i = -1                              #（没超阈值反而被拒）
    print(best_i)
```

<details>
<summary>点开查看逐步解答</summary>

闸门装反了——"没超阈值反而被拒、超了反而放行"。把条件改回：

```python
    if best_d > thr:                             # 超过阈值才拒绝
        best_i = -1
```

三个查询的最近距离分别是 $0.141$（配 0 号）、$0.224$（配 1 号）、$0.728$（超阈值拒绝）→ 输出 `0 / 1 / -1`。初始代码输出 `-1 / -1 / 2`——好匹配全灭、最坏的那对反而放行，整帧特征匹配全军覆没外加一个毒配对。闸门逻辑是匹配器的最后一道岗：**方向错一拍，系统就同时失去"跟得住"与"不认错"。**
</details>

**练习 2**：相机 $t f = 12$ 时量到某点位移 2 像素，深度多少？若把这颗点挪远一倍，位移变几像素？"位移读数越小的点深度越不可靠"对吗？

<details>
<summary>点开查看逐步解答</summary>

$Z = \frac{12}{2} = 6$；挪远一倍（深 12）位移缩到 1 像素。对——位移从 2 缩到 1，可 1 像素本身就是匹配噪声的量级：读数越小，同样 1 像素误差造成的**深度相对误差越大**（$\delta Z / Z = \delta(\Delta s)/\Delta s$）。这就是远处的点在地图上"发虚"的数值根源，也是采集时刻意让相机别离目标太远的又一次呼应。
</details>

## 7. 选读：回环检测——"这里我来过"

前端每一帧都在问"挪了多少"，还有一问更全局："**这个画面是不是以前见过的？**"主流做法是词袋模型（BoW）：把视觉词汇编成一部几万词的"词典"，每帧画面浓缩成一个词频直方图；两帧直方图一比，相似度爆表的候选就是回环——再送几何验证确认。回环边一旦坐实，第 140 课的位姿图就等到了那根决定性的弹簧：一整圈漂移被整体摊平。视觉 SLAM 的成熟度，很大程度上就是"回环认得多准、多快"的成熟度。
