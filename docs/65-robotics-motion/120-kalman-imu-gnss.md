# 状态估计：卡尔曼滤波与 IMU/GNSS 融合直觉

## 1. 从一个场景开始

无人机钻进桥洞，GNSS 信号应声消失——整整十秒，位置只剩惯性测量单元（IMU）在那里"闭眼数步子"。出来一看航线图：飞机明明走直线，记出来的轨迹却漂出去好几米。可 GNSS 在身边时也不省心：它一秒才报几次位置，每次还带着几米的抖动。

一个高频但漂移，一个低频但抖动——扔掉哪个都心疼。**卡尔曼滤波**就是那个按"谁此刻更靠谱"自动分账的会计：预测（信模型）与更新（信测量）两步走，卡尔曼增益 $K$ 一锤定音。

## 2. 直觉解释

两种传感器的脾气：

- **IMU 是急性子**：每秒几百拍，但它给位置靠积分——每拍的小毛刺都累进位置里，越走越飘。这种"航位推算"（dead reckoning）的误差**随时间累积**，的特点是"短时间内可信"。
- **GNSS 是慢性子**：一两秒才报一次，每次误差不累积（这次偏左不代表下次也偏），但单次抖动可能好几百毫秒——特点是"长期不漂、单发不准"。

卡尔曼的账法：用 IMU 往前推演（**预测**），同时让不确定性 $P$ 慢慢变大——闭眼走路，心里越来越没底；GNSS 一来就**更新**：看一眼自己此刻的方差 $P$ 和对方噪声 $R$ 谁大谁小，按比例把估计拉向测量。拉的比例就是增益：

$$K=\frac{P}{P+R}$$

$K$ 是个"信任旋钮"：预测越迷糊（$P$ 大）越信测量，测量越糙（$R$ 大）越信预测。分完账，$P$ 还要按 $(1-K)$ 缩水——汇报过一次，底气就足一分。

## 3. 正式定义

一维情形，预测与更新五件套：

| 步骤 | 公式 | 读法 |
| --- | --- | --- |
| 预测状态 | $x^-=x+v\,\Delta t$ | 惯性递推，位置加位移 |
| 预测方差 | $P^-=P+Q$ | 过程噪声 $Q$ 让底气漏气 |
| 增益 | $K=P^-/(P^-+R)$ | 信谁多一眼，全看方差比 |
| 更新状态 | $x=x^-+K(z-x^-)$ | 向测量 $z$ 拉 $K$ 份额 |
| 更新方差 | $P=(1-K)P^-$ | 汇报完毕，底气回升 |

真实无人机是二维三维的：位置、速度、姿态打包成状态向量，$P$、$R$ 升级成协方差矩阵，五个公式**逐字不变**，只是乘法换成矩阵乘法——这就是它一统 aerospace 的原因：账本结构简单到可以写进飞控的每个循环。

## 4. 分步例题

**例**：先验估计 $x^-=10$ 米、方差 $P^-=4$；GNSS 报 $z=12$ 米、噪声方差 $R=12$。融合。

1. 增益：$K=4/(4+12)=0.25$——先验比测量稳四倍，只信测量四分之一；
2. 更新：$x=10+0.25\times(12-10)=10.5$ 米；
3. 方差缩水：$P=(1-0.25)\times4=3$——比先验的 4 更有底气；
4. 解读：测量喊"12"，但因为它平时抖，估计只挪到 10.5；
5. 若反过来 $P^-=12$、$R=4$：$K=0.75$，估计挪到 11.5——**同一句话，谁底气足听谁的**。

### 实验 1（python）：过桥洞的二十秒

```python title="一维卡尔曼滚动：GNSS 在第 8 到 14 秒失锁"
import random                                   # 噪声发生器
random.seed(7)                                  # 固定随机种子：每次运行结果一致

dt = 0.1                                        # IMU 步长：0.1 秒
Q, R = 0.01, 4.0                                # 过程噪声（IMU 毛刺）与测量噪声（GNSS 抖动）
x_true, v_true = 0.0, 1.0                       # 真实运动：匀速 1 米/秒
x_est, v_est = 0.0, 1.05                        # 估计初值；IMU 速度偏快 5%——漂移之源
P = 0.0                                         # 位置方差：出发前刚校准，为零

for step in range(201):                         # 模拟 20 秒
    x_true = x_true + v_true * dt               # 真实世界照常前进
    x_est = x_est + v_est * dt                  # 预测：惯性递推（航位推算）
    P = P + Q                                   # 预测：不确定性随时间漏气
    locked = step < 80 or step > 140            # 第 8 到 14 秒：桥洞里 GNSS 失锁
    if locked and step % 20 == 0:               # 锁定时 GNSS 每 2 秒报到一次
        z = x_true + random.uniform(-2, 2)      # 测量值：真值加 ±2 米抖动
        K = P / (P + R)                         # 增益：按方差分账
        x_est = x_est + K * (z - x_est)         # 更新：向测量拉回 K 份额
        P = (1 - K) * P                         # 更新：底气应声回升
    if step in [0, 60, 110, 150, 200]:          # 五个观察点
        print(f"t = {round(step * dt, 1)}s  真值 {round(x_true, 2)}, 估计 {round(x_est, 2)}, 方差 {round(P, 3)}")
```

盯方差那一列：锁定段每两秒被 GNSS"汇报"压下去一次；桥洞里无人汇报，$P$ 一路爬升——滤波自己知道自己在瞎走。复锁瞬间估计被轻轻拉回真值，方差再次塌缩。估计与真值全程贴着走，尽管 IMU 的速度计偏了 5%。

### 实验 2（python）：三种信徒的对账

```python title="只信 IMU / 只信 GNSS / 卡尔曼，累计误差对账"
dt, steps = 0.1, 201                            # 步长 0.1 秒，跑 20 秒
Q, R = 0.01, 4.0                                # 过程噪声与测量噪声
noise = [2.0, -1.5, 1.0, -2.0, 1.5, -1.0]       # 硬编码噪声序列：结果可复现

def run(strategy):                              # 策略：'imu' / 'gnss' / 'kf'
    x_true, v_true = 0.0, 1.0                   # 真实运动
    x_est, v_est = 0.0, 1.05                    # IMU 速度偏快 5%
    P, total = 0.0, 0.0                         # 方差与累计绝对误差
    for step in range(steps):
        x_true = x_true + v_true * dt           # 真值推进
        x_est = x_est + v_est * dt              # 人人都要做的惯性递推
        P = P + Q
        if step % 20 == 0:                      # GNSS 每 2 秒来一次
            z = x_true + noise[(step // 20) % 6]    # 整除 // 把步数换成报点序号
            if strategy == 'kf':
                K = P / (P + R)                 # 卡尔曼：按方差分账
                x_est = x_est + K * (z - x_est)
                P = (1 - K) * P
            elif strategy == 'gnss':
                x_est = z                       # 纯 GNSS：闭眼全信
                P = R
        total = total + abs(x_true - x_est)     # 累计绝对误差
    return round(x_true - x_est, 2), round(total, 1)

for name in ['imu', 'gnss', 'kf']:
    end_err, tot = run(name)
    print(f"{name}: 末端误差 {end_err} 米, 累计误差 {tot} 米")
```

对账结果不留情面：只信 IMU 的误差随时间线性长个（20 秒末端就差出 1 米）；只信 GNSS 把每次 ±2 米的抖动原样吞进状态；卡尔曼两头都不沾——末端误差最小、累计误差也最小。融合不是和稀泥，是**按方差给两路信息定价**。

## 6. 练习

```exercise
# @title: 练习：给这一次汇报定个信任度
# @check: 卡尔曼增益 = 0.75
# @check: 融合估计 = 8.5
# @check: 更新后方差 = 2.25
# @hint: 增益的分子是先验方差 P（谁的方差小听谁的），抄成 R/(P+R) 就把信任度装反了；融合估计向测量拉 K 份额；方差按 (1-K) 缩水。
P, R = 9.0, 3.0                                 # 先验方差与测量噪声方差
x_prior, z = 10.0, 8.0                          # 先验估计与本次测量

K = R / (P + R)                                 # ← 错误行
x_fused = x_prior + K * (z - x_prior)           # 融合估计
P_new = (1 - K) * P                             # 更新后方差

print(f"卡尔曼增益 = {round(K, 2)}")
print(f"融合估计 = {round(x_fused, 1)}")
print(f"更新后方差 = {round(P_new, 2)}")
```

修好那行（分子是 $P$）：$K=0.75$——这次预测（方差 9）远比测量（方差 3）心虚，汇报喊 8，估计就从 10 挪到 8.5，顺带把方差压到 2.25。下一次汇报来时，滤波已经更有底气。

## 7. 选读：它其实是一次加权最小二乘

第 21 章的最小二乘把几组带噪声的观测折成一个最优估计，权重取"方差倒数"。卡尔曼更新正是它的单步版：把先验当作一次"伪测量"（值 $x^-$、方差 $P^-$），与真测量（值 $z$、方差 $R$）做加权平均，解出来恰是 $x=x^-+K(z-x^-)$、$K=P/(P+R)$。多维版本把标量方差换成协方差矩阵、倒数换成矩阵求逆，账本结构分毫未动——飞控里那段循环，本质上是每秒几百次的迷你回归。
