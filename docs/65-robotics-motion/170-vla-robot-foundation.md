# 视觉-语言-动作：机器人基础模型

## 1. 从一个场景开始

对机器人说"把桌上的红色杯子递给我"。传统方案是一条流水线：感知模块找杯子、任务规划器排步骤、运动规划算轨迹、控制器执行——四个模块四套接口，每换一句指令就得重新编程；而且"红色"这个词由感知模块解释，规划器根本"听不懂"。**VLA**（Vision-Language-Action，视觉-语言-动作模型）的野心是把这些全并成一件事：**一枚模型，看画面、听指令、直接吐动作**——RT-2（2023）验证了这条路：把机器人动作当成另一种"语言"，互联网级的图文知识真的能迁移成抓取能力。

## 2. 直觉解释

第 85 课的双塔把图文住进同一间房；视觉语言模型（VLM）更进一步，让图像以"外语词元"的身份流进语言模型。VLA 再往前一步，也是最后一步：**把动作也变成词**。

- **动作词元化**：机械臂每拍的动作（各关节速度、夹爪开合）是一串连续小数。把每个数**离散化**——比如切成 256 个桶——每个数变成一个"动作词"，编号 0~255。一条轨迹就是一句"动作话"；
- **一套词汇表，三种输入**：图像走视觉编码器、指令走文字词元、动作走动作词元——模型（Transformer，第 47 章）在同一本账上把三者连读；
- **像聊天一样生成动作**：模型自回归地"说"出下一串动作词，解码回连续数值，机器人就动起来。

红利来自**共训**（co-training）：同一枚模型既读互联网图文（学常识："红色杯子长什么样""递东西要杯口朝上"），又读机器人演示（学技能：手该怎么动，第 160 课的行为克隆批量供货）。语言理解与运动技能在同一套权重里会师——"没见过的杯子"靠图文常识泛化，"没说过的抓法"靠演示数据补齐。

## 3. 正式定义

VLA 是一个条件生成模型：

$$a_t \sim \pi_\theta(a \mid o_{\le t},\, l)$$

| 符号 | 名字 | 含义 |
| --- | --- | --- |
| $o_t$ | 观察 | 相机画面（+ 本体感觉：关节角、夹爪状态） |
| $l$ | 语言指令 | "把红色杯子递给我"——切词元后进模型 |
| $a_t$ | 动作 | 关节速度等连续量，词元化后进/出模型 |
| 词元化 | discretization | 每维动作切成 $N$ 桶（常用 256），连续 → 离散"词" |
| 共训 | co-training | 图文数据 + 机器人数据混合训练，一套权重两份技能 |

动作词元的解码是查表：词 $w$ → 桶中心值 $\hat{a} = \dfrac{w + 0.5}{N} \times$（动作量程）− 量程一半。生成一串动作词再逐个查表还原，机器人就"听懂了话"。

## 4. 分步例题

平面世界里解码一句"动作话"。动作码本只有三个词：词 0 = 往上 $(0, +1)$，词 1 = 往右 $(+1, 0)$，词 2 = 往下 $(0, -1)$。夹爪从原点出发：

1. 模型针对"走到右边桌角"说出动作词序列 $[0, 1, 0]$（先抬一下、右移、再抬一下）；
2. 逐词解码累加：$(0,0) + (0,1) = (0,1)$；$+ (1,0) = (1,1)$；$+ (0,1) = (1,2)$；
3. 终点 $(1, 2)$——一串离散的"词"，经查表与累加，变成一段连续的运动。真实 VLA 里"词"是关节角的桶号、序列长度几十拍，语法不变：**词元 → 桶中心 → 累加 → 运动**。

语言在这里当了"任务规范器"：同一个世界、同一套码本，"递杯子"与"推杯子"的差别只是模型说出的词序列不同——传统流水线里需要重新编程的部分，变成了语言条件的生成问题。

## 5. 动手实验

### 实验（python）：指令 → 接地 → 动作词 → 运动

```python title="玩具 VLA：把一句话变成一串动作"
import math
import matplotlib.pyplot as plt

world = {                                        # 桌面上的物件（视觉接地用的属性表）
    "红杯": {"pos": (3, 1), "color": "红"},
    "蓝盒": {"pos": (1, 3), "color": "蓝"},
}

CODEBOOK = {0: (0, 1), 1: (1, 0), 2: (0, -1), 3: (-1, 0)}   # 动作词：上右下左

def ground(instruction):                         # 语言接地：从指令里找到目标物件
    for name, attr in world.items():
        if attr["color"] in instruction:
            return name
    return None

target = ground("把红色的杯子递给我")
print("接地的目标 =", target, " 位置 =", world[target]["pos"])

# 生成动作词：玩具版按"先横后纵"的贪心计划产出（真 VLA 由模型自回归生成）
def plan_tokens(start, goal):                    # 规划：差值方向翻成动作词
    tokens = []
    dx = goal[0] - start[0]
    dy = goal[1] - start[1]
    tokens = tokens + [1] * abs(dx) if dx > 0 else tokens + [3] * abs(dx)
    tokens = tokens + [0] * dy if dy > 0 else tokens + [2] * abs(-dy)
    return tokens

pos = (0, 0)                                     # 机器人出发点
tokens = plan_tokens(pos, world[target]["pos"])
print("动作词 =", tokens)

path = [pos]                                     # 解码：查表 + 累加
for w in tokens:
    d = CODEBOOK[w]
    pos = (pos[0] + d[0], pos[1] + d[1])
    path.append(pos)
print("解码终点 =", pos, "（目标", world[target]["pos"], "）")

fig, ax = plt.subplots(figsize=(5, 5))
ax.plot([p[0] for p in path], [p[1] for p in path], marker="o")   # 运动轨迹
ax.scatter([world[t]["pos"][0] for t in world], [world[t]["pos"][1] for t in world],
           color=["#c0392b", "#2980b9"], s=120, zorder=3)         # 桌上两件物件
ax.set_xlim(-1, 4)
ax.set_ylim(-1, 4)
ax.set_aspect("equal")
plt.show()
```

怎么玩：一句中文指令先被**接地**成"红杯"这个具体目标（真实系统由视觉模型在画面里框出来），再被规划成动作词序列，最后逐词解码成轨迹——三段合起来就是 VLA 的一次心跳。把指令换成"把蓝色的盒子递给我"再跑：接地换了目标，后续链条自动重排——**语言变了，模型不用改**，这正是与传统流水线的分水岭。

```quiz
VLA 与传统"感知-规划-控制"流水线最大的不同是？
- VLA 的电机更精密
- 语言指令、视觉观察与动作在同一枚模型里端到端衔接，换任务不用重新编程 [*]
- VLA 不需要任何训练数据
? 传统流水线每个模块各管一段、接口靠人工对接；VLA 把三者塞进同一套词元账本，语言成为任务规范器——换任务=换一句话。
```

::::warning[常见误区]

**误区一**："你以为 VLA 能直接当大脑实时控制。" 大模型推理频率只有几赫兹，而关节控制要几百赫兹——真实系统是**分层**的：VLA 慢悠悠出"意图级"动作序列（或目标位形），底下第 100/155 课的轨迹跟踪与阻抗控制在千赫兹级兜底执行。VLA 是大脑皮层，不是脊髓。

**误区二**："你以为语言是精确的规格书。" "小心一点""稍微偏左"对人足够，对模型是模糊量词——语言粒度与动作精度之间隔着一条解释鸿沟。工程上靠演示数据给词语"标定含义"（"递"在数据里长什么样），指令超出标定范围时，模型会用最像的技能硬套——幻觉的机器人版。

**误区三**："你以为 VLA 一定会越来越强直到通用。" 它继承了大模型的全部旧病：训练分布外的物体、长视野多步任务、安全约束（"把剪刀递给我"该不该听？）都还是开放问题。通用机器人的账本上，VLA 是最强的一支笔，但账本远没写完——安全层（第 155 课的力控护栏）与验证层缺一不可。

## 6. 练习

```exercise
# @title: 练习：把动作词解码成运动
# @check: 1
# @check: 0
# @hint: 解码是"逐词查表 + 累加"——每一步都从上一步的位置出发，不是每次都从原点出发。
CODEBOOK = {0: (0, 1), 1: (1, 0), 2: (0, -1)}    # 动作词：上、右、下

tokens = [1, 0, 2]                               # 模型说出的一串动作词
pos = (0, 0)                                     # 出发点

for w in tokens:
    d = CODEBOOK[w]
    pos = CODEBOOK[2]                            # ← 问题在这：每步都拿"词2"的位移，没累加

print(pos[0])
print(pos[1])
```

<details>
<summary>点开查看逐步解答</summary>

解码的本分是"查表 + 累加"：

```python
for w in tokens:
    d = CODEBOOK[w]              # 查当前词的位移
    pos = (pos[0] + d[0], pos[1] + d[1])   # 从上一步出发累加
```

修正后：$(0,0) \to (1,0) \to (1,1) \to (1,0)$，终点 $(1, 0)$，输出 `1 / 0`。初始代码每一步都拿"词 2"的位移原地踏步，输出 `0 / -1`——词与词之间没有接力，"一句话"散成了三个孤立的字。**累加**正是自回归生成动作的具身含义：上一个词落下的地方，是下一个词的起点。
</details>

**练习 2**：动作每维切成 256 桶、量程 $[-1, 1]$。词 100 对应的连续动作是多少？这种离散化会带来多大的"分辨率天花板"？

<details>
<summary>点开查看逐步解答</summary>

$\hat{a} = \frac{100 + 0.5}{256} \times 2 - 1 \approx -0.2148$。分辨率天花板是桶宽 $2/256 \approx 0.008$——比这更细的动作差别，模型"说"不出来。工程对策：桶切多些（代价是输出空间变大）、或对高频精细维度（如夹爪开合）单独加密切分。词元化是把连续世界压进语言账本的关税，付多少、怎么付，是 VLA 设计的核心权衡之一。
</details>
