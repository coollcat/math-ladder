# 3DGS-SLAM：边飞边泼一张可微地图

## 1. 从一个场景开始

第 125 课的 SLAM 回答了"我在哪、地图长啥样"，但那本地图是粒子或地标坐标——稀疏、抽象，给导航够用，给人看不行。第 64 章第 95 课的 3DGS 能泼出照片级的场景，却默认离线训练：几百张照片、几万轮优化。**3DGS-SLAM** 把两条线焊在一起：无人机一边飞，一边把 3DGS 那张**可微的**地图当场织出来——地图不再是坐标的集合，而是一套"渲染出来必须像刚拍到的照片"的参数。位置与地图，都由同一个可微渲染器托着。

## 2. 直觉解释

SLAM 的老两问，在 3DGS-SLAM 里换了新问法：

- **跟踪（我在哪）**：地图参数**冻结**，只调相机位姿——调到"从这个位姿渲染出来的画面与刚拍到的那帧最像"为止。渲染损失就是定位损失；
- **建图（地图啥样）**：位姿**冻结**，只调高斯参数——调到"渲染画面再像一点"，顺手在画面里还没被覆盖的地方**添加新高斯**。

两步交替，像画家边走边画：先对好站位（跟踪），再补几笔（建图），再对站位……它与第 140 课 ICP 的关系值得划重点：ICP 靠"点与点的最近邻配对"当对应关系，3DGS-SLAM 靠"**渲染像素与照片像素**"当对应——不需要提取对应点，可微渲染把"差多少"直接变成了梯度。这是"可微"二字在机器人身上兑现的红利。

## 3. 正式定义

地图参数 $\theta$（所有高斯的位置、协方差、不透明度、SH 系数），当前帧照片 $I$，渲染算子 $R(T;\theta)$（位姿 $T$ + 地图 → 图像）：

$$\text{跟踪：}\quad T^{*} = \arg\min_{T} \big\lVert R(T;\theta) - I \big\rVert^2 \quad (\theta \text{ 冻结})$$

$$\text{建图：}\quad \theta^{*} = \arg\min_{\theta} \sum_{k \in \text{关键帧}} \big\lVert R(T_k;\theta) - I_k \big\rVert^2 + \lambda_{d}\, L_{depth} \quad (T_k \text{ 冻结})$$

| 符号 | 名字 | 含义 |
| --- | --- | --- |
| $\theta$ | 地图参数 | 几十万枚高斯的全部属性 |
| $R(T;\theta)$ | 可微渲染 | 从位姿与地图合成图像（第 64 章第 85 课的管线） |
| 关键帧 | keyframe | 不是每帧都建图：挑视角变化够大/信息够多的帧入账，控制优化成本 |
| $L_{depth}$ | 深度损失 | 深度传感器/立体视差给的监督，帮几何别跑飞 |
| $\lambda_d$ | 深度权重 | 照片管外观、深度管几何，按可靠度分账 |

两张损失表的化学分子式与离线 3DGS 完全一致（第 64 章第 95 课的流水线原班人马），新意只在**在线**：每来一帧，跟踪一次小优化 + 关键帧上一次建图小优化，与飞行同速进行。

## 4. 分步例题

**建图侧的一笔融合账**：地图里某处已有一枚高斯管着一小块亮度，历史账面是"估计 0.8、可信权重 3"；新关键帧在这个方向量到 0.2。按可信度加权平均：

1. 加权总账：$3 \times 0.8 + 1 \times 0.2 = 2.6$；
2. 除以总权重：$\dfrac{2.6}{3 + 1} = 0.65$——新观测把旧估计往新方向拉了一截，但没拉到底（旧账权重还在）；
3. 这正是建图的真实语法：**每一帧不是覆盖，是带权融合**；飞过同一条走廊十遍，那里的高斯就被十次观测反复校准——早期噪声被摊薄，地图越飞越实。

而跟踪侧的账在第 4 步例题里换个名目重演：位姿差 5 厘米 → 渲染画面整体错位 → 逐像素差平方和给出一口"误差碗"，梯度下降滚到碗底即定位（第 135 课的重投影误差碗换成了全画面版）。

### 实验 1（lab）：一维可微地图上的三条纪律

```lab

  "title": "3DGS-SLAM：冻结地图调位姿、冻结位姿补地图，以及「两个一起调」为什么不行",
  "mode": "track"
}
```

场景被压成一维：地图是 4 枚高斯的信念，真实世界里还多一个**没被建进地图的新物件**（位置 2.1，亮度 1.3），相机站在真值 2.4 处拍下一张照片。三个模式对应三条纪律——

**跟踪（冻结地图）**：扫一遍位姿，看光度误差 $E(p)$ 的谷底落在哪。注意它**不在 2.4**：那个没进地图的物件把谷底拽到了 **2.894**，误差谷底 $E=38.66$，而在真值 2.4 处 $E=59.90$。这就是「地图的疆域就是跟踪的疆域」的定量版，也是为什么 SLAM 必须不断把地图织到脚步前面去。按「扫一遍找谷底」亲手确认这个偏移。

**建图（冻结位姿）**：按「补一枚高斯」，机器在残差最大（渲染最不像照片）的方向长出一枚新的。这里有两组值得对比的走法——

*位姿还停在真值 2.4 时补*：一枚高斯补在 2.10 处，正好把那个没进地图的物件补上，误差 $59.90 \to 0.00$，谷底也回到 2.400。**位姿对了，补一枚就归零。**

*先按「扫一遍找谷底」把位姿拽到 2.894 再补*：误差 $38.66 \to 21.22 \to 10.95 \to 9.49$，台阶式往下掉却总也掉不到零，谷底始终卡在 2.888 附近——**位姿偏着补，补再多次也回不到真值**。两件事必须交替才能同时改善，这就是交替冻结的全部理由。

**同时调（对照）**：让位姿与整张地图一起平移 $s$。误差曲线是一条**水平线**——扫过 $s\in[-0.6,0.6]$，起伏只有 $10^{-29}$ 量级，照片一模一样。这不是「解出了正确答案」，而是「**根本没定解**」：单帧照片对「世界 + 相机」的组合零分辨率。这正是必须交替冻结的理由。

### 实验 2（python）：一张 1D 可微地图的跟踪与建图

```python title="一维 3DGS-SLAM：冻结地图调位姿，冻结位姿补地图"
import math
import matplotlib.pyplot as plt

gaussians = [                                    # 地图 = 几枚 1D 高斯：(中心, 宽, 亮度)
    [1.0, 0.35, 0.8],                            # 宽度要明显小于间距，否则相邻高斯会糊成一整片，
    [2.6, 0.30, 0.6],                            # 误差碗就失去谷底（曾因此把估计值顶到搜索网格边上）
    [4.2, 0.40, 0.9],
]

def render(px):                                  # 渲染：所有高斯在 px 处的亮度叠加
    s = 0.0
    for mu, sig, amp in gaussians:
        s = s + amp * math.exp(-(px - mu) ** 2 / (2 * sig * sig))
    return s

def scene(px):                                   # 真实世界：地图之外还多了一个"新箱子"
    return render(px) + 0.7 * math.exp(-(px - 4.5) ** 2 / (2 * 0.4 * 0.4))

true_pos = 3.4                                   # 相机真实位置（系统不知道）
frame = [(scene(true_pos + d / 10), d) for d in range(-12, 13)]   # 当前帧：局部窗口的亮度读数

# ---- 跟踪：冻结地图，网格搜索位姿让渲染最像这帧 ----
best_pos = None
best_err = None
curve = []
p_try = 0.0
while p_try <= 6.01:
    err = 0.0
    for value, d in frame:
        err = err + (render(p_try + d / 10) - value) ** 2    # 渲染 vs 照片：逐像素差
    curve.append((p_try, err))
    if best_err is None or err < best_err:
        best_err = err
        best_pos = p_try
    p_try = p_try + 0.05                     # 步长 0.05：再细就该看见采样噪声了
print("跟踪估计位置 =", round(best_pos, 2), "（真实位置 " + str(true_pos) + "）  渲染误差 =", round(best_err, 5))

# ---- 建图：把"渲染不出来"的残差处补一枚新高斯 ----
resid = []                                       # 每个方向的渲染残差
for value, d in frame:
    resid.append((value - render(best_pos + d / 10), d))
worst = max(resid)                               # 残差最大处 = 地图没覆盖的地方
gap_mu = best_pos + worst[1] / 10
gaussians.append([gap_mu, 0.5, worst[0]])
print("在", round(gap_mu, 2), "处补一枚高斯，残差从", round(worst[0], 3), "开始收敛")

fig, ax = plt.subplots(figsize=(7, 3))
ax.plot([c[0] for c in curve], [c[1] for c in curve])
ax.set_xlabel("camera pose")
ax.set_ylabel("photometric error")
plt.show()
```

怎么玩：跟踪那幕就是"局部窗口重投影误差碗"——位姿网格扫过去，碗底停在 3.35，紧贴真实位置 3.4（新箱子制造了一点偏移，但已建图的那几枚高斯账更有分量）；建图那幕找到"渲染不出照片"的最大残差处——算出来是 4.45，正是那个没进地图的新箱子所在，当场补一枚高斯，残差就从 0.639 开始收敛。把 `true_pos` 改到 9.5（地图疆域之外）再跑：这一帧落在所有高斯脚下最平坦的地方，误差碗彻底没有谷底，搜索被顶到网格最右端 6.0，**跟踪失败**——地图的疆域就是跟踪的疆域，这也是为什么 SLAM 系统要靠回环与关键帧不断把地图织到脚步前面去。

```quiz
3DGS-SLAM 的"跟踪"与"建图"两步是怎么分工的？
- 跟踪调地图参数，建图调相机位姿
- 跟踪冻结地图只调位姿，建图冻结位姿只调地图参数，交替进行 [*]
- 两者同时调所有参数求全局最优
? 冻结一方再调另一方，是为了把耦合的大问题拆成两个小优化交替逼近——渲染损失同时当定位损失与建图损失，可微渲染是共同的发动机。
```

::::warning[常见误区]

**误区一**："你以为在线 3DGS-SLAM 只是离线训练跑得快。" 离线训练敢于每轮全图优化几万枚高斯；在线系统必须省：关键帧筛选、局部窗口优化、跟踪只调位姿——每帧几十毫秒的预算，逼着工程把"全量"改写成"增量"。这是表示优势与算力现实的和解。

**误区二**："你以为照片损失够了。" 只对照片（外观）优化，几何可以"以假乱真"地错——从训练视角看完美、换个角度就穿帮（外观歧义）。深度损失（深度相机、立体视差）与正则就是来管几何的：照片管好看，深度管站得住。

**误区三**："你以为地图只会越来越全。" 动态物体是 3DGS-SLAM 的幽灵问题：走过一个人的高斯被泼进地图，人走了"人形鬼影"永驻——从此每次路过都把跟踪往鬼影上拉。掩码剔除动态区域、给高斯记"最后被看到的时间"做衰减，都是在给地图请一位幽灵清洁工。

::::

## 6. 练习

```exercise
# @title: 练习：给地图参数做带权融合
# @check: 0.65
# @check: 4.0
# @hint: 加权平均是"加权总账除以总权重"——别忘了分母也要把新旧权重加起来。
old_est = 0.8                                    # 地图参数的旧估计
old_w = 3.0                                      # 旧账的可信权重
obs = 0.2                                        # 新帧的观测值
new_w = 1.0                                      # 新观测的权重

num = old_w * old_est + new_w * obs              # 加权总账
fused = num                                      # ← 问题在这：忘了除以总权重

print(round(fused, 2))
print(old_w + new_w)
```

<details>
<summary>点开查看逐步解答</summary>

加权平均的另一半是分母：

```py
fused = num / (old_w + new_w)                    # 2.6 / 4 = 0.65
```

修正后融合值 $0.65$、总权重 $4.0$。初始代码直接拿加权总账 $2.6$ 当估计——权重加得越重读数越大，"可信"反而成了"放大器"。带权融合是 SLAM 建图的最小语法：滤波法（第 125 课的贝叶斯更新）与图优化（第 140 课的信息矩阵）本质都是它的进阶版——**新证据永远按可信度入账，不覆盖、不独裁**。
</details>

**练习 2**：跟踪与建图如果**同时**调位姿与地图（一起最小化同一帧的渲染损失），会出现什么病？提示：想象"整张地图连同相机一起朝照片挪过去"。

<details>
<summary>点开查看逐步解答</summary>

二者的误差可以**互相吸收**：位姿偏了，地图可以跟着扭来抵消；地图错了，位姿跟着偏来迁就——单帧照片对"世界 + 相机"的组合几乎无约束（还叠加 3DGS 天生的尺度模糊），联合优化会让地图与轨迹一起漂进一个自洽但错误的解。解法正是本课的交替冻结：跟踪时地图是"不动的证据"，建图时位姿是"确定的锚点"，再靠第 140 课的位姿图在多帧之间锁死全局。单帧不够，多帧才成账本——SLAM 的精髓永远在"跨帧的约束"。
</details>

## 7. 选读：从 SplaTAM 到开放问题

这条线上的代表系统（SplaTAM、MonoGS 等）已经把"照片级在线地图"做进真机：RGB-D 版用深度损失稳几何，纯单目版靠深度正则与尺度对齐硬撑。开放问题也明摆着：**速度**（每帧梯度更新的算力账）、**动态**（幽灵清洁工还不完善）、**尺度**（单目 3DGS-SLAM 的米数仍要 IMU 或先验来定）、**语义**（高斯只有外观没有"这是什么"——与第 170 课 VLA 的语义流对接是公认的下一步）。可以把它看作第 125 课那句"鸡蛋同解"的 3DGS 版：位姿与地图在同一个可微渲染器里互为锚点——只是这一回，地图长得像照片。
