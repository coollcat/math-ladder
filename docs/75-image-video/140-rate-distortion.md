# 码率控制与率失真

## 1. 从一个场景开始

主播端有一个再普通不过的滑杆："码率 4000 kbps"。往左拖，观众端不卡但画面糊；往右拖，画面通透但观众开始转圈。**每一次拖动，都是在"花多少比特"和"画质掉多少"之间下注。**

前三课解决了"怎么省"：预测、残差、排班表。这一课解决"省到什么程度"：预算给定的情况下，**怎么把每一比特花在刀刃上**。答案是本章、也是视频编码的终极答案——率失真曲线。

## 2. 直觉解释

压缩到一定程度就有损失，香农的理论早有预言：有损压缩没有免费午餐，只有**取舍**。熵与无损编码下界（第 40 章）是率失真的无损特例；有损版 R(D) 本体不在本书路线内，记住"失真越大、码率下限越低"的方向即可。把取舍画成一条曲线：

- **横轴**：码率 $R$——平均每个像素花多少比特（"花了多少"）；
- **纵轴**：失真 $D$——重建画面与原画面的差距（"坏了多少"），常用 PSNR 表示，越大越好。

这条曲线有两个铁律：**单调下降**（码率给得越多，失真越小）和**边际递减**（从 1000 kbps 加到 2000 kbps 画质提升明显，从 8000 加到 9000 几乎看不出来）。

真正有用的读法是**比较两条曲线**：同一码率下，失真更小的那条就是更好的编码方案。本章 lab 里那两条曲线——"8×8 DCT + 量化"对"直接压像素"——任意码率下前者都更高，这就是第 70 课变换编码的全部价值：**先把能量集中到少数系数，再扔掉剩下的，比一刀切划算得多。**

而控制曲线位置的方向盘是**量化步长**：步长越大，扔掉的系数越多、码率越低、失真越大。码率控制器的全部工作，就是在线调节步长，让实际码率贴着预算走，同时停在那条更优的曲线上。

## 3. 正式定义

**失真**——均方误差 MSE（8-bit 像素口径）：

$$\mathrm{MSE} = \frac{1}{N}\sum_{i=1}^{N}\left(C_i - \hat{C}_i\right)^2$$

**峰值信噪比 PSNR**（越大越好，工程惯例以 255 为峰值）：

$$\mathrm{PSNR} = 10 \cdot \log_{10}\frac{255^2}{\mathrm{MSE}}$$

**率**——本课用一阶熵口径（bit/像素，第 40 章）：对量化后的符号统计分布，$R = -\sum_v p_v \log_2 p_v$。

**率失真函数** $R(D)$：达到失真不超过 $D$ 所需的最小码率。香农证明它单调不增、下凸；实际编码器扫出的 R-D 曲线是对它的工程逼近。

| 符号 | 名字 | 含义 |
| --- | --- | --- |
| $C_i$ | 原始像素 | 参考答案 |
| $\hat{C}_i$ | 重建像素 | 编码再解码后的近似值 |
| MSE | 均方误差 | 差值平方的平均，失真的默认度量 |
| PSNR | 峰值信噪比 | 用 dB 表达的"保真度"，越大越好 |
| $q$ | 量化步长 | 一次吃掉多大的值域，越大码率越低、失真越大 |
| QP | 量化参数 | 编码标准里控制 $q$ 的旋钮（QP 每加 6，步长约翻倍） |

**码率控制**：给定预算（如 4000 kbps），控制器实时调节 QP——场景复杂就加大 QP 换码率，场景简单就减小 QP 攒质量。CBR（恒定码率）与 VBR（可变码率）只是约束方式不同，内核都是这个反馈环。

## 4. 分步例题

16 个像素的平滑渐变：`10, 18, 33, 41, 55, 62, 80, 87, 95, 110, 118, 130, 140, 152, 168, 180`。用均匀量化（步长 $q$：值除以 $q$ 四舍五入取整，再乘回 $q$ 重建），看三档步长的账。

1. **量化与重建（q = 16，以像素 33 为例）**：$33/16 \approx 2.06 \to$ 取整 2，重建 $2 \times 16 = 32$，误差 1；像素 87：$87/16 \approx 5.44 \to 5$，重建 80，误差 7；
2. **算失真**：q = 16 时 16 个像素误差平方和 397，$\mathrm{MSE} = 397/16 = 24.8$；
3. **换算 PSNR**：$10\log_{10}(255^2 / 24.8) = 34.2$ dB；
4. **对比三档**：q = 4 → MSE 1.8 → **45.5 dB**；q = 8 → MSE 3.8 → **42.3 dB**；q = 16 → **34.2 dB**；
5. **读曲线**：q 翻倍（码率大约省 1 bit/像素），PSNR 掉 3~8 dB——步长是方向盘，拧多少圈、掉多少画质，就是 R-D 曲线上的一次移动。

顺带看反例：若量化后忘了乘回 $q$（直接拿索引当重建值），MSE 飙到 9861，PSNR 只剩 8.2 dB——量化的数学一环扣一环，丢一步满盘皆输。

## 5. 动手实验

### 实验 1：拖着看（lab 组件）

```lab

  "rate": 1.6

```

图上有两条 R-D 曲线：蓝线走"8×8 DCT + 量化"（JPEG 那条路），橙线走"不换基直接压像素"。**拖动橙色竖线（目标码率）**，右侧实时给出两种方案的重建图。做三件事：

- 把竖线拖到最左：两种方案都糊，但蓝线糊得"体面"——整体变柔，橙线开始出现色带；
- 拖到中间某处停下，盯住读数：同一码率，两条曲线的 PSNR 差着一截。**码率相同，方案不同，画质可以差出一倍**；
- 右下角的重建图是"失真"两个字的具象：横轴的每一分钱，都花在了你看得到或看不到的地方。

### 实验 2：自己算（Python）

```python title="三档量化步长的率失真账单"
import math

px = [10, 18, 33, 41, 55, 62, 80, 87, 95, 110, 118, 130, 140, 152, 168, 180]

for q in (4, 8, 16):
    mse = 0
    for v in px:
        idx = round(v / q)       # 量化：除以步长取整
        recon = idx * q          # 反量化：乘回步长重建
        mse = mse + (v - recon) ** 2
    mse = mse / len(px)
    psnr = 10 * math.log10(255 * 255 / mse)
    print(f"q={q:>2}:  MSE={mse:>8.2f}   PSNR={psnr:.1f} dB")
```

三行输出（45.5 / 42.3 / 34.2 dB）就是例题的复核，也正是 R-D 曲线上的三个取样点。把 q 继续加大，PSNR 掉得越来越快——**曲线的"膝盖"以下，每一比特都花得很值；过了膝盖，加钱也买不来多少画质**。码率控制的功夫，就在于认出自己处在曲线的哪一段。

### 快问快答

```quiz
编码器拿到固定码率预算，为什么不会把 q 调到最小（画质最好）或最大（码率最省）？
- 因为极端 q 都会触发解码器报错
- 因为预算是硬约束：q 太小超出码率预算，q 太大失真超标；最优点在 R-D 曲线上按预算或质量要求选定 [*]
- 因为 q 必须是 6 的倍数
? q 是方向盘不是目标。固定码率下 q 由反馈环自动调到"码率恰好贴着预算"，固定质量下 q 调到"失真恰好达标"。两种模式停在同一条曲线的不同点上——曲线是地图，模式决定你停在哪。
```

::::warning[常见误区]

**误区一**："PSNR 高就一定好看。"
你以为 38 dB 必然比 36 dB 好看——PSNR 只度量逐像素误差，与人眼感受并不总一致：轻微色偏可以拉低 PSNR 却几乎看不出来，而错位的块效应 PSNR 不算太差却极其刺眼。现代编码器调优普遍改用感知类指标，PSNR 仍是入门与对账的通用语言。

**误区二**："码率越高画质一定越好。"
你以为码率是画质本身——码率只是预算，画质取决于预算花在哪条曲线、曲线的哪个点上。同一个 4000 kbps，好的编码方案可以把画质做到翻倍码率下烂方案的水平。先看曲线位置，再看预算大小。

**误区三**："量化矩阵是随便拧的旋钮。"
你以为 Q 表是经验参数随手调——标准量化矩阵是心理视觉实验的产物：人眼对高频不敏感（高频步长大胆扔）、对色度更宽容（色度步长更大）。每一格数字都是"哪里可以糊"的科学答案，乱调等于跟自己的眼睛作对。

::::

## 6. 练习

**练习 1**：下面的码率实验输出了 8.2 dB——画面糊到不像话。代码里有一行把量化的数学弄丢了，请修复并输出正确的 PSNR：

```exercise
# @title: 练习：丢掉的半步量化
# @check: 34.2
# @hint: 量化除以 q 取整后，重建时必须乘回 q。索引和原值之间还差着一整个步长的距离
import math

px = [10, 18, 33, 41, 55, 62, 80, 87, 95, 110, 118, 130, 140, 152, 168, 180]
q = 16

mse = 0
for v in px:
    idx = round(v / q)
    recon = idx          # ← 问题在这：量化索引 ≠ 重建值
    mse = mse + (v - recon) ** 2
mse = mse / len(px)
psnr = 10 * math.log10(255 * 255 / mse)
print(f"{psnr:.1f}")
```

修正后输出 `34.2`：重建值应为 `idx * q`。忘记反量化相当于把画面整体缩小 16 倍再评比，MSE 从 24.8 飙到 9861——量化的"除"与"乘回"是一对，缺一不可。

**练习 2**：上表中 q 从 4 加到 8，PSNR 只掉 3.2 dB；从 8 加到 16，却掉了 8.1 dB。结合"边际递减"解释这个不对称。

<details>
<summary>点开查看逐步解答</summary>

1. q = 4 时每像素误差最多 2（四舍五入半径），误差平方最多 4——失真本来就小，翻倍步长也只是小数字变大一点；
2. q = 16 时误差可达 8，误差平方 64——同样的"翻倍"作用在更大的基数上，MSE 与 PSNR 都剧烈反应；
3. 这正是 MSE 用**平方**的直接后果：大误差被平方放大。R-D 曲线的"膝盖"由此而来——小步长区间曲线平缓（加码率不值），大步长区间陡峭（掉码率很伤），编码器总想把工作点顶在膝盖偏左的位置。

</details>

## 7. 选读：香农的 R(D) 与编码器的 λ

<details>
<summary>选读 · 理论下界与工程逼近</summary>

率失真理论回答的是极限问题：给定信源统计分布，失真不超过 $D$ 时**理论上**最少要多少比特。熵与无损编码下界（第 40 章）是它的无损特例；有损版 R(D) 本体不在本书路线内，这里只取方向：**失真越大，码率下限越低**。对高斯信源，$R(D) = \frac{1}{2}\log_2(\sigma^2/D)$——一条优雅的凸曲线。真实图像不是高斯信源，这个公式给不出可用数值，但它划出了**所有编码器共同的 ceilings 与 floors**：任何实际方案的 R-D 曲线都在理论曲线的上方，差距就是"还有多少优化空间"。

工程上逐块做量化决策时，编码器把"多花码率"与"减少失真"折算成同一货币：最小化 $D + \lambda R$。λ 是失真与码率的兑换率——λ 大则惜码如金（低码率档），λ 小则画质优先（高码率档）。沿曲线滑动 λ，就把整条 R-D 曲线扫了出来：**理论给形状，λ 给位置**。直播平台的码率阶梯（1080p 高/中/低档）就是同一条曲线上的几个取样点。

</details>
