# 图像与视频方法地图

## 1. 从一个场景开始

同事扔来一段视频："客户说画质不行，你看看。"点开一看：确实糊。但糊从哪来？是拍摄时就没对上焦，是色彩空间搞错了，是量化太狠，还是码率预算根本不够？

学完本章 14 门课，工具箱已经塞满：像素模型、采样、色彩空间、卷积、梯度、二维傅里叶、DCT、量化矩阵、帧率、帧差、块匹配、预测残差、GOP、率失真。**现在的问题是：先抓哪一个？** 本课不添任何新工具，只做三件事：给全章画一张导诊地图、演练分诊两问法、把最容易踩的坑一次性展览。

## 2. 直觉解释

图像与视频的问题分诊，只需连问两个问题：

**第一问——问题在哪个域？**

| 域 | 典型症状 | 谁负责 |
| --- | --- | --- |
| **空域（单张图内）** | 模糊、噪点、边缘丢失、伪轮廓 | 像素、卷积、梯度、DCT、量化 |
| **频域（单张图内）** | 棋盘纹、环状伪影、高频细节没了 | 二维傅里叶、DCT、量化矩阵 |
| **色彩** | 肤色不对、红蓝颠倒、色带 | 色彩空间、色度子采样 |
| **时域（帧与帧之间）** | 卡顿、拖影、抖动、跟丢 | 帧率、帧差、块匹配、预测 |
| **码流结构** | 拖不动、切入糊一阵、误码扩散 | GOP、I/P/B 排班 |
| **预算** | 该清楚的糊、该省的费 | 率失真、码率控制 |

**第二问——特征尺度是什么？**

- **分辨率与帧率**：4K30 和 720p60 遇到的瓶颈完全不同——前者卡带宽，后者卡预测与编码速度；
- **内容类型**：静态屏幕分享（预测几乎白送）与运动镜头（预测失灵、残差巨大）用同一套参数就是浪费；
- **观看条件**：手机竖屏与电视大屏对"哪些失真看得见"的回答截然不同——量化矩阵与码率阶梯都该跟着变。

两问一对，科室基本锁定。剩下的分歧多半发生在"几种方案都能凑合"的地带——那时比的是 R-D 曲线上的位置，而不是谁听起来高级。

## 4. 分步例题

**题 A**：一段产品宣传片 200 MB，客户嫌大；画面本身没毛病。

1. 第一问：**预算**（文件大小）+ **时域**；第二问：内容是匀速运镜，帧率 30、1080p；
2. 逐层查：GOP 是否太短（I 帧太密）？预测是否没开 B 帧？量化是否太保守（q 太小）？
3. 处方：按[帧间预测](./120-inter-predict.md)确认预测链健康，再用[率失真](./140-rate-distortion.md)把工作点沿曲线右移——**同样的画质，通常能省一半**；最后查 GOP 长度（[GOP](./130-gop-structure.md)）。

**题 B**：监控视频夜间画面糊成马赛克，白天正常。

1. 第一问：**频域**（块效应是量化的指纹）；第二问：夜间噪点大、场景复杂；
2. 定位：噪点让残差暴涨，码率控制器被迫加大量化步长 → 块效应；
3. 处方：编码前先时域降噪（[卷积](./40-image-conv.md)的思路搬到时间轴），或按[率失真](./140-rate-distortion.md)重算预算——**噪声是码率的小偷**，先抓贼再谈省。

**题 C**：剪辑软件里拖动素材，每次都卡两秒才清晰。

1. 第一问：**码流结构**（切入糊 = 从 I 帧重新起步）；第二问：GOP 长达数秒；
2. 处方：转码代理时把 GOP 缩到 1 秒（[GOP](./130-gop-structure.md)），或生成全 I 帧的编辑用副本——剪辑台要的是随机访问，不是压缩率。

## 5. 动手实验

### 实验 1（python）：给视频问题自动挂号

```python title="按症状开具科室单"
def triage(file_too_big, colors_off, playback_jumps, blocky):
    # 优先级：先看能不能正常消费，再看颜色对不对，再看画质伤不伤
    if playback_jumps:
        return "gop-structure（先看排班：I 帧够不够密）"
    if colors_off:
        return "color-space（查色彩空间与色度子采样）"
    if blocky:
        return "jpeg-quant（查量化步长与码率预算）"
    if file_too_big:
        return "rate-distortion（把工作点沿 R-D 曲线右移）"
    return "image-pixels（回到底层：先弄清像素怎么存）"

cases = [
    ("拖动进度条就糊一阵", False, False, True, False),
    ("整片肤色发青", False, True, False, False),
    ("暗部一大块块的马赛克", False, False, True, False),
    ("画质没毛病，就是文件大", True, False, False, False),
    ("说不上来哪里不对", False, False, False, False),
]
for note, a, b, c, d in cases:
    print(triage(a, b, c, d), "|", note)
```

五张挂号单对应五类最常见的投诉。**if 台阶的顺序本身就是知识**：能不能播排第一（用户体验直接阵亡），颜色排第二（人眼第一敏感），块效应排第三（画质受损），文件大小排最后（可以事后转码补救）。

### 实验 2（python）：把"为什么要压缩"算成数字

```python title="裸码流与成品码流的数量级"
W, H, FPS = 1920, 1080, 30
raw = W * H * 3 * 8 * FPS            # RGB 每像素 3 字节 24 bit
target = 4_000_000                    # 流媒体典型码率 4 Mbps
print(f"裸码流：{raw/1e9:.2f} Gbps")
print(f"成品码流：{target/1e6:.0f} Mbps")
print(f"压缩率：约 {raw/target:.0f} 倍")
print("其中：")
print("  色度子采样先省一半   —— 30-color-space")
print("  帧间预测再省一个量级 —— 120-inter-predict")
print("  DCT+量化把余下能量装进少数系数 —— 70-dct-block / 80-jpeg-quant")
print("  熵编码按 40 章的分布定价 —— 每一步都在给残差挤水")
```

373 倍——这就是整章所有工具合力交出的答卷。**没有任何单一技术能扛下这个数字**：色度子采样、帧间预测、变换、量化、熵编码是接力关系，每一棒都在上一棒的基础上继续挤。调试时也如此：先弄清楚瓶颈在接力棒的哪一环，再对症下药。

### 快问快答

```quiz
一段视频每次拖动进度条，都要先糊两三秒才恢复清晰，最可能的原因是什么？
- 分辨率太高，解码器算不动
- GOP 太长：离拖入点最近的 I 帧太远，解码器只能从旧 I 帧开始追赶 [*]
- 码率太低，画面本来就糊
? 拖动只能从 I 帧起步，糊的那几秒正是解码器补齐预测链的过程。缩短 GOP（或做索引级快进）是标准解药，代价是码率略涨——又一次 R-D 取舍。
```

::::warning[常见误区]

**误区一**："画质不行就该调大码率。"
你以为加大预算是万能药——如果问题出在色彩空间搞错（颜色怎么压都不对）或 GOP 结构（拖动体验），码率翻倍也没用。**先分诊，再花钱**：率失真曲线管预算怎么花，管不了别的科目的病。

**误区二**："压缩是一根链条上的均匀损耗。"
你以为画质是"每压一次掉一点"的线性账——真实管线是接力赛：色度子采样丢的信息**永远回不来**，量化丢的是高频细节，预测丢的靠残差补。搞清每一环丢什么、留什么，才谈得上"哪一环可以松一点"。

**误区三**："方法地图是一条通关路线。"
它是按需查阅的工具书，不是进度条。真实工作只摘用其中两三页——本章真正想教的是**分诊顺序**：先看"能不能正常消费"（播不了、拖不动），再看"对不对"（颜色、时序），最后才看"好不好"（清晰度、文件大小）。顺序错了，会越调越乱。

::::

## 6. 练习

**练习 1**：挂号台的分支顺序被人调乱了：把"颜色不对"排在了"拖不动"前面，导致一个播放故障的片子被开了画质科的号。请把顺序扶正，使五张挂号单输出为 `gop-structure`、`gop-structure`、`gop-structure`、`color-space`、`image-pixels`：

```exercise
# @title: 练习：挂号台的优先级
# @check: gop-structure
# @check: gop-structure
# @check: gop-structure
# @check: color-space
# @check: image-pixels
# @hint: 「能不能正常消费」永远排在「内容对不对」之前。把 playback_jumps 的分支挪到最前
def triage(file_too_big, colors_off, playback_jumps, blocky):
    if colors_off:
        return "color-space"
    if playback_jumps:      # ← 问题在这：播放故障的优先级被压低了
        return "gop-structure"
    if blocky:
        return "jpeg-quant"
    if file_too_big:
        return "rate-distortion"
    return "image-pixels"

print(triage(True, False, True, False))     # 文件大 + 拖不动
print(triage(False, True, True, False))     # 偏色 + 拖不动
print(triage(False, False, True, True))     # 拖不动 + 马赛克
print(triage(True, True, False, False))     # 偏色 + 文件大
print(triage(False, False, False, False))   # 说不上来哪里不对
```

修正后五行输出与 @check 逐一对应。原代码会把"偏色 + 拖不动"的片子开成 color-space——用户连播放都成问题，颜色再正也没人看得到。

**练习 2**：拿到一段"夜间监控糊"的视频，请写出你的完整分诊流程（两问 + 处方），并说明每一步会去查本章哪门课。

<details>
<summary>点开查看参考答案</summary>

1. 第一问：糊是**空域**症状（块效应），但诱因可能在**时域**（夜间噪点让残差暴涨）；第二问：分辨率不高、内容夜视噪点大、码率有限；
2. 查 [量化矩阵](./80-jpeg-quant.md)：块效应是不是量化指纹（8×8 网格对齐）？是 → 继续查为什么量化被调狠了；
3. 查 [率失真](./140-rate-distortion.md)：码率控制器是不是被迫加大 q？夜景内容复杂度超出预算 → 先降噪（[卷积](./40-image-conv.md) 思路）再编码；
4. 查 [帧间预测](./120-inter-predict.md)：噪声让帧间预测失灵（每帧"内容"都在随机变）→ 时域降噪对预测是双重利好；
5. **结论**：症状在频域/空域，病根在时域 + 预算。分诊的价值正在于穿过症状找到病根，而不是头痛医头。

</details>

## 7. 选读：三条游览路线

<details>
<summary>选读 · 不同胃口的吃法</summary>

**编码工程线**（最快上手做视频）：色彩空间 → DCT → 量化矩阵 → 帧率 → 块匹配 → 预测残差 → GOP → 率失真。走完这条线，你能看懂一份 x264/HEVC 参数表里几乎每一个旋钮在干什么。

**视觉计算线**（图像处理与 AI 视觉的底子）：像素模型 → 采样量化 → 卷积 → 梯度与边缘 → 二维傅里叶 → 帧差与运动。这条线通向图像分割、特征提取、光流，是计算机视觉课程的地基。

**理论纵深线**（想知道"极限在哪"）：采样定理 → 信息熵 → 率失真 → 量化理论。这条线回答"最多能压到多少"与"为什么这条路已到头"，通往更 advanced 的信源编码研究。

**三条线共享同一个起点**：把图像看作定义在格子上的函数、把视频看作函数的序列。剩下的一切工具——无论卷积核还是 GOP——都是这个视角的推论。

</details>
