# 图像是二元函数

## 1. 从一个场景开始

把一张照片放进修图软件，放大、再放大——光滑的人脸和天空突然碎成了一格一格的小方块。再继续放大，每一格里只剩一个纯色的小方块，没有任何更细的结构了。

这张图到底"是"什么？它不是一团连续的色块，而是一张巨大的表格：每个格子填着一个数。数清楚了这张表，图像的一切处理——变亮、模糊、找边缘、压缩——都变成对一串数字的运算。

## 2. 直觉解释

20 章讲过二元函数：$z = f(x, y)$，输入平面上一个位置，输出一个高度，画出来就是一片起伏的地形。

**一张灰度图像，恰好就是这个东西。**

- 位置 $(x, y)$：第几列、第几行，即**像素**（picture element）的坐标；
- 函数值 $f(x, y)$：这个位置的**灰度**——0 是纯黑，255 是纯白，中间是深浅不同的灰。

把灰度当"高度"竖起来看，一张照片就是一片地形：天空是平缓的坡，物体的边是断崖，噪声是满地的碎石。修图软件里的"曲线调整"，本质上就是在改这片地形的高度表。

## 3. 正式定义

**数字灰度图像**是一个二元函数，定义在离散网格上：

$$f : \{0, 1, \dots, W-1\} \times \{0, 1, \dots, H-1\} \longrightarrow \{0, 1, \dots, 255\}$$

| 符号 | 名字 | 含义 |
| --- | --- | --- |
| $W \times H$ | 分辨率 | 横向 $W$ 列、纵向 $H$ 行，共 $W \times H$ 个像素 |
| $(x, y)$ | 像素坐标 | $x$ 是**列**（向右增），$y$ 是**行**（**向下**增——和数学课本里的 y 轴方向相反） |
| $f(x, y)$ | 灰度值 | 0 黑 → 255 白；8 个比特恰好装下 256 级 |
| 像素 | picture element | 网格上的一个采样点，不是一块"小方砖"——放大看到的方块只是显示器的呈现方式 |

两张坐标约定要一次说清：**先写列还是先写行**。数学记号里 $f(x, y)$ 是"先列后行"；但 Python 的二维列表 `img[y][x]` 是"先行后列"——行在外层、列在内层。本课程文统一用数学记号，代码统一用 `img[y][x]`，对照着看不要绕晕。

## 4. 分步例题

**例**：一张 $4 \times 4$ 的迷你灰度图（数字是灰度值）：

$$\begin{matrix} 0 & 32 & 64 & 96 \\ 32 & 64 & 96 & 128 \\ 64 & 96 & 128 & 160 \\ 96 & 128 & 160 & 192 \end{matrix}$$

1. **读一个像素**：$f(2, 1)$ 是第 2 列、第 1 行。按"先列后行"数过去：第 1 行是 $32, 64, 96, 128$，取第 2 列的 $96$。所以 $f(2, 1) = 96$；用规律验算：$f(x, y) = 32x + 32y$ 给出 $f(2,1) = 64 + 32 = 96$。✔
2. **看出结构**：每一行从左到右每次加 32，每往下走一行整体再加 32——这张图是 $f(x, y) = 32x + 32y$ 的离散版本，一片匀速上升的斜坡。
3. **求平均亮度**：16 个像素加起来是 $1536$，除以 16 得 $96.0$。斜坡的"平均海拔"正好是中点的值 $f(1.5, 1.5) = 96$——地形越对称，平均值越好算。
4. **翻译成代码视角**：这张表在 Python 里是嵌套列表 `img`，数学的 $f(2, 1)$ 写成代码是 `img[1][2]`（先 `[行]` 后 `[列]`），读出 96——两套记法说的是同一个格子。

真实照片就是这个游戏的放大版：一张 $1920 \times 1080$ 的图有二百多万个格子，但"每个格子一个数"的本质没变。

## 5. 动手实验

### 实验 1（lab）：灰度就是高度

```lab
{
  "type": "image-pixels",
  "title": "放大到看得见单个像素，再把灰度竖起来看",
  "src": "scene",
  "zoom": 6,
  "height": 0.7
}
```

左边是放大后的像素格子，鼠标悬停能读出每个格子的 $(x, y)$ 和灰度值；右边把同一块区域画成三维柱状地形——**柱子越高，像素越白**。做三件事：

- 把窗口拖到天空的渐变区：左边灰度平滑变化，右边是一片缓坡——这就是二元函数的"曲面"；
- 把窗口拖到右下角的高频棋盘：左边缘看着规整，右边已经起起伏伏像丘陵——**变化快的地方，地形就陡**；
- 把放大倍数拉到 1（整张图缩进一格视野）再拉到 16：感受"图像是表格"和"图像是照片"这两种视角怎么切换。

### 实验 2（python）：自己造一张图

```python title="用二维列表造一张 4×4 的灰度图"
img = [
    [  0,  32,  64,  96],
    [ 32,  64,  96, 128],
    [ 64,  96, 128, 160],
    [ 96, 128, 160, 192],
]
print("行数 =", len(img), " 列数 =", len(img[0]))
print("f(2,1) 的代码写法 img[1][2] =", img[1][2])   # 代码是先行后列：img[行][列]

total = 0
for row in img:          # 外层循环：一行一行地拿
    for v in row:        # 内层循环：拿这一行里的每个像素
        total += v
print("平均亮度 =", total / (len(img) * len(img[0])))
```

`img[1][2]` 读出 96，和第 4 节手算的 $f(2,1)$ 一致——数学记号与代码下标的换算就这一处坑，其余全是同一张表。平均亮度 96.0 也与手算一致：斜坡图的平均值恰是几何中点的值。

::::warning[常见误区]

**误区一**："像素坐标和数学课本一样，y 轴朝上。"
你以为 $(0,0)$ 在左下角——其实图像坐标里 $y$ **向下**增：$(0,0)$ 在左上角，$(0, H-1)$ 在左下角。这就是为什么代码里"第 1 行"对应 $y = 1$。做图像编程时画反了 y 轴，图会整张上下颠倒。

**误区二**："像素是一块有面积的小方块。"
你以为放大后看到的方砖就是像素本身——其实像素是一个**采样点的数值**，没有面积。显示器把每个值涂成一个方块给你看，那是显示方式，不是数据结构。所以"图像放大后变模糊"不是像素里藏着细节被拉开了，而是采样点之间的信息当初就没记下来。

**误区三**："灰度值是亮度物理量。"
你以为 255 代表某个物理亮度单位——其实它只是相机把光强**归一化后**的编码档位。同一场景在暗房和阳光下拍，同一个 128 对应的真实光强可以差千倍。灰度是"相对刻度"，不是绝对物理量。

::::

## 6. 练习

**练习 1**：求整张图的平均亮度。下面的代码只数了第一行，答案明显偏小，把循环改成走遍全部 16 个像素：

```exercise
# @title: 练习：求整张图的平均亮度
# @check: 96.0
# @hint: 外层循环应该遍历 img 里的每一行（for row in img），内层再遍历这一行里的每个值——现在只有一层循环，只数了 img[0]
img = [
    [  0,  32,  64,  96],
    [ 32,  64,  96, 128],
    [ 64,  96, 128, 160],
    [ 96, 128, 160, 192],
]
total = 0
for v in img[0]:     # ← 问题在这：只遍历了第一行
    total += v
print(total / (len(img) * len(img[0])))
```

**练习 2**：一张 $W \times H$ 的灰度图，第 $y$ 行的灰度是 $f(x, y) = 8x + 4y$（$x, y$ 从 0 数起，$W = H = 5$）。(a) 写出 $f(3, 2)$；(b) 不写代码，推理整张图的平均亮度。

<details>
<summary>点开查看逐步解答</summary>

1. $f(3, 2) = 8 \times 3 + 4 \times 2 = 32$；
2. $f(x,y) = 8x + 4y$ 对 $x$ 是每次加 8 的等差、对 $y$ 是每次加 4 的等差，两个方向都对称，平均亮度就是**几何中心**的值：
3. 中心在 $x = 2,\ y = 2$，$f(2, 2) = 16 + 8 = 24$；
4. 核对：25 个像素总和 $= \big(\sum_x 8x\big) \times 5 + \big(\sum_y 4y\big) \times 5 = 80 \times 5 + 40 \times 5 = 600$，$600 / 25 = 24$。✔

线性函数的平均值总落在几何中心——这正是第 4 节斜坡例子的推广，也是"地形图"直觉最省力的用法。

</details>

## 7. 选读：从真实场景到一个像素值

<details>
<summary>选读 · 相机是怎么把光变成 0–255 的</summary>

真实场景是连续的：每一点都有一个光强 $I(x, y)$，取值范围是无穷的实数。相机成像做了三件事：

1. **分格**：感光芯片把画面切成 $W \times H$ 个感光单元，每个单元只记录落在自己这一小格上的总光通量——这一步是**空间采样**（下一课的主角）；
2. **曝光积分**：快门打开的 $\Delta t$ 内，单元积累电荷 $\propto I(x,y) \cdot \Delta t$，把"光强"变成"电量"；
3. **量化**：模数转换器把电量归一化到 $0$–$255$ 共 256 个档位——这一步是**幅度量化**，同样是下一课的主角。

所以"图像是二元函数"这句话里的 $f$，天生就是一个**离散定义域 + 离散值域**的函数——它是连续世界 $I(x, y)$ 被两次"降级"后的产物。降级丢掉了什么、为什么通常丢得起，就是下一课的全部内容。

</details>
