# 色彩空间与色度子采样

## 1. 从一个场景开始

一集高清视频如果老老实实存 RGB，每帧光颜色就要吃掉几个 MB——可你下载的整集视频一帧摊下来往往不到 100 KB。省出来的空间里，最大的一笔账是把颜色从 RGB 换成了另一种记法：**亮度 + 色度**，然后把色度狠狠地"降采样"。

更妙的是，这套换法当年是为了让**黑白电视能播彩色信号**发明的：彩色信号里那一部分亮度信息，老电视照收不误。一个同时讨好压缩器和老电视的变换，凭什么这么好使？

## 2. 直觉解释

看一张彩色照片的三个 RGB 通道：红通道、绿通道、蓝通道三张灰度图**长得几乎一样**——哪里亮哪里暗，三个通道高度一致。这叫**高度相关**：三个通道里塞了大量重复信息。

既然是重复记账，就值得换一套记账方式。选三个新"坐标轴"：一个轴记**整体明暗**（亮度 Y），两个轴记**颜色偏红还是偏蓝**（色度 U、V）。换完之后发现：细节全在 Y 上（它几乎就是黑白照片），而 U、V 糊成一片、只有大片缓变。

于是就有了压空间的胆子：**色度可以降采样**，因为人眼对亮度细节敏感、对色度细节迟钝——看照片时你能看清发丝（亮度），却说不清发丝边缘的颜色是从哪一毫秒开始变的（色度）。这不是数学技巧，是**给眼球定制的有损压缩**。

## 3. 正式定义

**RGB → YUV** 是一个线性变换（BT.601 口径）：

$$\begin{aligned} Y &= 0.299\,R + 0.587\,G + 0.114\,B \\ U &= 0.492\,(B - Y) \\ V &= 0.877\,(R - Y) \end{aligned}$$

| 符号 | 名字 | 含义 |
| --- | --- | --- |
| $R, G, B$ | 三原色 | 红绿蓝分量，0–255（各通道等权重记账） |
| $Y$ | 亮度 | 加权平均：绿最重（$0.587$）、红次之、蓝最轻——权重来自人眼视锥细胞的敏感度 |
| $U$ | 色度（蓝向） | 蓝色相对亮度的偏移，0 附近表示"没偏蓝" |
| $V$ | 色度（红向） | 红色相对亮度的偏移 |
| $4{:}4{:}4$ | 无子采样 | 每个像素都保留自己的 U、V |
| $4{:}2{:}2$ | 横向减半 | 水平方向每 2 个像素共享一组 U、V，色度数据减半 |
| $4{:}2{:}0$ | 横竖各减半 | 每 $2 \times 2$ 的 4 个像素共享一组 U、V，色度数据只剩 1/4 |

用 11 章的话说：$(R,G,B)$ 和 $(Y,U,V)$ 是**同一组颜色的两套坐标**，YUV 变换就是换了一组基——旧基是三条颜色轴，新基是一条亮度轴加两条色度轴。换基本身**不丢信息**（矩阵可逆），丢信息的是后面把 U、V 降采样的那一步。

## 4. 分步例题

**例**：把手绘橙色 $(R, G, B) = (255, 128, 0)$ 翻译成 YUV。

1. **算亮度**：$Y = 0.299 \times 255 + 0.587 \times 128 + 0.114 \times 0 = 76.245 + 75.136 + 0 = 151.381 \approx 151.38$；
2. **算蓝向色度**：$U = 0.492 \times (0 - 151.381) = -74.48$——负得不少，说明这个颜色确实"远离蓝"；
3. **算红向色度**：$V = 0.877 \times (255 - 151.381) = 0.877 \times 103.619 \approx 90.87$——大正数，"很偏红"；
4. **解读**：橙色在 YUV 里是"中等偏亮的灰 + 大幅偏红、远离蓝"。黑白电视收到这个信号，就按 $Y \approx 151$ 的灰度显示——比纯白暗、比中灰亮，正是橙色该有的明暗；
5. **核对白点**：$(255, 255, 255)$ 的 $Y = 255 \times (0.299 + 0.587 + 0.114) = 255.0$，$U = V = 0$——纯白亮度顶格、色度为零，权重和恰为 1 不是巧合，是这套系数的设计要求。

## 5. 动手实验

### 实验 1（lab）：三通道拆开看，再把色度扔一扔

```lab
{
  "type": "color-space",
  "title": "把颜色拆成亮度与色度，再看看能扔掉多少",
  "mode": "sub",
  "gain": 8
}
```

切到"通道拆分"模式先看证据：RGB 三个通道是不是高度相似，而 Y 通道独占全部细节、U/V 糊成大片。再切回"色度子采样"：4:4:4 / 4:2:2 / 4:2:0 三张图肉眼几乎分不出——把放大裁切窗口拖到红顶小屋的边缘、把差值增益拉高，才能逼出那一点点渗色。**这就是全世界视频都敢用 4:2:0 的底气。**

### 实验 2（python）：手算三个像素的 YUV

```python title="把三个颜色像素翻译到 YUV"
def rgb_to_yuv(r, g, b):            # BT.601 口径的线性变换
    y = 0.299 * r + 0.587 * g + 0.114 * b
    u = 0.492 * (b - y)
    v = 0.877 * (r - y)
    return y, u, v

pixels = [(255, 255, 255), (255, 128, 0), (0, 0, 255)]
for r, g, b in pixels:
    y, u, v = rgb_to_yuv(r, g, b)
    print(f"RGB({r},{g},{b}) → Y={y:.2f}  U={u:.2f}  V={v:.2f}")
```

三行输出与第 4 节口径一致：纯白是 $(255.00, 0.00, 0.00)$，橙色是 $(151.38, -74.48, 90.87)$，纯蓝是 $(29.07, 111.16, -25.49)$。注意纯蓝的 $Y$ 只有 29——**蓝色在人眼里本来就很暗**，这就是 $0.114$ 这个小权重的含义。

### 快问快答

```quiz
从 4:4:4 改成 4:2:0，色度数据量和总数据量各变成原来的多少？
- 色度 1/2，总量 1/2
- 色度 1/4，总量约 1/2 [*]
- 色度 1/4，总量 1/4

```

::::warning[常见误区]

**误区一**："YUV 是把 RGB 压缩过的格式。"
你以为 YUV 比 RGB 小——其实换基**一个字节都没省**：三通道进、三通道出，矩阵可逆，随时换回去。真正省空间的不是 YUV 本身，而是 YUV **之后**对 U、V 做的降采样。先把信息摆到"重要"和"不重要"两堆上，再对不重要那堆下手——次序不能乱。

**误区二**："色度子采样丢了 3/4 的色度，画质一定崩。"
你以为 4:2:0 是偷工减料——其实人眼视网膜上感知色度的细胞（视锥）密度远低于感知亮度的细胞，天生就"看不清"颜色的细节。4:2:0 只是把分辨率预算按人眼的真实分配重新下注，正常观看距离下几乎不可见。

**误区三**："子采样随便哪个方向减半都行。"
你以为 U、V 各自独立砍就行——实际标准都是**成组共享**：4:2:0 是每 $2\times 2$ 的四个像素共用一组色度，插值时位置对齐有严格规定。随手乱采样再乱插值，饱和色边缘会渗出彩色锯齿（lab 里 gain 拉高就能看到）。

::::

```exercise
# @check: 151.38
# @hint: BT.601 的权重是 R=0.299、G=0.587、B=0.114——绿光对人眼最亮，权重最大的是 G
R = 255
G = 128
B = 0
Y = 0.587 * R + 0.299 * G + 0.114 * B   # ← 权重抄反了
print(round(Y, 2))
```

**练习 2**：纯蓝 $(0, 0, 255)$ 的 $Y$、$U$、$V$ 各是多少？再回答：为什么把蓝色通道单独拿去做"亮度主干"会是灾难？

<details>
<summary>点开查看逐步解答</summary>

1. $Y = 0.299 \times 0 + 0.587 \times 0 + 0.114 \times 255 = 29.07$；
2. $U = 0.492 \times (255 - 29.07) = 0.492 \times 225.93 \approx 111.16$；$V = 0.877 \times (0 - 29.07) \approx -25.49$；
3. 若用蓝色当亮度主干，那么深蓝的海面和纯黑的天鹅将拥有几乎相同的"亮度"——可人眼明明觉得海面亮得多。黑白电视时代若选蓝通道，整个世界都会亮暗颠倒；
4. 权重 $0.587$ 给绿，是因为日光场景里绿色贡献了人眼感知亮度的大半；红色次之、蓝色垫底。**YUV 的三个系数是测量人眼测出来的，不是数学推出来的**——这是它与纯几何"换基"唯一的分界线。

</details>

## 7. 选读：这个变换为什么可逆

<details>
<summary>选读 · 从 YUV 矩阵反解 RGB</summary>

把三个式子写成矩阵（对 $Y$ 与 $B - Y$、$R - Y$ 三元）：

$$\begin{pmatrix} Y \\ B-Y \\ R-Y \end{pmatrix} = \begin{pmatrix} 0.299 & 0.587 & 0.114 \\ -0.299 & -0.587 & 0.886 \\ 0.701 & -0.587 & -0.114 \end{pmatrix} \begin{pmatrix} R \\ G \\ B \end{pmatrix}$$

11 章 40 课讲过：坐标没有变，变的只是描述语言。这个矩阵**可逆**（行列式非零），所以 $\mathrm{RGB} \to \mathrm{YUV} \to \mathrm{RGB}$ 可以无损往返——先由后两行反解出 $B = Y + U/0.492$ 与 $R = Y + V/0.877$，再代回第一行解出 $G$。

设计这个矩阵时真正的约束有两条：**第一行**的三个权重和必须是 1（中性灰的色度自动为零，黑白电视直接收 $Y$ 就能播）；**第二、三行**都写成"某通道减 $Y$"的形式——灰色处 $B - Y = R - Y = 0$，U、V 天然只度量"偏离中性"的量，不携带亮度成分。**"人眼要什么"决定第一行，"结构好不好用"决定后两行**——工程变换几乎都是这个配方。

</details>
