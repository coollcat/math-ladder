# 现代视频编码：H.264 到 AV1 的共同套路

## 1. 从一个场景开始

同一条 1080p 视频，用 H.264 压到 4 Mbps 观众觉得"能看"，换成 AV1 只要 2.5 Mbps 就差不多——**标准换了一代，码率省掉快四成**。可你要是把两份压缩代码摊开对比，会发现它们根本不是两套不同的数学：从 H.264 到 HEVC 再到 AV1，用的都是**同一副骨架**，只是每个零件都拧得更紧了。

这一课就是把那副骨架拆开来：四个零件，各自负责什么、代际增益从哪里来。

## 2. 直觉解释

第 140 课已经把视频编码的哲学说透了：在"花多少比特"与"画质掉多少"之间做取舍。骨架就是执行这个取舍的四道工序：

1. **块划分**：图像不再是固定 16×16 的格子。平坦的大片天空用一个 64×64 的大块描述最划算，头发丝边缘则要切到 4×4 才不吃亏。现代编码器的做法是**四叉树**——一块要么整体编码，要么切成四块各自再决定。
2. **预测**：帧内，从**左边和上面已经解码的像素**按某个方向"猜"过来（几十种角度）；帧间，找到前一帧里最像的那块，只记"从哪里搬来的"。前者吃掉空间冗余，后者吃掉时间冗余。
3. **亚像素运动补偿**：物体位移很少恰好落在整像素格上。把参考帧插值到 **1/4 像素**精度，预测块就能更贴合真实位移——位移找得越准，剩下的残差越空，越空越好压。
4. **环内滤波 + 熵编码**：块边界会有接缝（去块滤波抹平它），滤波后的帧又要拿去当后续帧的参考——所以这一步必须**在编码环内**，不是事后美化。最后 CABAC 把"哪个符号常出现"这件事也编进去，让平均码长逼近熵。

四个零件合起来的一句话：**先在空间和时间两个方向尽可能猜准，再把猜不准的那一点点用最省的编码送出去**。

## 3. 正式定义

**块划分（四叉树）**：一个 $2L\times 2L$ 块要么整体作为一个编码单元，要么拆成 4 个 $L\times L$ 子块递归判断。划分与否由率失真代价决定：

$$J = D + \lambda R$$

**帧内预测**：用重建后的邻块像素沿方向 $\theta$ 外推，$\hat x(i,j) = x^{\text{ref}}(i - t\sin\theta,\ j - t\cos\theta)$；方向数量随代际增加（H.264 的 9 种 → HEVC 的 35 种 → AV1 的 56 种以上）。

**亚像素插值**：整像素位置的样本记作 $s[i]$，半像素用 6 抽头滤波器

$$h[k] = \tfrac{1}{32}(1,-5,20,20,-5,1),\qquad s\!\left[i+\tfrac12\right]=\sum_{k=0}^{5}h[k]\,s[i+k-2]$$

1/4 像素再在半像素结果上双线性插值——**代价是搜索候选点变成整像素的 16 倍**。

**CABAC（上下文自适应二进制算术编码）**：把每个符号二值化成若干 bin，用**已编码邻块的统计**为每个 bin 选一个概率模型，再送进算术编码器。平均码长逼近 $-\sum_v p_v\log_2 p_v$，即第 40 章的一阶熵。

| 符号 | 名字 | 含义 |
| --- | --- | --- |
| $D$ | 失真 | 重建块与原块的差距（常用 SSE 或 PSNR 折算） |
| $R$ | 码率 | 描述这个块花的比特数 |
| $\lambda$ | 拉格朗日乘子 | 失真与码率的兑换率，第 140 课那条曲线上的位置由它决定 |
| $\theta$ | 帧内预测方向 | 从哪个角度把邻块像素外推过来 |
| $h[k]$ | 插值核 | 由整像素造半像素的 6 个权重（和为 1） |
| bin | 二值化符号 | CABAC 里真正被编码的最小单位 |

**与 H.264 的分工对照**：块划分从"固定 16×16 + 可变的子划分"进化到完全四叉树；帧内方向从 9 种涨到 35+；去块滤波后**新增** SAO（样点自适应偏移）做二次修正；熵编码从上下文自适应变长编码（CAVLC）统一到 CABAC，HEVC 起 CABAC 成为唯一选择。

## 4. 分步例题

**例 A（模式抉择）**：某 16×16 块有两种候选模式。模式 A（不划分）$D=12.0$、$R=0.8$；模式 B（切成 4 个 8×8）$D=6.0$、$R=2.0$。取 $\lambda=10$。

1. 模式 A 的代价：$J_A = 12.0 + 10\times0.8 = 20.0$；
2. 模式 B 的代价：$J_B = 6.0 + 10\times2.0 = 26.0$；
3. $J_A < J_B$，**选 A**——省下的失真（6.0）不值多花的那 1.2 bit/像素；
4. 若把 $\lambda$ 调到 2（高码率档），$J_A=13.6$、$J_B=10.0$，**选 B**——同样的两个模式，换个兑换率结论就反了。

**例 B（亚像素搜索点数账）**：搜索半径 $r=16$ 整像素的全搜索。

1. 候选点：横竖各 $2r+1=33$ 个，共 $33\times33=1089$ 个位置；
2. 每个整像素位置再细分 $4\times4$ 个亚像素位置，总候选 $1089\times16=17424$ 个；
3. 半径翻倍到 32，候选点变 $65\times65=4225$，亚像素版 $67600$ 个——**搜索点数按半径平方增长，亚像素再乘 16**；
4. 所以真实编码器从不做全搜索：先用整像素快速定位，再在最优位置邻域做亚像素细化，这就是第 43 章"先粗后精"的优化策略。

## 5. 动手实验

### 实验 1（viz）：所有编码器都在追同一条理论下界

```viz

  "expr": "0.5*log(s/x)/log(2)",
  "label": "香农理论下界 R(D)",
  "expr2": "0.5*log(s/x)/log(2) + 1",

  "xmin": 0.2,
  "xmax": 10,
  "sliders": [

  ]
}
```

横轴是允许的失真 $D$，纵轴是所需码率 $R$，滑杆 $s$ 是信源方差。**蓝线是理论下界**（高斯信源的 $R(D)=\tfrac12\log_2(\sigma^2/D)$），**橙线是"多花 1 bit/像素"的工程编码器**。做两件事：把 $s$ 从 10 拧到 100，两条曲线**整体上移**——画面越复杂（方差越大），同样的失真就要更多比特；盯住两条线的间距，它几乎不随 $s$ 变。**这就是代际增益的用武之地：新标准的一切努力，都是把橙线往下按、逼近蓝线。**

### 实验 2（python）：理论上界算一遍

```python
import math                     # math.log 是自然对数；log2(x) = ln(x)/ln(2)

sigma2 = 50.0                   # 信源方差（把像素灰度当作信号）
for d in [1.0, 2.0, 5.0, 10.0, 25.0]:        # d：允许的失真（MSE 口径）
    r = 0.5 * math.log(sigma2 / d) / math.log(2)   # 率失真函数 R(D) = ½·log₂(σ²/D)
    print(round(d, 1), "→", round(r, 2), "bit/像素")
```

五行输出：`1.0 → 2.82`、`2.0 → 2.32`、`5.0 → 1.66`、`10.0 → 1.16`、`25.0 → 0.5`。**失真放大 5 倍（1→5），码率只降了不到一半**——曲线在低失真端陡、高失真端平，这就是第 140 课说的"膝盖"的数学来源。实际编码器的工作点都停在膝盖附近。

### 实验 3（python）：亚像素的搜索点数账

```python
for r in [16, 32, 64, 128]:          # r：运动搜索半径（整像素）
    full = (2 * r + 1) ** 2          # 全搜索候选：横竖各 2r+1 个位置
    quarter = full * 16              # 1/4 像素：每个整像素位置再分 4×4 个更细位置
    print(f"半径 {r:>3}: 整像素 {full:>5} 点 → 1/4 像素 {quarter:>6} 点")
```

四行输出：半径 16 从 1089 点涨到 17424 点；半径 128 从 66049 点涨到 1056784 点。**帧率 60、每秒要处理上千个块时，这个数字就是编码器算力的天花板**。所以 HEVC/AV1 用更聪明的搜索（菱形、多精度分层）替代全搜索：同样的精度，点数少一个数量级。

## 6. 常见误区

:::warning[常见误区]

**误区一**："新标准就是把同一件事压得更狠。" 其实压缩率的每一分都要用算力换。HEVC 的解码算力大约是 H.264 的两倍，AV1 更高——所以老手机宁可解 H.264。**标准之争从来不是"谁更省比特"，而是"谁的省法落在当下硬件的预算里"**。

**误区二**："1/4 像素精度纯属浪费。" 其实位移是连续量，整像素只是把连续量四舍五入的结果，误差可达半个像素；插值到 1/4 像素把这一步的误差压到 1/8 像素以内。残差小一点点，后面熵编码就能省一大截——**花在插值上的算力，从码率上连本带利挣回来**。

**误区三**："去块滤波是为了让画面好看才加的。" 它不是美化滤镜，而是**预测链上的必要修正**：块接缝如果不抹平，下一帧拿它当参考时就会把接缝也预测进来，误差逐帧放大。好看的画面只是顺带的结果。

:::

## 7. 练习

**练习 1**：编码器在两种模式之间的抉择。下面的代码能跑，但它选了码率最低的那个——因为代价函数漏了一件事，改到输出 `A`：

```exercise
# @title: 练习：编码器的模式抉择
# @check: A
# @hint: RD 代价 J = D + λ·R。λ 是"失真换码率"的兑换率，漏乘它机器就会一味贪便宜选低码率、低质量的模式。
lam = 10.0                                    # 拉格朗日乘子 λ
cands = [("A", 12.0, 0.8), ("B", 6.0, 2.0)]   # (模式名, 失真 D, 码率 R)

best_name = None
best_j = None
for name, d, r in cands:
    j = d + r                                 # ← 问题在这：忘了乘 λ
    if best_j is None or j < best_j:
        best_j = j
        best_name = name
print(best_name)
```

**练习 2**：上题里把 $\lambda$ 从 10 改成 2，结论变成什么？从"码率档次"的角度解释为什么高码率档更容易选择划分（模式 B）。

<details>
<summary>点开查看逐步解答</summary>

1. $\lambda=2$：$J_A=12.0+1.6=13.6$，$J_B=6.0+4.0=10.0$，选 **B**；
2. 直觉：$\lambda$ 是"1 bit/像素值多少失真"。低码率档比特贵（$\lambda$ 大），编码器宁可不划分、少花比特；高码率档比特便宜（$\lambda$ 小），它愿意多花比特去换质量——所以高清档可以放心用更细的块划分；
3. 这正是现代编码器"同一套算法、不同 QP 档位"的秘密：**分块、帧内方向、滤波强度都由同一个 $\lambda$ 统一驱动**。

</details>

**练习 3**：若半像素插值核 $h=(1,-5,20,20,-5,1)/32$ 的权重之和不为 1，会出什么问题？

<details>
<summary>点开查看逐步解答</summary>

1. 权重和 $=(1-5+20+20-5+1)/32 = 32/32 = 1$——**恰为 1 是刻意的**；
2. 直流（所有样本相等，记作 $c$）经过滤波应保持 $c$ 不变，只有权重和为 1 才做得到。若和为 0.9，平坦区域会整体变暗；
3. 后果：插值出的参考帧整体亮度漂移，被当成后续帧的参考后误差累积——又变回"参考必须和原图统计一致"这条铁律。

</details>

## 8. 选读：三代标准各自拧紧了哪颗螺丝

<details>
<summary>选读 · H.264 → HEVC → AV1 的增益清单</summary>

- **H.264（2003）**：把编码从"固定 16×16 + 可选子块"升级为可变块尺寸，帧内 9 种方向，引入 CABAC。它的历史地位是**第一次把 RD 代价显式写进标准**——$J=D+\lambda R$ 从研究论文变成了编码器的日常决策。
- **HEVC / H.265（2013）**：块划分升级为**完全四叉树**（编码单元 64×64 到 8×8，还有更深一层的预测单元与变换单元），帧内方向 35 种，新增 **SAO** 在去块之后做二次样点修正，CABAC 成为唯一熵编码器。约 50% 的码率节省，代价是解码复杂度翻倍。
- **AV1（2018）**：块划分再开叉（四叉树 + 二叉树 + 三叉树的混合枚举），帧内方向 56 种以上，新增 **CDEF**（约束方向增强滤波）与环路恢复滤波器，熵编码用多符号算术编码。开源、免专利费是它的另一半武器。
- **再往前**：H.266/VVC（2020）加了多类型树与自适应环路滤波（ALF）与仿射运动，约再来 40%。

看清单会发现：**每一代都在同一个四个格子里加料**——划分更灵活、预测更精细、滤波更聪明、熵编码更贴统计。骨架不变，螺丝越拧越紧。

</details>
