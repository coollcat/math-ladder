# 计算机系统

第 72 章造出了一台会取指、会译码、会流水的机器。可你双击一个图标，从磁盘上的一串字节到屏幕上跳出的窗口，中间隔着的不只是 CPU——是**操作系统、编译器、数据库和网络协议**这四层"看不见的软件"。

这一章回答一个朴素的问题：**机器凭什么能同时干一百件事，还不把任何一件事干错？**

主线只有一条：**一台机器 → 许多任务 → 共享的资源 → 共享的真相。**

## 方法主线

**抽象 → 共享 → 调度 → 一致性。**

前两课先把"一个程序"拆成静态映像与动态进程；三四五课处理最紧俏的资源——CPU 与内存，核心工具是**排队、图论与概率**；六到八课进入"把一种语言变成另一种语言"的编译器世界，工具是**形式文法与图算法**；九到十一课是数据的持久化与并发，工具是**集合代数与偏序**；最后五课把单机放大到网络，工具是**图论、反馈控制与多数派投票**。

你会发现整章只反复使用一个动作：**把"同时发生"的一团乱麻，排成一个可以判定的顺序。** 调度排任务，页表排地址，事务排读写，共识排日志——系统工程的艺术，几乎全在这个"排"字上。

## 实战挑战 · 一次内存访问到底多久

> 场景说明：以下数字取自典型 x86-64 服务器（DDR4、4 级页表、4 KB 页），用于建立数量级直觉。

L1 缓存命中约 1 ns，内存访问约 100 ns，磁盘约 10 ms。若 TLB 命中率 99%、TLB 未命中时要额外走 4 级页表（4 次内存访问），求有效访问时间（ns）。修到输出 `105`：

```exercise
# @title: 实战挑战：TLB 命中率 99% 时的有效访问时间
# @check: 105
# @hint: 分两条路：命中路径是「查 TLB + 访内存」≈ 1 + 100；未命中路径是「查 TLB + 走 4 级页表（4×100）+ 访内存」= 1 + 400 + 100。按 0.99 / 0.01 加权求和
t_mem = 100.0      # 一次内存访问（ns）
t_tlb = 1.0        # 一次 TLB 查找（ns）
h = 0.99           # TLB 命中率
levels = 4         # 4 级页表

hit = t_tlb + t_mem
miss = t_tlb + levels * t_mem + t_mem
eat = h * hit + (1 - h) * miss
print(eat)
```

<details>
<summary>点开查看逐步解答</summary>

1. 命中路径：查 TLB 1 ns，直接拿到物理地址，访内存 100 ns，共 101 ns；
2. 未命中路径：查 TLB 1 ns，再依次读 4 级页表（每级一次内存访问 = 400 ns），最后访数据 100 ns，共 501 ns；
3. 加权：$0.99 \times 101 + 0.01 \times 501 = 99.99 + 5.01 = 105.0$ ns；
4. 结论：TLB 把"最坏 501 ns"压成了平均 105 ns——**多出来的 5 ns 就是虚拟内存的定价**。若命中率掉到 90%，$0.9\times101+0.1\times501 = 141$ ns，慢了三分之一。

这个 105 ns 是第 50 课的核心数字。它解释了为什么 4 KB 页、多级页表、TLB 这三件东西必须打包出现。

</details>
