## 1. 从一个场景开始
同一段 C 代码，用 `-O0` 编译跑 3.2 秒，加个 `-O2` 变成 0.7 秒。**编译器什么都没改你的逻辑，它只是把账重新算了一遍。**
它凭什么敢改？因为语法树里藏着大量"算了等于没算"的活：`4 * 2` 在编译期就知道是 8；`a + b` 算了两遍；某个变量算出来后再没人用过；循环里每轮都在算一个根本不变的东西。
## 2. 直觉解释
编译器是个**会计**：
- **三地址码**是它用的记账格式——每条账目只允许"两个来源、一个去向"（`t1 = a + b`），复杂表达式被拆成一串流水账；
- **常量折叠**是"能当场算的就不记流水账"（`4*2` 直接写 8）；
- **公共子表达式消除（CSE）** 是"同一笔账不记两遍"（第二次 `a+b` 直接抄第一次的结果）；
- **死代码删除**是"这笔账没人看，撕掉"（从出口往回推，看谁的结果真的会被用到）；
- **循环不变量外提（LICM）** 是"每月都一样的水电费，别每月重算，年初一次算好"。
**每一种优化都必须保证语义不变**。这也是编译器 bug 最可怕的地方：它生成的程序会安静地算出错误答案。
## 3. 正式定义
**三地址码（TAC / IR）**：形如 $x \mathrel{:=} y \ \mathbf{op}\ z$ 的指令序列，每条至多一个运算符、至多三个地址。
**基本块（basic block）**：一段只能**从入口进、从出口出**的指令序列（中间没有跳转进出的目标）。基本块是优化的基本单位。
**控制流图（CFG）**：节点是基本块，边是可能的跳转。数据流分析就在这张图上跑。
四种经典优化：
| 优化 | 判据 | 变换 |
| --- | --- | --- |
| 常量折叠 | 两个操作数都是编译期常量 | 当场算出结果，改成一条传送 |
| 代数化简 | 匹配 $x\cdot 0$、$x\cdot 1$、$x + 0$ 等恒等式 | 直接换成 $0$、$x$、$x$ |
| 公共子表达式消除 | 同一 $(op, a, b)$ 此前算过，且 $a,b$ 此后未被重定义 | 复用上次的临时变量 |
| 死代码删除 | 反向做**活跃变量分析**：出口活跃集 $L_{\text{out}}$ 已知，则 $L_{\text{in}} = (L_{\text{out}} \setminus \lbracex\rbrace) \cup \lbracey, z\rbrace$ | 目标变量不在 $L_{\text{out}}$ 中的指令整条删掉 |
| 循环不变量外提 | 在循环体内，但其操作数都不在"循环内被修改集合"中 | 搬到循环前置块，只算一次 |
注意 CSE 那条"此后未被重定义"的限定——**变量被重新赋值后，旧结果立刻失效**，这是最容易写错的一处。
## 4. 分步例题
**例**：对下面这段 IR 依次做常量折叠、CSE、死代码删除（出口活跃变量为 $y, z$）：
```text
t1 = 4 * 2      t2 = a + b      t3 = a + b
t4 = t1 * x     t5 = t2 * 2     t6 = t2 * 2
t7 = t6 * 0     y  = t4 + t3    z  = t5 + t6
```
1. **常量折叠**：`t1 = 4 * 2` → `t1 = 8`；
2. **代数化简**：`t7 = t6 * 0` → `t7 = 0`（恒等式 $x \cdot 0 = 0$）；
3. **CSE**：`t3 = a + b` 与 `t2` 的表达式相同，且其间 $a,b$ 都没被改写 → `t3 = t2`；同理 `t6 = t5`；
4. **死代码删除**：从出口 $\lbracey, z\rbrace$ 倒着推。$z$ 用到 $t_5,t_6$；$y$ 用到 $t_4,t_3$；$t_3 = t_2$、$t_6 = t_5$、$t_5 = t_2\cdot2$、$t_4 = t_1\cdot x$、$t_2 = a+b$、$t_1 = 8$ 依次被"用上"——**只有 $t_7$ 从头到尾没人要，删掉**；
5. 结果：9 条变 8 条（改写 3 条、删除 1 条）。实验室里那段**带循环的 13 条 IR**，四个开关全开后变成 **12 条**：删掉 1 条死代码，把 1 条循环不变量提出循环。
## 5. 动手实验
### 实验 1（lab）：四个开关，逐个打开
```lab
{
  "type": "ir-optimize",
  "title": "IR 优化：常量折叠 / CSE / 死代码删除 / 循环不变量外提"
}
```
左栏是优化前的 13 条三地址码，右栏随开关实时变化：被改写的标成橙色并注明原因，被删除的划掉，被外提的加一个 `↑` 前缀。读数里给出"指令数 13 → N"与三类变化的计数。
按这个顺序点，效果最清楚：
- 只开**常量折叠**：`t1 = 4 * 2` 变成 `t1 = 8`，`t7 = t6 * 0` 变成 `t7 = 0`——**代数化简是折叠的近亲**；
- 再加**公共子表达式**：`t3` 与 `t6` 被复用，`t6` 甚至因此整条变成了 `t6 = t5`；
- 再加**死代码删除**：只有 `t7` 被划掉。为什么 `t1 = 8` 还在？因为 `t4 = t1 * x` 用了它，而 `t4` 又被 `y` 用了——**活跃性是链条，不是单条指令的性质**；
- 最后加**循环不变量外提**：`t9 = k * 4` 被搬到循环前面（`k`、`4` 在循环里都没人改），而 `t10 = arr[t9]` 没动——**数组访问不能随便外提**，因为 `arr` 可能被循环内的写操作改写（别名问题）。
### 实验 2（python）：把前三个 pass 写出来
```python title="常量折叠 → 公共子表达式消除 → 死代码删除"
ir = [
    ("t1", "*", "4", "2", ""), ("t2", "+", "a", "b", ""), ("t3", "+", "a", "b", ""),
    ("t4", "*", "t1", "x", ""), ("t5", "*", "t2", "2", ""), ("t6", "*", "t2", "2", ""),
    ("t7", "*", "t6", "0", ""), ("y", "+", "t4", "t3", ""), ("z", "+", "t5", "t6", ""),
]
def is_num(s):
    return s.lstrip("-").isdigit()      # lstrip：去掉左边可能带有的负号再判断
def fold(ir):
    out = []
    for dst, op, x, z, note in ir:
        if is_num(x) and is_num(z):
            v = int(x) * int(z) if op == "*" else int(x) + int(z)
            out.append((dst, "=", str(v), "", "常量折叠"))
        elif op == "*" and (x == "0" or z == "0"):
            out.append((dst, "=", "0", "", "代数化简 x·0"))
        else:
            out.append((dst, op, x, z, note))
    return out
def cse(ir):
    seen = {}                            # (op, x, z) → 上次算出的临时变量
    out = []
    for ins in ir:
        dst, op, x, z, note = ins
        for k in list(seen):             # list()：边遍历边删，先复制一份键
            if k[1] == dst or k[2] == dst:     # 操作数被重定义 → 旧结果作废
                del seen[k]
        key = (op, x, z)
        if key in seen:
            out.append((dst, "=", seen[key], "", "CSE 复用"))
        else:
            seen[key] = dst
            out.append(ins)
    return out
def dead(ir, exits):
    live = set(exits)                    # set：当前活跃的变量集合
    keep = []
    for ins in reversed(ir):             # reversed：从最后一条倒着往回推
        dst, op, x, z, note = ins
        if dst not in live:
            continue                     # 算了没人用 → 不保留（即删除）
        live.discard(dst)                # discard：从集合移除，不存在也不报错
        for v in (x, z):
            if v:
                live.add(v)              # 它用到的操作数变为活跃
        keep.append(ins)
    return list(reversed(keep))
n0 = len(ir)
step1 = fold(ir)
step2 = cse(step1)
step3 = dead(step2, ["y", "z"])
print(f"指令数：{n0} → {len(step1)} → {len(step2)} → {len(step3)}")
for ins in step3:
    tail = "   ← " + ins[4] if ins[4] else ""
    print("  ", ins[0], "=", ins[2], ins[1], ins[3], tail)
```
注意 `cse` 里那三行"失效处理"：**没有它，优化就是错的**。下一节的练习 1 正是这个坑。
:::warning[常见误区]
**误区一**："优化就是让代码更短，短就一定更快。" 你以为指令数与运行时间成正比——**指令数只是最粗的一个代理指标**。真正的目标是**关键路径上的周期数**：寄存器分配（把变量留在寄存器里而不是反复读写内存）、指令调度（填满流水线空隙）、缓存局部性，任何一个的收益都可能超过指令数的减少。有些"优化"（如激进的循环展开）反而会让代码变大、缓存命中率下降。
**误区二**："编译器绝不会改变程序的含义。" 你以为优化是绝对安全的——**编译器也有 bug**。`-O2` 出问题的经典原因是编译器利用了"未定义行为"：C 里 `int` 溢出、数组越界、`*p++ = *q++` 的求值顺序都是未定义的，编译器可以假设它们**不会发生**并据此优化。于是你写的"能跑的 UB"在 `-O0` 下正常，`-O2` 下就跑飞了。**这类 bug 的根源在源代码，不在编译器。**
**误区三**："优化一遍就够了，顺序无所谓。" 你以为 pass 是一组可任意排列的开关——**优化之间互相创造机会**：CSE 制造了大量"只被用一次"的临时变量，常量折叠后又有新的常量可用于传播，死代码删除之后某些表达式又变成了可复用的。**工业编译器的 pass 是流水线，会来回跑好几轮**，直到没有变化（到达不动点）为止。
:::
## 6. 练习
**练习 1**：这段 CSE 复用了 `a + b` 的旧结果，可 `a` 在中间被改写了。修到输出 `55`：
```exercise
# @title: 练习：复用了一个已经失效的表达式
# @check: 55
# @hint: CSE 的前提是「上次算完之后，参与运算的变量都没被改写」。a 被重新赋值时，必须把表里所有涉及 a 的条目删掉，之后遇到 a+b 就得重新算
ir = [
    ("t1", "+", "a", "b"),    # t1 = a + b
    ("a", "=", "10", ""),     # a := 10（重新定义！）
    ("t2", "+", "a", "b"),    # t2 = a + b（字面一样，含义已经变了）
    ("y", "+", "t1", "t2"),
]
env = {"a": 5, "b": 20}       # 环境：变量名 → 当前值
seen = {}                     # 表达式 (op, x, z) → 上次算出的临时变量
vals = {}                     # 临时变量 → 它的值
for dst, op, x, z in ir:
    if op == "=":
        env[dst] = int(x)
        continue              # ← 问题在这：重新定义了 a，却没有把 seen 里相关条目作废
    key = (op, x, z)
    if key in seen:
        vals[dst] = vals[seen[key]]          # 复用旧结果
    else:
        vals[dst] = env[x] + env[z]
        seen[key] = dst
print(vals["y"])
```
**练习 2**：下面这段循环里，哪些计算是循环不变量？外提之后循环体还剩几条指令？
```text
L1:  t1 = n * 4
L1:  t2 = arr[t1]
L1:  s  = s + t2
L1:  i  = i + 1
```
<details>
<summary>点开查看逐步解答</summary>
1. 先求"循环内被修改的集合"：被赋值的目标有 `t1`、`t2`、`s`、`i`；
2. 逐条看操作数是否被这个集合命中：`t1 = n * 4` 的操作数是 `n` 与 `4`，**都不在集合里** → 是循环不变量，可以外提；
3. `t2 = arr[t1]` 的操作数含 `t1`，而 `t1` 在循环内被改写 → 不能外提；
4. `s = s + t2` 含 `s`（循环内被改）→ 不能外提；`i = i + 1` 同理；
5. 外提后：循环前置块多一条 `t1 = n * 4`，循环体从 4 条减到 3 条；
6. 若循环执行 $N$ 次，就省下 $N - 1$ 次乘法——**这是最划算的一类优化：省下的量与循环次数成正比。**
</details>
## 7. 选读：数据流分析与不动点
<details>
<summary>选读 · 为什么「来回跑几轮」一定会停下来</summary>
死代码删除、CSE、常量传播都属于**数据流分析**：在 CFG 的每个节点上求一个集合（活跃变量、可用表达式、可达定义），集合沿控制流边传播。
以**向前分析**（如可达定义）为例，对每个块 $B$：
$\text{IN}[B] = \bigcup_{P \in \text{pred}(B)} \text{OUT}[P], \qquad \text{OUT}[B] = \text{gen}[B] \cup (\text{IN}[B] \setminus \text{kill}[B])$
这是一组**方程**（不是赋值），要用迭代求解：先把所有集合初始化为空，反复套用这两条规则直到不再变化。
**为什么一定会停**：集合的元素来自一个有限集合（比如"所有定义点"的子集），而每次迭代中 $\text{OUT}[B]$ 要么变大要么不变——**单调不减且有上界**，所以最多迭代 $|\text{全集}| \times |\text{块数}|$ 轮必然到达**不动点**（fixed point）。
这个框架就是编译器中端的骨架：换掉"格（lattice）"与"传递函数"，就得到不同的分析——活跃变量、常量传播、部分冗余消除。第 27 章的偏序与不动点思想，在这里找到了最实用的一处应用。
</details>
