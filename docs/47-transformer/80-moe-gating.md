# MoE 与稀疏门控：专家们的分诊台

## 1. 从一个场景开始

上一课末尾留了一道算术阴影：前馈车间一个人囤下全模型约三分之二的参数——几十层叠起来，模型越练越胖。想让它更渊博，就得盖更大的车间；可每个 token 无论问什么都动用整条生产线，电费先撑不住。

医院的解法早已有之：**分诊台**。病人进门时不搞全院大会诊，护士扫一眼症状就把你送进最对口的两三个诊室，其余科室照常闲着。MoE（混合专家）模型把这套制度搬进了 FFN 层：车间扩建成一整个专家楼，却让每个 token 只敲响少数几扇门。

## 2. 直觉解释

把上一课的前馈站想象成一个**巨型 FFN 被复印成 E 份**，每份叫一位"专家"；门前加一道**路由器**（router）：

1. token 报到，路由器给它做一次快速体检，给$E$位专家各打一个"对口分"；
2. 只挑分数最高的 $k$ 位（比如 $k=1$ 或 $2$）上岗，其他人这个 token 根本见不着；
3. 上岗者的产出按"对口程度"加权合并——这正好又是第 30 课的老朋友 softmax 在打分排座次。

于是出现了一件新鲜事：**参数量与计算量第一次分家**。专家楼的床位数（参数）可以堆到天文数字——反正闲着的专家不消耗算力；每个 token 的计算量只由 $k$ 和单间诊室的大小决定。代价是新的：如果大家总往同一间诊室挤（"一号专家独大"），其余专家等于白养——这就需要"接诊配额管理"，即负载均衡辅助损失。

## 3. 正式定义

设某 token 的路由打分为 $\ell_1,\dots,\ell_E$。选出分数最大的集合 $\text{TopK}$（大小 $k$），在被选者内部重新归一化成门控权重：

$$g_i = \frac{e^{\ell_i}}{\sum_{j\in\text{TopK}} e^{\ell_j}}\quad (i\in\text{TopK})\qquad \text{MoE}(x) = \sum_{i\in\text{TopK}} g_i\cdot \text{Expert}_i(x)$$

| 符号 | 含义 |
| --- | --- |
| $E$ | 专家数量（现代大模型常见 $64\sim 256$ 位） |
| $k$ | 每 token 实际激活的专家数；$k=1$ 称 Switch 结构，常用 $k=2$ |
| $g_i$ | 门控权重：预算如何在入选专家间分配 |
| $\text{Expert}_i$ | 第$i$位专家：结构与上一课 FFN 相同的小 MLP |

**负载均衡辅助损失**：训练时同时优化主任务和一笔"接诊公平费"。记 $f_i$ 为批次中实际流向第$i$位专家的比例、$P_i$ 为门控给它的平均概率，则

$$L_{\text{aux}} \propto \sum_{i=1}^{E} f_i\,P_i$$

均匀接诊时 $f_i=P_i=\tfrac1E$，总额最小；全都涌向一号专家时该项被推到最大。辅助损失越小越均衡，从而逼迫路由"雨露均沾"。

## 4. 分步例题

**例**：四位专家，某 token 的路由原始分为 $(3.0,\ 0.9,\ 0.1,\ 2.0)$，$k=2$。

1. 全体 softmax 看倾向：指数 $(20.086,\ 2.460,\ 1.105,\ 7.389)$，总和 $31.04$，配比约 $(0.647,\ 0.079,\ 0.036,\ 0.238)$——一号与四号明显领先；
2. 入选 TopK：$\lbrace \text{一号，四号}\rbrace$，另外两位今天不用上班；
3. 入选者内部重新归一：$20.086/(20.086+7.389)=0.731$，四号得 $0.269$——先淘汰后排名，配比只在幸存者之间分蛋糕；
4. 设一号输出 $(1,\ 0)$、四号输出 $(0,\ 2)$，合并：$0.731\,(1,0)+0.269\,(0,2)=(0.731,\ 0.538)$。

对照记账：注意这是假设**不开分诊台、四人都干活**的对照情形（二号 $(−1,1)$、三号 $(0,−1)$ 也各干一份活），按全员 softmax 加权会得到约 $(0.568,\ 0.519)$ 的相近融合——但花了**整整四份**算力。top-2 只用一半工，结果已在一个可接受的邻域里；误差嘛，正是训练要逼着专家们各自变得更专业的原因。

### 实验 2（viz）：拖动温度与名额数，看门控权重怎么分

实验 1 用一条静态曲线讲了温度，这枚组件把它变成可以拖的。**怎么玩**：拖 t，看四位专家的概率条此消彼长——t 调小，领先者条形窜高、其他人被压扁，分诊台变得独断；t 调大，四条趋于齐平，分诊台开始犹豫。拖 k，在 top-1 与 top-2 之间切换，高亮条随之变化，被选中的条下方给出重新归一后的门控权重 g——注意 top-2 的 g 不是原始概率，而是被 k 个入选者瓜分后的占比。读数区有两项要盯：**落选票权合计**（被冷落的专家原本拿到多少概率质量，k=2 时明显小于 k=1）与**最大接诊占比**（越接近 100% 越失衡，正是下文实验 3 要用容量因子去治的病）。读数与实验 3 的接诊计数是同一件事的两种视角：这里看单个病例的权重分配，那里看一整批病例撞上限额后怎么分流。

### 实验 3：分诊台模拟器——名额不限时失衡，挂上限额后分流

```python title="top-1 路由计数与容量配额的效果"
import matplotlib.pyplot as plt

NAMES = ["一号", "二号", "三号", "四号"]
CAP = 3                       # 每位专家本轮只放 3 个号源（容量因子）
cases = [                     # 12 位病人的路由原始分（手工设定的玩具数据）
    [3.0, 1.8, 0.2, 0.4],
    [2.8, 1.6, 0.5, 0.3],
    [3.2, 1.9, 0.1, 0.7],
    [0.2, 2.5, 0.4, 0.1],
    [0.1, 2.2, 0.3, 0.5],
    [3.1, 1.7, 0.6, 0.2],
    [0.3, 2.4, 0.2, 0.2],
    [2.9, 1.5, 0.4, 0.8],
    [0.5, 2.3, 0.3, 0.2],
    [2.7, 2.0, 0.2, 0.3],
    [0.2, 0.4, 2.6, 0.5],
    [0.4, 0.3, 0.2, 2.7],
]

free_counts = {}                          # 第一轮：不加管制的自然路由
for row in cases:
    win = row.index(max(row))
    free_counts[win] = free_counts.get(win, 0) + 1

def pick_first_free(row, used):
    temp = row[:]                         # 切片复制列表，不碰原始数据
    for _ in range(len(temp)):
        j = temp.index(max(temp))         # 当前最对口的专家
        if used[j] < CAP:                 # 还有号源就直接收
            return j
        temp[j] = float('-inf')           # 号满了：划掉这位，找次对口
    return -1                             # 全都满员：放弃专家（生产中走残差）

used = [0] * len(NAMES)                   # 各专家本轮已接诊数
cap_counts = {}
rerouted = []                             # 因满员被迫改道的病例编号
for no, row in enumerate(cases):
    win = pick_first_free(row, used)
    if win != row.index(max(row)):
        rerouted.append(no)
    used[win] += 1
    cap_counts[win] = cap_counts.get(win, 0) + 1

print([free_counts.get(i, 0) for i in range(4)])
print([cap_counts.get(i, 0) for i in range(4)])
print(rerouted)

fig, axes = plt.subplots(1, 2, figsize=(9, 4))
axes[0].bar(NAMES, [free_counts.get(i, 0) for i in range(4)])
axes[0].set_title("不限号：一号专家门前排长队")
axes[1].bar(NAMES, [cap_counts.get(i, 0) for i in range(4)])
axes[1].set_title("限号 3 位：长队被拆散")

plt.tight_layout()
```

左图是一号门前的长队（接诊比 6 : 4 : 1 : 1）；右图实行限额后，撞上满员门诊的病例被迫转投各自"次对口"的科室——单打独斗的长队被拆成人流均匀的四股（四家恰好各接 3 位，是这份玩具数据精心设计的巧合）。辅助损失走的正是同一条路：训练时软性地削峰填谷，推理时才需要这种硬性的溢出处置——被挤掉的 token 沿残差高速路绕过整个专家层继续前行，绝不至于断流。

### 快问快答

```quiz
一个 MoE 层的总参数是同尺寸稠密 FFN 的 8 倍，为什么单 token 的计算成本几乎不变？
- 参数翻倍，计算必然同比变贵
- 每个 token 经路由只走进 k 位专家，其余专家本次完全不参与 [*]
- 反而比稠密层更快出炉
? 参数常驻显存、但要耗费算力的只有真正被激活的那几个 MLP。计算账跟着 k 走而不跟着专家总数走——参数量与计算量自此分家。
```

:::warning[常见误区]

**误区一**："MoE 是全体专家加权平均的大拌菜。"——从未选中的视角看它们产出的权重是**零**而不是小数：top-k 名单之外无人上班；加权只发生在入选者之间。

**误区二**："专家分工一定对应学科：数学专家、代码专家、历史专家。"——观察到的分化常常相当表面（有的专收标点、有的专收高频词），而且相邻层的专家编号彼此没有传承关系。专家是功能单元，不是知识目录。

**误区三**："负载均衡损失调得越强越健康。"——过强的均衡会强行把病人塞给不对口的科室，专业化无从谈起；它是一种温和的压力阀门，不是追求绝对平均的指标。

:::

## 6. 练习

**练习 1**：为什么"不选中就不产生计算"能让参数堆到万亿级而训练成本可控？

<details>
<summary>点开查看逐步解答</summary>

因为单步开销 = 每 token 走过的$k$条通路 $\times$ 每位专家的规模，与专家总数 $E$ 无关。加大 $E$ 只是拓宽了"货架"（记忆容量），读写速度不变。显存倒是水涨船高——这正是现代稀疏大模型普遍采用专家并行的原因之一。
</details>

**练习 2**：亲手扮演路由器，补完冠军专家的配额与流失的票权：

```exercise
# @title: 练习：找出分诊冠军
# @check: 0
# @check: 0.87
# @check: 0.13
# @hint: 冠军权重就是列表 g 里最大的那个数；落选者的权重加起来，就是本次没能投出去的票权（三张权重之和为 1）。
import math

logits = [2.0, 0.0, -2.0]     # 三位专家的路由原始分

m = max(logits)               # 减最大值防溢出
exps = []
for s in logits:
    exps.append(math.exp(s - m))
total = sum(exps)

g = [e / total for e in exps] # 门控权重：全体 softmax 配比

win = g.index(max(g))         # 已示范：冠军的下标
w_top = 0                     # ← 问题在这：冠军拿到的门控权重
print(win)
print(round(w_top, 2))

lost = 0                      # ← 问题在这：落选两位合计流走的票权
print(round(lost, 2))
```

**练习 3**：概念题——若砍掉辅助损失，训练大概率走向哪种病态？为什么"病态"偏偏是稳定的状态？

<details>
<summary>点开查看逐步解答</summary>

路由塌缩：早期某位专家偶然略强 → 收到的样本更多 → 得到更多训练变得更专业 → 吸引更多样本……正反馈滚雪球直至其他专家名存实亡。稳定是因为它自我强化：无需外力也能维持，所以才会成为默认趋势——辅助损失的职责就是把这条正反馈环剪开一个小口。
</details>

## 7. 选读：稀疏化简史一分钟

<details>
<summary>选读 · 从 1991 年的想到今天的标配</summary>

"条件计算"的想法很早就有了（Jacobs 等，1991，分层专家网络），工程化起步于 Shazeer 等 2017 年的稀疏门控层（1370 亿参数的 LSTM 版 MoE）；GShard 把它搬进 Transformer 编解码器并引入**容量因子**——给每位专家预分配有限槽位，超额 token 当场放弃专家、直接沿残差捷径通行（上节课的高速路在此救场，保证丢弃不至于断流）；Switch Transformer 证明 $k=1$ 就够用；Mixtral 8x7B 以"8 选 2"夺得开源热度；DeepSeek-V3 再进一步拆细粒度专家、另配永远在线的共享专家。演变主线始终未变：**货架随便涨，通道保持窄**。
</details>
