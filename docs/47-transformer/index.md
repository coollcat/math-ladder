# Transformer 数学

Transformer 的关键不是神秘架构，而是把序列中的元素两两比较，再按相关性加权汇总信息。本章逐个拆开它的张量形状和计算含义。

这一章共 10 门课，按下述路线图依次推进：

1. [Token 与词向量](./10-token-embedding.md)——你对着手机说"给妈妈回个消息"，ChatGPT 这类模型却根本不认识汉字——它眼里只有一串编号：先切分、再查表，把门牌号翻译成一张学出来的语义身份证；
2. [注意力：查询、键、值](./20-attention-qkv.md)——读"小明把书放下，因为他累了"——你瞬间知道"他"指小明而不是书，靠的是"按需求加权取材"的检索动作；
3. [Softmax 与温度](./30-softmax-temperature.md)——问 ChatGPT"天空为什么是蓝色"，它的每一步都在掷骰子：先把打分变成合法概率表，再用温度旋钮决定口吻笃定还是放飞；
4. [自注意力手算](./40-self-attention.md)——前三课的零件组装成心脏：全员互相打分、加权抄录价值，一次运算人人带上全句语境；
5. [位置编码](./50-positional-encoding.md)——「狗咬人」是新闻，「人咬狗」显然不是同一条；一组正弦波时钟把座位号缝进词向量，还不破坏并行计算；
6. [多头注意力的子空间分工](./60-multihead-attention.md)——一场会议记不全那么多线索：把空间切成几份同时开几桌小会，有的头盯语法、有的头追远亲，散会后拼回一本总账；
7. [LayerNorm、残差与前馈层：每个 Transformer 块的骨架](./70-layernorm-residual-ffn.md)——明星工位之外还得有输送带、质检仪和仓储车间，顺带揭开参数大头藏在哪一站；
8. [MoE 与稀疏门控：专家们的分诊台](./80-moe-gating.md)——每位病人只进对口的诊室而非全院会诊；参数量与计算量在这里第一次分家；
9. [KV cache 与推理成本](./90-kv-cache-inference-cost.md)——模型每多说一个字都要回头翻整本书吗？把旧的存档卡片留在桌上，显存与算力的账才压得住；
10. [注意力之外：线性 RNN、状态空间与 RWKV](./100-modern-rnn-ssm.md)——注意力的账单随上下文平方增长；把循环捡回来、用对角状态空间换 $O(T)$ 推理，S4、Mamba、RWKV 三条路线都在这道交换题上做文章。

## 实战挑战 · 给下一个词下注

大语言模型每生成一个字，本质都在回答一个问题："给定前文，词表里每个候选的概率是多少？"把连续几个词的概率**连乘**，就得到整句话的出现概率——这是语言模型的经典题型（概率链式法则 $P(x_1,\dots,x_n)=\prod_t P(x_t \mid x_{<t})$，情境为教学原创）。

某迷你模型的概率表如下：

| 前文 | 候选词 | 概率 |
| --- | --- | --- |
| 句首 | 我 | 0.5 |
| 我 | 爱 | 0.6 |
| 我 爱 | 数学 | 0.2 |
| 我 爱 | 物理 | 0.1 |

**(a)** 算出两句话各自的整句概率：「我爱数学」与「我爱物理」；**(b)** 判断模型会把赌注押给谁。第一问已示范：

```exercise
# @title: 实战挑战：下一个词的概率链
# @check: 0.06
# @check: 0.03
# @check: 1
# @hint: 整句概率 = 沿途条件概率连乘；第三处比较两个整句概率，数学更大就打印 1。
p_start = 0.5              # P(我 | 句首)
p_love = 0.6               # P(爱 | 我)
p_math = 0.2               # P(数学 | 我 爱)
p_physics = 0.1            # P(物理 | 我 爱)

joint_math = p_start * p_love * p_math       # 已示范
joint_physics = 0                            # ← 问题在这：算出「我爱物理」的整句概率

print(round(joint_math, 3))
print(round(joint_physics, 3))

# ← 问题在这：比较两个整句概率——「数学」更大就打印 1，否则打印 0
```

<details>
<summary>点开查看逐步解答</summary>

**(a)** 「我爱数学」：$0.5 \times 0.6 \times 0.2 = 0.06$；「我爱物理」：$0.5 \times 0.6 \times 0.1 = 0.03$。

**(b)** $0.06 > 0.03$，模型押"数学"——注意两个候选共享同一条前缀 $0.5 \times 0.6 = 0.3$，胜负完全由最后一个条件概率决定。这就是为什么 ChatGPT 的每个字都由局部概率竞争产生，而整段文字的概率随长度指数缩小：再乘十个 0.x 的因子，任何句子都会变成小概率事件。

**延伸一步（注意力视角）**：若模型融合两个语义方向的信息——以权重 0.7 取"数量语义"价值向量 $(1,\ 2)$、以权重 0.3 取"学科语义"价值向量 $(3,\ 0)$，加权结果为：

$$0.7 \times (1,2) + 0.3 \times (3,0) = (1.6,\ 1.4)$$

这正是第 40 课自注意力最后一站的手算。
</details>

相关课程：[Softmax 与温度](./30-softmax-temperature.md)（分数怎么变成抽样概率表）、[自注意力手算](./40-self-attention.md)（加权融合的完整流程）。

## 实战挑战 · softmax 别忘了除以和

softmax 把分数变成概率表：$p_i = \frac{e^{z_i}}{\sum_j e^{z_j}}$，分母是所有指数的**和**。分数 $z=(1,0)$ 时，$p_0 = \frac{e}{e+1} \approx 0.731$。下面这题漏了分母，修到输出 `0.731`：

```exercise
# @title: 实战挑战：softmax 别忘了除以和
# @check: 0.731
# @hint: p0 = e^z0 / (e^z0 + e^z1)，分母是两个指数之和。
import math

z = [1.0, 0.0]
e0 = math.exp(z[0])      # e^1 = e
e1 = math.exp(z[1])      # e^0 = 1
p0 = e0                  # ← 问题在这：漏了除以 (e0 + e1)
print(round(p0, 3))
```

<details>
<summary>点开查看逐步解答</summary>

softmax 要除以所有指数之和：

```python
p0 = e0 / (e0 + e1)    # e / (e + 1)
print(round(p0, 3))    # 0.731
```

改完：$p_0 = \frac{e}{e+1} = \frac{2.718}{3.718} \approx 0.731$。初始代码直接输出 $e \approx 2.718$——那不是概率（概率必须落在 $[0,1]$ 且总和为 1）。这个"除以总和"的归一化，正是 softmax 能把任意打分变成合法概率表、供注意力加权和采样使用的全部秘密。

</details>
