# 解码策略：模型吐出概率之后怎么办

## 1. 从一个场景开始

你在对话框里敲下"今天天气真"，模型立刻吐出一张概率表：下一个字是"好"的概率 0.40、"糟"的概率 0.25、"冷"的概率 0.15……它**只给了分数，没有替你决定**。真正的选择发生在分数之后——挑最亮的那一盏灯，还是照亮度掷一次骰子？

同一条前文、同一张概率表，换一种挑法，模型的话风就从"复读机"变成"诗人"再变成"胡言乱语"。这一课拆开这块最容易被忽视的零件：**解码策略**。

## 2. 直觉解释

把概率表想成一排亮度不一的灯泡，解码就是"怎么把手指按下去"：

- **贪心**：永远按最亮的那盏。稳定、可复现，但容易绕圈——"好的好的好的"；
- **纯采样**：完全照亮度成正比地掷骰子。花样有了，可偶尔会点到最暗的灯泡，蹦出莫名其妙的字；
- **温度**：一个对比度旋钮。调低 = 把亮的更亮、暗的更暗；调高 = 整排灯趋近一样亮；
- **top-k / top-p**：先**剪枝**再掷骰子。top-k 只留亮度排名前 k 的灯；top-p 则按亮度从高往低累加，凑够一束光（比如总量 80%）就砍掉剩下的。区别在于：分布很尖时 top-p 只留一两盏，分布很平时它自动放宽到七八盏。

一句话：**温度决定"多随机"，top-k/top-p 决定"在哪几盏灯里随机"**，两者正交，可以叠用。

## 3. 正式定义

模型每一步先算出所有候选的**打分**（logits）$z_i$，softmax 把它变成概率表

$$p_i = \frac{e^{z_i}}{\sum_j e^{z_j}}, \qquad \sum_i p_i = 1 .$$

**温度重标定**：把 $z_i$ 换成 $z_i/T$ 再 softmax，等价于

$$p_i^{(T)} = \frac{p_i^{1/T}}{\sum_j p_j^{1/T}} .$$

**三种筛选/挑选**：

$$\text{贪心}:\ x^\ast=\arg\max_i p_i,\qquad \text{top-}k:\ S=\lbrace\text{概率最大的 }k\text{ 个}\rbrace,\qquad \text{top-}p:\ S=\text{最小的集合，使}\ \textstyle\sum_{i\in S}p_i\ge p .$$

保留集 $S$ 确定后，把 $S$ 内的概率**重新归一化**（除以 $\sum_{i\in S}p_i$），才是真正抽签用的分布。

| 符号 | 名字 | 含义 |
| --- | --- | --- |
| $z_i$ | logit | 模型对候选 $i$ 的原始打分，可为任意实数 |
| $p_i$ | 概率 | softmax 归一化后的合法性分数 |
| $T$ | 温度 | $T<1$ 锐化、$T=1$ 不变、$T>1$ 摊平；$T\to0$ 退化为贪心 |
| $k$ | top-k 的 k | 固定保留几个候选，与分布形状无关 |
| $p$ | top-p 的 p（核） | 累积概率阈值，保留集**大小自动伸缩** |
| $B,\alpha$ | beam 宽、长度惩罚 | beam search 每步保留 $B$ 条序列，按累计 score $=\frac{1}{L^\alpha}\sum_t\log p$ 排序 |

## 4. 分步例题

给定一张概率表（已归一化）：

| 候选 | 数学 | 物理 | 化学 | 语文 | 体育 | 其他 |
| --- | --- | --- | --- | --- | --- | --- |
| $p_i$ | 0.40 | 0.25 | 0.15 | 0.10 | 0.06 | 0.04 |

1. **贪心**：直接取 $\arg\max=0.40$ → 选"数学"。每步都这么干就是贪心解码。
2. **top-k，k=3**：保留 $\lbrace0.40,0.25,0.15\rbrace$，和 $=0.80$，重新归一化 → $0.50,\ 0.3125,\ 0.1875$。尾巴三盏灯被彻底掐灭。
3. **top-p，p=0.8**：从大到小累加 $0.40\to0.65\to0.80$，**刚好**在第三个候选凑够 $0.80$，保留集与 top-3 相同；若 $p=0.9$，累加到第四个 $0.40+0.25+0.15+0.10=0.90$ 才达标，于是保留 4 个，重归一化得 $0.444,\ 0.278,\ 0.167,\ 0.111$。
4. **温度 T=0.5**：$p_i^{(0.5)}\propto p_i^{2}$，平方后 $0.16,0.0625,0.0225,0.01,0.0036,0.0016$，和 $=0.2602$ → 冠军从 $0.40$ 升到 $0.615$，尾巴被压扁。
5. **温度 T=2**：$p_i^{(2)}\propto\sqrt{p_i}$，开方后归一化 → $0.277,0.219,0.170,0.139,0.107,0.088$，六盏灯几乎一样亮，最冷门的"其他"也从 $0.04$ 涨到 $0.088$。

对照 3 与 4：**top-k/top-p 是"砍选项"，温度是"重排亮度"**——前者改变候选集合，后者只改变集合内的相对高低。

按 `切换零基线` 按钮看看纵轴起点的影响。蓝色三根就是 top-3 的保留集：把它们的高度重新按比例"抬满"，就是抽签用的新分布。

### 实验 2（python）：温度旋钮的锐化与摊平

```python title="温度重标定：T<1 锐化、T>1 摊平"
p = [0.40, 0.25, 0.15, 0.10, 0.06, 0.04]   # 模型吐出的概率表（已归一化）

def reweight(probs, T):        # def：定义函数；probs 概率表，T 温度
    raw = [v ** (1.0 / T) for v in probs]  # 列表推导：逐个把概率取 1/T 次方
    s = sum(raw)               # sum：求和（此前课程已引入的内置函数）
    return [v / s for v in raw]  # 再归一化，保证总和回到 1

for T in [0.5, 1.0, 2.0]:
    q = reweight(p, T)
    print("T =", T, "→ 冠军概率", round(q[0], 3))
```

$T=0.5$ 时冠军升到 $0.615$，$T=2$ 时跌到 $0.277$——温度一格不动候选集合，只把概率高低差重新拉开或抹平。

### 实验 3（python）：top-k 与 top-p 各留下谁

```python title="两种剪枝：固定个数 vs 累积质量"
cands = ["数学", "物理", "化学", "语文", "体育", "其他"]
p = [0.40, 0.25, 0.15, 0.10, 0.06, 0.04]

order = sorted(range(len(p)), key=lambda i: p[i], reverse=True)  # lambda：按概率降序排下标

def renorm(idx):
    s = sum(p[i] for i in idx)                 # 保留集的概率之和
    return [(cands[i], round(p[i] / s, 3)) for i in idx]

print("top-3 :", renorm(order[:3]))            # 切前 3 个下标

keep = []                                      # top-p：累加直到够 0.8
acc = 0.0
for i in order:
    keep.append(i)
    acc += p[i]
    if acc >= 0.8:                             # 达标就停
        break
print("top-p :", renorm(keep), "累积", round(acc, 2))
```

top-k 固定砍到 3 个；top-p=0.8 在两个例子里恰好也留下 3 个——但若把分布换成"冠军独占 0.9"，top-p 只会留 1 个，而 top-k 仍坚持留 3 个。这就是核采样"随分布自适应"的本色。


## 6. 常见误区

:::warning[常见误区]

**误区一**："你以为贪心就是最优解。" 贪心只在"每步的局部最优"意义上最优，整句概率却常常不如采样。它最大的毛病是**退化**：同一段前文反复出现时，贪心会稳定地选同一个词，于是生成"好的好的好的"这类循环。

**误区二**："你以为 top-p 的 p 是一个概率阈值。" 它是**累积质量**，不是单点门槛。分布很尖时 $p=0.9$ 可能只保留一两个词，分布很平时会保留十来个——集合大小自动跟着分布走，这正是它比 top-k 更受欢迎的原因。

**误区三**："你以为温度越高模型越聪明、越有创意。" 温度只是**重新分配已有概率**，不会凭空增加知识。调得太高会把几乎不可能的错字也抬上台面；真正的多样性来自 top-p 加适度温度的组合，而不是把温度拉满。

:::

## 7. 练习

**练习 1**（判题）：下面的 top-k 忘了重新归一化，三个数加起来不等于 1——修到通过：

```exercise
# @title: 练习：把 top-k 的截断做对
# @check: 0.5
# @check: 0.3125
# @check: 0.1875
# @hint: 保留概率最大的 k 个后，要除以这几个数之和，让它们重新加回 1。现在分母写死成了 1。
p = [0.40, 0.25, 0.15, 0.10, 0.06, 0.04]
k = 3
order = sorted(range(len(p)), key=lambda i: p[i], reverse=True)
keep = order[:k]                 # 概率最大的 3 个下标
raw = [p[i] for i in keep]
s = 1.0                          # ← 问题在这：分母应是 raw 三个数之和
for v in raw:
    print(round(v / s, 4))
```

修好后输出 $0.5,\ 0.3125,\ 0.1875$——正是 $0.40:0.25:0.15$ 按比例抬满的结果。**不归一化就不是概率分布**，抽样会直接出错。

**练习 2**（概念）：温度 $T\to 0^{+}$ 与贪心解码是不是同一回事？

<details>
<summary>点开查看逐步解答</summary>

极限意义上是。$p_i^{(T)}\propto p_i^{1/T}$，当 $T\to0^+$ 时指数 $1/T\to+\infty$：原本最大的那个概率被抬向 1，其余全部被压向 0，分布退化成"冠军概率 1"。所以 $T\to0$ 就是贪心的软版本。工程上通常不真的取 0（会除零），而是设一个很小的正数。这也说明"温度"不是一个独立概念，它的一个端点就是贪心。

</details>

**练习 3**（概念）：为什么 top-p 比 top-k 更常用？

<details>
<summary>点开查看逐步解答</summary>

top-k 用一个**固定个数**切分布，遇到尖分布时它会硬塞进一堆几乎不可能的词（k 填不满高质量集合），遇到平分布时又砍得太狠（漏掉真正合理的候选）。top-p 用**累积质量**切，集合大小随分布自适应：尖分布自动收缩、平分布自动放宽。代价是它多算了一步累积排序，且 $p$ 的合适取值要按任务调。实际系统常"top-k 打底 + top-p 精调 + 温度定语气"三件套叠用。

</details>

## 8. 选读：beam search 与长度惩罚

<details>
<summary>选读 · 为什么报童式的贪心会被 beam 打败，beam 又为什么在开放对话里失宠</summary>

**beam search** 把"每步只留 1 条最优路径"放宽成"每步并行保留 $B$ 条候选序列"：第 $t$ 步从每条序列各扩展出词表里所有可能的下一个词，得到 $B\times|V|$ 个候选，再按**累计对数概率**挑出最好的 $B$ 条继续。它把"逐步最优"换成了"这 $B$ 条里最有希望的一条"，在机器翻译、语音识别这类**目标明确**的任务上明显强于贪心。

但累计 $\sum_t\log p_t$ 天然偏袒短句子（每多一个词就多扣一笔负分），所以要用**长度惩罚**校正：

$$\text{score}(y)=\frac{1}{|y|^{\alpha}}\sum_{t=1}^{|y|}\log p_t ,$$

$\alpha>0$ 时越长的句子被除得越多，鼓励模型把话说完。

beam search 的裂缝在**开放对话与创作**上暴露无遗：它倾向产出"安全、平庸、高概率"的句子，多样性差；训练时模型见的是真实前缀，推理时却被迫沿着自己算出的候选走，误差会累积（曝光偏差）。所以聊天类模型几乎清一色用"温度 + top-p 采样"，把 beam search 留给翻译、摘要这些"有标准答案"的任务。

</details>
