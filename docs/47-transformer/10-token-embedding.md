# Token 与词向量

## 1. 从一个场景开始

你对着手机说"给妈妈回个消息"，ChatGPT 这类模型却根本不认识汉字——它眼里只有一串编号：`[3021, 884, 1062, …]`。更神奇的是，它还知道"猫"和"狗"是近亲、"猫"和"微分方程"是陌生人。

从文字到数字、再从冷冰冰的编号到"懂语义"的数学结构，中间发生了两步：**切分（tokenization）**和**嵌入（embedding）**。这是 Transformer 一切魔法的入口。

## 2. 直觉解释

**第一步，切分**：把文本剁成小块（token）。英文常按词根切块（`unbelievable` → `un` + `believ` + `able`），中文常按字或词块。每个块在词表里有固定编号——注意，编号只是门牌号，**没有任何语义**：编号 3021 并不比 3020 "更像"什么。

**第二步，嵌入**：给每个编号发一张**语义身份证**——一个高维向量（比如 768 个数）。设计目标是：意思相近的词，向量也指向相近的方向。于是"语义"变成了几何：

- 同义词 → 夹角小；
- 反义词 → 方向相反；
- 无关词 → 近似垂直。

查表动作本身平淡无奇：拿编号去矩阵里取出对应那一行。真正的魔法在于**这张表是学出来的**——训练中它被反复微调，直到语义结构自动浮现。

## 3. 正式定义

设词表大小为 $V$，嵌入维度为 $d$。嵌入矩阵 $E$ 是一张 $V \times d$ 的表；token 编号 $t$ 的词向量即 $E$ 的第 $t$ 行 $\vec e_t \in \mathbb{R}^d$。

两个词的相似度用点积度量（第 11 章）：$\vec e_s \cdot \vec e_t$ 越大越相似。工程上常用余弦版本以消除向量长度的影响：

$$\cos(\vec e_s, \vec e_t) = \frac{\vec e_s \cdot \vec e_t}{\lVert \vec e_s \rVert\, \lVert \vec e_t \rVert}$$

| 符号 | 含义 |
| --- | --- |
| $V$ | 词表规模（GPT 级模型约十万量级） |
| $d$ | 嵌入维度：语义空间的维数 |
| $E$ | 嵌入矩阵：全模型的"词典 + 地图" |
| $\vec e_t$ | 一个词在语义空间中的坐标 |

## 4. 分步例题

**例**：三维迷你词表：$\vec e_{猫} = (0.9,\ 0.8,\ 0)$，$\vec e_{狗} = (0.8,\ 0.9,\ 0)$，$\vec e_{汽车} = (0,\ 0.1,\ 0.9)$。

1. 猫·狗 $= 0.9 \times 0.8 + 0.8 \times 0.9 + 0 \times 0 = 1.44$；
2. 猫·汽车 $= 0.9 \times 0 + 0.8 \times 0.1 + 0 \times 0.9 = 0.08$；
3. 判断：$1.44 \gg 0.08$，"猫"与"狗"方向接近，与"汽车"近乎无关；
4. 几何解读：前两维像是"宠物性"，第三维像是"机械性"——猫狗在前两维同高，汽车只在第三维活跃。（真实模型里维度没有如此清晰的人设，但几何逻辑相同。）

## 5. 动手实验

### 实验 1：相似度就是夹角

```viz
{
  "type": "dotprod",
  "title": "两个词向量的点积：夹角越小越像",
  "u": [4, 1],
  "v": [3, 3]
}
```

把蓝色、绿色向量想象成两个词的语义身份证。拖动它们：几乎同向时点积很大（近义）；垂直时归零（无关）；反向时为负（反义）。注意力机制稍后要做的第一件事，就是大量地做这个乘法。

### 实验 2：手写一个迷你语义地图

```python title="查表 + 余弦相似度 + 最近邻"
E = {                            # dict 字典：花括号里"键: 值"成对存放
    "猫":   [0.9, 0.8, 0.0],
    "狗":   [0.8, 0.9, 0.0],
    "鱼":   [0.7, 0.6, 0.2],
    "汽车": [0.0, 0.1, 0.9],
}

def dot(u, v):                   # 点积：对应位置相乘再求和
    total = 0
    for i in range(len(u)):
        total += u[i] * v[i]
    return total

def cos_sim(u, v):               # 余弦相似度：点积除以两条长度
    len_u = dot(u, u) ** 0.5     # **0.5 即开平方
    len_v = dot(v, v) ** 0.5
    return dot(u, v) / (len_u * len_v)

query = E["猫"]                  # 查表：用键取出对应的词向量
for word in E:                   # 遍历字典得到所有键（单词）
    if word != "猫":
        print(f"猫 vs {word}: {round(cos_sim(query, E[word]), 2)}")
```

跑一下：狗最像猫（约 0.99），鱼次之，汽车垫底但仍为正（约 +0.07）。整张"语义地图"只有几行代码的查表加循环——Transformer 的第一个积木就是这么朴素。

### 快问快答

```quiz
为什么不直接把词的编号（比如猫=3021）当输入喂给网络？
- 编号太长，浪费内存
- 编号没有语义：3021 和 3020 毫无关系，网络学不到"相近"[*]
- 编号会泄露训练数据
? 编号只是门牌号，任意两号的差值毫无意义。嵌入矩阵才把"语义相近"翻译成"坐标相近"。
```

:::warning[常见误区]

**误区一**："嵌入的每一维都有明确含义。"——本课例题里的"宠物维"是为了教学硬编的；真实模型训练出的维度是纠缠的整体，没有人类可读的名字。

**误区二**："点积大就一定相似。"——点积同时受方向和长度影响：一个长向量跟谁都"聊得来"。严格比较要用余弦或先把向量归一化。

**误区三**："一个词只有一个向量。"——静态嵌入确实一词一向量，因此处理不了多义词（"苹果手机"与"吃苹果"共享同一张身份证）。上下文相关的动态表示正是下一课注意力要解决的问题。

:::

## 6. 练习

**练习 1**：若 $\vec e_{国王} - \vec e_{男人} + \vec e_{女人} \approx \vec e_{女王}$ 成立，这说明嵌入空间有什么性质？

<details>
<summary>点开查看逐步解答</summary>

语义关系被编码成了**方向**：性别差是一个稳定向量，减掉再加回来就完成"性别转换"。著名的 word2vec 类比实验（国王−男人+女人≈女王）说明训练好的嵌入空间里，关系本身也是几何对象。
</details>

**练习 2**：补全下面的相似度程序，让模型自动说出谁更像"猫"：

**练习 3**：概念题——为什么大模型的词表常按"子词"而非完整单词切分？

<details>
<summary>点开查看逐步解答</summary>

按词建表会遇到灾难性的生词率（新词、错拼、罕见专业术语全是表外词）；按字符又太碎、序列太长。子词折中：高频词整体保留，低频词拆成常见碎块拼接，任何新词都能分解进表内且序列不至于爆炸。这套算法的代表是 BPE（字节对编码），"看不见的词"由此不再是问题。
</details>

## 7. 选读：嵌入是怎么"学"出来的？

<details>
<summary>选读 · 从统计到梯度</summary>

早期 word2vec 的思路朴素：能用上下文预测彼此的词就该挨得近——"猫"和"狗"经常出现在相似的句子里，训练一个"看词猜邻居"的小任务，副产品就是嵌入矩阵。如今大模型不再单独训练嵌入：嵌入层作为网络第一层，随主任务（下一词预测）一起被反向传播端到端调整。所以第 46 章的反向传播在这里再次登场——连"词典"都是梯度下降的作品。
</details>
