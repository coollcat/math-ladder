# 时序约束：建立与保持

## 1. 从一个场景开始

把时钟从 100 MHz 提到 120 MHz，电路一模一样，测试却开始间歇性出错；再提到 150 MHz，机器彻底算不了数。**电路没坏，坏的是「时间表」**：触发器采样要提前站稳的脚跟（建立时间），信号在导线与门里爬行要花的时间（传播延迟）——这些物理常数不会因为你改了时钟频率就跟着变。

从这一课起，我们离开「逻辑对不对」的世界，进入「来得及来不及」的世界。这是前面所有课的物理地基，也是芯片设计里最烧脑（也最烧钱）的一道工序——时序收敛。

## 2. 直觉解释

看一条最典型的路径：触发器 FF1 的输出 $Q$，穿过一段组合逻辑，到达触发器 FF2 的 $D$ 端。FF2 在时钟沿上采样——它对 $D$ 有两条铁律：

- **别来太晚（建立时间 tSU）**：新数据必须在下一个采样沿**之前**至少 $t_{SU}$ 就站稳。FF1 在沿后 $t_{CQ}$ 才把新数据放出来，再爬过组合逻辑花 $t_{PD}$——所以数据实际到达 FF2 的时刻是 $t_{CQ} + t_{PD}$（从一个沿算起）。要赶上**下一个**沿，就得 $t_{CQ} + t_{PD} \le T - t_{SU}$，其中 $T$ 是时钟周期；
- **别走太早（保持时间 tH）**：旧数据也不能在本次沿后 $t_{H}$ 之内就撤——FF2 的采样窗口还没关，数据中途换人，采到的就是「正在变的值」，亚稳态。

两条铁律变成两道不等式：

$$\text{建立：} \quad t_{CQ} + t_{PD} + t_{SU} \le T \qquad\qquad \text{保持：} \quad t_{CQ} + t_{PD} \ge t_{H}$$

建立约束里**藏着 $T$**——时钟太快就犯规，降频能救；保持约束里**没有 $T$**——降频一点用都没有，只能改电路（加延迟、换路径）。这半句差别，是整个时序分析的灵魂。

## 3. 正式定义

对任意一条「发射触发器 → 组合逻辑 → 捕获触发器」的路径：

| 量 | 记号 | 含义 |
| --- | --- | --- |
| 时钟周期 | $T$ | 相邻两个采样沿的间隔，$f = 1/T$ |
| 时钟到输出延迟 | $t_{CQ}$ | 时钟沿之后，FF1 的 Q 更新所需时间 |
| 组合逻辑延迟 | $t_{PD}$ | 数据穿过中间逻辑（含布线）的耗时 |
| 建立时间 | $t_{SU}$ | 数据须在捕获沿前稳定的最短时长 |
| 保持时间 | $t_{H}$ | 数据须在捕获沿后稳定的最短时长 |

**建立裕量**与**保持裕量**（正值 = 合格，负值 = 违规）：

$$\text{建立裕量} = T - t_{SU} - (t_{CQ} + t_{PD}), \qquad \text{保持裕量} = (t_{CQ} + t_{PD}) - t_{H}$$

**最高时钟频率**：建立约束取等号时的频率上限：

$$T_{min} = t_{CQ} + t_{PD} + t_{SU}, \qquad f_{max} = \frac{1}{T_{min}}$$

一条芯片路径跑多快，由**最慢的那一条**决定——这条最慢路径的学名就是「关键路径」。第 90 课状态机的组合逻辑（$D_1 = Q_1\bar{Q_0} + \bar{Q_1}Q_0x$ 等方程）从发射到捕获走几级门，就决定了那台机器能跑多少 MHz。

## 4. 分步例题

**例**：路径参数 $t_{CQ}=1$ ns、$t_{PD}=3$ ns、$t_{SU}=2$ ns、$t_{H}=1$ ns。求 $f_{max}$ 与 10 MHz（$T=10$ ns）下的两个裕量。

1. **建立**：数据沿后 $t_{CQ}+t_{PD} = 4$ ns 到达 FF2；下一个沿在 $T=10$ ns 处，扣掉 $t_{SU}=2$ ns 的窗口，截止线是 8 ns——裕量 $= 10 - 2 - 4 = 4$ ns，合格；
2. **保持**：数据至少站到沿后 1 ns，实际 $t_{CQ}+t_{PD}=4$ ns 才变——裕量 $= 4 - 1 = 3$ ns，合格；
3. **最高频率**：$T_{min} = 1+3+2 = 6$ ns，$f_{max} = 1000/6 \approx 166.7$ MHz；
4. **若把时钟提到 200 MHz**（$T=5$ ns）：截止线 $5-2=3$ ns，数据 4 ns 才到——**建立违规 1 ns**。降回 160 MHz（$T=6.25$ ns）就恢复合格；
5. **反向事故**：若组合逻辑被优化得只剩 $t_{PD}=0.2$ ns，数据沿后 1.2 ns 就到，保持裕量 $= 1.2 - 1 = 0.2$ ns，勉强合格；再激进些 $t_{PD}=0.1$ ns、$t_{CQ}=0.5$ ns，裕量 $= 0.6 - 1 = -0.4$ ns——**保持违规**，而这时把时钟降到 1 MHz 也无济于事。

第 3、4 步与第 5 步的对比，就是第 5 节实验里那两颗按钮的剧本。

## 5. 动手实验

### 实验 1（lab）：把数据沿拖进橙色窗口

```lab
{
  "type": "timing-setup",
  "title": "把数据沿拖进橙色窗口，看看什么叫建立时间违规",
  "T": 10,
  "tSU": 2,
  "tH": 1,
  "tCQ": 1,
  "tPD": 3
}
```

- 拖 FF2.D 那条虚线（就是改 $t_{PD}$）：数据沿在时间轴上爬行，撞进橙色窗口（建立违规）或紫色窗口（保持违规）立刻报警，读数里的两个裕量跟着翻负；
- 点「拉到临界」——数据沿恰好贴住橙色窗口左缘，建立裕量归零，读数里的 $f_{max}$ 就是这条路径的天花板；
- 点「制造一次保持违规」——数据沿被拽到紫色窗口里，注意读数：**无论把时钟周期拖到多长，违规都消不掉**；
- 拖 CLK 行的三角改时钟周期，看橙色窗口整体平移而紫色窗口纹丝不动——建立约束随 $T$ 走，保持约束不随 $T$ 走，图像上就是这么直白。

### 实验 2（python）：算频率天花板与保持红线

```python title="算一条路径的最高频率"
tCQ, tPD, tSU = 1.0, 3.0, 2.0       # ns
Tmin = tCQ + tPD + tSU
fmax = 1000 / Tmin                  # 1000 ns 除以 Tmin(ns)，得 MHz
print(f"Tmin = {Tmin} ns, fmax = {fmax:.1f} MHz")
```

$T_{min}=6$ ns、$f_{max}\approx 166.7$ MHz。想跑 200 MHz？先把 $t_{PD}$ 压到 2 ns 以下——**「关键路径优化」在工程里就是这个不等式的填空题**。

```python title="保持时间检查：跟时钟快慢无关"
tCQ, tH = 0.5, 1.0                  # ns：发射快、保持要求高，危险组合
for tPD in [3.0, 0.5, 0.1]:
    margin = tCQ + tPD - tH
    ok = "安全" if margin >= 0 else "违规!"
    print(f"tPD={tPD} ns  保持裕量={margin} ns  {ok}")
```

三行输出里 $t_{PD}=0.1$ 那行亮出 `违规!`——裕量 $-0.4$ ns。把它抄进实验 1 的滑块，你会看到同样的报警；然后拖时钟周期滑块从 2 ns 拖到 40 ns，**报警一次都不会消失**。保持违规只能靠改电路（在快路径上串延迟单元、或重新布线绕远路）来修——这也是芯片「流片」后最贵的一类事故，因为它没法靠改固件补救。

### 快问快答

```quiz
一条路径出现保持时间违规，把时钟从 100 MHz 降到 50 MHz 能解决吗？
- 不能 [*]
- 能，频率减半时间宽裕一倍
- 能，只要降到 10 MHz 以下
? 保持约束 tCQ + tPD ≥ tH 里根本没有时钟周期 T：违规发生在同一个时钟沿附近（新数据冲掉旧数据太快），降频只会让相邻沿离得更远，对沿后头 1 ns 里发生的事毫无影响。修保持违规只能改电路路径延迟。
```

::::warning[常见误区]

**误区一**：「时钟越快机器越快，频率是白捡的。」
你以为提频只有好处——其实每个周期都短过一次 $t_{CQ}+t_{PD}+t_{SU}$ 的路就失效了，芯片里最慢的那条路径是全体时钟的天花板（$f_{max} = 1/T_{min}$）。性能设计的第一课不是「加频率」，而是「找关键路径」。

**误区二**：「建立、保持违规是一类问题，降频都能救。」
你以为时间不够就慢慢来——建立违规确实降频可救（它跟 $T$ 有关），保持违规**完全无效**（跟 $T$ 无关，是同沿附近的赛跑）。两类违规的修法截然不同：前者改时钟或优化路径，后者只能改电路。混为一谈会在调试时白烧半天。

**误区三**：「裕量是正的就行，零点几纳秒不必在意。」
你以为正裕量就是安全——真实芯片还有时钟偏斜（skew，同一沿到达两个触发器的时间差）与时钟抖动（jitter），每个都在偷吃裕量。手册标 0.5 ns 裕量的路径，实机上可能已经是负的。工程裕度不是保守，是给没写进等式的物理现实留的座位。

::::

**练习 1**：路径参数 $t_{CQ}=1.2$ ns、$t_{PD}=2.9$ ns、$t_{SU}=0.9$ ns。求最高频率（MHz）。期望 `200.0`。这段代码忘了扣建立时间：

```exercise
# @title: 练习：算路径的最高频率
# @check: 200.0
# @hint: Tmin = tCQ + tPD + tSU 三项都要——建立时间 tSU 是数据在捕获沿前必须提前站稳的时长，不能漏
tCQ = 1.2
tPD = 2.9
tSU = 0.9
Tmin = tCQ + tPD           # ← 问题在这：漏了 tSU
fmax = 1000 / Tmin
print(f"{fmax:.1f}")
```

**练习 2**：一条路径 $t_{CQ}=0.8$ ns、$t_{PD}=5.2$ ns、$t_{SU}=1.0$ ns、$t_{H}=0.4$ ns，时钟 125 MHz。(a) 求建立裕量；(b) 求保持裕量；(c) 判断能否提到 200 MHz。

<details>
<summary>点开查看逐步解答</summary>

1. $T = 1000/125 = 8$ ns；数据到达 $= t_{CQ}+t_{PD} = 6$ ns；
2. 建立裕量 $= T - t_{SU} - 6 = 8 - 1 - 6 = 1$ ns，合格；
3. 保持裕量 $= 6 - t_{H} = 6 - 0.4 = 5.6$ ns，合格且很富裕；
4. 提到 200 MHz：$T = 5$ ns，建立裕量 $= 5 - 1 - 6 = -2$ ns——**建立违规**，降不降？不是降，是这条路径 200 MHz 跑不了；$f_{max} = 1000/(0.8+5.2+1.0) = 142.9$ MHz 才是天花板。注意第 3 步那 5.6 ns 的保持裕量在这里一点忙也帮不上——两道约束各管各的河段。

</details>

## 7. 选读：时钟偏斜——不等式里的隐藏项

<details>
<summary>选读 · 当两个触发器看到的「同一个沿」不同时</summary>

前面的不等式默认时钟沿**同时**到达 FF1 与 FF2。真实芯片里时钟走时钟树，两处到达相差一个偏斜 $t_{skew}$（FF2 晚收沿记正）：

$$\text{建立：} \quad t_{CQ} + t_{PD} \le T - t_{SU} + t_{skew} \qquad\qquad \text{保持：} \quad t_{CQ} + t_{PD} \ge t_{H} + t_{skew}$$

有意思的是两项符号相反：FF2 **晚**收沿，等于捕获deadline放宽了 $t_{skew}$（建立变容易），可它也在沿后多等了 $t_{skew}$（保持变难）。所以**偏斜能借给建立的时间，正是它从保持手里抢走的**——时钟树设计师挪动每一根时钟线的长度，都是在两个不等式之间转移风险。

极端用法甚至成了技术：故意给快路径「借」正偏斜（time borrowing），把建立裕量抢救回来；代价是这些路径的保持检查从此绷紧。时序收敛工程师的工具箱里，降频、改逻辑、挪时钟线三件套，最后一件事最精细也最危险——因为保持违规是流片后无法挽回的那一类。

</details>
