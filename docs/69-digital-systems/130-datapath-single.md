# 单周期数据通路

## 1. 从一个场景开始

前面十节课，你手里的零件已经能拼出一个「会算的部位」：加法器（40 课）、ALU（120 课）、触发器与寄存器（60、70 课）、状态机（90 课）。但拼到现在，它还只是个**零件库**——没有谁告诉它「先算哪步、结果存哪、下一条去哪」。

这一课把这些零件焊成一台完整的机器。标准要定得苛刻一点：**给它一小段程序，它能一条一条自己跑起来，全程不需要人碰**。看完这一课，你对「CPU 执行程序」这件事的想象，会从一句抽象口号变成一张你亲手画得出连线图的电路。

玩具尺寸先说清：4 位 ALU、8 个寄存器、16 字内存、16 位一条的指令。窄是故意的——每个数字都能一眼看全，手算核对；部件与连线却和真实的单周期 CPU 一一对应。

## 2. 直觉解释

一条指令的一生只有五拍（五个节拍），像一条**串行的装配线**：

1. **取指**：程序计数器 PC 拿着地址，从指令存储器里取出当前那条指令；
2. **译码**：控制单元把 16 位指令按位域切开（op、rs、rt、val），拉起该拉的控制线；
3. **执行**：ALU 按控制线干活——算术、算地址，或者做减法只看零标志；
4. **访存**：只有 lw / sw 用这一拍，从数据存储器读一个字或写一个字，其余指令空过；
5. **写回**：把结果写进寄存器堆（$0 除外），同时 PC 加一指向下一条。

**关键认识：这不是五台机器接力，而是同一批部件在一拍里按固定顺序被用一遍。** 单周期的「单」就是每条指令恰好占一个时钟周期——周期一结束，新指令已经躺在寄存器里，PC 已经指向下一条。

和第 90 课的状态机对上号：整台 CPU 就是一个状态机，五个节拍是它的状态序列，只不过**转移条件不是外部输入，而是指令本身**。控制单元本质上是把「op 字段」翻译成「各部件控制线」的译码器（50 课的译码器思想，规模放大）。

## 3. 正式定义

**指令格式**（16 位，定长）：

| 字段 | 位宽 | 含义 |
| --- | --- | --- |
| op | 4 | 操作码：0=add 1=sub 2=and 3=or 4=lw 5=sw 6=beq |
| rs | 3 | 源寄存器 1（lw/sw 里当基址） |
| rt | 3 | 源寄存器 2（lw/sw 里是数据寄存器） |
| val | 6 | R 型：低 3 位是目的寄存器 rd；访存：地址偏移；beq：跳转偏移 |

**部件与职责**：

| 部件 | 干什么 | 记住谁造的 |
| --- | --- | --- |
| PC | 存当前指令地址，每拍加一（或跳转） | 70 课寄存器 |
| 指令存储器 IM | 按 PC 取指令 | — |
| 寄存器堆 | 8 个寄存器，**$0 恒为 0** | 70 课 |
| ALU | 算术 / 算地址 / 比较看 Z | 120 课 |
| 数据存储器 DM | lw / sw 访问的 16 字内存 | — |
| 控制单元 | op → 各控制线 | 90 课状态机思想 |
| 符号扩展 | beq 的 val 按 4 位补码读：val ≥ 8 减 16（范围 −8..7） | 110 课补码 |

**三条关键语义**：

- R 型（add/sub/and/or）：`rd = rs op rt`；
- 访存（lw/sw）：地址 = `regs[rs] + val`，读写 `rt`；
- 分支（beq）：ALU 做 `rs − rt`，Z=1 时 `nextPC = pc + 1 + 符号扩展(val)`，否则 `pc + 1`。

## 4. 分步例题

**例**：一条指令的一生——追踪默认程序的第一条 `add $3, $1, $2`（$1=3, $2=5）。

1. **取指**：PC=0，IM[0] 吐出 16 位指令 `0000 0010 1000 0011`；
2. **译码**：切开 → op=`0000`(add)、rs=`001`(1)、rt=`010`(2)、val=`000011`，低 3 位当 rd=$3。控制线：ALU 做 ADD，寄存器堆「读 $1 $2、写 $3」；
3. **执行**：ALU 算 $3 + 5 = 8$；
4. **访存**：add 用不着，空过；
5. **写回**：8 写进 $3，同时 PC 变 1。一拍结束。

**进阶**：同一段程序走到第 5 条 `beq $5, $5, 11` 时（此前 $5 = 8 − 3 = 5，$5 等于 $5）：

1. 译码：op=beq，rs=rt=$5，val=`001011` = 11；
2. 执行：ALU 做 $5 − 5 = 0$，Z=1；
3. 符号扩展：val = 11 ≥ 8，按 4 位补码口径读作负数，$11 - 16 = -5$；
4. 分支命中：`nextPC = 4 + 1 + (-5) = 0`——**跳回第一条**。程序成了死循环，但对演示数据通路来说，死循环恰恰是「机器自己会转」的证明。

## 5. 动手实验

### 实验 1（lab）：看着数据在总线上流

```lab
{
  "type": "datapath-single",
  "title": "单步推进一拍：跟着小圆点看 add 怎么从取指走到写回",
  "regs": [0, 3, 5, 0, 0, 0, 0, 0]
}
```

底部五段节拍条可以直接拖，「单步」一次推一拍，「连跑」自动转。做三件事：

- 单步走完第一条 add 的五拍，对照例题核对：执行拍 ALU 亮起、写回拍 $3 变成 8、PC 顺移；
- 连跑：程序算 3+5、存进内存再取回、减一下、然后 beq 命中**跳回开头**——盯着 PC 与寄存器怎么循环往复；
- 单步到访存拍，看 sw 与 lw 用的是同一个加法器：地址 = $0 + 4，这就是「ALU 兼职算地址」。

### 实验 2（python）：手工模拟一轮五拍

```python title="把数据通路的每一拍写成两行代码"
regs = [0, 3, 5, 0, 0, 0, 0, 0]     # 8 个寄存器
mem = [0] * 16                       # 16 字内存
pc = 0

regs[3] = regs[1] + regs[2]          # IM[0]: add $3, $1, $2（执行+写回）
pc = pc + 1
mem[4] = regs[3]                     # IM[1]: sw  $3, 4($0)（ALU 算地址 $0+4）
pc = pc + 1
regs[4] = mem[4]                     # IM[2]: lw  $4, 4($0)
pc = pc + 1
regs[5] = regs[4] - regs[1]          # IM[3]: sub $5, $4, $1
pc = pc + 1
pc = pc + 1 - 5                      # IM[4]: beq $5, $5, 11 → Z=1，偏移 -5，跳回 0

print(regs[3], regs[4], regs[5])
print("pc =", pc)
```

五行注释就是五拍：每条指令压成一行赋值，注释里写清它动用了哪些部件。输出 `8 8 5` 与 `pc = 0`——3+5=8 存进内存、原样取回、减去 3 得 5，beq 把 PC 送回 0。**数据通路的全部行为，就是这五行代码的电路化**：赋值号左边是写回目标，右边是「ALU / 访存」那一拍。

### 快问快答

```quiz
单周期 CPU 里，时钟周期（一拍的时间）由什么决定？
- 由加法器的速度决定
- 由最慢的那条指令决定 [*]
- 由程序的长短决定
? 单周期意味着每条指令都恰好在一拍内走完五段。取指到写回的电路路径里 lw（访存）最长，时钟周期必须迁就最慢路径——快指令也只能跟着慢节奏走。
```

::::warning[常见误区]

**误区一**："单周期就是流水线，五拍就是五条指令同时在跑。"
你以为五拍是五级流水——其实单周期是**一条指令从头到尾占满一拍**，拍与拍之间没有重叠。流水线才是五条指令各自处在不同拍上同时推进，那是第 150 课的主角。

**误区二**："$0 是个普通寄存器，只是碰巧值为 0。"
你以为可以拿 $0 当临时变量——其实 $0 被**硬件焊死**为 0：读它永远得 0，写它等于把结果倒进下水道。它的真正用途是当「0 常数」用：`beq $1, $0` 就是判 $1 是否为零，连专门的比较指令都省了。

**误区三**："lw 的 val 就是内存地址。"
你以为地址直接写在指令里——其实地址是 `regs[rs] + val` **算出来**的：rs 给基址，val 给偏移（本机的偏移取 0..15；真实的 MIPS 里偏移按补码读、可以是负的，原理相同）。这个设计让数组下标、结构体成员寻址全都顺理成章，也解释了为什么访存指令也要「占用」ALU。

::::

```exercise
# @title: 练习：beq 靠什么判定相等
# @check: True
# @hint: beq 的「相等」不是加出来的——ALU 做的是 a-b，然后看 120 课讲过的哪个标志位？
regs = [0, 3, 3, 0, 0, 0, 0, 0]

taken = (z == 0)
print(taken)
```

**练习 2**：手工模拟 `sw $2, 3($1)` 这一条指令的五拍（$1=2, $2=9），写出每个节拍里「哪个部件动了、动成了什么值」。

<details>
<summary>点开查看逐步解答</summary>

1. **取指**：PC 指向这条 sw，IM 吐出 `0101 001 010 000011`（op=5, rs=1, rt=2, val=3）；
2. **译码**：控制单元拉起「ALU 做 ADD + 内存写」两条线；符号扩展把 3 补成全宽（正数，原样）；
3. **执行**：ALU 算地址 $1 + 3 = 2 + 3 = 5；
4. **访存**：把 rt 的值 $2 = 9 写进内存字 mem[5]；
5. **写回**：sw 没有寄存器要写（这一拍寄存器堆闲置），PC 加一。

注意两个细节：ALU 在访存指令里「兼职」算地址；val=3 同时扮演「偏移」角色——同一个 6 位字段，在 R 型里是 rd、在访存里是偏移、在 beq 里是跳转偏移。**字段的含义由 op 决定**，这正是下一课的主题。

</details>

## 7. 选读：单周期为什么「天生平慢」

<details>
<summary>选读 · 关键路径与「一拍做完全部事」的代价</summary>

单周期把取指、译码、执行、访存、写回**串在一条电路路径**上，信号要顺序流过五个部件。时钟周期必须 ≥ 这条路径的总延迟——由最慢的 lw 决定：取指 + 译码 + ALU 加法 + 内存读取 + 写回，一段都不能省。

难堪的是：add 根本不用访存，却也要陪 lw 一起等满一拍。统计一下真实程序里 add 类指令占大头，等于**大多数时间电路在干等**。

这就是 150 课流水线的出发点：把五段路径**切成五段独立电路**，各段之间加寄存器锁存——一拍之内每段只干自己那 1/5 的活，五条指令像装配线一样错拍并行。理论加速比接近 5，代价是「冒险」——下节课你会看到，抢跑是有代价的。

</details>
