# 指令集与译码

## 1. 从一个场景开始

双击一个程序，磁盘里那几兆字节的 `.exe` 文件被装进内存，CPU 开始一条一条地执行。你后来在调试器里看到的 `add $t0, $t1, $t2` 是**给人看的花体字**——内存里实际躺着的，是 `0x012A4020` 这么一个 32 位数。

上一课的数据通路每次取指，从 IM 里吐出的就是这样的数。CPU 凭什么知道 `0x012A4020` 的意思是「把 $t1 和 $t2 相加、结果放 $t0」？凭一份**合同**：硬件设计者和软件（编译器、汇编器）事先约好——哪些位是操作码、哪些位是寄存器编号、哪些位是常数。这份合同叫**指令集架构**（ISA）。这一课拆开它，再亲手把一串 0/1 翻译回汇编。

## 2. 直觉解释

**位域就是信封上的分格。** 邮政信封印好了固定的格子：左上角收件人邮编、中间地址、右下角寄件人——格子是死的，内容随信而变。机器码同理：32 个比特从最高位起划成几段，每段有名字、有位置、有宽度，**写的人和读的人按同一张格子表**。译码器不「理解」指令，它只是按格子把比特切下来、各自接走。

**为什么要不止一种格式？** R 型（寄存器-寄存器运算）需要 3 个寄存器编号 + 功能码；I 型（访存、立即数）需要 2 个寄存器 + 一个 16 位常数；J 型（跳转）只要一个大地址。32 位装不下所有愿望，于是**按 op 分派格式**：

- op ≠ 0：op 自己说了算（lw、sw、beq、j……）；
- op = 0：这是 R 型，具体做哪种运算**再看最低 6 位 funct**——两级查表。

第 31 章说「语言是字母表上字符串的集合」。指令集正是 $\{0,1\}^{32}$ 这个巨型字母表幂上一个**结构极其规整的子集**：合法字符串被 op/funct 字段切成有限的几类，每一类内部再由字段取值细分。译码器就是这门小语言的识别器——而且是第 31 章里最舒服的那类：**定长、正则、一遍扫完**。

## 3. 正式定义

以 MIPS（教学事实标准）为准，三种格式：

| 格式 | 31..26 | 25..21 | 20..16 | 15..11 | 10..6 | 5..0 | 代表 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| R | op=0 | rs | rt | rd | shamt | funct | add sub and or slt sll |
| I | op | rs | rt | imm（16 位） | | | addi lw sw beq bne |
| J | op | 26 位 target | | | | | j jal |

**字段语义**：

| 字段 | 含义 |
| --- | --- |
| op | 操作码，格式分派的总开关（R 型恒为 0） |
| rs / rt | 两个源寄存器编号（5 位 → 32 个寄存器） |
| rd | 目的寄存器（结果写回处，R 型才有） |
| shamt | 移位量（只有移位指令用，其余恒 0） |
| funct | 功能码，R 型二级区分：`100000`=add、`100010`=sub、`100100`=and… |
| imm | 立即数：**按补码读**，lw/sw 的偏移可正可负（110 课的回归） |

**寄存器有名字**：$t0..$t7（临时）、$s0..$s7（留存）、$sp（栈指针）、$ra（返回地址）……编号 0..31，名字是给汇编员的助记。$zero 恒 0——上一课 $0 的「焊死」在真 ISA 里的正式身份。

**译码**：把 32 位按格式切段，字段值各自送往数据通路的对应端口；op/funct 组合再译成 12 条控制线（上一课控制单元干的事）。纯组合逻辑，不占一拍之外的任何额外时间。

## 4. 分步例题

**例 1**：手拆 `0x012A4020`。

1. 写成二进制：`0000 0001 0010 1010 0100 0000 0010 0000`；
2. 看 op（最高 6 位）= `000000` → R 型，具体运算看 funct；
3. 切字段：rs=`01001`=9($t1)、rt=`01010`=10($t2)、rd=`01000`=8($t0)、shamt=`00000`、funct=`100000`=0x20；
4. 查 funct 表：0x20 = add；
5. 翻译：**add $t0, $t1, $t2**——「$t0 = $t1 + $t2」。与调试器里看到的一字不差。

**例 2**：反方向，把 `lw $t0, 8($t1)` 编成机器码。

1. lw 是 I 型：op=0x23=`100011`；
2. rs=$t1=9=`01001`（基址）、rt=$t0=8=`01000`（数据去处）、imm=8=`0000 0000 0000 1000`；
3. 拼接：`100011 01001 01000 0000000000001000`；
4. 合成十六进制：**0x8D280008**。汇编器干的就是这件事，每条指令一个不落的四步。

**例 3**：立即数的符号——`lw $t0, -4($sp)` 的偏移编码为 $-4 + 65536 = 65532$（`0xFFFC`）。译码时按补码读回 $-4$。指令里没有负号，**补码把符号带进了一切字段**。

## 5. 动手实验

### 实验 1（lab）：一格一格刷出一条指令

```lab
{
  "type": "isa-decode",
  "title": "从默认的 0x012A4020 开始：拖比特格、看汇编逐字段跟着变",
  "word": 19546144
}
```

（`19546144` 就是 0x012A4020 的十进制。）最上面一排 32 个比特格能点、能按住横刷；下面的位域彩条与字段表告诉你每一段归谁管。做三件事：

- 把 funct 那 6 位（最右端）刷成 `100010`——汇编立刻变成 sub。**op 没动、只有 funct 变了**，这就是 R 型两级查表；
- 下拉框换成 lw，imm 滑块拖成负数——看机器码高 16 位全是 1：补码在立即数字段现身；
- 换成 j 型：26 位 target 被一个 imm 滑块控制（组件取小值好观察），想想真实的 26 位能跳多远。

### 实验 2（python）：编码与解码是同一张格子表的正反两用

```python title="add $t0, $t1, $t2 的编码四步，再原路解码"
op, rs, rt, rd, shamt, funct = 0x00, 9, 10, 8, 0, 0x20

word = (op << 26) | (rs << 21) | (rt << 16) | (rd << 11) | (shamt << 6) | funct
print(hex(word))

op2 = (word >> 26) & 0x3f      # 右移 26 位，切下最高 6 位
funct2 = word & 0x3f           # 掩码 0x3f（六个 1），切下最低 6 位
print(op2, funct2)
```

编码是「各字段左移到自己的格子再按位或」，解码是「右移到最低位再用掩码切下」——**移位量互为镜像**。输出 `0x12a4020` 与 `0 32`：op=0 进 R 型大门，funct=32=0x20 是 add。汇编器、反汇编器、译码器，用的都是这几行位运算。

### 快问快答

```quiz
MIPS 的 R 型指令 op 全是 000000，硬件靠什么区分 add 和 sub？
- 靠 rd 的取值
- 靠最低 6 位 funct（功能码）[*]
- 靠指令总长度
? op=0 相当于总开关：告诉硬件「这是 R 型」，具体哪种运算看最低 6 位 funct——add 是 100000，sub 是 100010。同一条位串里，「谁说了算」是可以分层的。
```

::::warning[常见误区]

**误区一**："机器码是一堆随机的 0 和 1，反汇编像破译密码。"
你以为要靠统计和猜——其实每一位都有归属：哪 6 位是 op、哪 5 位是 rs，位置和宽度全部事先写死在 ISA 手册里。反汇编是**确定性的查表**，比你想象的机械得多。

**误区二**："op 字段决定指令的一切。"
你以为 R 型也直接由 op 区分——其实 op=0 只说明「进了 R 型大厅」，做什么运算要**再看 funct**。同样，shamt 只在移位指令里有意义，其他 R 型指令里它是全 0 的占位格。字段有效性与格式绑定，格式由 op 分派。

**误区三**："立即数就是普通的无符号整数。"
你以为 imm 永远按 0..65535 读——其实 lw/sw 的偏移、beq 的跳转量都**按补码读**：0xFFFC 是 -4 不是 65532。110 课「位模式没有含义、读法决定含义」在指令字段的粒度上又赢了一局。

::::

## 6. 练习

**练习 1**：把 `add $t0, $t1, $t2` 编码成 32 位机器码，输出十六进制（应为 `0x12a4020`）。这段代码把字段挤错了位：

```exercise
# @title: 练习：R 型指令的编码
# @check: 0x12a4020
# @hint: 从高到低是 op(6) rs(5) rt(5) rd(5) shamt(5) funct(6)——rd 和 funct 之间还隔着 5 位的 shamt，别把它挤掉
op, rs, rt, rd, funct = 0x00, 9, 10, 8, 0x20
word = (op << 26) | (rs << 21) | (rt << 16) | (rd << 6) | funct   # ← 问题在这：rd 挪错了格子
print(hex(word))
```

**练习 2**：解码机器码 `0x8D280008`：判断格式、切出全部字段、翻译成汇编。

<details>
<summary>点开查看逐步解答</summary>

1. op = 0x8D280008 >> 26 = `100011` = 0x23 → 非 0，I 型，查 op 表得 **lw**；
2. rs = (word >> 21) & 0x1f = `01001` = 9 = $t1；rt = (word >> 16) & 0x1f = `01000` = 8 = $t0；
3. imm = word & 0xffff = `0000 0000 0000 1000` = 8（最高位 0，正数）；
4. 翻译：**lw $t0, 8($t1)**——从地址 $t1 + 8 取一个字，放进 $t0；
5. 对照第 130 课数据通路：译码拍里控制单元拉起「ALU 做 ADD（算地址）+ 内存读 + 写回 $t0」，imm 经符号扩展送进 ALU——三个字段的每一.bit 都在那张部件图上有去处。

</details>

## 7. 选读：定长与变长——两种合同哲学

<details>
<summary>选读 · MIPS 的「定长」与 x86 的「变长」之争</summary>

MIPS 立了规矩：**所有指令一律 32 位**。译码器一刀切三段、并行读字段、单周期里从容完成——快，代价是浪费：add 用不上 shamt 与 16 位空隙，R 型里躺着一堆必为 0 的占位格。

x86 走另一条路：**指令 1 到 15 字节不等**，常用指令短、带立即数的指令长。省内存（30 年前内存以 KB 计时是生死线），代价是译码噩梦：必须先确定这条指令多长，才能找到下一条从哪开始——译码器要一路啃着变长前缀走，这是 x86 译码器复杂出名的根源。

两种哲学对应两种时代约束：教育架构（MIPS、RISC-V）选**规整**，把简单教给你；商业架构（x86）选**兼容与密度**，把复杂藏进硅里。读别人的汇编时，先问一句：这门 ISA 的合同是定长还是变长？字段的格子表长什么样？问完这两个问题，任何新 ISA 都只是「换个格子表」而已。

</details>
