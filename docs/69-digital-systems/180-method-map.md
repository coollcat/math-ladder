# 数字系统方法地图

## 1. 从一个场景开始

17 门课学完了，工具箱塞得满满当当：卡诺图、触发器、状态机、建立保持窗口、补码、数据通路、译码表、流水线气泡、命中率、中断现场……样样都学过，样样都记得点。

可现在桌上摆着一块"跑得不对"的板子，汇报只有一句含混的描述。**先查哪一个？**

学完一章工具最大的风险不是忘了公式，而是"拿着锤子看什么都是钉子"。本课不添任何新知识，只做三件事：把全章课程排成一张**导诊地图**、演练一遍**分诊两问法**、把最容易踩的坑一次性列队展览。

## 2. 直觉解释

数字系统的故障分诊只需连问两个问题：

**第一问——症状落在哪一层？**

| 层 | 典型症状 | 谁负责 |
| --- | --- | --- |
| **数值表示** | 算术结果怪异、溢出、负号错乱 | 二进制、补码、定点 |
| **逻辑功能** | 真值表对不上、毛刺、竞态 | 化简、组合逻辑、冒险 |
| **时序节拍** | 提频后出错、偶发、可复现性差 | 触发器、状态机、建立保持 |
| **性能吞吐** | 功能对但慢、气泡多、访存拖后腿 | 流水线、缓存、局部性 |
| **系统边界** | 设备丢事件、抢总线、CPU 干等 | 中断、轮询、仲裁、DMA |

**第二问——你手上能改什么？**

- **改逻辑**：加一个门、化简一片卡诺图——最便宜，只动真值；
- **改时序**：调时钟、插流水段——中等代价，动的是节拍；
- **改代码**：重排指令、改遍历顺序——不动硬件就见效，动的是访问流；
- **改架构**：加缓存、加相联度、换中断——最贵，动的是系统形状。

两问答案往地图上一对，"科室"基本锁定。剩下的分歧多半发生在"多种工具都能凑合"的地带——那时比的是代价与可维护性，不是比谁听起来高级。

## 4. 分步例题

**题 A**：时钟从 50 MHz 提到 100 MHz 后，状态机偶发进错态，降温后又好了。

1. 第一问：**时序节拍层**（提频诱发 + 温度敏感是时序违例的签名）；第二问：不能改逻辑（功能本来对）；
2. 定位：频率翻倍后建立约束踩线——数据在下一拍时钟沿之前赶不到触发器；
3. 处方：查 [时序约束](./100-timing-setup.md) 的建立窗口，缩短关键路径或插流水段；顺手查 [状态机](./90-fsm-lab.md) 是否有未用状态的归宿；
4. **不要先改逻辑**——时序违例改逻辑是给错误的药方加剂量。

**题 B**：图像处理循环功能正确，但比同事的版本慢 6 倍，代码几乎一样。

1. 第一问：**性能层**；第二问：能改代码（访问流）；
2. 逐层排查：流水线没气泡（[流水线](./150-pipeline-hazard.md)）；内层循环按**列**遍历二维数组——空间局部性全毁（[缓存](./160-cache-lab.md)）；
3. 处方：转成行主序遍历，命中率回升，6 倍差距消失；
4. 这类问题的分诊信号是"**同样的代码，换个遍历方向差几倍**"——纯缓存病。

**题 C**：键盘偶尔丢按键，日志显示按键时刻 CPU 正在跑一段 2 ms 的临界区。

1. 第一问：**系统边界层**；第二问：能改架构（中断策略）；
2. 定位：临界区里把键盘中断屏蔽太久，请求线挂起；若键盘硬件缓冲只有一次深度，就丢事件；
3. 处方：查 [总线中断](./170-bus-interrupt.md)——缩短临界区、或改用带 FIFO 缓冲的读取路径；
4. 复诊看量级：响应要求（几十 ms）远宽于临界区（2 ms）本不该丢——丢在**屏蔽纪律**上，不在频率上。

## 5. 动手实验

### 实验 1（python）：给症状自动挂号

```python title="按症状开具科室单"
def triage(wrong_value, glitch, slow_loop, devices_starved):
    # 优先级闸门：越会污染后续结果的越早分流
    if glitch:
        return "timing-setup（先查建立/保持，别急着改逻辑）"
    if wrong_value:
        return "twos-complement（先查数的表示）"
    if slow_loop:
        return "cache-lab（数命中率，按 3C 用药）"
    if devices_starved:
        return "bus-interrupt（轮询换中断，排优先级）"
    return "karnaugh（回头化简逻辑）"

cases = [
    ("时钟提频后偶发进错态", False, True, False, False),
    ("3 - 5 得了个怪数", True, False, False, False),
    ("内层循环比同事慢 6 倍", False, False, True, False),
    ("键盘按十次才响应一次", False, False, False, True),
]
for note, a, b, c, d in cases:
    print(triage(a, b, c, d), "|", note)
```

四行输出就是四张挂号单。**注意 if 台阶的顺序本身就是知识**：时序违例排第一——它产出的错数据会被后面每一级放大、存储、传播；等发现"算术结果怪"时，病根可能早就跑到了两公里外。

### 实验 2（python）：一张表把量级钉住

```python title="数字工程师脑内必备的数量级"
print("── 时间 ─────────────")
for name, t in [("一个门延迟", 1e-10), ("1 GHz 时钟周期", 1e-9),
                ("L1 缓存访问", 1e-9), ("主存访问", 1e-7), ("SSD 一次读写", 1e-4)]:
    print(f"{name:>10}: {t*1e9:8.2f} ns")
print("── 经验系数 ─────────")
print("  理想 CPI→1，每档冒险多 1~2 拍   命中率 95%→AMAT 6 拍、98%→3 拍")
print("  中断 80 拍/次 ÷ 事件间隔 2000 拍 = 占 4%   轮询占比 = 单次查费 ÷ 间隔")
```

三段输出是"工程直觉"的量化版。判断一个设计靠不靠谱，往往不需要精确计算，只需要看数量级对不对——**门延迟和时钟周期同量级，CPU 就该跑不满频；主存比 L1 慢百倍，缓存命中率就是生死线**。

### 快问快答

```quiz
一个温度传感器，数值每秒才变一次，MCU 主循环每圈 10 ms。要不要为它配中断？
- 配高优先级中断，一变就响应
- 轮询就够：事件频率远低于主循环频率，中断的保存现场开销反而更贵 [*]
- 用 DMA 常驻搬运
- 把主循环提到 1 MHz
? 中断的开销随事件次数走（每次 80 拍的仪式），轮询的开销随轮询频率走。每秒 1 次的事件配每秒 100 次的主循环，顺手读一个寄存器就完事——为它装门铃纯属给系统加仪式。分诊口诀：事件稀而要快用中断，密而可等用轮询，这里两头的"稀"与"可等"都占了。
```

::::warning[常见误区]

**误区一**："工具越高级越好，上来就超标量。"
你以为性能问题都该用重武器——五级流水的气泡还没数清，就谈乱序执行和分支预测器，等于地基没平就盖三楼。**先数气泡、再谈转发、最后才轮到深流水**；这一章的每一件工具都踩着前一课的肩膀。

**误区二**："方法地图是一条通关路线。"
它是按需查阅的工具书，不是进度条。真实工作只摘用其中两三页。这张表真正想教的是**分诊的顺序**：先看会不会污染数据（时序违例、数值表示），再看功能对不对，最后才优化性能。**顺序错了，会越修越坏。**

**误区三**："把每课的结论背下来就是掌握了。"
你以为地图可以背诵——地图给的是路标，判断靠**量级**和**场景**。背下"中断比轮询先进"不如记住"事件稀而要快用中断"；背下"缓存越大越快"不如记住"冲突失效加容量没用"。结论会过期，量级永不背叛。

::::

## 6. 练习

**练习 1**：分诊台的分支顺序被人调乱了：把"循环慢"排在了"偶发毛刺"前面，导致一块时序违例的板子被开了缓存科的单。请把它扶正，使输出依次是 `timing-setup`、`cache-lab`、`twos-complement`：

```exercise
# @title: 练习：谁的科室单开错了
# @check: timing-setup
# @check: cache-lab
# @check: twos-complement
# @hint: 会继续污染后续数据的硬件问题优先级最高——时序违例产出的坏数据会被每一级放大。交换 glitch 与 slow_loop 两支的先后
def triage(glitch, slow_loop, wrong_negative):
    if slow_loop:
        return "cache-lab"
    if glitch:
        return "timing-setup"
    if wrong_negative:
        return "twos-complement"
    return "karnaugh"

print(triage(True, False, False))    # 时钟提频后偶发算错
print(triage(False, True, True))     # 循环慢，而且负数结果也怪
print(triage(False, False, True))    # 单纯负数错
```

**练习 2**：一块气象采集板要在户外跑一年：温度传感器每秒采一次样，SD 卡每分钟写一条记录，无线模块不定时收包且要求 10 ms 内应答。请为三路 I/O 各选机制（轮询/中断/DMA），并说明理由。

<details>
<summary>点开查看逐步解答</summary>

1. **温度传感器：轮询**。主循环每圈 10 ms，顺手读一个寄存器；事件频率（1 次/秒）远低于主循环频率（100 次/秒），装中断纯属加仪式开销；
2. **SD 卡写记录：中断 + DMA**。每分钟一次、一次搬一大块——事件稀（中断成本可忽略）而数据量大（DMA 免得 CPU 逐字节搬）；若 CPU 亲自搬 512 字节，几十次中断全花在仪式上；
3. **无线模块：中断（高优先级）**。事件不定时且要求 10 ms 内应答——"稀而要快"正是中断的主场；10 ms 对 1 GHz 的 MCU 是千万拍量级，中断那 80 拍开销毫无压力；
4. **顺序检查**：无线应答的 ISR 里不要写 SD 卡（慢设备进快 ISR 会拖死高优先级）——应答数据放缓冲，由主循环或低优先级中断慢慢落盘；
5. 这道题的全部判断依据就是分诊口诀加两个量级：**事件频率 vs 轮询频率、响应要求 vs 一次中断开销**。

</details>

## 7. 选读：三条游览路线

<details>
<summary>选读 · 不同胃口的吃法</summary>

**数字前端线**（最快上手做逻辑）：从模拟到数字 → 逻辑门 → 卡诺图 → 加法器 → 触发器 → 状态机 → 时序约束。走完这条线，你能用 HDL 写出并验证一块靠谱的同步时序电路。

**处理器纵深线**（想懂 CPU 内部）：前端线 + 补码 → ALU → 数据通路 → 指令集 → 流水线。重点在"一条指令的一生"：从取指、译码到写回，以及每一段可能卡住的时刻。这条线直通第 70 章——程序是怎么跑起来的。

**系统整合线**（做完整产品的读法）：处理器线 + 缓存 + 总线中断，再补第 70 章的进程、调度与虚拟内存。重点不在"算得对"，而在"喂得饱、等得起、不丢事"——性能与边界的权衡从这一章开始成为主角。

**三条线最后都汇入同一句话**：数字系统设计的本质不是堆门电路，而是**在时序、面积、功耗与复杂度之间做取舍**——地图能帮你找到工具，取舍只能靠你自己拍板。

</details>
