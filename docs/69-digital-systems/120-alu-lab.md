# ALU 设计

## 1. 从一个场景开始

你手机里的芯片每秒做几万亿次运算，但拆开看，其中「算术」的部分小得惊人——真正的核心就是一个几毫米见方的部件，接住两个二进制数和一根「做什么」的信号线，吐出一个结果加几根状态线。这个部件叫 **ALU**（算术逻辑单元，Arithmetic Logic Unit）。

上一课你已经凑齐了它最难的一块拼图：**同一个加法器，既算加法又算减法**。这一课把加、减、与、或、异或全部并联起来，装上一个「分诊台」，再造几根告诉外界「结果怎么样了」的标志线——一台 4 位 ALU 就完工了。它就是第 130 课数据通路里真正干活的那个手。

## 2. 直觉解释

ALU 的结构是「**一堆电路并联，一根开关线选答案**」：

- 进来的两个操作数 A、B 被**同时**送到加法器、减法器、与门阵列、或门阵列……所有运算电路一起开算；
- 操作码（op）是分诊台的号码牌：op=2 就把加法器的输出接到出口，其他电路的答案全部作废；
- 第 50 课的多路选择器在这里上岗：8 路运算、8 选 1。

**标志位是 ALU 的「体检报告」**，一共四根线：

| 标志 | 名字 | 什么时候置 1 |
| --- | --- | --- |
| Z | 零 | 结果全 0 |
| C | 进位/借位 | 无符号世界的「装不下」信号 |
| V | 溢出 | 有符号世界的「装不下」信号 |
| N | 负 | 结果最高位是 1（补码读法为负） |

为什么 C 和 V 要分开？因为**同一个 4 位加法器服务两个世界**：无符号世界（0..15）的「装不下」看 C，补码世界（-8..7）的「装不下」看 V。电路不知道有这两个世界，是**读结果的人**用不同的标志各自把关——上一课「位模式没有含义、含义来自读法」的哲学，在标志位上再演一遍。

## 3. 正式定义

**4 位 ALU**：输入操作数 $A, B \in \{0,\dots,15\}$ 与操作码 $op \in \{0,\dots,7\}$，输出 4 位结果与四个标志位：

| op | 操作 | 定义 |
| --- | --- | --- |
| 0 | AND | 逐位 $a_i \wedge b_i$ |
| 1 | OR | 逐位 $a_i \vee b_i$ |
| 2 | ADD | 补码加法 $A + B$（模 16） |
| 3 | SUB | $A + \overline{B} + 1$，即补码减法 |
| 4 | XOR | 逐位 $a_i \oplus b_i$ |
| 5 | NOT | 逐位取反 $A$（$B$ 被无视） |
| 6 | 移位 | 结果左移一位、移出的最高位进 C（等价于 $\times 2$ 再模 16） |
| 7 | CMP | 算的还是 $A - B$，但**结果不写回**，只留标志位 |

**溢出标志 V 的判定**（加法/减法通用）：进位**进入**符号位与**走出**符号位**不相等**时 $V=1$。

**借位约定**：SUB / CMP 中走出符号位的进位 $C=0$ 表示「不够减」（无符号世界里 $A < B$），$C=1$ 表示够减。

**移位**：本课 ALU 的 op 6 是**左移**——结果等于 $(A \times 2) \bmod 16$，被挤出去的最高位记进 C。左移一位 = 乘 2，右移一位 = 除 2 取整，方向由设计者规定，乘除 2 的幂这个本质不变。

## 4. 分步例题

**例 1**：SUB 的位级全演算，算 $6 - 7$（4 位）。

1. $B = 7$ = `0111`，按位取反 $\overline{B}$ = `1000`；
2. 做 $A + \overline{B} + 1$ = `0110 + 1000 + 1`：
   - 第 0 位：0+0+1 = 1，写 1 进 0；
   - 第 1 位：1+0+0 = 1，写 1 进 0；
   - 第 2 位：1+0+0 = 1，写 1 进 0；
   - 第 3 位：0+1+0 = 1，写 1 进 0；
3. 结果 `1111` = 补码读法 $-1$ ✓（$6-7=-1$）；
4. 标志：走出符号位的进位 $C = 0$ →「不够减」正确报告（无符号 6 < 7）；进、出符号位的进位相等 → $V = 0$，无溢出。

**减法电路从头到尾没出现过**——取反是异或门阵列（op 5），加法器是 op 2，仅此而已。

**例 2**：ADD 算 $6 + 7$，两个世界各自报告。

1. `0110 + 0111 = 1101`，真实和 13；
2. 无符号世界：13 在 0..15 内，$C = 0$，一切正常；
3. 补码世界：$6+7=13$ 超出 $-8..7$，**溢出**。逐位看进位：进入符号位（第 3 位）的进位是 1，走出符号位的进位是 0——不等，$V = 1$；
4. 结果 `1101` 按补码读是 $-3$：**两个正数相加得负**，V 就是干这个报警的。

**例 3**：CMP 是怎么「比较」的——判 $3 < 5$。

1. CMP 做的还是 $3 - 5$：$\overline{0101}$ = `1010`，`0011 + 1010 + 1 = 1110`（补码读 $-2$）；
2. 关键在**结果不写回**：差值 $-2$ 被扔掉，只留下 $Z=0$（不为零）、$N=1$（结果为负）、$C=0$（不够减）；
3. 后续指令看一眼 $N=1$ 就知道 $3 < 5$，该跳转跳转。**比较 = 做一次不记答案的减法。**

## 5. 动手实验

### 实验 1（lab）：操作码一换，ALU 换脸

```lab
{
  "type": "alu-lab",
  "title": "默认就是一次溢出：6 + 7 在 4 位补码世界装不下，看 V 亮灯",
  "a": 6,
  "b": 7,
  "op": 2
}
```

A / B 两行位格子都能点、能按住拖过去刷；分段按钮（或 op 滑块）切操作码。必玩三件事：

- 开局就是 **6 + 7**：结果标红、V=1。用例 2 的进位核对一遍「进符号位 1、出符号位 0」；
- 切到 **SUB**：电路什么都不用你改，结果立刻变成 $-1$（例 1）；再看 CMP——同样的标志位，结果一行不再写回；
- 把 A 刷到 `1100`、B 刷到 `1100`（无符号 12 + 12 = 24）：$C = 1$ 亮了，但按补码读 $-4 + (-4) = -8$ **完全正确**、$V = 0$。C 和 V 是两个世界各自的声音，谁也不理谁。

### 实验 2（python）：C 与 V 的两副面孔

```python title="同一套加法器，无符号与补码各自把关"
for a, b in [(6, 7), (14, 5), (12, 12), (15, 1)]:
    u = a + b
    wrapped = u % 16                                    # 4 位加法器吐出的位模式
    sa = a - 16 if a >= 8 else a                        # 操作数按补码读
    sb = b - 16 if b >= 8 else b
    sv = wrapped - 16 if wrapped >= 8 else wrapped      # 结果按补码读
    C = 1 if u > 15 else 0                              # 无符号世界：0..15 装不下
    V = 0 if -8 <= sa + sb <= 7 else 1                  # 补码世界：-8..7 装不下
    print(f"{a:>2}+{b:>2} → 位模式 {wrapped:>2}（补码读 {sv:>3}）  C={C}  V={V}")
```

四行输出正好把「两副面孔」摆上桌：`6+7` 是 $C=0, V=1$（无符号好好、有符号爆了）；`14+5` 与 `12+12`、`15+1` 都是 $C=1, V=0$（无符号爆了，可 $-2+5=3$、$-4+(-4)=-8$、$-1+1=0$ 全都在 $-8..7$ 内，补码结果全对）。**C 和 V 谁亮谁灭，取决于你把位模式当哪个世界读——电路只负责同时把两份报告都递出来。**

### 快问快答

```quiz
CMP 和 SUB 算的是同一件事 a-b，它们的区别是什么？
- CMP 不处理负数
- CMP 不把结果写回，只留下标志位 [*]
- CMP 更快，不经过加法器
? 两者走的是同一条 a + ~b + 1 电路。区别只在结果去哪：SUB 把差值写回寄存器，CMP 把差值扔掉，只留 Z/C/N/V 给后面的分支指令看。
```

::::warning[常见误区]

**误区一**："ALU 是一个『会算术的器件』，内部有个专门的减法器、除法器。"
你以为每种运算各有一套电路——其实只有与、或、异或、取反、加法器这几样并联，减法是「取反加一再加法」，乘除法在早期 CPU 里干脆没有（靠移位加法编出来）。ALU 的全部秘密是**复用**：op 信号决定哪一路输出被接走。

**误区二**："溢出 V 亮了，说明寄存器装不下、结果作废。"
你以为溢出是硬件错误——其实 V 只是一根**提示线**：它说明「如果你按补码读这个结果，结果不可信」。无符号世界读同一个结果完全正确（6+7=13，C=0）。溢不出溢，取决于读者站在哪个世界。

**误区三**："标志位是给程序员看的调试信息。"
你以为 Z/C/V/N 只是状态显示——其实它们是 CPU 控制流的**输入**。第 130 课的 beq（条件跳转）就是 ALU 算完 CMP、控制单元读 Z 线、再决定 PC 走哪条路。没有标志位，if 和循环全都无从谈起。

::::

## 6. 练习

**练习 1**：4 位补码世界算 $6 + 7$，加法器吐出位模式。求按补码读法得到的有符号值（应为 `-3`）。这段代码忘了换读法：

```exercise
# @title: 练习：读出溢出后的位模式
# @check: -3
# @hint: 位模式是同一个，读法有两种。最高位是 1 时，补码读法和无符号读法差多少？
a = 6    # 4 位补码：+6
b = 7    # 4 位补码：+7
u = (a + b) % 16    # 4 位加法器吐出的位模式（无符号值 13）
signed = u          # ← 问题在这：把无符号读法直接当成了补码读法
print(signed)
```

**练习 2**：只用 op 2（ADD）和 op 5（NOT），手推 $A=5, B=3$ 时「$A - B$」的四位结果与 C、V、N、Z 四个标志。

<details>
<summary>点开查看逐步解答</summary>

1. $\overline{B}$：`0011` 逐位取反得 `1100`（即 op 5 的输出，$12$）；
2. ADD：`0101 + 1100 + 1` = `10010`，5 位——超出 4 位，低 4 位 `0010` 是结果，走出符号位的进位是 1；
3. 结果 `0010` = 2，补码读也是 2：$5 - 3 = 2$ ✓；
4. 标志：$C = 1$（够减，无符号 5 > 3）；进入符号位的进位 = 1、走出 = 1，相等 → $V = 0$；$N = 0$（最高位 0）；结果非全 0 → $Z = 0$。

注意 $C=1$ 在减法里的语义是「够减」——和加法里「装不下」正好相反的读法，这是借位约定把进位**借**来当借位用了。

</details>

## 7. 选读：行波进位——ALU 的阿喀琉斯之踵

<details>
<summary>选读 · 为什么 32 位加法不能「一位一位慢慢来」</summary>

本课加法器是**行波进位**结构：第 $i$ 位的和与进位都要等第 $i-1$ 位的进位算出来才能开算。4 位无所谓，32 位的真实 CPU 里，最坏情况（比如 `0000...0001 + 0111...1111`）进位要一路波过 31 级门——时钟都快不起来，因为**时钟周期必须迁就最慢的那条路径**。

工程解法是**超前进位加法**（carry-lookahead）：观察到「第 $i$ 位产生进位」与「第 $i$ 位传播进位」可以只看本位操作数就提前算出，于是先并行算好所有「生成/传播」信号，再两级门深算出全部进位。代价是门数量涨一大截，换来的是加法延迟从「正比于位数」压到「正比于位数的对数」。

这也是数字设计的通用配方：**用面积换时间**。同样的主题你在第 160 课会再遇到一次——用存储空间换访问时间（缓存）。

</details>
