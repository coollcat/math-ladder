# 数字系统与计算机组成

模拟电路（第 68 章）把数学逼到了必须兑现的地方；这一章把兑现过的信号**彻底交还给数字**——从此不再有噪声累积、不再有器件漂移，一切布尔。而"计算机"并不是被发明的，它是从**一个能记住 1 个位的元件**开始，一级一级长出来的：记住一位 → 记住一串 → 按状态行动 → 按节拍行动 → 会算术 → 会执行指令 → 会流水 → 会记住更多。

## 方法主线

**离散 → 逻辑 → 记忆 → 状态 → 节拍 → 算术 → 指令 → 流水 → 层次。**

前五课解决"信号与逻辑"：离散化要付代价，布尔代数是通用语言，化简是省钱，加法器是第一件正经计算。六到十课解决"记忆与时序"：锁存器给了记忆，状态机给了行为，时钟给了节拍，建立保持窗口给了物理底线。十一到十四课解决"算术与指令"：补码让减法消失，ALU 让运算集中，数据通路让指令流动，指令集让软件与硬件签约。最后四课解决"跑得快与记得多"：流水线重叠指令，缓存掩盖延迟，中断让 CPU 一心多用。

## 实战挑战 · 200 装进 8 位会发生什么

8 位无符号数只能装 0–255，可程序里就是要写 200 + 100。硬件不会报错——它默默按模 256 卷回去，你看到的还是那个位模式，只是**按补码读**时它变成了负数。下面这段代码的"按补码读回"忘了看符号位，修到输出 `11001000` 与 `-56`：

```exercise
# @title: 实战挑战：8 位补码的溢出与读回
# @check: 11001000
# @check: -56
# @hint: 位模式 = 值按模 256 取（v % 256 再转二进制）；按补码读回时，最高位是 1 就要减 256——200 − 256 = −56
def to_bits8(v):
    return format(v % 256, '08b')   # 位模式：按模 256 取

def from_bits8(b):
    return int(b, 2)                # ← 问题在这：最高位是 1 时这不是它表示的值

print(to_bits8(200))
print(from_bits8(to_bits8(200)))
```

<details>
<summary>点开查看逐步解答</summary>

1. $200$ 超出了 8 位有符号范围 $[-128, 127]$，硬件按模 $2^8 = 256$ 卷回：位模式 $200 = 11001000_2$；
2. 按补码读：最高位是 1，表示的值为 $200 - 256 = -56$；
3. 这就是 $100 + 100$ 在 8 位补码里的下场：结果"变成了" $-56$——溢出不报错，只换脸；
4. 验算：$-56$ 的补码 $= 256 - 56 = 200 = 11001000_2$，往返一致 ✓。

初始代码把 $11001000_2$ 读成 200——那是无符号的读法。补码的世界里同一个位模式有两副面孔，符号位决定用哪副。

</details>
