# 存储层次与缓存

## 1. 从一个场景开始

手机刚开机，打开一个 App 要两三秒；用了一阵之后，再打开同一个 App 几乎是瞬间的。App 没变，手机也没换零件——**只是"常用的东西"被搬到了近处**。

CPU 也有同样的烦恼。1 GHz 的处理器一拍只要 1 纳秒，而主内存响应一次要约 100 纳秒——**流水线精心省下的每一拍，一次访存就全赔进去**。解法不是把内存造快（造不起），而是在中间垫几层"又小又快又贵"的货架，把最常用的数据放在离 ALU 最近的地方。这套从寄存器到磁盘的金字塔，叫**存储层次**；架在 CPU 和内存之间的那层小货架，叫**缓存**。

## 2. 直觉解释

你在书桌前写作业：

- **桌上**（寄存器）：正在用的笔和草稿纸，伸手就到，但桌面很小；
- **书架**（缓存）：这门课的全部课本，站起来够得着；
- **书房书柜**（内存）：全家藏书，要走几步；
- **图书馆**（磁盘）：什么都有，但要坐车去。

桌、架、柜、馆，**越小越快、越大越慢越便宜**。系统的快慢几乎不取决于"能不能找到"，而取决于"**要找的东西在不在近处**"——这由程序的行为决定：

- **时间局部性**：刚用过的数据，多半马上还要用（循环变量）；
- **空间局部性**：用了一个数据，多半马上用隔壁的（数组按顺序扫）。

缓存赌的就是这两条。赌中了（**命中**），快如桌面；赌输了（**缺失**），就得跑一趟图书馆——还要顺路把整排相关的书都搬回来（一次搬一块，叫**缓存块**）。

## 3. 正式定义

**命中率** $h$：访问序列中命中所占的比例。单次访问的命中/缺失是一次随机试验，命中率是大样本下的频率——访问流驱动缓存内容变化，而缓存"现在装着什么"决定了下一次命中与否：把缓存状态看成状态、访问流看成转移，这正是第 37 章马尔可夫链的设定。LRU 这类"只看当前状态"的替换策略，恰恰保证这个过程是马尔可夫的。

**平均访问时间**（AMAT，Average Memory Access Time）：

$$\text{AMAT} = t_{\text{hit}} + (1 - h) \cdot t_{\text{miss}}$$

**直接映射缓存的地址切分**（块大小 $B$、组数 $S$）：

$$\text{块号} = \left\lfloor \frac{\text{地址}}{B} \right\rfloor, \qquad \text{组号} = \text{块号} \bmod S, \qquad \text{标记} = \left\lfloor \frac{\text{块号}}{S} \right\rfloor$$

每个地址只能进**唯一确定**的那一组——便宜，但两个"投缘"的地址会抢同一个位置。

**组相联度**：每组放 $A$ 行（$A = 1$ 是直接映射，$A = S$ 是全相联）。组内满了按替换策略踢人（LRU：最久没用的先走）。

**3C 失效分类**：**冷失效**（第一次访问，谁都躲不掉）、**冲突失效**（容量够但撞组）、**容量失效**（工作集比缓存还大）。

| 符号 | 名字 | 典型量级 |
| --- | --- | --- |
| $t_{\text{hit}}$ | 命中耗时 | L1 约 1 ns（1 拍量级） |
| $t_{\text{miss}}$ | 缺失代价 | 去主存约 100 ns（上百拍） |
| $B$ | 块大小 | 64 字节量级 |
| $h$ | 命中率 | 90%~99%（取决于程序） |
| $A$ | 相联度 | 1~16 路 |

## 4. 分步例题

**例 A**：容量 4 字、块大小 1 字的直接映射缓存（4 组各 1 行），程序反复访问地址 0,1,2,3 共 16 次。前一轮 4 次全缺失（冷失效，搬进来），之后 12 次全命中——命中率 $12/16 = 75\%$。

**例 B**：同样的缓存改成 8 组各 1 行（容量 8 字），程序访问 0,8,0,8,……地址 0 和 8 的块号是 0 和 8，对 8 取余**都是第 0 组**——每次访问都把对方踢出去，命中率 $0\%$。容量绰绰有余（只用了两个地址），输在**冲突**：解药是 2 路组相联，让第 0 组同时住下两个。

**例 C**：命中 1 拍、缺失代价 100 拍，命中率 95%：

$$\text{AMAT} = 1 + 0.05 \times 100 = 6\ \text{拍}$$

命中率提到 98%？$1 + 0.02 \times 100 = 3$ 拍——**命中率每抢救两个百分点，平均耗时砍一半**。这就是为什么缓存值得花大钱。

## 5. 动手实验

### 实验 1（lab）：看着一块数据被踢进踢出

```lab
{
  "type": "cache-lab",
  "title": "乒乓冲突：容量明明够，命中率却是零",
  "seq": [0, 8, 0, 8, 0, 8, 0, 8, 0, 8, 0, 8, 0, 8, 0, 8],
  "capacity": 8,
  "blockSize": 1,
  "assoc": 1,
  "axis": "assoc"
}
```

顶部一排地址逐个走：绿色是命中、红色是缺失，能看到每次落在第几组、踢掉了谁。做三件事：

- 按「单步」走几步：地址 0 和 8 永远在互相踢——这就是例 B 的冲突失效；
- 把「关联度」调到 2 路：两个地址同住第 0 组，命中率立刻从 0% 跳上去；
- 看下方曲线（横轴已切到「关联度」）：这就是 3C 的直观版——**冲突失效靠加相联度，容量失效靠加容量，冷失效只能靠预取**。

### 实验 2（python）：亲手模拟一个直接映射缓存

```python title="直接映射缓存：小循环 vs 乒乓冲突"
def simulate(seq, lines):
    cache = [-1] * lines        # 每行存一个块号，-1 表示空
    hits = 0
    for addr in seq:
        line = addr % lines     # 块大小 1 字：组号 = 块号 mod 组数
        if cache[line] == addr:
            hits = hits + 1
        else:
            cache[line] = addr  # 装进这一行，旧住户被顶掉
    return hits

loop = [0, 1, 2, 3] * 4      # 小循环重用：4 个地址来回跑
ping = [0, 8] * 8            # 乒乓冲突：两个地址抢同一行
for name, seq, lines in [("小循环", loop, 4), ("乒乓", ping, 8)]:
    h = simulate(seq, lines)
    print(f"{name}: 命中 {h}/{len(seq)} → {h/len(seq)*100:.0f}%")
```

模拟器只有十行，却复现了例 A 和例 B 的全部结论：小循环 75%（冷失效只付一次），乒乓 0%（冲突失效付到天荒地老）。

### 实验 3（python）：命中率救两个百分点，AMAT 砍一半

```python title="命中率与平均访问时间"
hit_time = 1.0        # L1 命中 1 拍
miss_penalty = 100.0  # 缺失去主存 100 拍
for rate in [0.90, 0.95, 0.98, 0.99]:
    amat = hit_time + (1 - rate) * miss_penalty
    print(f"命中率 {rate*100:.0f}%  →  AMAT = {amat:.1f} 拍")
```

90% 命中率听着很高，AMAT 却是 11 拍——**一次缺失吃掉九十九次命中省下的时间**。缓存的数学是残酷的：它的收益不成比例地押在尾部那两个百分点上。

### 快问快答

```quiz
缓存容量 16 字（16 组、直接映射），程序交替访问地址 0 和 32，命中率 0%；把容量翻倍到 32 字，命中率还是 0%。最有效的改进是？
- 换成 LRU 替换策略
- 改成 2 路组相联 [*]
- 提高时钟频率
? 地址 0 和 32 对 16 或 32 取余都落进第 0 组——单行组里替换策略再聪明也只有一个位置可让。改成 2 路组相联，第 0 组同时住下两块，命中率立刻起飞。这是典型的冲突失效：容量不缺，缺的是"同组几个位置"。
```

::::warning[常见误区]

**误区一**："容量大 = 命中率高。"
你以为加容量是万金油——例 B 里容量翻几倍都没用，因为失效原因是**冲突**不是容量（3C 里各管各的）。加容量救容量失效，加相联度救冲突失效，预取救冷失效；用错药，钱白花。

**误区二**："命中率是硬件的固定参数。"
你以为命中率写在芯片手册上——它是**访问流的函数**：同一个缓存，顺序扫描、小循环、跨步访问，命中率天差地别（实验组件里那四个预设就是四种"访问人格"）。换一批输入数据，命中率这个"随机变量的均值"就变了——这是第 37 章的口吻。

**误区三**："缓存是硬件工程师的事，写代码的管不着。"
你以为性能是编译器赏的——**局部性是可以写出来的**：按行遍历二维数组（行主序）与按列遍历，同样的循环命中率能差几倍；数据结构选数组还是链表，本质是在赌空间局部性在不在。

::::

## 6. 练习

**练习 1**：命中耗时 1 拍、缺失率 4%、缺失代价 100 拍，AMAT 应为 `5.0`。这段代码忘了乘缺失率：

```exercise
# @title: 练习：平均访问时间 AMAT
# @check: 5.0
# @hint: AMAT = 命中耗时 + 缺失率 × 缺失代价——乘缺失代价的是缺失率，别把它整个加上去
hit_time = 1.0       # 命中耗时（拍）
miss_rate = 0.04     # 缺失率：4% 的访问在缓存里找不到
miss_penalty = 100   # 缺失代价（拍）
amat = hit_time + miss_penalty    # ← 问题在这：4% 的访问要付 100 拍，不是所有访问都付
print(f"{amat:.1f}")
```

**练习 2**：把实验 2 的模拟器改成**全相联**（地址可以进任何空行，满了按 LRU 踢），跑一遍乒乓序列，命中率是多少？为什么？

<details>
<summary>点开查看逐步解答</summary>

1. 全相联下 8 行缓存可以同时住下 0 和 8：前 2 次缺失（冷失效），之后 14 次全命中；
2. 命中率 $14/16 = 87.5\%$；
3. 对比直接映射的 0%——**同样的容量、同样的数据，只改了"往哪放"的规则**，结果天壤之别；
4. 代价也要看见：全相联要拿地址与**所有行**的标记比较（8 路比较器），直接映射只需查 1 行。工程上 4~16 路组相联是"命中率 vs 比较器开销"的折中甜点。

</details>

## 7. 选读：写命中怎么办——写回与写穿

<details>
<summary>选读 · 脏位与两条写策略</summary>

读命中简单：直接从缓存拿。写命中就麻烦了——数据改了，缓存和内存谁先改？

**写穿**（write-through）：改缓存的同时立刻写内存。内存永远新鲜，但每次写都要等 100 拍的总线事务，写多的程序会被拖死。

**写回**（write-back）：先只改缓存，在该行加一个**脏位**（dirty bit）标记"内存里那份过时了"；被踢出去时**若是脏块才写回内存**，干净的块直接丢。写操作享受缓存的速度，代价是控制逻辑复杂、踢人那一拍更贵。

组件里那个「写策略」开关就是它。配合**写缓冲**（写内存的事排队慢慢办，CPU 先走人），写穿也能做得很能打。真实 L1 几乎清一色写回——**脏位是"少跑图书馆"的记账本**。

</details>
