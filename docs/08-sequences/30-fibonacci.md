# 斐波那契与递归：自己定义自己的数列

## 1. 从一个场景开始

1202 年，意大利商人斐波那契在《计算之书》里出了一道兔子题：一对小兔关进围场。兔子长一个月才成年，此后每个月生一对新的小兔（一雌一雄），所有兔子永不死亡。一年之后，围场里有多少对兔子？

拿笔从第一个月记起：1 对，还是 1 对，然后 2 对、3 对、5 对……数字越跳越快，却乱得毫无规律。斐波那契不会想到，这串"数兔子的账"日后会在向日葵、松果、鹦鹉螺和钢琴键盘上反复现身，成为数学史上最著名的数列。

## 2. 直觉解释

把每月的对数排开：$1, 1, 2, 3, 5, 8, 13, 21, \dots$

盯两秒就会发现规律：**每一项都是前两项之和**——$2=1+1$，$5=3+2$，$13=5+8$。为什么？想清楚兔子的构成：第 $n$ 个月的兔子分两拨：

- **上个月就在的所有老兔子**：一只都没少，共 $F(n-1)$ 对；
- **新生的小兔**：只有上上个月就存在的兔子才够年龄当爸妈，它们有 $F(n-2)$ 对，各生一对。

所以 $F(n) = F(n-1) + F(n-2)$——每一项都回头问前两项要答案。

## 3. 正式定义

**斐波那契数列**：由两条规则共同定义：

$$F(1) = 1, \qquad F(2) = 1, \qquad F(n) = F(n-1) + F(n-2) \quad (n \ge 3)$$

| 部件 | 名字 | 含义 |
| --- | --- | --- |
| $F(1), F(2)$ | 基础情形（种子） | 数列的头两块砖，必须直接给出 |
| $F(n)=F(n-1)+F(n-2)$ | 递推关系 | 用前面的项定义后面的项 |
| $F(n)$ | 第 $n$ 项 | 想知道它？先去问 $F(n-1)$ 和 $F(n-2)$ |

注意它与等差等比的本质区别：这里没有"$a_n = $ 关于 $n$ 的公式"，而是**用数列自己来定义自己**。这种"自指"的定义方式叫递归——听起来像绕圈子，但只要种子齐全、每次都朝种子的方向退，链条就有尽头。它的合法性正是上一课归纳法保证的：种子是基础情形，递推是归纳步骤。

## 4. 分步例题

**例**：逐月记录，回答兔子问题。

1. 第 1 月：1 对小兔 → $F(1)=1$；
2. 第 2 月：小兔长大 → $F(2)=1$；
3. 第 3 月：老兔生一窝 → $F(3) = F(2)+F(1) = 2$；
4. 继续递推：$F(4)=3$，$F(5)=5$，$F(6)=8$，$F(7)=13$，$F(8)=21$，$F(9)=34$，$F(10)=55$，$F(11)=89$，$F(12)=144$。

一年后围场里有 **144 对**兔子。手算 12 步还行，要是问十年后呢？这种机械重复的活儿该交给机器了。

## 5. 动手实验

### 实验 1（viz）：方块螺线与黄金比

```viz
{
  "type": "fibspiral",
  "n": 8
}
```

怎么玩：拖动 n 滑杆让边长为 $1, 1, 2, 3, 5, 8, \dots$ 的方块一圈圈生长，弧线扫过每个方块拼成一条螺线——鹦鹉螺的外壳就是这个形状。同时盯着上方的读数：相邻两项之比 $\frac{8}{5}=1.6$，$\frac{13}{8}=1.625$……越往后越死死咬住 **1.618**。这个数叫黄金比 $\varphi$，选读部分解释它为什么必然出现。

### 实验 2（python）：让函数自己调用自己

```python title="递归版斐波那契"
def fib(n):                          # def 定义函数：造一台叫 fib 的机器，接收序号 n
    if n <= 2:                       # 基础情形：第 1、2 项直接交答案，不再往下追问
        return 1
    return fib(n - 1) + fib(n - 2)   # 递归：机器在自己的定义里调用自己——先问前两项再相加

for n in [5, 10, 20]:
    print(f"F({n}) = {fib(n)}")
```

怎么玩：`fib(20)` 会层层追问 `fib(19)`、`fib(18)`……一路追到种子 `fib(1)`、`fib(2)` 才折返往上加。对照第 4 节的手算表核对结果。试着跑一次 `fib(35)`——明显变慢了，原因见实验 3。

### 实验 3（python）：循环版，只记住最近两项

```python title="循环版：从种子一路爬到顶"
def fib_fast(n):                 # 同样定义一台机器，换一种干法
    prev = 1                     # 前一项，从 F(1) 起步
    curr = 1                     # 当前项，从 F(2) 起步
    for k in range(3, n + 1):    # 从第 3 项一路算到第 n 项
        nxt = prev + curr        # 新项 = 前两项之和
        prev = curr              # 老的前一项退役
        curr = nxt               # 新项顶上
    return curr

print(f"F(20) = {fib_fast(20)}")
print(f"F(80) = {fib_fast(80)}")
```

怎么玩：循环版算 $F(80)$ 也是眨眼间，而递归版算 $F(80)$ 得等到天荒地老。差距的原因一句话：递归把同一道题反复重算，而且重算的遍数随 $n$ 按约 $1.6^n$ 爆炸（练习 2 解答里刚领教过）——`fib(50)` 就已经历上百亿次重复加法，到 `fib(80)` 更是**超过 $10^{16}$ 次的天文数字**：单是 `fib(20)` 这道小题，就会被从头重算上万亿遍。循环版则只向前走一遍。修复这个问题叫"记忆化"，是算法课的经典开场白。

### 快问快答

```quiz
斐波那契数列相邻两项的比值 F(n+1)/F(n)，当 n 很大时最接近哪个数？
- 1.414
- 1.618 [*]
- 不趋近任何数
? 比值越来越接近黄金比 1.618...。选读部分用一行代数式说明这是必然结局。
```

:::warning[常见误区]

**误区一**："你以为比值趋近 1.618，所以斐波那契就是等比数列。" 其实它不是等比也不是等差——每一项与前一项的比值只是**越来越接近** 1.618，却永远差着一点点。"公比为黄金比的等比数列"是它的极限化身，不是它本身。

**误区二**："你以为递归函数可以没有基础情形。" 删掉实验 2 里那两行 `return 1` 再跑试试——机器会无穷无尽地追问自己直到崩溃。这正是上一课骨牌的教训：没有第一块被推倒，传导规则写得再漂亮也是空谈。

**误区三**："你以为兔子的账是严肃的生物观察。" 现实中兔子会死、会停育，模型早就不成立。但它的价值在于结构：凡是"下一项由前两项决定"的系统——松果鳞片的螺旋数、钢琴一个八度里的黑键分组——都共享这条数学，模型抽象的是骨架而非血肉。

:::

## 7. 选读：黄金比的必然登场

<details>
<summary>选读 · 两行代数请出 φ</summary>

记相邻比值 $R_n = \frac{F(n+1)}{F(n)}$。由递推关系：

$$R_{n+1} = \frac{F(n+2)}{F(n+1)} = \frac{F(n+1) + F(n)}{F(n+1)} = 1 + \frac{1}{R_n}$$

比值序列越滚越稳，稳到一个不再变化的值 $L$：它代入上式右边后左边不变，即

$$L = 1 + \frac{1}{L} \quad\Longrightarrow\quad L^2 = L + 1$$

解方程取正根：$L = \dfrac{1+\sqrt{5}}{2} \approx 1.618$，正是黄金比 $\varphi$。更惊人的是，借助它还能反推出通项公式（比奈公式）：$F(n) = \frac{\varphi^n - (1-\varphi)^n}{\sqrt{5}}$——一串纯粹整数，居然藏在两个无理数的差里。归纳法可以验证它（练习一下？），但发现它，得等第 13、15 章的工具到位。

</details>
