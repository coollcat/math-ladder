# 机电与嵌入式方法地图

## 1. 从一个场景开始

样机摆在工作台上：电机偶尔嗡一声不转，位置读数偶尔跳一下，串口偶尔出半个乱码，客户现场还会偶发复位。16 门课学完了，工具箱塞满了：电机模型、PWM、编码器、PID、采样、调度、状态机、总线、去耦、EMC、闭环……

可现在的问题是：**先翻哪一课？**

学完整章工具最大的风险从来不是忘了公式，而是"拿着锤子看什么都是钉子"。本课不添任何新定理，只做三件事：把全章课程排成一张**导诊地图**、演练一遍**分诊两问法**、再把最容易踩的坑列队展览。

## 2. 直觉解释

机电系统的故障分诊只需连问两个问题。

**第一问——症状落在哪一层？**

| 层 | 典型症状 | 谁负责 |
| --- | --- | --- |
| **动力层** | 不转、没劲、发烫、丢步 | 电机、PWM 与 H 桥、驱动 |
| **感知层** | 位置漂、读数跳、噪声大 | 编码器、传感器调理 |
| **控制层** | 稳态误差、超调、振铃 | PID、采样率与控制周期 |
| **计算层** | 卡顿、丢任务、死机 | 实时调度、状态机 |
| **通信层** | 乱码、丢帧、总线挂死 | UART/I2C/SPI/CAN |
| **电源层** | 复位、塌轨、纹波 | 去耦与电源完整性 |
| **干扰层** | 实验室好、现场坏，偶发出错 | EMC |
| **产品层** | 各项都"还行"，成不了产品 | 设计闭环 |

**第二问——量级与工况是什么？**

- **频率量级**：机械带宽几 Hz~几十 Hz，电流环 kHz 级，PWM 20 kHz——**差着两个数量级的环，出问题不能互相背锅**；
- **电流量级**：信号 mA 级、驱动 A 级、电机堵转几十 A——电流错一个量级，选型全盘错；
- **环境量级**：实验室桌面还是车间（变频器、接触器、长电缆）？**"现场才坏"几乎总是环境问题，不是代码问题**。

两问一对，科室锁定。剩下的分歧多半在"几层都沾边"的地带——那时按**损害优先级**排顺序：先复位级（会丢数据、会伤机），再功能级（不动、不准），最后性能级（抖、慢、吵）。

## 4. 分步例题

**题 A**：桌面 3D 打印机高速打印时 X 轴偶发丢步，层间错位。

1. 第一问：丢步落在**动力层**或**计算层**——先区分：丢步瞬间电机有无嗡声与发烫（堵转征兆）；
2. 若发烫：加速度设太高，转矩跟不上 → [步进与细分](./50-stepper-microstep.md)：查转矩-转速曲线，把加减速斜率放缓，或查 [PWM 驱动](./60-pwm-hbridge.md) 的电流设定是否不足；
3. 若无嗡声且丢步与 USB 联机时相关：运动规划任务被通信任务挤占 → [实时调度](./110-rtos-task.md)：给运动任务更高优先级、查截止期；
4. **别先动细分档**——细分治平滑，不治丢步，这就是"拿着锤子看什么都是钉子"。

**题 B**：云台 PID 调好 Kp 后低速小幅抖动，加大 D 又出现高频嘶嘶声。

1. 第一问：抖动落在**控制层**与**感知层**交界；
2. 低速抖 + D 有效 → 测速噪声被微分放大 → [编码器与测速](./70-encoder-speed.md)：低速下换 T 法或提高编码器分辨率；
3. 加 D 后高频嘶声 → 微分噪声直通驱动 → [PID 数字实现](./90-pid-discrete.md)：对微分项低通滤波，别硬加大 Kd；
4. 顺手核 [采样率](./100-control-timing.md)：增益推高后带宽逼近采样率的十分之一红线，就该提频率而不是继续堆增益。

**题 C**：产品实验室全绿，到客户车间偶发复位。

1. 第一问："现场才坏"落在**电源层 + 干扰层**——先别怀疑固件；
2. 第一刀切电源：车间电网电压跌落、长线电感放大动态电流需求 → [电源完整性](./140-decoupling-pdn.md)：加宽电压跌落监测记录，核对目标阻抗；
3. 第二刀切干扰：变频器/接触器的干扰经电缆耦合 → [EMC](./150-emc-design.md)：缩环、滤波、接地三味药按 dB 记账；
4. 最后回 [设计闭环](./160-design-closure.md)：**测试大纲缺了"车间工况"这一项**——指标分解时补上环境项，下次闭环才不重蹈覆辙。

## 5. 动手实验

### 实验 1（python）：给故障自动挂号

```python title="按症状开具科室单"
def triage(brownout, field_only, motor_stall, control_jitter):
    # 分诊优先级：复位级（丢数据/伤机）> 环境级 > 动力级 > 控制性能级
    if brownout:
        return "power-integrity（先记电压跌落，再核目标阻抗）"
    if field_only:
        return "emc-design（实验室好现场坏，先数干扰三要素）"
    if motor_stall:
        return "stepper / pwm（转矩曲线与加减速规划）"
    if control_jitter:
        return "control-timing（带宽与采样率红线）"
    return "mechatronics-intro（回到三环图）"

cases = [
    ("上电就复位", True, False, False, False),
    ("车间偶发复位", False, True, False, False),
    ("高速丢步，电机发烫", False, False, True, False),
    ("增益一高就振铃", False, False, False, True),
]
for note, a, b, c_, d_ in cases:    # 元组解包：一次领出整行
    print(triage(a, b, c_, d_), "|", note)
```

四行输出就是四张挂号单。**注意 if 台阶的顺序本身就是知识**：复位级排第一（会丢数据、会伤机），环境级第二（它同时伪装成一切软故障），然后才是动力与控制性能。**分诊永远先看会不会坏，再看跑得好不好。**

### 实验 2（python）：把量级钉在脑子里

```python title="机电与嵌入式工程师脑内的数量级"
print("── 控制环频率（Hz）─────")
for name, f in [("机械带宽", 10), ("位置环", 200), ("速度环", 1000), ("电流环", 20000)]:
    print("%-12s %8d" % (name, f))
print("── 电机电流（A）─────")
for name, i in [("信号调理 mA 级", 0.01), ("云台无刷", 3), ("桌面关节", 10), ("堵转瞬间", 50)]:
    print("%-12s %8.2f" % (name, i))
print("── 其他关键量 ─────────")
print("  PWM 频率 20 kHz（避开可听域）   死区 0.5~2 µs")
print("  采样率 ≥ 10× 带宽              目标阻抗 10~100 mΩ")
print("  CISPR 限值 40/47 dBµV/m        单味 EMC 药 8~20 dB")
```

三段输出是"工程直觉"的量化版本。**判断一个机电设计靠不靠谱，往往不需要精确计算，只需要量级对不对**：电流环想跑到 100 kHz 就撞采样墙；目标阻抗 1 Ω 在 A 级电流面前就是裸奔；EMC 超标 60 dB 意味着没有单味药能救。

### 章级实战挑战

下面这台"分诊台"的分支顺序被调乱了，导致"又复位又丢步"的机器被误挂到动力科。请把它扶正，使输出依次是 `power-integrity`、`stepper`、`control-timing`：

```exercise
# @title: 章级实战挑战：谁的科室单开错了
# @check: power-integrity
# @check: stepper
# @check: control-timing
# @hint: 复位级（丢数据、会伤机）永远排在动力级之前：把 brownout 这一分支提到 motor_stall 前面
def triage(brownout, motor_stall, control_jitter):
    if control_jitter:
        return "control-timing"
    if motor_stall:
        return "stepper"
    if brownout:
        return "power-integrity"
    return "mechatronics-intro"

print(triage(True, True, False))    # 偶发复位，同时高速丢步
print(triage(False, True, True))    # 电机发烫丢步，伴随振铃
print(triage(False, False, True))   # 只有增益一高就振铃
```

### 快问快答

```quiz
样机在实验室一切正常，一到车间就偶发复位。第一站应该翻哪张表、做什么？
- 通信总线：先把 UART 换成抗干扰的 CAN
- 电源完整性与 EMC：先在现场记录复现时刻的电压跌落与干扰源，再对照三要素开药 [*]
- 数字 PID：先把所有控制参数调保守
? 「现场才坏」几乎总是环境问题：电网跌落（电源层）或干扰耦合（干扰层）。第一步是记录工况而不是改代码——没有记录的复位只能瞎猜。总线换型是后面的可选项，调参数则是拿锤子找钉子。
```

:::warning[常见误区]

**误区一**：「固件先背锅。」
你以为偶发故障是软件 bug——机电系统的偶发问题，**电源与干扰占大头**：一次电压跌落、一串共模脉冲，症状与"指针越界"一模一样。分诊顺序里复位级与环境级排在最前，就是为了让硬件先于代码受审。

**误区二**：「控制器越强，问题越好解决。」
你以为换更快的 MCU 能治抖动——**先定瓶颈再动 BOM**：低速抖常常是测速分辨率（感知层）；振铃常常撞的是采样红线（控制层）；丢步常常是转矩规划（动力层）。三层各有一半药方不花一分钱，**"换芯片"是最贵的解法，通常也最没用**。

**误区三**：「方法地图是通关路线。」
它是按需查阅的工具书，不是进度条。真实项目只摘用其中几页，但**顺序不能乱**：指标先于方案（[闭环](./160-design-closure.md)）、量级先于精确、复位先于抖动、环境先于代码。**顺序错了，会越修越坏。**

:::

**练习 2**：把一台"桌面级两轴云台"从需求带到样机，给出八环节的 checklist。

<details>
<summary>点开查看逐步解答</summary>

1. **需求**：手持拍摄稳定，电池供电，成本敏感 → 提取"用户要的是画面稳"；
2. **指标分解**：扰动抑制（手持晃动 2 Hz 内抑制 20 dB）、阶跃响应 ≤ 150 ms、整机 ≤ 3 W、噪声 ≤ 25 dB；
3. **方案**：执行器选**无刷 + 编码器**而非步进（云台要低噪高速闭环，[BLDC](./40-bldc-commutation.md)）；IMU 做角度感知（[传感器调理](./80-sensor-conditioning.md)）；
4. **建模**：电机一阶模型 + 机械极点（[传递函数](./30-motor-model.md)），陀螺噪声谱进模型；
5. **仿真**：级联 PID 增益初值、验证采样率余量（[采样率](./100-control-timing.md) 10× 红线）；
6. **样机**：驱动级 [PWM 与死区](./60-pwm-hbridge.md)、按 [目标阻抗](./140-decoupling-pdn.md) 布去耦、电流环路走 [环路面积](./150-emc-design.md) 最短路径；
7. **测试**：转台正弦扰动测抑制比、温升、电池掉电曲线、跌落试验；**偏差清单**逐条记录；
8. **迭代**：实测发现 5 Hz 处残留扰动 → 回第 4 步发现陀螺安装谐振 → 加软垫改模态；**偏差清单从 7 条销到 0**，闭环健康。

**这道题的价值在"回环"**：第 8 步改的是"模型"而不是"增益"——增益治不了的，往往是模型里少了一个模态。

</details>

## 7. 选读：三条游览路线

<details>
<summary>选读 · 不同胃口的吃法</summary>

**动力链**（做执行器的读法）：概貌 → 直流电机 → 传递函数 → BLDC → 步进 → PWM 与 H 桥 → 编码器。这条线回答"力从哪来、到哪去"，终点是驱动与反馈——**机械的世界里，一切性能最终折算成转矩与带宽**。

**信息链**（做控制与固件的读法）：传感器调理 → PID 数字实现 → 采样率 → 实时调度 → 状态机 → 总线。这条线回答"数据怎么流、来得及吗"，终点是实时性与通信预算——**嵌入式工程的一半本事是"算清楚时间"**。

**落地链**（做产品的读法）：去耦 → EMC → 设计闭环。这条线回答"实验室与车间之间隔着什么"，终点是偏差清单清零——**它是三条线里唯一不教"怎么算"的，只教"怎么不返工"**。

三条线最后汇入同一句话：机电系统设计是在**相互矛盾的约束之间做取舍**——带宽与功耗、噪声与成本、实时与灵活、指标与工期。地图能帮你找到工具，**取舍只能靠你自己拍板**。

</details>
