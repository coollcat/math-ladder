# PID 的数字实现

## 1. 从一个场景开始

52 章你学会了连续 PID：$u = K_p e + K_i\int e\,dt + K_d \frac{de}{dt}$。它优美、完整——并且**在单片机上根本没法运行**。积分要连续累加，微分要取无穷小极限，而你的 MCU 每 20 毫秒才醒来一次：读一次编码器、算一次输出、继续睡。

把连续公式塞进离散世界，会撞上两个 52 章没遇到的新怪物：**积分饱和**（执行机构早就顶到限幅了，积分还在闷头涨）和**微分冲击**（设定值一跳变，微分项炸出一个尖峰，大到把输出瞬间顶穿）。

这一课的任务：把 PID 翻译成每拍执行一次的差分方程，并且驯服这两个怪物。

## 2. 直觉解释

连续 PID 像一条永不停的河，离散 PID 像每隔 20 毫秒拍一张照片再行动。

**积分 = 记账**。连续积分是每一瞬间都在记账；离散版本是每拍记一笔"误差 × 采样间隔"——就是用一个个细长矩形去铺曲线下的面积（14 章积分的定义本来就是矩形和的极限）。

**微分 = 相邻两拍的差**。连续微分是 $dt \to 0$ 的极限；离散版本只能拿 $e[k] - e[k-1]$ 除以 $T_s$——梯子只有两级，也得估出坡度。

**积分饱和 = 刹车失灵前的惯性**。目标从 0 跳到 1，电机爬得慢，误差一直是正的，积分一笔笔记下去——可 PWM 早就 100% 了，多记的账**一分钱都花不出去**。等输出终于追上目标，账本上还压着一堆"欠账"，PID 以为还得加把劲，结果冲过头。欠得越多，冲得越狠。

**抗饱和 = 花不出去就别记账**。既然输出已经顶到限幅、误差还在往同一方向推，这笔账记了也是白记——冻结它。等误差反向了再恢复记账，账本永远只记"花得出去的账"。

**微分冲击 = 拍照拍到了闪电**。设定值瞬间跳变，$e[k]-e[k-1]$ 是一整个跳变量除以小小的 $T_s$——坡度瞬间"无限大"。可这个尖峰是**你自己的指令**造成的，不是被控对象真动了。解决办法：微分不盯误差，盯**测量值**——测量值不会跳变，指令怎么跳都炸不出尖峰。

## 3. 正式定义

**位置式数字 PID**（后向矩形积分 + 后向差分微分）：

$$u[k] = K_p\,e[k] + K_i T_s \sum_{i=0}^{k} e[i] + K_d \frac{e[k] - e[k-1]}{T_s}$$

逐项对照连续版：积分 $\int e\,dt$ 变成矩形和 $T_s \sum e[i]$，微分 $\frac{de}{dt}$ 变成差分商。

**积分饱和**：执行机构存在限幅 $|u| \le u_{max}$ 时，实际输出

$$u_{real}[k] = \mathrm{clamp}(u[k], -u_{max}, u_{max})$$

若积分项照常累加，则 $I[k] = K_i T_s \sum e[i]$ 会累积到远超 $u_{max}$ 的值，反向退出需要时间——表现为大幅超调。

**条件积分抗饱和**（clamping）：只在"饱和且误差继续同向推"时冻结积分——

$$\text{若 } |u_{try}[k]| > u_{max} \text{ 且 } \mathrm{sign}(e[k]) = \mathrm{sign}(u_{try}[k]), \text{ 则 } I[k] = I[k-1]$$

**微分作用于测量值**（消除微分冲击）：

$$D[k] = -K_d \frac{y[k] - y[k-1]}{T_s} \quad \text{（代替 } +K_d \frac{e[k]-e[k-1]}{T_s}\text{）}$$

由 $e = r - y$，当设定值 $r$ 不变时两者完全等价；只有 $r$ 跳变的那一拍，前者平静、后者炸峰。

| 符号 | 名字 | 单位 | 含义 |
| --- | --- | --- | --- |
| $T_s$ | 控制周期 | 秒 s | 两次计算之间的间隔 |
| $e[k]$ | 第 $k$ 拍误差 | — | $r[k] - y[k]$ |
| $I[k]$ | 积分项 | — | $K_i T_s \sum_{i\le k} e[i]$，"账本" |
| $u_{max}$ | 执行机构限幅 | — | PWM 占空比/电压的物理上限 |
| $\mathrm{clamp}$ | 限幅函数 | — | 把值夹在 $[-u_{max}, u_{max}]$ 内 |

**增量式 PID**（工程变体）：不存账本全量，只算两拍之差 $\Delta u[k]$——天然免受部分饱和问题，但需要执行机构支持增量接口（步进电机、累积型 DAC）。

## 4. 分步例题

**例**：$K_p = 2$，$K_d = 0.2$，$T_s = 20$ ms，$u_{max} = 3$。设定值从 0 跳到 1，前一拍 $y = 0$、$e = 0$。比较微分作用于偏差与作用于测量值的第一拍输出（设 $y$ 尚未变化，$I = 0$）。

1. **第一拍误差**：$e[1] = 1 - 0 = 1$；
2. **比例项**：$P = K_p e = 2 \times 1 = 2$；
3. **微分作用于偏差**：$D = K_d \frac{e[1]-e[0]}{T_s} = 0.2 \times \frac{1-0}{0.02} = 10$；
4. **作用于测量值**：$D = -K_d \frac{y[1]-y[0]}{T_s} = -0.2\times\frac{0}{0.02} = 0$；
5. **限幅对比**：前者 $u = 2 + 0 + 10 = 12 \to$ 被夹到 3；后者 $u = 2 \to$ 原样输出。

同一拍，一个 12、一个 2——**差出来的 10 全是设定值自己跳变的镜像**，对被控对象毫无信息量。而它被限幅吃掉后还污染了后续：执行机构在 3 上顶了若干拍，等微分项回落，输出又剧烈回落——一串本不该有的抖动。

画面三层：上为设定值（虚线）与输出，中为控制量（红虚线是限幅带），下为 P/I/D 三项实时占比。两个分段开关分别控制**抗积分饱和**与**微分作用位置**。

按顺序做四件事：

- **默认状态（抗饱和关、微分作用偏差）**：看中图控制量顶在限幅带上——读数"积分项"一路涨到 2 以上，超调量一栏显示 15% 左右。这就是饱和：**账本欠账 2.08，执行机构只能付 1.2**；
- **打开抗积分饱和**：积分项峰值立刻被钉在 1.0 附近，超调几乎归零——账本只记花得出去的账；
- **把 Kd 从 0 拖到 1**（微分作用偏差）：设定值每次跳变，控制量上都出现一根冲破限幅带的尖刺；
- **切到"微分作用于测量值"**：尖刺消失，但注意下方的 D 条——它依然在干活，只是不再对指令跳变过度反应；
- **把 Ts 拖到 200 ms**：曲线明显变粗糙——离散化误差在放大，这是下一课的主题。

### 实验 2（python）：条件积分为什么这样写

```python
# 对象：一阶惯性 y' = (u - y)/τ（电机模型的简化版）
Kp, Ki, umax, tau = 3.0, 6.0, 1.2, 0.5
Ts, h = 0.05, 0.001              # 控制周期 50 ms，仿真步长 1 ms

def run(aw):
    # aw=True 开条件积分抗饱和，False 关
    y = 0.0; I = 0.0; u = 0.0; acc = 0.0; iPeak = 0.0; yPeak = 0.0
    for k in range(4000):              # 仿真 4 秒
        t = k * h
        acc += h
        if acc >= Ts:                  # 控制节拍到了才更新一次控制量
            acc -= Ts
            r = 0.0 if t < 0.1 else 1.0
            e = r - y
            P = Kp * e
            iTry = I + Ki * Ts * e     # 候选积分：先算出来但先不提交
            uTry = P + iTry
            sat = abs(uTry) > umax
            windup = sat and (e > 0) == (uTry > 0)
            if not (aw and windup):    # 条件积分：饱和且同向 → 冻结积分
                I = iTry
            u = max(-umax, min(umax, uTry))
        y += h * (u - y) / tau         # 对象在两次控制之间连续演化
        iPeak = max(iPeak, abs(I)); yPeak = max(yPeak, y)
    return (yPeak - 1) * 100, iPeak

for aw in (False, True):
    ov, ip = run(aw)
    print(("抗饱和 开:" if aw else "抗饱和 关:"), f"超调 {ov:5.1f}%   积分峰值 {ip:.2f}")
```

输出：`抗饱和 关: 超调  15.6%   积分峰值 2.08`、`抗饱和 开: 超调  -0.0%   积分峰值 1.00`。

注意条件积分的判据不是简单的"饱和就冻结"：**还得要求误差方向与输出方向一致**。如果输出顶在正限幅、误差已经反向（超调了），这时冻结积分反而错——需要积分往下走把输出拉回来。`windup` 那一行的 `(e > 0) == (uTry > 0)` 干的就是这件事。

### 快问快答

```quiz
系统已超调、误差变负，但输出仍顶在正限幅上。这时条件积分抗饱和应该怎么处理积分项？
- 继续冻结积分，只要饱和就一律不记账
- 允许积分继续累加，因为误差方向与输出方向相反 [*]
- 把积分项直接清零，从头再来
? 判据是「饱和且同向」才冻结。误差为负时记账会让积分下降、把输出从正限幅上拉下来——这正是我们想要的。一律冻结会让系统在限幅上多卡很多拍。
```

:::warning[常见误区]

**误区一**："数字 PID 就是把连续公式抄进代码，除以 Ts 就行。"
你以为只是换个写法——其实离散化是**近似**：矩形和逼近积分、差分商逼近微分，$T_s$ 越大近似越差；更深的坑在于采样与保持给回路引入了额外相位滞后，增益上限被压低（下一课专门算这笔账）。"抄进去能动"和"抄进去稳定"之间隔着采样周期的选择。

**误区二**："微分冲击是干扰，把 Kd 设成 0 最省心。"
你只看到尖峰难看——其实冲击的根源是**微分作用在了会跳变的信号上**，不是微分本身有罪。切到"微分作用于测量值"后，微分照样提供阻尼、抑制超调，而指令跳变时纹丝不动。一棒子打死 Kd 等于扔掉了相位超前这一最值钱的补偿手段。

**误区三**："抗饱和就是把积分钳位在 ±limit。"
你以为给 I 加个上下限就万事大吉——其实钳位值怎么选是个新难题：钳小了还没饱和就冻结（欠账不够用，稳态误差消不掉），钳大了照样饱和。条件积分不需要这个魔数参数，它让"该不该记"由系统当前状态自己决定——工程上更常用也更稳健。

:::

**练习 1**：误差恒为 0.5、$K_i = 2$、$T_s = 0.01$，累计 50 拍后积分项是多少？代码忘了乘 $T_s$，修到输出 `0.5`：

```exercise

# @check: 0.5
# @hint: 每拍记账额是 Ki × Ts × e，不是 Ki × e。矩形的高是 e，宽是 Ts——宽不乘上去，面积就错了 100 倍
Ki = 2.0
Ts = 0.01
e = 0.5
I = 0.0
for k in range(50):
    I += Ki * e        # ← 问题在这：记账忘了乘采样间隔 Ts
print(round(I, 2))
```

**练习 2**：为什么增量式 PID（只算 $\Delta u[k]$）对积分饱和天然更不敏感？

<details>
<summary>点开查看解答</summary>

1. 位置式的 $I[k]$ 是**全量账本**，饱和期间每拍都在往上垒，欠账可以任意深；
2. 增量式算的是 $\Delta u[k] = u[k] - u[k-1]$，其中积分贡献是 $K_i T_s e[k]$——**每一拍独立**，不存在累积的账本；
3. 执行机构（或输出累加器）自己带着限幅：饱和时输出顶住，新的增量自动无效，没有"深欠账"可退。

代价：$u[k] = \sum \Delta u[i]$ 这个累加挪到了执行机构侧，若执行机构不提供累积接口，就得在软件里自己维护一个同样会饱和的累加器——问题没有消失，只是换了地方。**任何声称"彻底消灭"饱和问题的方案都值得警惕**，工程只能搬移和约束矛盾。

</details>

## 7. 选读：抗饱和方案小史

<details>
<summary>选读 · clamping、反算反饱和与观测器法</summary>

条件积分（clamping）只是抗饱和家族里最简单的一员：

**反算反饱和（back-calculation）**：把"限幅后的真实输出"与"PID 想要的输出"之差按增益 $1/T_t$ 反馈回积分器：

$$I[k+1] = I[k] + K_i T_s e[k] + \frac{T_s}{T_t}\left(u_{real}[k] - u[k]\right)$$

饱和期间 $u_{real} < u$，反算项持续把 I 往回拉，像给账本装了个泄压阀。$T_t$ 是"追踪时间常数"，越小退出饱和越快，太小则积分项抖动。它比 clamping 平滑（没有冻结/解冻的切换），是工业 PID（如 PID 算法库）里的主流。

**观测器法**：把执行机构限幅建成对象模型的一部分，用状态观测器估计"如果没饱和输出会是多少"——理论最优雅，实现最重，一般只在高性能伺服里出现。

选择的经验法则：**温度这类慢对象用 clamping 足够**（切换毛刺无关痛痒）；**电机电流环这类快对象用反算**（切换不平滑会激起机械谐振）。

</details>
