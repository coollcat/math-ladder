# 蒙特卡洛树搜索与证明策略

## 1. 从一个场景开始

第 30 课把证明搜索画成了一棵树，并预告了老练探险者的两难：既想走进业绩好的岔口（利用），又不愿错过没踩过的野路（探索）。那一课停在公式层面；本课把镜头拉到引擎室内部——一套叫蒙特卡洛树搜索（MCTS）的循环机器，靠**四本实时更新的账本**导航：它不问"哪条路看着对"，只问"哪条路的账最值得继续记"。规则驱动的证明器背的是法典（第 30 课），这台机器背的是流水账。

## 2. 直觉解释

想象路口立着四本公示账：

- **选择账**：站在当前路口，给每个备选岔口算一个综合分——战绩越好分越高，被冷落越久补贴越多（第 30 课的置信上界思路）；
- **扩展账**：选中一个还没登记过的岔口，新开一页档案；
- **模拟账**：从新岔口随便走到黑，把这一趟的收获（赢了/输了/离目标多近）记在这页档案上；
- **回传账**：这一趟的收获沿着来路**逐级汇入所有祖先**的账本——祖先们的平均战绩因此被改写。

循环往复。魔力全在第四本：一个岔口今天运气好，账会连累它祖上三代一起好看；明天连续失败，整个家族的信用同步缩水。**局部的一次采样，全局的一份记性**——这就是反哺。

## 3. 正式定义

每轮迭代固定四拍：

$$\text{选择（置信上界准则）} \to \text{扩展（登记新节点）} \to \text{模拟（rollout 估值）} \to \text{回传（祖先累加）}$$

| 账本 | 每节点维护的字段 | 回传时的动作 |
| --- | --- | --- |
| 访问数 $n$ | 该节点被路径经过的次数 | 沿途 +1 |
| 回报和 $Q$ | 历次模拟收益的总和 | 沿途加上本次收益 |
| 平均价值 $Q/n$ | 经验战绩 | 重新计算，供下一轮选择使用 |

第 30 课给出的 UCT 选择公式（经验价值加探索奖励）在这里照常生效；本课强调三条当时没展开的纪律。其一，探索系数不能压成零——否则机器会从第二轮起死咬偶然走运的岔口，这正是第 50 章 bandit 语言里 regret 讨论的另一种说法。其二，模拟不必是随机乱走：可以是快速近似、价值网络打分，或（定理证明场景）符号引擎的可达性抽查——只要它给得出一个数。其三，账本只是**搜索的地图**：估值有偏的模拟会把地图画歪，机器随之真心实意地走向错误的富矿。

## 4. 分步例题

三岔口玩具：各岔口背后藏着未知的"真实得分"（机器不知道），模拟一次就抽取一份该岔口的预录样本。跟着四本账走三轮：

1. **第 1 轮**：三岔口全是白纸，选择账无账可查——按登记顺序扩展 1 号；模拟抽到 0.30，回传后 1 号档案：访问 1、均值 0.30；
2. **第 2 轮**：2 号仍是白纸，探索补贴压倒一切——扩展 2 号；模拟抽到 0.90；此刻 1、2 号账面 0.30 对 0.90；
3. **第 3 轮**：3 号补登记，抽到 0.55。三页档案齐了，游戏进入正循环；
4. **第 4 轮起**：选择账开始认真比较 UCT 分——2 号高均值虽然诱人，但 1、3 号的"低访问补贴"仍在挣扎；访问次数逐步分化的过程，就是探索退潮、利用涨潮的过程；
5. 十二轮后结算：2 号以压倒性访问次数和最高均值当选——**它从未被告知自己真实得分最高，是账本把它推上去的**。

## 5. 动手实验

### 热身：模拟估计会忘掉第一次的好运

设某岔口真实平均得分为 $a$，第一次模拟走了大运抽到 $c$，之后每次都如实抽到 $a$。账面均值 $(c + a \cdot (x-1))/x$ 随访问次数 $x$ 的演化：

```viz

  "expr": "(c + a*(x - 1))/x",

    { "name": "c", "min": 0, "max": 1, "step": 0.05, "value": 0.95 }

}
```

曲线从 0.95 一路滑回 0.35：回传账本的"逐级稀释"天性替机器过滤了单次运气。反过来看，若后继样本有系统性偏差，曲线会稳定停在一个**错的**水平上——账本只忠于喂进来的样本。

### 实验 1：完整跑一遍四拍循环

```python title="微缩 MCTS：三岔口、预录模拟样本、十二轮记账"
import math

BOOK = [                                  # 预录样本代替随机模拟：每臂一串"抽签结果"
    [0.30, 0.40, 0.35, 0.25, 0.45, 0.30, 0.35, 0.40],
    [0.90, 0.80, 0.85, 0.75, 0.90, 0.85, 0.80, 0.85],
    [0.55, 0.60, 0.50, 0.65, 0.60, 0.55, 0.50, 0.60],
]
C_EXPLOR = 1.0                            # 探索系数：第 30 课公式里的 c
ROUNDS = 12

visits = [0, 0, 0]                        # 选择账与回传账共用的访问计数
rewards_sum = [0.0, 0.0, 0.0]             # 回报和

def select_arm(total):
    untried = [i for i in range(3) if visits[i] == 0]
    if untried:
        return untried[0]                 # 白纸岔口优先扩展
    best_i = 0
    best_v = -1.0
    for i in range(3):
        mean = rewards_sum[i] / visits[i]
        bonus = C_EXPLOR * math.sqrt(math.log(total) / visits[i])   # sqrt/log：开方与自然对数
        val = mean + bonus
        if val > best_v:
            best_v = val
            best_i = i
    return best_i

for t in range(1, ROUNDS + 1):
    arm = select_arm(t)                   # 第 1 拍：选择
    gain = BOOK[arm][visits[arm]]         # 第 2、3 拍：扩展并模拟（抽一份预录样本）
    visits[arm] += 1                      # 第 4 拍：回传——单层树时祖先就是它自己
    rewards_sum[arm] += gain
    if t % 3 == 0:                        # 每三轮公示一次账面
        means = [round(rewards_sum[i] / visits[i], 2) for i in range(3)]
        print("第%d轮后 访问 %s 均值 %s" % (t, visits, means))

final_best = 0
final_top = -1.0
for i in range(3):
    m = rewards_sum[i] / visits[i]
    if m > final_top:
        final_top = m
        final_best = i
print("最终推荐岔口:", final_best)
print("其平均回报:", round(final_top, 2))
print("访问分布:", visits)
```

对照分步例题逐行核对账目：三轮白纸扩展、之后 UCT 分化，12 轮时 2 号以 7 次访问胜出。真实系统里这棵树会长到几十万层，账本字段一模一样。

### 实验 2：修好一本被写歪的回传账

结账时有人拿**总轮数**当每个岔口自己的访问次数来算平均——样本少的岔口被无中生有地稀释。修复标记行，让回传账按真实访问数记账。

```exercise
# @title: 练习：把回传账本记对
# @check: 回传后推荐: 岔口A
# @check: 账面均值: 0.9
# @hint: 平均数=回报和除以该岔口自己的访问次数；总轮数里还有别的岔口分走的份额，掺进来只会冤枉勤奋者。
LEDGER = {
    "岔口A": [0.9],                 # 只被访问过 1 次，但那次收获惊人
    "岔口B": [0.8, 0.7, 0.8, 0.7],  # 访问 4 次，稳定中等
    "岔口C": [0.1, 0.2],            # 访问 2 次，表现不佳
}
TOTAL_ROUNDS = 7

winner = None
top = -1.0
for name, gains in LEDGER.items():    # items：同时取键和值成对遍历
    score = sum(gains) / TOTAL_ROUNDS # ← 问题在这：分母被偷换成了总轮数
    if score > top:
        top = score
        winner = name

print("回传后推荐:", winner)
print("账面均值:", round(top, 2))
```

修正前岔口B冤枉地登顶（它只是出现得勤）；改对分母后，账本把诚实的一票投回给岔口A。千万别小看这一行：MCTS 的全部方向感都建立在"平均数除对分母"这类朴素纪律上。

```quiz

- 变得无法预测，取决于随机种子

```

## 常见误区

:::warning[常见误区]

**误区一**："模拟随便跑跑就行，反正是随机的。"
rollout 是有成本的估值器：太浅则噪声淹没信号（热身曲线迟迟不回落），太偏则账本集体失真。现代系统普遍用神经网络替代纯随机模拟，理由正是方差。

**误区二**："访问次数最多的节点就是最优解。"
账本偏好"被反复抽中的"，而反复抽中依赖探索设置与估值的合谋。工程上常对根节点做最终决策时另算一笔：用平均价值而不是访问计数来拍板。

**误区三**："MCTS 收敛于最优，所以放任跑就行。"
收敛是有条件的：奖励有界、所有动作被无限次访问。实践预算有限，条件形同虚设——这正是第 50 章 regret 视角的价值：承认次优，量化离最优多远。

:::

## 6. 练习

**练习 1**：手工记账：接续分步例题的第 4 轮。此时各账访问为 1,1,1、均值为 0.30,0.90,0.55，探索系数 c=1。算三个岔口的 UCT 分并判断第 4 轮扩展谁。

<details>
<summary>点开查看逐步解答</summary>

父访问 N=3，ln 3 约 1.10，三项补贴同根号相同约 1.05。粗算：1 号 0.30+1.05=1.35，2 号 0.90+1.05=1.95，3 号 0.55+1.05=1.60——补贴同额时均值说了算，第 4 轮模拟 2 号。**同父节点下白纸优先**；不同父节点间的比较才轮到访问悬殊带来的补贴差。
</details>

**练习 2**：把实验 1 的 C_EXPLOR 改成 0 跑一次，再改成 5 跑一次，观察访问分布如何极端化，并用一句话总结 c 的角色。

<details>
<summary>点开查看逐步解答</summary>

c=0 时除首轮外永远押当前均值冠军，其余岔口访问数冻结在 1；c=5 时补贴碾压均值，机器近乎轮流撒网、迟迟不定重心。c 是两个声部之间的音量旋钮：拧太小是赌徒，拧太大是观光客。
</details>

**练习 3**：概念辨析：把本课四拍循环与第 30 课 AlphaGeometry 的"引擎演绎 + 模型点辅助线"对齐，哪些环节一一对应、哪些不对应？

<details>
<summary>点开查看逐步解答</summary>

对应：符号引擎演绎≈确定性"模拟+扩展"（它不猜，直接推）；模型提议构造≈按打分选择岔口。不对应：AlphaGeometry 不做概率 rollout，也无需回传均值——其"账"由符号状态代替。MCTS 是骨架的抽象名，真实系统允许把四拍中的任意一拍换成确定性部件。
</details>

## 7. 选读：当模拟被网络替换之后

<details>
<summary>选读 · 从 AlphaZero 到证明树</summary>

AlphaZero 的关键一步是干脆拆掉随机 rollout：一个价值网络直接读盘面输出胜率估计，四拍循环的第三拍从此变成一次前向计算。省下的算力被折进更深的树，棋力跃升在围棋上已无须辩护。搬到定理证明（如 AlphaProof 在 Lean 内核上训练）时，价值网络学的是"这个证明状态离完工还有多远"——没有胜负盘面可数，训练信号来自最终是否证毕的稀疏结果，于是过程奖励模型（上一课选读）成了配套必需件。四本账的框架原样保留，只是每一本的"记账员"都换成了可学习的零件。
</details>
