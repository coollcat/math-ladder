# LLM 的数学推理与幻觉边界

## 1. 从一个场景开始

让语言模型做大学习题册上的证明题，它写出漂亮的排版、"由著名的格林辅助定理立得"——去翻教材，第 7.3 节根本不存在。这不是程序故障，而是它天生工作机制的一次如实表演：**每一个字都是"下一个词的概率预测"挑出来的**。概率挑词在写小说时无伤大雅，在写数学时却会即兴发明引理。

本课不诉诸神秘主义，把三件事讲透：编造为什么必然发生；"易验证难寻找"如何反转了这个行业的机会成本；以及温度采样与多数投票这些 prompt 技巧，剥开包装后到底是什么。

## 2. 直觉解释

把自回归生成想成**接成语**：模型看过海量文本，"因此……由著名的______"这个空格填什么的概率分布，完全来自语料统计。两条推论立刻出现：

- **填最常见的**：语料里"由著名的定理"这类模板俯拾皆是，所以模型倾向编一个听起来最"著名"的名字。它不是在撒谎——撒谎需要知道真相再说假话，而它压根没查证机制；
- **流畅度与真实度无关**：一句话通顺到无可挑剔，恰恰说明它踩着高频模板走——模板是统计性的，真理不是。

于是生成了大量廉价的话，谁来把关？这里出现了本章最重要的经济学事实：**生成一句像证明的话便宜，验证它是真证明昂贵**（自然语言层面几乎无法机械化）；可是这个不对称可以被形式化检查器反转成它的反面——**机器验一步只要一瞬间，机器寻出这一步却举步维艰**。前者叫人提防大模型的嘴，后者给整条 AI for Math 流水线发了营业执照。

## 3. 正式定义

设单个候选答案答对的概率为 $p$，采样 $n$ 个互相独立的候选：

| 机制 | 数学骨架 | 说明 |
| --- | --- | --- |
| 温度采样 | 温度参数改软最大化的锐度 | 调高=更敢冒险，调低=更认死理 |
| best-of-n 配验证器 | $1-(1-p)^n$ | 有可靠判卷员时，抽签越多越好 |
| 自洽性多数投票 | 二项分布尾概率 $\Pr(\text{过半})=\sum \binom{n}{k}p^k(1-p)^{n-k}$ | 无需外部判卷员，拿数量换可靠度 |

三条骨架全是概率运算——它们改变的是"命中率的期望"，从不改变模型的内在能力上限；一个 p 小于半数的系统投再多票也是稳定的错误多数。这就是为什么投票只能当放大器，不能当家。

## 4. 分步例题

拆解那句虚构引用是怎么被"合理地"说出来的：

1. 上文已写到"由著名的"：此处的条件概率表给了诸如《格林辅助定理》46%、单调收敛原理 32%、柯西不等式 22% 一类的候选权重；
2. 温度偏高或默认贪心都会选中最高的那项——《格林辅助定理》胜出；
3. 关键盲区：这三个名字都有"定理气质"，但对模型而言**彼此可互换**，因为打分依据是共现频率而非语义真值；
4. 下一步接着为假引理续写正文，新的概率表照样平稳运转——雪球滚下山；
5. 复盘：全链每一步都严格执行了下一词预测，**机制没有失灵；失灵的是"机制里没有真值按钮"这件事本身**。

## 5. 动手实验

### 实验 1：亲手当一回"下一词发生器"

```python title="玩具版下一词链条：贪心挑最大权重"
NEXT_TOK = {
    "因此": [("由著名的", 40), ("由刚才的", 35), ("由显而易见的", 25)],
    "由著名的": [("格林辅助定理", 46), ("单调收敛原理", 32), ("柯西不等式", 22)],
}

def greedy_chain(start):
    words = [start]                    # 词序列从起点开始生长
    node = start
    guard = 0                          # guard 计数封顶，防止失控循环
    while guard < 10 and node in NEXT_TOK:
        best = NEXT_TOK[node][0]
        for cand in NEXT_TOK[node]:    # 扫一遍候选取最大者
            if cand[1] > best[1]:
                best = cand
        node = best[0]
        words.append(node)
        guard += 1
    return words

chain = greedy_chain("因此")
print(" ".join(chain))
print("这句话中的引理可在原书检索到的页码数: 0")
```

输出连起来读毫无破绽——贪心的每一步都选了最可能的词，得到的却是一句彻头彻尾的编造。语言模型每天做的正是这件事的放大版。

### 实验 2：修好一台偏听的计票器

下面的小实验用固定种子的伪随机数模拟"每个候选独立以 p=0.55 的概率答对"。当前代码的表决环节犯懒：直接抄了第一个候选的答案当整体结果。把标记行改成真正的多数表决逻辑后重跑。

```exercise
# @title: 练习：让多数投票名副其实
# @check: 0.568
# @check: 0.626
# @hint: 过半判定怎么写都不必讨论奇偶边缘：True 计数为 1，两倍以后与总数比大小即可绕开平票。
seed = 7                       # 固定随机种子：任何机器上都产出同一串"随机"数

def lcg():
    global seed                # global：函数内要改写模块级变量时的声明
    seed = (seed * 48271) % 2147483647   # 线性同余：乘、加、取模三步造均匀散布
    return seed / 2147483647

P_CORRECT = 0.55
N_CAND = 9                     # 每题采样的候选个数
TRIALS = 3000                  # 实验重复次数

solo_hits = 0                  # 单听一号候选的命中计数
maj_hits = 0                   # 表决机制的命中计数
for _ in range(TRIALS):
    votes = []
    for _ in range(N_CAND):
        votes.append(lcg() < P_CORRECT)   # True/False 即该候选是否答对
    if votes[0]:
        solo_hits += 1
    chosen = votes[0]          # ← 问题在这：把整场投票偷换成了一号发言人
    if chosen:
        maj_hits += 1

print(round(solo_hits / TRIALS, 3))
print(round(maj_hits / TRIALS, 3))
```

修改只允许动那一行：把 `votes[0]` 换成表达式 `sum(votes) * 2 > N_CAND`。修好后第二行从 0.568 抬升到 0.626——九个不太准的评委过半表决，确实压过了一位评委独断；也别忘了反面教材：若把 P_CORRECT 调到 0.45 再跑，投票反而比单听更稳地错下去。

```quiz
关于自洽性多数投票，下列哪句话是对的？
- 它能让模型突然学会训练数据里没有的知识
- 它不提升单次能力上限，只是用多次采样把"多数派碰巧一致的那个答案"淘出来 [*]
- 只要投票人数足够多，错误答案的概率严格归零
? 二项尾概率只会逼近而不触及零，且基线 p 决定一切走向。投票是诚实的平均器：好答案占优时锦上添花，坏答案占优时将错就错。
```

## 常见误区

:::warning[常见误区]

**误区一**："把温度调到零就不会再幻觉了。"
低温只是掐灭了**随机性引入**的多样编法，锁定成"每次都说同一种最可能的话"；如果那份最可能的话本身就是编的，它会以一种极其自信的姿态反复出现。确定性 ≠ 正确性。

**误区二**："它说'显然'就是有把握。"
语气词与标点同样出自统计习惯。校准研究反复提醒：表述的笃定程度与实际正确率并不挂钩（第 54 章过自信话题在此原样适用）。读模型输出请摘掉语气滤镜。

**误区三**："思维链越长越可靠。"
推理链是延续上文的长文：开头的任意一处轻微偏差会被后续每一步"顺理成章"地继承并放大。长链提高的是**解决难题的上限**，同时抬高了中途翻车的跨度——长度买复杂度，也买脆弱性。

:::

**练习 1**：手算：p=0.4 时采 3 个候选做过半表决，列出全部三元组情形并计算表决成功率，说明结论与直觉相反在哪里。

<details>
<summary>点开查看逐步解答</summary>

成功情形是至少两人答对：恰两人（三种组合各 $0.4^2\times0.6$）加三人全对（$0.4^3$），合计约 0.352——**低于单发 0.4**。基线不过半时，合议把噪声也一并放大了。
</details>

**练习 2**：映射练习：把少样本示例、要求分步写出、投票三次取公共项这三种常见做法，逐一翻译成搜索术语（引导初始分布、展开深度、重启多样性）。写不出对应关系的那条，多半是你还没理解它。

<details>
<summary>点开查看逐步解答</summary>

少样本=改写起点概率分布，令后续步继承好范式；分步书写=显式展开中间状态供检视（也让中途错误可见）；重复采样=扩大样本容量换取投票的信噪比。三者没有一条触碰真值层——共同短板仍是缺少第 2 步之后的裁判。
</details>

<details>

## 7. 选读：结局奖励与过程奖励的分野

<details>
<summary>选读 · 给推理链打分的两种姿势</summary>

只用最终答案判分（outcome reward model）省钱但含糊：结果对了看不出推导纯属侥幸还是步步扎实，结果错了也无法定位坍塌在哪一步。逐过程打分（process reward model）能给每个中间步骤标注可疑点，代价是需要人类逐步标注的高质量监督数据——这在数学内容上是真金白银的开销。近年主流系统的组合拳正是本章结构的工程化：LLM 海量产出（便宜的运气）、形式化内核逐步核销（昂贵的确信）、奖励信号回流精调生成器。链条每一环都站在前面几课的地基上。
</details>
