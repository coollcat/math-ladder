# LLM Agent：会调用工具的推理循环

## 1. 从一个场景开始

问语言模型"3.7 的平方根乘以 891 等于多少"，它可能答对，也可能答得一本正经却差了两位小数——第 70 课说过，它在"最像答案的地方下注"，算术不是它的强项。可你口袋里的计算器百算百准。**Agent**（智能体）的想法就一步：**别让模型硬算，让它开口"用工具"**——模型负责想，计算器、搜索引擎、代码解释器负责算，答完再把工具的结果喂回去继续想。

## 2. 直觉解释

把第 80 课的 MCTS 语言搬过来：MCTS 是"搜索树 + 模拟器 + 统计回传"，Agent 是"思考循环 + 工具 + 观察回喂"。它的工作节拍叫 **ReAct**（Reason + Act），一圈三拍：

1. **想**（Thought）：看当前局面，决定下一步缺什么——"我需要先算 3.7 的平方根"；
2. **动**（Action）：发出一次结构化的工具调用——`sqrt(3.7)`；
3. **看**（Observation）：工具的真实结果被**拼回上下文**，成为下一拍的已知条件。

这个"观察喂回"是全课的灵魂：工具结果不是拿来展示的，是**进入下一轮推理的输入**。一圈一圈滚下去，直到模型认为"够了"，才给出最终答案。表面上模型还是会写"答案是 57.2"，但这次它的每一步都踩在工具返回的实数上——**推理的骨架是语言的，地基是计算器的。**

## 3. 正式定义

一轮 Agent 循环的形式化：模型是策略 $\pi$，历史 $h_t = (q,\ a_1,\ o_1,\ \dots,\ a_{t-1},\ o_{t-1})$（问题、历次动作与观察），每一拍：

$$\text{Thought/Action: } a_t \sim \pi(\cdot \mid h_t) \qquad \text{Observation: } o_t = \mathrm{Tool}(a_t) \qquad h_{t+1} = h_t \oplus (a_t, o_t)$$

| 符号 | 名字 | 含义 |
| --- | --- | --- |
| $q$ | 任务 | 用户交给 Agent 的问题 |
| $a_t$ | 动作 | 结构化的工具调用（工具名 + 参数） |
| $\mathrm{Tool}$ | 工具 | 计算器、检索、代码执行……**确定性**的外部函数 |
| $o_t$ | 观察 | 工具返回的真实结果 |
| $\oplus$ | 拼接 | 观察进入历史，供下一拍条件化 |

与第 80 课对照着读：MCTS 的"模拟器"回答"这步棋之后局面如何"，Agent 的"工具"回答"这个算式等于几"——**都是用可靠的评估器替换不可靠的想象**；区别只在 MCTS 回传的是统计值，Agent 回喂的是文字观察。

## 4. 分步例题

任务：算 $\sqrt{3.7} \times 891$（保留一位小数）。模型只会调两个工具：`sqrt(x)` 与 `mul(x, y)`。

1. **想**："先算平方根，再乘 891。" **动**：`sqrt(3.7)`；
2. **看**：工具返回 `1.9235`——这一拍起，1.9235 是**已知事实**，不再靠模型猜；
3. **想**："乘上去。" **动**：`mul(1.9235, 891)`；
4. **看**：`1713.8385`；
5. **想**："够了。" **答**：约 1713.8。

对照第 70 课：同一个模型裸答这道题，是在成千上万道算术题的统计影子里"押"一个最像的数；Agent 模式下它只做两件可靠的事——**拆步骤**与**读观察**，所有算术都外包给了不会幻觉的工具。分工的本质：把"知识的不可靠"换成"过程的可核查"。

## 5. 动手实验

### 实验（python）：亲手滚一个 ReAct 小循环

```python title="玩具 Agent：想一步、调一次工具、把观察喂回去"
import math

def tool_square(x):                     # 工具一：平方
    return x * x

def tool_halve(x):                      # 工具二：减半
    return x / 2

TOOLS = {"square": tool_square, "halve": tool_halve}

question = "把 3 连续平方再减半，重复两轮，最后是多少？"   # 任务
x = 3.0                                 # 当前已知量（观察的起点）
plan = [("square", None), ("halve", None), ("square", None), ("halve", None)]

print("任务：", question)
for step, (name, _) in enumerate(plan):             # ReAct 循环：想→动→看
    # 想：决定这拍调用什么（玩具版计划已列好；真 Agent 由模型生成）
    # 动：发起工具调用
    obs = TOOLS[name](x)
    # 看：观察喂回，成为下一拍的已知量——灵魂在这一行
    x = obs
    print("拍", step + 1, " 调用", name, " 观察 =", round(obs, 4))

print("最终答案 =", round(x, 4))
```

怎么玩：四拍滚完，答案 10.125（$3 \to 9 \to 4.5 \to 20.25 \to 10.125$）。注意循环里那句 `x = obs`——**观察不喂回，循环就是空转**：把这一行删掉、改成一直用初始 3 去调工具，四拍全输出 9 和 4.5 的复读机。真 Agent 的差别只在"想"那一拍由模型现场生成（计划随观察随机应变），"动"与"看"的机械结构一模一样。

```quiz
Agent 循环里"观察喂回上下文"这一步是在模仿什么？
- 把工具结果存档备查
- 让下一步推理以真实的工具结果为已知条件，而不是继续靠模型记忆瞎猜 [*]
- 给工具调用打分排名
? 观察喂回后，模型的每一拍都条件化在"确定的事实"上——这正是它区别于纯生成的地方：地基换成了工具返回的实数。
```

::::warning[常见误区]

**误区一**："你以为工具能根治幻觉。" 工具只保证**它负责的那段**是对的（算术、检索）；拆解步骤、解读观察、决定何时收工仍是模型在做——第 70 课的押注惯性一个不少。检索型工具还会带来新麻烦：查到的资料错了，Agent 会错误得更自信（RAG 课的误区在这里重演）。

**误区二**："你以为 Agent 会无限聪明地试下去。" 每一拍都花真金白银的算力，循环失控（反复调同一个工具、原地打转）是常态——工程上必须有**预算与止损**：最多几拍、重复调用检测、失败即上报，而不是指望模型自己想明白。

**误区三**："你以为'会调工具'等于'会用对工具'。" 参数填错（把 891 填给了平方）、工具选错（该检索却硬算）都常见——工具接口的描述写得越清楚（名字、参数、返回什么），模型用对的概率越高。给 Agent 造工具，一半功夫在写说明书。

::::

## 6. 练习

```exercise
# @title: 练习：把观察喂回循环
# @check: 6
# @check: 12
# @check: 10
# @hint: 第二次工具调用必须用第一次的观察当输入——"观察喂回"就是让上一拍的结果变成这一拍的已知量。
def double(x):                  # 工具：翻倍
    return 2 * x

x = 3                           # 初始已知量（整数，保证判题输出与期望逐字一致）

o1 = double(x)                  # 第一拍：调用工具
print(o1)
o2 = double(x)                  # ← 问题在这：又用了旧的 x，观察没喂回
print(o2)
final = o2 - 2                  # 收尾：最后一次加工
print(final)
```

<details>
<summary>点开查看逐步解答</summary>

第二拍要喂回第一拍的观察：

```python
o1 = double(x)                  # 3 → 6
o2 = double(o1)                 # 6 → 12：上一拍的观察是这一拍的输入
final = o2 - 2                  # 12 → 10
```

修正后输出 `6 / 12 / 10`。初始代码第二拍还在用初始的 `x = 3`，翻出来仍是 6——两拍之间没有接力，循环退化成复读机。真 Agent 的循环里，"观察进入历史"正是靠这种接力实现：上一拍的工具结果，就是下一拍推理的已知条件。这一行写错，Agent 立刻变哑巴。
</details>

**练习 2**：MCTS（第 80 课）与 ReAct Agent 的循环里，各有一个"替代想象"的可靠部件。分别指出它们，并说明一句"为什么可靠"。

<details>
<summary>点开查看逐步解答</summary>

MCTS 的可靠部件是**模拟器/评估器**：局面价值由真实规则推演或训练有素的网络估值，不靠即兴发挥；Agent 的可靠部件是**工具**：计算器与代码解释器执行的是确定性程序，同样输入永远同样输出。两者的设计哲学同源——**模型负责"往哪走"（生成假设），可靠部件负责"对不对"（评估事实）**；也都要靠回传/回喂把评估结果并入下一步决策。区别在于：MCTS 回传统计量做全局搜索，Agent 回喂文字观察做局部接力。
</details>

## 7. 选读：规划、反思与多 Agent

单圈 ReAct 之上还有两层的加法。**规划先行**：开工前让模型先列全步骤清单（Plan-and-Solve），循环只负责逐项执行与补救——减少"走一步看一步"的拍数；**反思**：任务卡住或失败时，把失败轨迹喂回模型，让它自我点评"哪一拍选错了工具"，带着教训重试（Reflexion 一类）。再往外一步是**多 Agent**：把"出题的"与"审题的"分给两个会话互相挑刺——本站内容生产流水线里的对抗审核，正是同一个思想：单模型的自信不可信，可核查的流程才可信。而所有这些结构的尽头有个现实的刹车：拍数越多、工具越多，错误传播的链条越长——Agent 工程的真正手艺，不是让循环更狂野，而是让每一步都可验证、可回滚。
