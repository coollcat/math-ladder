# 数学阶梯 · 宣传片（两支）

两支片子都是**自包含的 HTML 文件**：画面全部由 WebGL / Canvas 现场算出来，配乐全部由 Web Audio 现场合成。
**没有一张图片、没有一帧视频、没有一段采样音频、没有任何外部依赖** —— 离线双击就能播。

| | 快闪版 | 完整版 |
| --- | --- | --- |
| 入口 | [`short/index.html`](./short/index.html) · 站点 URL `/promo/short/` | [`full/index.html`](./full/index.html) · 站点 URL `/promo/full/` |
| 片长 | **45.6 秒** · 13 镜 | **2 分 47 秒**（167 秒）· 12 幕 |
| 结构 | 骨架是**音乐网格**：140 BPM · 26 小节，每一刀切在小节线上 | 骨架是**秒**：每幕一个连续长镜头 |
| 节奏 | 四四拍电子：底鼓 / 拍手 / 开镲 / Sub 贝斯 / 16 分琶音 / 冲击音 | 84 → 126 BPM 渐强，Am–F–C–G 变奏 |
| 运镜 | 硬切 + 相机抖动（跟底鼓）+ 切镜白闪 + RGB 撕裂 + 故障切片 | 幕间压黑淡入，长镜头连续运动 |
| 字 | 动能大字：0.14 秒从 1.5 倍砸到 1 倍，白芯 + 主色描边 + 拖影 | 字幕逐字显现 + 余晖 |
| 用途 | 首页头图 / 社媒开场 | 完整叙事 / 给人从头看一遍 |
| 索引页 | [`index.html`](./index.html)（两张卡片 + 规格对照） | 同左 |

两片共用的底层：20 万 GPU 粒子（顶点着色器里在「星云」与「符号点云」之间插值）、
片元着色器实时分形（牛顿 z³=1 ↔ 曼德博）、3D 线框（网格变形 / 神经网络 / 环面流形）、
半分辨率两级高斯 Bloom、色差 / 颗粒 / 暗角 / 扫描线。

## 一、怎么播

```bat
:: ① 最简单：直接双击（零外部请求，file:// 也能跑）
static\promo\index.html           :: 索引页，选一支
static\promo\short\index.html     :: 快闪版
static\promo\full\index.html      :: 完整版

:: ② 走站点（Docusaurus 的 static/ 会被原样发布）
npm start            打开  http://localhost:9452/promo/       :: 索引
                           http://localhost:9452/promo/short/ :: 快闪版
                           http://localhost:9452/promo/full/  :: 完整版
:: 顶栏「宣传片」入口也指向 /promo/

:: ③ 任意静态服务器指向这个目录都行
node scripts/promo/serve.mjs      :: 起一个 8788 端口的本地服务
```

> 站点侧说明：这三个页面在 `static/promo/` 下，**不是 Docusaurus 路由**，
> 靠 nginx 的 `index index.html` 解析目录。
> 顶栏那一项因此标了 `raw: true`，渲染成原生 `<a href>`（用 `<Link to>` 会被构建期断链检查拦下）。

开场是一张**演算纸卡片**（和站点首页同一套「演算纸 × 印章朱砂」视觉），
两个入口：**▶ 播放（带配乐）** / **🔇 静音播放**。
浏览器不允许页面自己出声，所以必须点一下 —— 这是 Web 音频的规矩，不是 bug。

### 快捷键（两支片子一样）

| 键 | 作用 | 键 | 作用 |
| --- | --- | --- | --- |
| `空格` | 暂停 / 继续 | `1`–`9` `0` `-` `=` | 跳到第 N 镜 / 幕 |
| `R` | 从头重播 | `←` `→` | 上一个 / 下一个 |
| `M` | 静音开关 | `F` | 帧率信息面板（默认关） |
| `Q` | 循环切换画质档（极致 → 标准 → 省电） | 双击画面 | 全屏 |

> 播放中**鼠标不动 2.5 秒，右下角控制条会自动隐去**（画面里只留内容），动一下就回来。
> 快闪版默认**开着**抬头显示（左上进度 + 13 个镜头刻度 + 左下秒表），按 `F` 可整层关掉。

## 二、录成真正的视频文件

### 1. 页面内置录屏（推荐，画质最好）

右下角 **● 录制** → **自动回到片头开始播** → 再点一次 **■ 停止录制** → 浏览器直接下载
`math-ladder-promo-<时间戳>.webm`（**1920×1080 · VP9 + Opus · 带配乐**）。

原理是 `canvas.captureStream(60)` + `MediaStreamAudioDestinationNode` 合成一条流交给
`MediaRecorder` —— 这是**编码**，不是生成，画面与声音依旧是页面实时算出来的。
（录制支路挂在压缩器之后、总音量之前：**就算你把页面静音，成片照样带配乐**。）

录之前建议：全屏（双击画面）、`F` 确认信息面板是关的、别动鼠标。

### 2. 转 mp4（兼容性最好）

```bat
ffmpeg -i math-ladder-promo-<时间戳>.webm ^
  -c:v libx264 -crf 19 -preset medium -pix_fmt yuv420p -r 60 -fps_mode cfr ^
  -c:a aac -b:a 192k -movflags +faststart out.mp4
```

`-r 60 -fps_mode cfr` 是必须的：MediaRecorder 出的是变帧率 webm，
不强制成固定帧率的话容器里会写上 `r_frame_rate=2000/1` 这种畸形值，部分播放器会卡。

### 3. 无头批量出片（CI 也能跑）

```bat
node scripts/promo/record.mjs --film short --transcode          :: 快闪版
node scripts/promo/record.mjs --film full  --transcode          :: 完整版
node scripts/promo/record.mjs --film short --quality 2 --w 1600 --h 900 --transcode
```

用 Edge/Chrome 无头模式 + CDP 驱动：自动点录制、播完、停录、把 webm 落盘到
`scripts/promo/out/`，`--transcode` 再交给 ffmpeg 出一版 constant 60fps 的 mp4。
（Chrome 偶尔来不及把 `.crdownload` 改名，脚本会等大小稳定后替它改名。）

> **本仓库里已经出好的成片**（`scripts/promo/out/`，已加 .gitignore 不入库）：
>
> | 文件 | 规格 |
> | --- | --- |
> | `math-ladder-promo-1080p.mp4` / `-web.mp4` | 完整版 · 1920×1080 · 60fps · AAC 立体声 · 104 MB / 51 MB |
> | `math-ladder-short-1080p.mp4` / `-web.mp4` | 快闪版 · 同规格 · 22.6 MB / 11.4 MB |
> | `*.webm` | MediaRecorder 原始产物（65 MB / 14.2 MB） |
>
> 无头环境是 SwiftShader **软件渲染**，只跑得到 20fps，所以这几份是「20fps 的内容装进 60fps 的容器」。
> **要真 60fps 的成片，请在浏览器里点「● 录制」。**

## 四、技术：它凭什么又炫又稳

```
┌─ WebGL 层（下层 · 光）─────────────────────────────────────────┐
│  ① 背景场：透视方格纸 + 纸纹噪点 + 暗角 + 脉冲环                  │
│  ② 粒子云：20 万点精灵，星云/符号两态在**顶点着色器**里插值        │
│  ③ 3D 线框：网格变形、神经网络（带脉冲传播）、环面流形             │
│  ④ 复数域：牛顿分形（z³=1 三片流域）↔ 曼德博，分数权重交叉淡入      │
│  ⑤ 后处理：亮部提取 → 半分辨率两级高斯 → 合成                     │
│     （色差·颗粒·暗角·扫描线；快闪版另加整帧抖动与故障切片）        │
└──────────────────────────────────────────────────────────┘
┌─ Canvas2D 层（上层 · 话）──────────────────────────────────────┐
│  公式（真上标/下标排版）· 坐标轴 · 曲线 · 黎曼矩形 · 单位圆 ·      │
│  高尔顿板 · 傅里叶本轮与解析轨迹 · 损失曲面 · 注意力矩阵 ·        │
│  六卷阶梯 · 字幕 / 动能大字 · 印章 · 抬头显示                     │
└──────────────────────────────────────────────────────────┘
```

**流畅的几条硬约束（改代码时别破坏）：**

1. **音频时钟是唯一真源**：`AudioContext.currentTime` 同时驱动音符调度与画面时间轴，
   掉帧不会让音画漂移；没有音频时退回 `performance.now()` 累积。
   快闪版更进一步——**分镜位置就是小节位置**，所以「节奏感」是结构给的，不靠调参。
2. **一个 rAF 循环**，`dt` 夹在 50ms 以内；粒子运动全在 GPU，CPU 每帧不做数组分配。
3. **Bloom 走半分辨率**，两轮 H/V 高斯；画质档 0 直接跳过，只留合成与暗角。
4. **自适应画质**：滚动平均帧时长 > 22ms 逐级降（20万→13万→4.9万粒子、渲染分辨率 1.0→0.7、关 Bloom），
   < 13.5ms 再升回去；手动按 `Q` 后 30 秒内不自动降级。
5. **带状态的幕/镜（高尔顿板、梯度下降）按 `dt` 推进**，暂停时 `dt = 0`，所以暂停/恢复不会跑飞。
6. **傅里叶轨迹是解析窗口不是逐帧累积**：任何帧率下画出来的都是同一段干净的方波。

**粒子是怎么变成字的**：把文字光栅化到离屏 canvas → 采样不透明像素 → 归一化成点云 →
作为顶点属性传给 GPU；着色器在「星云位置」与「目标点」之间按每颗粒子各自的延迟插值，
自由态只画 12% 的点（全画会糊成雪花噪点）。切幕/切镜时换一张点云纹理即可，CPU 不参与逐帧计算。

## 五、已经验过什么

| 检查 | 完整版 | 快闪版 |
| --- | --- | --- |
| 无头 Chromium 加载，控制台 | 零报错零警告 | 零报错零警告 |
| 逐幕/逐镜定格截图 | 12/12 出画 | 13/13 出画 |
| 整片真实播放 | 167.0s 播完自动停，无异常 | 45.57s 播完自动停，无异常 |
| 配乐电平探针（RMS） | 峰值 0.02–0.05 且起伏 | 峰值 0.26、随四踩强弱交替（在打拍子） |
| 500×900 竖屏 | 自适应不崩 | 自适应不崩 |
| 内置录屏启停 | 正常 | 正常 |
| 低配档（省电） | 软渲染下即达 60fps | 同左 |

> 软渲染下 1280×720 / 标准档约 20–46fps；**这些数字只说明逻辑正确，不代表真机**——
> 真机 GPU 上 20 万粒子 + 半分辨率 Bloom 是远低于预算的负载。

开发中修掉的 bug（都记在这里，别再踩）：跳幕起播给 `AudioParam` 传负数时间；
录制时音频图未初始化导致成片是哑片；傅里叶轨迹逐帧累积导致不同帧率下波形不同；
`bam()` 自带淡出导致「片名/落版标题」在 0.4 秒后消失；镜头里同一句大字画了两遍。
