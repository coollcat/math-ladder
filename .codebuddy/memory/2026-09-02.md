## 踩坑记录（重要）

- **辅助函数必须 exec 进 `_ml_console_g`**：enhancer 新增的 `execInConsole(source,{helpers})` 里，若用 `py.runPythonAsync(helpers)`，函数定义落在 Pyodide 全局命名空间，而单元代码是 `exec(code, _ml_console_g)`，`show()` 会 NameError。正确写法：`py.runPythonAsync('exec(compile(_ml_helpers_src,"<helpers>","exec"), _ml_console_g)')`。
- **公式 token 别用 `\u0000`**：Markdown 渲染先把 `$$..$$`/`$..$` 抽成 token 再排版最后换回 KaTeX。用 NUL 时构建链路（Rspack/SWC）会在日志刷 `Character { value: '?', raw: Some(Atom("\0")) }`，且一旦被吞掉、token 变空串，正则 `(\d+)` 会把正文里每个数字都当公式。改用私有区 `U+E000`（已验证产物里是 `RegExp("\uE000(\\d+)\uE000","g")`）。
- 那条 `Character {...}` 警告**是本仓库原有的**（与 KaTeX 的 unicodeTextInMathMode 警告一起出现），不是本次改动引入，构建 0 error。
- 动态 import 生效：katex 单独 270KB chunk、notebook 27KB、repo 9KB，都没进主包。
- 验证 Markdown 渲染器的办法：用 node 读源码截出 `renderMd` + 自建 `esc`，`new Function` 求值后喂假 katex 跑用例（不必起浏览器）。
