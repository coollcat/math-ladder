# 02 · 课程体系

## 一句话

**七卷 · 79 个章目录 · 1029 门正式课**，全部是 `docs/` 下的纯 markdown；每门课一个概念，用「九段式」写，用四种围栏承载交互，用三道闸门保证依赖顺序与「工具都有出生证明」。

## 门数口径（最容易算错的地方）

三个数字都真实存在，**指的完全不是一回事**：

| 数字 | 由谁输出 | 含义 |
| ---: | --- | --- |
| **1191** | `node scripts/validate.mjs` 结尾那行 `✔ N 门课…` | `docs/` 下**全部** `.md` 文件数（`1203`）减去 12 个 `COMPONENT_SPEC.md`。含 `docs/intro.md`、79 个 `index.md`、79 个 `999-references.md`、17 章 3 门导览课 |
| **1029** | `node scripts/check-chapter-sync.mjs` 的 `CHAPTER_INFO：78 章 / 1029 门课`；`gen-graph.mjs` 生成 `LESSON_COUNT` 也是这个数 | **正式课数**。`docs/NN-*/` 下的 `.md` 减去 `index.md` / `999-references.md` / `COMPONENT_SPEC.md`，**再排除第 17 章导览章的 3 门** |
| **78** | 同上 | `CHAPTER_INFO` 里的章数。79 个章目录减去第 17 章（导览章不入图谱/知识树/首页统计） |

推导一次就再也不会错：

```text
docs/ 下 .md 文件                     1203
  − COMPONENT_SPEC.md                  −12   → 1191  ← validate 报的就是这个
  − index.md                           −79
  − 999-references.md                  −79
  − docs/intro.md                       −1
  = 章目录内的课文件                   1032
  − 第 17 章导览课（不入图谱）           −3   → 1029  ← 正式课
```

三个脚本里同一套过滤规则各写了一份，改的时候三处必须一致：`validate.mjs` 的 `collectLessons`、`gen-graph.mjs` 的 `files` 过滤、`check-chapter-sync.mjs` 的 `SKIP_FILE`。

## 编号与目录规则

| 规则 | 说明 |
| --- | --- |
| 目录 | `docs/NN-slug/`，`NN` 两位章号 |
| 课文件 | `MM-slug.md`，`MM` 步长 10；插课用缝隙号（`15/25/45/55/62/65` 这类） |
| 冻结 | **00–17 冻结**：URL、`lesson_id`、`prereqs`、依赖深度都建立在上面，不重排 |
| 排序 | 侧边栏是 `sidebars.js` 的 `autogenerated`，顺序由目录与文件名的数字前缀决定，**不用手写 sidebar** |
| 路由 | 数字前缀被剥掉：`docs/01-arithmetic/40-division.md` → `/docs/arithmetic/division` |
| 章首页 | 每章一个 `index.md`，是**章节元数据（title/short/volume）的唯一源头**，也是本章课表 |
| 章尾 | 每章一个 `999-references.md`（编号 999 保证垫底），由 `references-data.json` 生成 |
| 组件档案 | 部分章有 `COMPONENT_SPEC.md`（12 个），是组件生产档案，**不计入课数** |
| 单文件长度 | 目标 ≤300 行；当前 1032 个课文件里超 300 行的有 21 个，中位数 210 行 |

词表校验分期：字段写了就查合法性（错就 error），没写先 warn；`chNum ≥ 18` 缺 `volume/layer/track` 即 error，卷一与 17 章豁免。

**方法准入**是本站的招牌规则：Python 里出现 `math.sqrt` / `sum()` / `import numpy` 之前，必须有更早的课把它「发明」出来。当前词表规模（扫全库 front matter 得到，正式数字以 `validate` 输出为准）：`math.*` 28 个、内置函数 9 个、import 根 11 个（含 `matplotlib.pyplot`、`numpy`、`scipy`、`torch` 等）。`validate.mjs` 逐行扫描每个 python/exercise 围栏，命中未登记的调用直接报错。

## 九段式

| # | 段落 | 要点 |
| --- | --- | --- |
| 1 | `## 1. 从一个场景开始` | 真实问题，三句话立起悬念 |
| 2 | `## 2. 直觉解释` | 类比 + 图示先行，不放公式 |
| 3 | `## 3. 正式定义` | KaTeX + 符号逐一列表 |
| 4 | `## 4. 分步例题` | 编号步骤，每步只做一件事 |
| 5 | `## 5. 动手实验` | viz/lab 在前，python 在后 |
| 6 | 练习 | 判题式 `exercise` 优先；概念题用 `<details>` |
| 7 | 选读 | `<details>` 标注「选读」，跳过不影响主线 |
| 8 | `## N. 下一站` | 一句话悬念 + 相对链接（带 `.md` 后缀） |

**段号同章必须一致，全站不统一是历史现状**（04 章 8 段、05/09/13 章 9 段；04 章内部还 8/9 混用）。写新课前查同章相邻课的段标题，照同章多数来。现有课文件的 `##` 数量分布：8 段 624 门、9 段 230 门、10 段 153 门、7 段 17 门，其余零星。完整模板与语料见 [LESSON_TEMPLATE.md](../LESSON_TEMPLATE.md)。

## 三道闸门

| 闸门 | 命令 | 查什么 | 会不会改文件 |
| --- | --- | --- | --- |
| 课程闭环 | `node scripts/validate.mjs` | front matter 必填项、id 唯一、prereqs 存在且更前、工具准入、viz/lab JSON + type 白名单 + 滑块规格、quiz 结构、exercise 元信息、`input()`、`999-references` 是否落后 | 否 |
| 章节信息同步 | `node scripts/check-chapter-sync.mjs` | 章首页 `title/short/volume` ↔ 生成物 `CHAPTER_INFO`；课数三方对账（磁盘 ↔ CHAPTER_INFO ↔ NODES）；`src/` 里是否又长出 `CH_TITLES` / `CH_SHORT` 手写表 | 否 |
| 机械体检 | `node mechanical-audit.cjs`（是 `npm run build` 的最后一步） | 每课 h2 源/产物数量比对、线上页面是否存在、Python compile（一次进程批量跑）、字面 `\{` `\}`、多行 `$$`、quiz 里出现 `$`、`input()` / `while True`、viz JSON 与 type、`<details>` 详解与 `@check` 脱节预警 | 否（需先有 `build/`） |

## 参考资料（论文 / 文献）

- **数据只改** `scripts/references-data.json`，然后 `node scripts/gen-references.mjs` 生成各章 `999-references.md`；`--check` 模式是闸门（`validate` 会调）。
- PDF 归档顺序不能反：`fetch-papers.mjs`（抓进 `static/papers/`）→ `gen-references.mjs`（磁盘上真有文件才写 `@local64`）。`static/papers/` 不入库，`scripts/papers-local.json` 入库。
- 链接纪律：**任何 `@f`（PDF）必须是机器验证过的链接，宁缺毋滥、不编造 ID**，拿不到就留 `@page`。当前 295 个 paper 围栏、82 个 `@pdf64`、`@local64` 为 0（本机无归档副本，PDF 按钮全部走原始出处）。找源方法与验证流程见 `UNIT_GUIDES/paper-links.md`。

## 内容生产流水线

1. **规划先行**：读 VISION（层级/支线/编号总表）+ LESSON_TEMPLATE + AGENTS；跨章专属组件先汇总清单再实现，防重复造轮子。
2. **集群生成**：多个子代理并行分区，按目录切分零重叠。
3. **整理线程**：汇总各区产物，统一术语 / front matter 体例 / 组件命名。
4. **批量对抗审核**：独立子代理只审不改——判题链实测、viz spec 对照渲染器、MDX 双坑体检、首现注释抽查、prereqs 顺序、h2 计数比对。
5. **终检合并**：问题回炉 → `validate` + `build` 全绿 + `mechanical-audit` 通过才算交付。

### 并发规程（多写手同批生产的硬约束）

- **共享规范先落文件**，成员 prompt 只要求「先读某某文件」，不把几千字规范复制进每个 prompt。
- 三条禁令：① **只写分配给自己的文件**，不碰任何 `index.md`、不碰已有课文的「下一站」链路；② 不跑 `npm run validate` / `npm run build`（并发会打架，由 main 统一跑）；③ 不写共享 memory 文件（并发追加会整文件互相覆盖）。
- **额度中断要主动探**：子代理可能中途被额度打断且零落盘，重活派发后要探一次进度。
- **审查组与写手组并行**：写完一组就派一个审查员打一组。
- **跨组重复由 main 拍板**：判据是「重叠面有多大」——一方顺手用工具、另一方系统讲授，就用螺旋编排（承认句 + 前向指引）缝上，**不改编号**。全站统一用 `:::note[与别章的分工]` 声明分工，不删课。

## 写课的两条自检（闸门查不到）

1. `@check` 的值必须是「按 `@hint` 改完后代码的**实跑输出**」。Python 的 `round` 是银行家舍入（`round(2.5)=2`），`int` 与 `float` 打印不同（`1` vs `1.0`）。
2. 正文里「初始代码会输出 X」的描述必须与实跑一致——学生一跑就穿帮。

判题比对带浮点容差：两段都能解析成有限数时按**相对误差 1e-9** 比，否则精确字符串相等。**容差不加绝对下限**——那会给接近 0 的期望值开口子。
