## 一、审查方法与可信度边界

### 1.1 方法

静态注册检查只能证明"类型注册了"，证明不了"能跑"。本次采用**三层递进**：

| 层 | 做法 | 回答的问题 |
| --- | --- | --- |
| L1 静态 | 解析全站 709 个 viz 围栏 JSON + 提取 `viz.js` 的 `RENDERERS` 注册表做差集 | 类型是否注册、JSON 是否合法 |
| L2 运行时 | 写最小 DOM 垫片（无 jsdom/canvas 依赖），加载**真实** `src/pyrunner/viz.js`，逐个挂载 709 个规格 | 渲染器是否抛异常 |
| L3 交互 | 挂载后自动触发：range 滑杆扫 min/中/max 三值、select 遍历选项、按钮点击、canvas 按下-拖动-抬起、resize 重绘 | 交互回调是否抛异常 |

垫片补齐了 `append/prepend/replaceChildren/closest/querySelectorAll`（含 `[attr*="v"]` 属性选择器与后代组合）、`canvas 2d` 上下文桩、`ResizeObserver`、`requestAnimationFrame`（带 4 层深度护栏）、`getComputedStyle`。

### 1.2 可信度边界（必须声明）

- **已验证**：JS 层异常、JSON 合法性、类型注册、交互回调不崩、表达式文法。
- **未验证**：像素级视觉效果、真实布局尺寸、主题色取值（垫片 `getComputedStyle` 返回空串，走 fallback）、动画观感、触摸事件。
- 因此本报告对"是否报错"高置信，对"好不好看"零结论——后者仍需人眼抽测。

### 3.2 【P0】10 处 viz 表达式缺陷（唯一需要立即处理的项）

| # | 文件 | 块 | 类型 | 表达式 | 页面实际显示 |

| 10 | `docs/49-generative-models/76-score-matching.md` | 2 | `slope-field` | `(-((y+2)*exp(-(y+2)^2/2))-(y-2)*exp(-(y-2)^2/2))/(…)` | Unary operator… |

#### 根因

`src/pyrunner/viz.js:319` 把表达式编译成 JS：

```js
const body = pre + 'return (' + src.replace(/\^/g, '**') + ');';
```

`^→**` 裸替换后，`-x^2` 变成 `-x**2`——**JS 语法禁止一元负号紧贴 `**`**（设计上就是为了让 `-x**2` 报错以免歧义）。而 `-x^2` 是数学里的常规写法，含义明确为 `-(x^2)`。

第 5 条是另一支：正文用了 Unicode 减号 `−`（U+2212），解析器的白名单 `'+-*/%^()'` 不认，抛「无法识别的字符」。

#### 影响面

- 9/10 集中在**高斯核相关表达式**（`exp(-x^2)`），即凡是画正态钟形曲线、高斯核、贝叶斯后验、score 场的地方都会踩中。
- 命中了全站最高价值的几章：49 生成模型（3 处）、39 贝叶斯（2 处）、47 Transformer（1 处）。
- `npm run validate` 与 `npm run build` **全部照绿**——这是典型的校验器盲区（与 `OPEN_ITEMS.md` §十一第 1 条同型）。

#### 修法（推荐 A，A 与 C 同时做）

| 方案 | 做法 | 评价 |
| --- | --- | --- |
| **A（推荐）** | 在 `viz.js` 编译前加一步表达式规范化：① Unicode 归一化（`−`U+2212 / `–` / `—` → `-`，`×`→`*`，`÷`→`/`，全角括号→半角）；② 一元负号处理——把幂运算底数前的一元 `-` 改写为 `(0-1)*`，或直接给整个幂底加括号 | 一劳永逸，作者继续写 `-x^2` 也不会踩坑；改动集中在 1 处，风险可控 |
| B | 只改这 10 处正文，给 `-x^2` 加括号 | 见效快，但陷阱留给下一个作者，且 `LESSON_TEMPLATE.md` 未警示 |
| **C（配套）** | 在 `scripts/validate.mjs` 加硬闸门：抽出所有 viz 的 `expr/f/expr2/dydx/rhs` 等表达式字段，用与 `viz.js` **同一套**编译函数试编译一次，失败即报错 | 把这类问题从"发布后才发现"前移到构建闸门 |

验收：修完后 §3.1 的 L2 冒烟应输出 `BAD=0`，且 `npm run validate && npm run build` 全绿。

**第 5 门（RWKV/SSM）的内容骨架建议**：

1. 场景：Transformer 的注意力是 $O(T^2)$，1M 上下文的账单长什么样
2. 直觉：把注意力"蒸馏"回循环——如果状态更新能做成线性的，就能像 RNN 一样 $O(T)$ 推理，又像注意力一样可并行训练
3. 定义：状态空间模型 $h_t = \bar A h_{t-1} + \bar B x_t,\ y_t = C h_t$；线性 RNN 的对角化形式
4. 三条路线对照：S4（结构化状态空间，卷积化并行训练）→ Mamba（选择性状态空间，让 $\bar B,\bar C$ 依赖输入）→ RWKV（注意力式加权衰减的线性 RNN，WKV 机制）
5. 实验：viz 组件对比「注意力矩阵热力图 vs 循环状态递推」的计算复杂度与感受野
6. 误区：线性 ≠ 弱；可并行训练 ≠ 可并行推理；RWKV 不是"去掉注意力的 Transformer"

### 6.4 写作硬红线

1. **零新知识**：总结页不得出现 `introduces_math` / `introduces_builtin` / `introduces_import` / `introduces_concepts` 任何非空项。

3. **MDX 双坑**：显示公式一律**单行顶格**；集合花括号用 `\lbrace` / `\rbrace`，禁写字面 `\{` `\}`。

7. **必须双向链接**：页首链回 `index.md` 与首课，页尾链回 `index.md` 与下一章。

## 九、复现本次审查的命令

```bat
npm run validate                  :: 基线闸门（全绿）
node mechanical-audit.cjs         :: h2 体检
```

下列三步即本次 L1–L3 的做法概要（脚本为临时产物，已清理）：

1. **L1 静态**：遍历 `docs/**/*.md` 取 ```` ```viz ```` 围栏 → `JSON.parse` → 与 `viz.js` 的 `RENDERERS` 键集做差集。
2. **L2 运行时**：把 `src/pyrunner/viz.js` 复制为 `.mjs` 后 `import`，在最小 DOM 垫片（实现 `append`/`closest`/`querySelectorAll`/`canvas 2d` 桩/`ResizeObserver`/`rAF`）上逐个构造 `pre.language-viz` 容器并调用 `enhanceViz`，收集渲染器写入的 `.ml-quiz__bad` 错误节点。
3. **L3 交互**：挂载后对组件内的 `input[type=range]`、`select`、`button`、`canvas` 派发事件，捕获回调异常。

> **给后续审查者的提醒**：L2 的假阳性几乎全部来自垫片缺口（首轮误报 395 处，全部是 `row.append is not a function`）。**看到批量同文案报错，先怀疑垫片，不要急着报缺陷**；真正的缺陷通常是"少量、文案各异、能指出具体文件"的那几条。
